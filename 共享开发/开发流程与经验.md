# 深空当铺模组开发流程与编程规范

这份文档只写实际开发里真正用得上的工程标准、宿主约束和排障要点。

---

## 1. 工程与代码设计原则

1. **最简单可维护优先**：一个功能尽量内聚在一个文件里，按自然职责拆分，不为“将来可能扩展”或“方便离线假测试”提前造抽象层。
2. **禁止防御性套娃**：
   - 不写无意义的 `*Policy.cs` / `*Seams.cs` / `*Bridge.cs` 机械分层；
   - 不为了防“虚构的第三方模组重入”而堆几百行票据栈、弱引用缓存、代际版本号和五重状态校验；
   - 宿主已经保证的单线程顺序调用，不需要额外加一堆再入布尔锁。
3. **异常策略：对内暴露，边界兜底**：
   - **禁止**在内部工具函数或业务逻辑里写 `try { ... } catch { }` / `catch { return false; }` 把错误吃掉；
   - 内部流程参数非法、对象缺失或配置损坏时，直接打 `LogError` 或抛明确异常，第一时间暴露问题；
   - 只在 Unity 生命周期回调（`Init`、`OnGameLoaded`、`Update`）和 Harmony 补丁最外层做 `try/catch`，捕获后必须记录完整异常信息（含堆栈），不静默吞错。
4. **能直写就别微雕 IL**：
   - 优先使用 `ModHook` 和原版公开方法；
   - 必须改原版逻辑时优先 Harmony `Prefix` / `Postfix`；
   - 只有在 Prefix/Postfix 确实无法切入的单一热点处，才用简明直接的 `Transpiler`，绝不把整个模块写成几十处操作码校验和状态机。

## 2. 《深空当铺》宿主与 Unity Mono 硬约束

1. **运行时与编译器**：游戏是 Unity Mono / .NET Framework 4.7.2，本机 .NET 10 SDK 仅作 Roslyn 编译器，编译引用一律取游戏当前 `Managed\` 目录下的 DLL。
2. **补丁重载必须写精确签名**：`DirectoryMaster.Item` 等宿主方法存在多个重载，不写参数类型表会触发 `AmbiguousMatchException` 并中断同批补丁注册。
3. **就绪与单例子对象访问**：
   - 检查 `PlayerStore` 时先判断 `PlayerStore.HasInstance`（直接读 `PlayerStore.Instance` 会自动实例化半初始化对象）；
   - `Init` 阶段场景和 `ModLoader.Mods` 尚未就绪，依赖目录/贴图/存档的注册必须挂在 `ModHook.OnGameLoadedNormal`（以及 `HotReloadActivate`）里，且要成对清理静态缓存和 UI 引用。
4. **物品与容器规则**：
   - 判注册：`DirectoryMaster.Has<GameItem>(id)`（不要用 `ItemSpawner.Spawn` 试探，它对无效 id 会返回空壳）；
   - 发放给玩家：`DirectoryMaster.Item(id, true)`；发给 NPC：`DirectoryMaster.Item(id, false)`；
   - 工厂预装子物品会被 `DirectoryMaster.Item` 剥除，机器内的便签/芯片必须在发放后塞入；
   - 精确投放：用 `GraphUtils.CanAccept(inv, item)` + `GraphUtils.TryAccept(inv, item)`，校验是否落入目标槽用引用比较 `item.parentInventory == targetInv`（`EmporiumTryAdd` 会自动兜底塞进背包）；
   - 品类扩展：只用 `EnableTag`，不要往 `SetGameItemType` 写入原版没有的类型（否则 Tooltip 查不到本地化键会刷蓝字 `[Translation Error]`）。
5. **真伪与成色铁律**：
   - 一律以 `ItemFeature.realCondition.identifier` 为准；
   - 物品名、显示文本、`fakeCondition` 全部属于公开伪装层，绝不参与任何业务判定。
6. **存档兼容**：
   - 不修改原版存档数据结构；
   - 模组状态写入自己的私有键，旧存档缺键时平滑走默认值。
7. **热重载兼容**：
   - 入口实现 `HotReloadPrepare()` / `HotReloadActivate()`，清理静态缓存、重新注册物品与立绘；
   - 避免对运行期动态 `Type` 做 `GetMethods` / `AccessTools.Method`（会被加载器标为 `reflection-external`）。

## 3. 编译、权限扫描与发布闭环

1. **本地编译**：统一用 [Build-Mod.ps1](../工具库/build/Build-Mod.ps1)：
   - 日常开发：`.\工具库\build\Build-Mod.ps1 -Mod Arcade`（默认输出到 `深空电玩\build\latest\`，支持直接覆盖；加 `-Install` 自动同步 DLL、Textures、Books 到游戏目录）；
   - 群友模组：`.\工具库\build\Build-Mod.ps1 -Mod Freya`；
   - 正式发布候选：`.\工具库\build\Build-Mod.ps1 -Mod Arcade -PublicRelease -Scan`。
2. **能力与权限要求**：
   - 开发版允许保留磁盘贴图自愈（`files` 能力）；
   - 正式发布候选（`-PublicRelease`）必须在编译期彻底剔除所有文件读写、反射外部和网络代码；
   - 正式包 `manifest.xml` 必须保留自闭合 `<Capabilities/>`（缺该节点会被 ModLoader 报错拒载），并经 [Test-ArcadeLoaderScan.ps1](../工具库/build/Test-ArcadeLoaderScan.ps1) 确认能力为空。
3. **打包出货**：使用 [New-ArcadeReleasePackage.ps1](../工具库/build/New-ArcadeReleasePackage.ps1) 生成干净的发布目录，只包含 `manifest.xml`、零能力 `DeepSpaceArcade.dll`、`Textures\`、`Books\`，不夹带 `src/`、`tests/`、`writing/`、`art/`、`evidence/`、`archive/` 或临时文件。

## 4. 测试与真机验证要点

1. **离线回归**：运行 `.\工具库\regression\Run-Regression.ps1`，只保留面向真实行为和核心不变量的测试（如 `appraisal` 浮窗/判定/翻新、`texts` 台词与立绘字节校验）。新增测试统一放 `<项目>\tests\`，严禁写绑死源码字面量的字符串匹配断言。
2. **真机验证**：
   - 始终在 Slot 1 测试，**绝不进入或写入 Slot 0 主档**；
   - 游戏启动走 `steam://rungameid/4348910`（不带命令行参数）；
   - 通过 `深空桥接器`（`ModDevBridgeNext`）做状态读取、热重载、机器快进与探针调用；涉及游戏自绘 `PixelWindow` 槽位拖拽时，可使用 `工具库\probes\ps-modbridge\native-input.ps1`；
   - 装机同步必须包含 `Textures\` 和 `Books\`（不能只拷 DLL，否则冷启动缺少贴图）。
3. **排障分清层次**：源码修改 → 编译产物 → 磁盘落盘 → 游戏实际加载哈希（`mod-audit.log`）→ 实机行为表现。遇到异常先核对加载哈希，再查业务日志。
