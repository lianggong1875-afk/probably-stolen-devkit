# 云备份说明

本地工作区是唯一全量备份源，云端三个私有仓库是它的分片镜像。

## 三个仓库

| 仓库 | 内容 | 历史 |
| --- | --- | --- |
| [probably-stolen-devkit](https://github.com/lianggong1875-afk/probably-stolen-devkit) | `共享开发/`（经验库、开发流程与规范、AI 技能库）+ `工具库/` + `深空桥接器/` + `AGENTS.md` / `README.md` | 每次同步一个新快照提交，连续累积 |
| [deepspace-arcade](https://github.com/lianggong1875-afk/deepspace-arcade) | `深空电玩/`，即 `deepspace_arcade` / `DeepSpaceArcade.dll` | 用 subtree 拆出的真实开发历史 |
| [probably-stolen](https://github.com/lianggong1875-afk/probably-stolen) | `深空当铺：可能是群友/`，即 `freya_cornell` / `DeepSpacePawn.dll` | 同上 |

三个仓库都是 **private**，所有者 `lianggong1875-afk`。

## 同步

```powershell
# 先看会做什么
pwsh -File .\共享开发\云备份.ps1 -DryRun

# 全量同步
pwsh -File .\共享开发\云备份.ps1

# 只同步某一个
pwsh -File .\共享开发\云备份.ps1 -Target devkit
pwsh -File .\共享开发\云备份.ps1 -Target arcade
pwsh -File .\共享开发\云备份.ps1 -Target pawn
```

同步前记得先把本地改动提交：`git add -A; git commit`。devkit 导出的是 `HEAD` 的内容，未提交的改动不会上云。

## 机制

- **devkit**：`git archive HEAD` 精确导出目标目录，覆盖到 `缓存文件夹\cloud-repos\devkit` 的工作副本（该副本保留自己的 `.git`，所以历史连续），提交后推送。首次运行会从远端克隆，续上已有历史。
- **arcade / pawn**：`git subtree split --prefix=<目录> -b cloud/<名字>` 把该目录的提交历史拆成独立分支，推送到远端 `main`，然后删掉临时分支。所以这两个仓库的提交历史是真的开发历史，不是快照。

## 边界

- `缓存文件夹\`（反编译产物、临时输出、云备份工作副本）和 `Git仓库\`（本地 Git 对象库）**不上云**，已在 `.gitignore` 里。
- `工具库\body-locator\models\*.pt`（109 MB 模型）和 `工具库\build\ilspycmd\.store\` **不上云**，同样被忽略。要备份它们得单独传网盘或走 Git LFS。
- 单文件都在 2.3 MB 以下，没有触碰 GitHub 的 100 MB 单文件上限。

## 凭证

推送走系统 Git Credential Manager 里已保存的 GitHub 账号，脚本不读取、不写任何 token。

环境里还装了 `gh` CLI（2.106.0，在环境 `npm-prefix` 里），但系统那个 token 缺 `read:org` scope，`gh auth login` 会拒绝。建仓库、查状态直接走 GitHub API 或 `git` 就行，不需要 gh。

## 恢复

任意一个云端仓库都能单独克隆出可用内容：

```powershell
git clone https://github.com/lianggong1875-afk/deepspace-arcade.git
```

还原整个工作区时，把三个仓库的内容按上表放回各自目录，再补回 `缓存文件夹\` 里需要的东西即可。
