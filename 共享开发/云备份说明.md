## 同步

> ⚠️ 本机**只有 Windows PowerShell 5.1，没有 `pwsh`（PowerShell 7）**。下面统一用 `powershell`。

```powershell
# 先看会做什么
powershell -NoProfile -ExecutionPolicy Bypass -File .\共享开发\云备份.ps1 -DryRun

# 全量同步（默认同步 main 分支）
powershell -File .\共享开发\云备份.ps1

# 只同步某一个
powershell -File .\共享开发\云备份.ps1 -Target devkit
powershell -File .\共享开发\云备份.ps1 -Target arcade
powershell -File .\共享开发\云备份.ps1 -Target pawn

# 同步某条功能分支（云端会建同名分支，等于本地刚开分支就有一份异地副本）
powershell -File .\共享开发\云备份.ps1 -Branch feat/arcade-burner-animation
```

分支协同的用法见 [分支与备份规范](分支与备份规范.md)：`New-FeatureBranch.ps1` 会自动调上面最后那条，把新分支推上云。

同步前记得先把本地改动提交：`git add -A; git commit`。devkit 导出的是**该分支 HEAD** 的内容，未提交的改动不会上云。

## 机制

- **devkit**：`git archive <分支>` 精确导出目标目录，覆盖到 `缓存文件夹\cloud-repos\devkit` 的工作副本（该副本保留自己的 `.git`，所以历史连续），提交后推送。首次运行会从远端克隆，续上已有历史。
- **arcade / pawn**：`git subtree split --prefix=<目录> <分支的 rev> -b cloud/<名字>` 把该目录的提交历史拆成独立分支，推送到远端**同名分支**（`-Branch main` 时就是原来的 `main`），然后删掉临时分支。所以这两个仓库的提交历史是真的开发历史，不是快照。
- **远端分支**：`-Branch <名字>` 决定推云端哪个分支，主仓库和两个模块仓都会建同名分支。默认 `main`，行为与以前完全一致。

## 还有一路：本地多路备份

云端只管"异地"，**本地还必须有第二份**（云端仓库被误删、断网、账号出问题时它就是唯一的）。由 `工具库\build\Backup-All.ps1` 负责：

```powershell
.\工具库\build\Backup-All.ps1                          # 裸仓镜像 + bundle + 资产包
.\工具库\build\Backup-All.ps1 -MirrorRoot "E:\backup\ps-git"   # 指定另一块盘
```

- ① **裸仓镜像**：`git push --mirror` 到另一块物理盘的裸仓库（全部分支 + 全部 tag）
- ② **bundle**：`git bundle create --all` 成一个单文件（可拷网盘/移动硬盘）
- ③ **资产包**：美术与文案打 zip + SHA-256 清单

详见 [分支与备份规范](分支与备份规范.md) 第 4 节。

## 边界

- `缓存文件夹\`（反编译产物、临时输出、云备份工作副本）和 `Git仓库\`（本地 Git 对象库）**不上云**，已在 `.gitignore` 里。
- `工具库\body-locator\models\*.pt`（109 MB 模型）和 `工具库\build\ilspycmd\.store\` **不上云**，同样被忽略。要备份它们得单独传网盘或走 Git LFS。
- 单文件都在 2.3 MB 以下，没有触碰 GitHub 的 100 MB 单文件上限。

## 凭证

推送走系统 Git Credential Manager 里已保存的 GitHub 账号，脚本不读取、不写任何 token。

环境里还装了 `gh` CLI（2.106.0，在环境 `npm-prefix` 里），但系统那个 token 缺 `read:org` scope，`gh auth login` 会拒绝。建仓库、查状态直接走 GitHub API 或 `git` 就行，不需要 gh。

## 恢复

任意一个云端仓库都能单独克隆出可用内容：

```powershell
git clone https://github.com/lianggong1875-afk/deepspace-arcade.git
```

还原整个工作区时，把三个仓库的内容按上表放回各自目录，再补回 `缓存文件夹\` 里需要的东西即可。
