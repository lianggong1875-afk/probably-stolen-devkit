# 分支、门禁与多路备份规范

> 什么时候读：**每次开工前**、**每次合并前**、**每次发布前**、**任何一次"我好像把东西弄丢了"之后**。
> 配套脚本：`工具库\build\New-FeatureBranch.ps1`、`工具库\build\Invoke-PreMergeGate.ps1`、`工具库\build\Backup-All.ps1`，云端同步仍是 `共享开发\云备份.ps1`（已支持 `-Branch`）。

---

## 0. 一句话总则

**主干永远可编译、可运行、零能力达标；一切新东西先进分支，过五道门禁才回主干；代码、美术、历史三样各有多路备份，任何单点损坏都能恢复。**

---

## 1. 分支模型

工作区是**一个仓库装三个项目**（深空电玩 / 可能是群友 / 工具与经验库），所以分支是**工作区级**的，用前缀区分是哪个项目的事。

| 分支 | 用途 | 允许直接提交 | 生命周期 |
| --- | --- | --- | --- |
| `main` | **主干**。永远可编译、真机可跑、零能力达标 | ❌ 只接受合并 | 永久 |
| `feat/<域>-<短句>` | 新功能。域 ∈ `arcade` / `freya` / `tools` / `kb`（知识库） | ✅ | 合并后删除 |
| `fix/<域>-<短句>` | 修 bug | ✅ | 合并后删除 |
| `docs/<域>-<短句>` | **纯文档**改动（经验库、PROGRESS、规范本身，不含代码） | ✅ | 合并后删除 |
| `exp/<主题>` | 实验性（可能永远不进主干，比如"试试换掉 ES3"） | ✅ | 结论出来就删，结论进经验库 |
| `release/vX.Y.Z` | 发布候选（要上工坊时开） | ✅（只放版本号/简介/封面这类发布物） | 发布后合回 main 并删 |

命名规则：
- 全小写、连字符分词、**不写中文**（避免跨平台/工具链编码问题）
- 一眼能看出改哪个项目：`feat/arcade-burner-animation`、`fix/freya-siren-purity`、`docs/kb-batch6`、`feat/tools-conflict-export`
- 一个分支只做一件事。**发现要顺手改别的项目 → 另开分支**（这是"两项目互不引用"的延伸）

```powershell
git switch -c feat/arcade-burner-animation
```

## 2. 一次功能开发的完整流程（照这个走）

```text
① 开分支（本地）        git switch -c feat/<域>-<短句>
② 开分支（云端）        .\工具库\build\New-FeatureBranch.ps1 -Name feat/<域>-<短句>
                        （把本地分支推到云端同名分支，等于多一份异地副本）
③ 写代码 / 画图 / 写文案
   每完成一小块就 commit    git add -A; git commit -m "feat(arcade): ..."
④ 自测（本地）          .\工具库\build\Build-Mod.ps1 -Mod Arcade
                        .\工具库\build\Build-Mod.ps1 -Mod Arcade -PublicRelease -Scan
                        .\工具库\regression\Run-Regression.ps1
⑤ 冲突扫描              python .\工具库\workshop-tools\conflict_scan.py --dir 深空电玩\src ... --out 缓存文件夹\conflict.md
⑥ 过门禁                .\工具库\build\Invoke-PreMergeGate.ps1 -Mod Arcade
                        （五道门禁全绿才允许合并，见第 3 节）
⑦ 真机验证（Slot 1）    按 04-真机测试与探针 走；**只进 Slot 1，绝不碰 Slot 0**
⑧ 回主干                git switch main
                        git merge --no-ff feat/arcade-burner-animation
⑨ 更新账本              PROGRESS.md（版本快照 + SHA + 实测结论）、经验库（新坑/新 API）
⑩ 打标签 + 上云          git tag -a v0.2.3 -m "..." ; .\共享开发\云备份.ps1 -Branch main
                        再 .\工具库\build\Backup-All.ps1（本地裸仓 + bundle + 资产包）
```

**关键约束**：
- **② 和 ⑩ 都不能省**。"开分支就上云"保证的是"本地硬盘炸了还有分支在云端"；"合并后打 tag + 本地裸仓"保证的是"云端仓库被误删/覆盖还有本地另一份"。
- ③ 里的 commit 要**小而清**：一个 commit 一件事，消息写"为什么"而不是"改了什么"。
- ⑦ 之前的 ①②③④⑤⑥ 都可以重来；⑦ 之后就不要在分支上乱改了——真要改，回 ③ 再走一遍。

## 3. 五道门禁（合并前必须全绿）

脚本 `工具库\build\Invoke-PreMergeGate.ps1` 会按顺序全跑一遍，任何一道红就停下并打印失败的原始输出。

| # | 门禁 | 命令 | 判定 |
| --- | --- | --- | --- |
| 1 | 开发版编译 | `Build-Mod.ps1 -Mod <Arcade\|Freya>` | 0 错误 0 警告 |
| 2 | 正式候选 + 零能力扫描 | `Build-Mod.ps1 -Mod <..> -PublicRelease -Scan` | 输出含 `Refused: False` 且 `Capabilities:` 后为空 |
| 3 | 离线回归 | `Run-Regression.ps1` | `ALL SUITES PASS`，fail=0 |
| 4 | 跨模组冲突扫描 | `conflict_scan.py`（我们 + 已装模组） | **ERROR 数 = 0**（WARN 允许，但要在 PROGRESS 里写明理由） |
| 5 | 工作区洁净 | `git status --short` | 空（或只有明确要带的未跟踪文件） |

**真机验证（Slot 1）不进门禁脚本**——它需要人进游戏，脚本替不了。但**发布到工坊之前必须有真机结论**，没验就写"未真机验证"，不许含糊。

**评审**（多人/多窗口协作时）：合并前按 `code-review` 技能的两轴各看一遍——
- **Standards**：是否违反 AGENTS.md 的六条硬规范（简单直白 / 异常策略 / Harmony 与生命周期 / 物品铁律 / 零权限 / 真测试）；
- **Spec**：是否真的做完了当初要做的那件事（拿 PROGRESS 里的验收条目逐条对）。

## 4. 多路备份（四路，缺一路就不算备份）

美术与文案是**不可再生资产**（重画一遍的成本远高于重写代码），所以备份策略必须针对"最不可替代的东西"设计。

| 路 | 内容 | 频率 | 位置 | 恢复方式 |
| --- | --- | --- | --- | --- |
| **① 本地工作区 + git** | 全部源码/美术/文档的历史 | 每次 commit | `D:\0深空当铺模组开发` + `Git仓库\`（190 MB） | `git checkout <tag/branch>` |
| **② 云端三仓** | `devkit`（共享开发+工具库+桥接器）/ `deepspace-arcade` / `probably-stolen` | 每次合并到 main 后 | 三个私有 GitHub 仓库 | `git clone` 任一仓 |
| **③ 本地裸仓镜像** | 整个仓库的**全部分支与标签** | 每周 / 每次发布 | **另一块物理盘**（当前盘出问题也不怕） | `git clone <镜像路径>` |
| **④ bundle 单文件** | 同上，压成一个 `.bundle` | 每次发布 | 网盘 / 移动硬盘（`缓存文件夹\backups\`） | `git clone repo.bundle` |

另有**资产专用包**（第 ⑤ 路，建议每次美术有改动就打）：

| 路 | 内容 | 说明 |
| --- | --- | --- |
| **⑤ 美术/文案资产包** | `深空电玩\Textures`、`深空电玩\art`、`群友\Textures`、`群友\art`、`群友\writing`、`Books` | 打 zip + 生成 SHA-256 清单，和 git 无关（即使 git 全毁也能从 zip 复原图） |

一键跑 ③④⑤：

```powershell
.\工具库\build\Backup-All.ps1                       # 默认全做
.\工具库\build\Backup-All.ps1 -SkipAssets           # 只做仓库备份
.\工具库\build\Backup-All.ps1 -MirrorRoot "E:\backup\ps-git"
```

**不备份的东西**（故意的，别喂给备份脚本）：
- `缓存文件夹\`（反编译产物、云备份工作副本、gh.zip…）——都是可再生
- `工具库\body-locator\models\*.pt`（109 MB 模型）、`工具库\build\ilspycmd\.store\`——体积大且可重新下载
- `Git仓库\`（它本身就是路①的载体，复制它请用 ③ 的镜像方式而不是直接拷贝）

### 4.1 ⚠️ 备份必须做"恢复演练"，否则等于没备份（2026-11-27 实测踩到）

第一次把裸仓镜像跑通时，脚本报"OK、186.7 MB、main + 2 tag + 52 提交全在"，看起来完美。但真去 `git clone` 一次，得到的是**空工作区**：

```
warning: remote HEAD refers to nonexistent ref, unable to checkout
fatal: your current branch 'master' does not have any commits yet
```

**原因**：`git init --bare` 的默认 HEAD 是 `refs/heads/master`，而我们的分支是 `main`；`git push --mirror` **只同步 refs，不修正裸仓的 HEAD 符号引用**。于是数据全在、但 clone 不知道该检出哪条分支 → 工作区空。

**修法**（已写进 `Backup-All.ps1`）：
1. `git init --bare --initial-branch=main`（git 2.28+；本机 git 2.56.1 支持）
2. push 之后再强制一次 `git -C <bare> symbolic-ref HEAD refs/heads/main`
3. 同步完成后检查 `symbolic-ref --short HEAD` 是否为 `main`，不是就 Warn

**纪律**：每次改过备份脚本、或换过备份介质（新 U 盘 / 新盘），**必须真 clone 一次做恢复演练**，至少核对三样：
```powershell
git clone <镜像或 bundle> $tmp
git -C $tmp branch --show-current        # 必须是 main（不是 master）
git -C $tmp log --oneline -1             # 必须是最新提交
Test-Path "$tmp\深空电玩\src\ArcMarket.cs"   # 关键目录必须真有文件
```
演练完记得删临时目录。**"文件存在"和"能恢复"是两件事**，和编译产物那条是同一个道理。

### 4.2 本机实际备份位置（2026-11-27 实测）

| 路 | 位置 | 状态 |
| --- | --- | --- |
| ①/②/⑥ | `D:\0深空当铺模组开发` + `Git仓库\` | 主仓，190 MB / 2560 跟踪文件 |
| ③ 裸仓镜像 | **`E:\backup\ps-git\ps-workspace.git`**（U 盘 `USSD SMI` 116 GB） | ✅ 186.7 MB，HEAD=main，main + 全部 tag 都在 |
| ④ bundle | `E:\backup\ps-files\ps-workspace-<时间>.bundle`（另在 `缓存文件夹\backups\` 留 5 份） | ✅ 186.5 MB，verify 通过 |
| ⑤ 资产包 | `E:\backup\ps-files\ps-assets-<时间>.zip` + `.sha256.txt` | ✅ 152.5 MB + 71 KB 清单 |

**U 盘单独可恢复**：已实测从 `E:\backup\ps-git\ps-workspace.git` 克隆 → main / 54 提交 / 2 tag / 2560 跟踪文件 / 关键路径全部存在。

`Backup-All.ps1` 不带 `-MirrorRoot` 时会自动按 `Z: Y: E: F: G:` 找第二块盘，**现在会自动命中 E 盘**（工作区在 D 盘）。

## 5. 标签与版本

- **每次合并到 main 打一个 tag**（轻量里程碑）+ **每次发工坊打一个 annotated tag**：
  ```powershell
  git tag -a v0.2.3 -m "arcade 0.2.3: 刻录机动画 + 冲突加固"
  git tag -a distill/batch-6 -m "蒸馏第六批：7 个大型玩法模组"
  ```
- tag 必须**随分支一起推上云**（`云备份.ps1 -Branch main` 会带 `--tags`）。
- tag 与工坊发布的对应关系写进各项目 `PROGRESS.md` 的回执表（已有 r1/r2/r3 格式，继续加一列 tag 即可）。

## 6. 回滚与恢复（三种场景，照做就能救回来）

**场景 A：改坏了，还没合并** → 直接丢分支。
```powershell
git switch main
git branch -D feat/arcade-burner-animation
# 云端那份也删掉（可选，留着也无害）
```

**场景 B：合并后才发现坏了** → 用 `revert` 造一个反向提交（**不要 `reset --hard`**，会改写历史、让云端和本地对不上）。
```powershell
git log --oneline -5              # 找到那次合并
git revert -m 1 <merge-commit>    # 反向撤销整个合并
```

**场景 C：工作区或 `.git` 物理损坏** → 从备份恢复。
```powershell
# 从本地裸仓镜像
git clone "E:\backup\ps-git\workspace.git" "D:\0深空当铺模组开发-new"
# 或从 bundle
git clone "缓存文件夹\backups\ps-workspace-<日期>.bundle" "D:\...-new"
# 或从云端（只有 main + 已推的分支/标签）
git clone https://github.com/lianggong1875-afk/deepspace-arcade.git
```
恢复后**第一件事**：核对三个项目的 `build\public` DLL SHA-256 与 `PROGRESS.md` 记录是否一致（证明拿到的确实是那一版）。

## 8. 三张检查清单（打印出来贴墙上）

**开工前**
- [ ] 我在 `main` 上且是干净的（`git status` 空）
- [ ] 本地分支已建：`git switch -c feat/<域>-<短句>`
- [ ] 云端分支已建：`New-FeatureBranch.ps1 -Name ...`
- [ ] 知道这次要改哪个项目的哪个功能，以及"做完的判定标准"是什么

**合并前**
- [ ] `Invoke-PreMergeGate.ps1 -Mod <..>` 五道全绿
- [ ] 没违反 AGENTS.md 六条硬规范（尤其：没有空 `catch {}`、重载方法写了 `new Type[]{...}`）
- [ ] `PROGRESS.md` 与经验库已更新（新坑、新 API、新规范）
- [ ] 需要真机的部分，明确写了"已验/未验"

**发布前**
- [ ] 真机 Slot 1 跑通（**Slot 0 一次都没碰**）
- [ ] 打 tag：`git tag -a vX.Y.Z -m "..."`
- [ ] 上云：`云备份.ps1 -Branch main`（带 `--tags`）
- [ ] 本地备份：`Backup-All.ps1`
- [ ] 发布包零能力校验 + 封面 1280×720 + 包内无多余扩展名
- [ ] **用户已确认**可以上传
