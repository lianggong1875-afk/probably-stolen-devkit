# 12 立绘引擎、高清道具与配音资源架构

**什么时候读它**：要理解 Portrait Studio 引擎底层怎么扫描与渲染立绘、要给模组加「高清去像素化」、要做高清道具图标与图集裁切、或者要给自定义 NPC/台词接配音时。

**来源**：反编译蒸馏 `PortraitStudio`（工坊 `3829932963`，152 个源码文件）与 `PortraitStudio.AuthorKit`（工坊 `3840289739`，立绘 SDK / 便捷立绘管理器 / 道具切图工具 / 配音 SDK）。

## 一、Portrait Studio 引擎的三层角色发现机制

引擎在 `CharacterCatalogRuntime.Refresh()` 里拼装「角色来源目录」，实际有**三条并行路径**（之前 08 号文档早期只看到白名单，2026-11-26 完整反编译后确认是三层）：

| 发现路径 | 引擎源码位置 | 扫描原理 | 模组侧代价 | 效果 |
| --- | --- | --- | --- | --- |
| **1. Mono.Cecil IL 扫描** | `CharacterCatalogRuntime.Scan(TypeDefinition, modId, name)` | 遍历已启用模组 DLL 内全部方法体，找 `stfld StoreClient::spriteName` 且**紧邻前一条指令为 `ldstr`** 的字符串字面量，记为该模组拥有该 sprite key | **零能力、零运行时开销**：只需在永不调用的静态方法里写朴素 `client.spriteName = "key";` | 角色在「人物来源」里准确归属到本模组，不掉进「来源未识别」 |
| **2. 特性式补丁发现** | `HasSpriteDictGetSpritePatch(folder)` | 扫 DLL 的 `CustomAttributeData`，找目标类名为 `SpriteDict` 且方法名为 `"GetSprite"` 的 `[HarmonyPatch]` | 零能力，但多一条游戏更新易炸的 Harmony 缝 | 列入 `DirectSpritePatchIds`，视为可选图源 |
| **3. 协议注册 + 历史白名单** | `RegisterProvider(id, name)` + `OfficialWriterHost` / `OfficialManagedHost` | 识别声明了 `portrait-studio-provider.json` / `static-v1` / `managed` / `dynamic` 协议的模组（外加一批早期工坊模组硬编码表） | 独立立绘包通常需 `files` 能力；托管/动态协议需编入 SDK | 开放 Studio 接管该角色立绘的写图权（换装、选候选、构图） |

### 工程判断口诀

- **只想「我画的独立角色在 Studio 目录里被正确归属，且不交出表情差分控制权」** → 走路径 1（IL 字面量声明，如深空电玩的 `ArcPortraitDeclaration.cs`）。**绝不要把声明“优化”成数组循环或查表**，否则 IL 变成 `ldelem.ref` + `stfld`，直接扫描失效。
- **确定要让玩家在 Studio 里替换我们 NPC 的立绘** → 才走路径 3（`static-v1` / `managed` / `dynamic`）。
- **为什么路径 1 不会干扰模组自带的表情差分**：Studio 必须通过 `ModHelper.SendMessage(providerId, "static-v1", …)` 走 `acquire` 会话才能获得写图权，且依赖来源主动注册 `ModHelper.OnMessage(providerId, "PortraitStudio:static-v1", cb)` 与 `ModHelper.Expose(providerId, "portrait-studio-static-active/1", …)`。未注册这两个通道时，Studio 对你的 key 是纯只读目录。

## 二、跨模组协议总线架构（`ModHelper.Expose` + `OnMessage/SendMessage`）

Portrait Studio 的 `PortraitStudio.ManagerStatic` 是目前工坊里**最成熟的跨模组弱耦合通信架构**，核心构件完全基于原版 `ModHelper`（不需要互相引用 DLL）：

1. **服务发现用 `ModHelper.Expose` / `ModHelper.Lookup<T>`**：
   - 暴露带版本号的委托键，例如 `ModHelper.Expose(modId, "portrait-studio-static-active/1", (Func<string>)GetActiveJson)`。
   - 停用/热重载时必须 `ReferenceEquals` 核对后再置空（`ModHelper.Expose(modId, key, null)`），防止误清别人的注册。
2. **命令与事件用 `ModHelper.SendMessage` / `OnMessage` / `OffMessage`**：
   - JSON 信封走版本号通道（`static-v1`、`managed`、`dynamic`）。
   - `MessagePump` + `WriterTransaction` 用两阶段事务（`Plan` → `Reserve` 显存预算 → `BeginPrepare` → `Commit` / `Cancel` / `Rollback`）处理多候选切换，超时自动过期（`Expired`），防止某一方异常导致画面卡死。
3. **磁盘预处理缓存（`PortraitDiskCache`）**：
   - 解码后的 RGBA 像素按 `SHA256("static-rgba-v1|" + 路径 + "|" + 大小 + "|" + LastWriteTimeUtc + "|" + 几何参数)` 落盘到 `ModHelper.GetModDataFolder(modId)\cache\portraits-v1\<64hex>.rgba`。
   - 先写 `.tmp-<guid>` 再原子替换，总容量硬限 256 MiB（`268435456L`），写入前做路径逃逸检查（`PortraitCacheCleanup.Inside`）。

## 三、零反射跨模组高清去像素化（场景节点租约模式）

原版在低分辨率或开启像素完美时，由 `EmporiumEntry.Instance.pixelPerfectCamera` 对整个店内画面先降采样再放大，高清立绘和精细道具图标会被糊成马赛克。

直接粗暴改 `pixelPerfectCamera.enabled = false` 的坑在于：**两个模组同时开关时会互相打架，谁先关闭就把玩家原版设置改丢了**。

`PortraitStudio.AuthorKit` 的 `StandaloneHighResolution.cs` 给出了一个**零反射、零能力、跨独立 DLL 自动协同**的标准租约范式（已提取为模板 `工具库/templates/mod-patterns/HdCameraLease.cs`）：

```csharp
// 核心思想：借用 Unity 场景树当共享引用计数器
// 1. 在 pixelPerfectCamera.transform 下找共享节点 "PortraitStudio.AuthorHD.Leases"
// 2. 如果相机本来就是关的且没有租约根节点 → 不介入（尊重玩家或原版已关闭状态）
// 3. 需要高清时，在共享节点下挂一个空子 GameObject 作为自己的 token，并每帧维持 camera.enabled = false
//    （游戏在切焦点或改分辨率时会重新启用相机，所以 Tick 里要护持）
// 4. 不再需要或 OnDisable 时销毁自己的 token；当 root.childCount == 0 时：
//    先把 root 重命名为 ".released"（因为 Unity Destroy 延迟到帧末才生效！），销毁 root，
//    再调用 EmporiumOption.Instance.ApplyPixelPerfectCamera() 恢复玩家当前的真实设置。
```

**关键防坑**：Unity 的 `Destroy(go)` 到帧末才真正移除，所以释放最后一个租约前必须立刻改名 `root.gameObject.name = LeaseRoot + ".released"`，避免同一帧里别的模组 `Find(LeaseRoot)` 拿到将死的节点。

## 四、高清道具图标与图集切图规范

源自 `PortraitStudio.AuthorKit\道具\高清道具图标案例.md` 与 `cut_atlas.py`，做高清非像素物品时记住**三分离原则**：

### 1. 贴图、显示、占格三分离
- **贴图**：保留裁切后的高分辨率原图；高清非像素图可开 mipmap + 三线性过滤（`FilterMode.Trilinear`）；像素风原图则必须在 `ModHook.OnModAssetsLoaded` 里把 `mod.Sprites` 与 `mod.PaperSprites` 统一设为 `FilterMode.Point` 防止发糊。
- **显示 PPU 精确公式**（游戏参考 PPU = 100，每格 `gridSize = 16`）：
  $$\text{PPU} = 100 \times \max\left(\frac{\text{texWidth}}{\text{gridCols} \times 16},\; \frac{\text{texHeight}}{\text{gridRows} \times 16}\right)$$
  例：120×180 的图塞进 2×2 格框（32×32），`PPU = 100 × max(120/32, 180/32) = 562.5`，最终渲染为 `21.33 × 32` 等比居中。切忌把 PPU 设为 `1`，否则 `SetNativeSize` 会把图标炸到 100 倍大。
- **占格**：旧存档按存档保存的形状算显示，新生成物品用新形状，避免为了换图迁移旧物品占格。
- **点击命中**：细链条或中空物品如果走原版按 alpha 像素命中很难点中，实心矩形占格可直接让占格矩形接管点击命中。

### 2. 白底/绿底抠图与边缘防染算法
`cut_atlas.py` 用两步数学操作彻底解决边缘白边/黑边/绿边：
1. **抗锯齿反混色（针对白底母图）**：用内部深色像素做最近邻参考（`cv2.distanceTransformWithLabels`），在 1.45px 过渡带内估算真实不透明度 `opacity`，按 `rgb = 255 - (255 - raw) / opacity` 还原未混白的前景色；
2. **透明像素边缘色扩散（通用）**：对所有 `alpha == 0` 的透明像素，填上最近可见像素的 RGB（alpha 保持 0 不动）。这样不管是 Point 还是 Bilinear/Mipmap 采样，都不会从透明区采到绿幕或白底脏边。
3. **双底验收**：裁切完毕同时铺在浅底 `#f2eee6` 与深底 `#202730` 拼图检查。

## 五、零第三方依赖的配音挂载架构（AuthorVoice SDK）

`PortraitStudio.AuthorKit\配音\skills\voice-pack-author\assets\SDK\` 揭露了给《深空当铺》加角色配音的完整零依赖架构：

### 1. 纯 C# WAV 解码 + 后台异步加载（`VoiceWave.cs`）
- 规范格式：RIFF PCM16、单/双声道、8~96 kHz、单条 ≤120 秒、解码上限 32 MiB。
- 纯字节解析 `RIFF` / `WAVE` / `fmt ` / `data` 块，每 4096 样本检查一次 `CancellationToken` 和过期标记，完全不依赖 NAudio 或 `UnityWebRequestMultimedia`。
- 通过 `ModHelper.RunInBackground` 在后台线程解码为 `float[] samples`，回到主线程调用 `AudioClip.Create(...)` + `clip.SetData(samples, 0)` 播放（已抽成模板 `工具库/templates/mod-patterns/WavPcmDecoder.cs`）。

### 2. 台词溯源神技（`VoiceGameHooks.cs`）
**痛点**：当 `DialogUIManager.DisplayClientText(Dialogue)` 触发时，原版只传了翻译后的纯文本 `Dialogue`，丢失了原始本地化表名和 key，且不同台词的译文可能相同（如多处都是「好。」）。

**解法（极其巧妙，零泄漏）**：
1. Patch 四个本地化入口（`LocHelper.GetLocalizedDialogue` / `GetLocalizedDialoguePhone` / `GetLocalized` / `GetLocalizedOrDefault`）的 Postfix：
   ```csharp
   // 关键一行：用 new string(result.ToCharArray()) 制造独立引用身份，打破字符串驻留！
   result = new string(result.ToCharArray());
   strings.Add(result, new Origin { Table = table, Key = key }); // ConditionalWeakTable<string, Origin>
   ```
2. Patch `Dialogue.SetText(string, string)`，用 `strings.TryGetValue(text, out origin)` 把溯源接力绑定到 `ConditionalWeakTable<Dialogue, Origin>`。
3. 多配音包共存时，最后执行的包会再次 clone 字符串——通过 `ModHelper.Expose(id, "voice.origin/1", Func<string, string>)` 暴露只读溯源查询，其它配音包遍历 `ModLoader.Mods` 查 `voice.origin/1` 接力找回原始 `(Table, Key)`。
4. 监听全部展示与打断入口（全部是 public 方法，零内部反射）：
   - 播放：`DialogUIManager.DisplayClientText` / `DisplayerPlayerText` / `DisplaySecText` / `PlayClientSingleText` + `DialoguePhoneUIManager.DisplayClientText` / `DisplayerPlayerText`
   - 立即停播（Prefix）：两套对话管理器的 `OnAdvancePressed` / `EndConversation` / `HideAllDialogUI` / `InterruptDialog`
   - **重要边界**：只做观察与播音，绝不篡改对话继续链。
