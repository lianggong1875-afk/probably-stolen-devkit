# 18-工坊模组逆向与蒸馏

**这份文件回答**：怎么从 Steam 创意工坊挑模组、下载、反编译、读透，并把学到的东西落成可复用的东西。

## 1. 为什么做这件事

单个模组遇到的问题（原版接口叫什么、过夜在算什么、读档怎么恢复自定义数据），靠猜和试错成本极高。工坊里已经有几百个模组把这些问题解决过一遍，**源码是唯一权威文档**。蒸馏的目标不是抄代码，是拿到：

1. **原版接口的真相**（类名/方法名/字段/标签/时序）；
2. **踩过的坑**（哪些写法会坏档、会白屏、会和别人打架）；
3. **能搬的范式**（架构、缓存、兼容、分帧、DSL、协议）。

产出固定分四类落盘：①技能 ②经验库经验 ③工具 ④模组制作规范。

## 2. 流水线（四步，全部有工具）

```text
① 扫列表  fetch_workshop.py list   → 缓存文件夹\workshop-scan\items.md（799 项，含订阅数/体积/是否已下载）
② 读简介  fetch_workshop.py brief  → 按 id 清单批量导出名称+简介摘要，人读筛选
③ 订阅下载 WorkshopUploader.exe --fetch "@清单.txt"  → 订阅 + 等下载完成 + 打印安装路径
④ 反编译  distill_prep.py --ids-file 清单.txt       → 反编译到 缓存文件夹\decomp_ws\<id>\ + inspect 报告
⑤ 精读    人工/subagent 读源码 → 写 共享开发\模组制作经验库\workshop-distill\<id>-<名字>.md
⑥ 收尾    蒸馏完成后 --unsub "@清单.txt" 取消订阅，避免订阅列表堆积
```

工具位置：
- `工具库\workshop-tools\fetch_workshop.py`（列表/详情/本地对比/简介摘要）
- `工具库\build\WorkshopUploader\`（`--list-subs/--sub/--unsub/--download/--fetch`，与上传共用同一套 Steam 会话）
- `工具库\workshop-tools\distill_prep.py`（批量反编译 + `inspect_mod.py` 透视报告）

## 3. 筛模组的方法（省时间的关键）

工坊 799 项里 **值得读的不超过 60 个**。判据，按性价比排序：

1. **看简介里的技术词**：出现"API / 框架 / 兼容 / 让位 / 协议 / 脚本 / 缓存 / 归因"这类词的优先。
2. **看 Patch 面**：装之前就可以从体积/订阅数猜。装上之后 `inspect_mod.py` 会直接给 Patch 数与目标类——**Patch 数多且目标集中**说明它啃过原版硬骨头；Patch 数为 0 但功能复杂（如 Zoh、StorageControlTerminal）说明它找到了一条纯公开 API 的路，价值更高。
3. **小而刁的最值钱**：`SpriteHeal`（180 行）解释了一个原版标记位 bug；`Locale Error Fix`（341 行）解释了文字表时序。**几 KB 的模组往往对应最深的逆向**。
4. **大而全的只看架构**：`ContainerLink`（1 万行）要看的是"它怎么不新增容器类型"，不是每个细节。
5. **纯美术/纯数值搬运模组跳过**（除非要研究资源配置格式）。

## 4. 读到什么程度算够

对每个模组，只回答六个问题（蒸馏档案也按这六节组织）：

1. **入口与生命周期**：IMod 实现、挂了哪些 `ModHook`、静态状态在哪重置（读档 / 热重载 / `OnDisable`）。
2. **数据结构**：它把状态存在哪（物品 Tag / ModData / ES3 / 原版字段）、键是什么、怎么持久化。
3. **Patch 语义**：每个 Patch 拦的是哪个原版方法、为什么必须拦这里、拦完返回什么。
4. **与原版的边界**：怎么避免碰坏原版语义（`parentInventory`、真伪、存档）。
5. **风险与限制**：作者自己标出来的坑 + 我从代码里看出来的坑（含"别抄"的部分）。
6. **可复用模式**：2~4 个带原样代码摘录（标文件与行号）的范式 + 对我们的可用点。

**必须诚实标注**：读不到、推断的，写「（推测）」；没真机验证的，单独成节。

## 5. 权威参照物：`共享开发\reference\Assembly-CSharp\`

原版游戏反编译源码就在工作区里（947 个 .cs / 24.8 万行），关键类型都有：
`ModHook.cs` / `ModHelper.cs`（47KB）/ `PlayerStore.cs`（124KB）/ `GameItem.cs`（80KB）/ `ChemicalHelper.cs` / `GraphUtils.cs` / `NetworkUpgrade.cs` / `CustomUIManager.cs` / `ModReflect.cs` / `LocHelper.cs` / `SaveManager.cs` / `EmporiumEntry.cs` …

**铁律：蒸馏得到的任何原版 API 结论，落进经验库之前必须在这里 grep 核对一次**，别只信第三方模组的反编译代码（它可能改过、可能是旧版本）。

## 6. 本次踩过的坑（工具链层）

| 症状 | 原因 | 修法 |
| --- | --- | --- |
| `curl.exe` 访问 steamcommunity 报 `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS` | 本机 curl 走 schannel，在受限会话里拿不到凭证 | **改用 Python `urllib`**（走 OpenSSL），已写成 `fetch_workshop.py` |
| PowerShell 里 `tasklist` / `netstat` 报 Access denied | 会话权限受限 | 端口探测用 Python socket；进程信息别依赖 tasklist |
| `Invoke-RestMethod` 访问 Steam API 报 "The underlying connection was closed" | Windows PowerShell 5.1 默认 TLS 1.0 | 用 Python，或先 `[Net.ServicePointManager]::SecurityProtocol = 'Tls12'`（仍不稳，推荐 Python） |
| Python 打印中文在 pwsh 里显示成 `����` | PS 5.1 按 GBK 解码子进程输出 | 跑前设 `[Console]::OutputEncoding = [Text.Encoding]::UTF8` 与 `$env:PYTHONIOENCODING='utf-8'`；或让脚本直接写 UTF-8 文件再用 read 工具看 |
| `dotnet build` 报 `DllNotFoundException: steam_api64` | exe 目录缺原生库 | 把 `Managed\..\Plugins\x86_64\steam_api64.dll` 复制到输出目录，并写 `steam_appid.txt`（内容 `4348910`） |
| 编译 `WorkshopUploader.csproj` 报 `MSB3191 无法创建目录 bin\Release\net10.0` | 当时受文件沙箱限制 | 放开写权限后正常；构建产物本就在 `.gitignore` 的 `**/bin/ **/obj/` 内 |
| `GetItemState(id, out state)` 编译不过 | Steamworks.NET 里签名是 **返回值**：`uint GetItemState(PublishedFileId_t)` | 直接 `uint state = SteamUGC.GetItemState(pid);` |
| Verbatim 字符串 `@"..."` 里写 `"已安装"` 报一堆 CS1040/CS1002 | verbatim 字符串中的双引号必须写 `""` | 改用中文书名号/引号 `「」` |
| `ilspycmd` 反编译出的 `[HarmonyPatch(/*Could not decode attribute arguments.*/)]` | 特性实参是 `Type[]`/复杂表达式时解码失败 | 结合 `inspect_mod.py` 的报告与相邻文件名推断；**不要凭猜写进经验库** |

## 7. 蒸馏别人的代码时，**不要抄**的东西

反编译出来的代码普遍有这些毛病，抄结构可以，抄写法不行：

1. **大量空 `catch {}`**（DigitalVault 96 处、ContainerLink、SpriteHeal 均有）——违反我们的异常规范。我们只在 Unity 帧回调 / Harmony 边界捕获，且必须 `LogError` 带堆栈。
2. **整段替换原版入口**（SleepLagOptimizer 直接换掉 `RunNightlyChemicalSimulation`）——能立刻见效，但和所有同类模组互斥。我们自己优先局部优化 + 官方钩子。
3. **无 `HarmonyPriority` 声明的密集 Patch**（ValueCache 44 个）——顺序不确定，容易和别人的 Patch 打架。
4. **吞掉原版 fallback 链**（Locale Error Fix 永不执行原版）——某些语言下会退化成显示 key。
5. **反编译后的可读性陷阱**：`if (!(a <= b))` 这种反向条件、`(object)` 强制转换，很多是反编译器产物，不代表作者原意。

## 8. 归档规范

- 每个模组一份：`共享开发\模组制作经验库\workshop-distill\<工坊id>-<英文短名>.md`
- 头部三行固定写：工坊 id、反编译目录、**这个模组为什么值得读**。
- 结尾必须有「对我们的可用点」，点名到 `深空电玩`（`deepspace_arcade`）或 `深空当铺：可能是群友`（`freya_cornell` / `DeepSpacePawn`）的具体功能。
- 跨模组的通用结论**再往上一级沉淀**：接口进 `03-原版接口速查`，坑进 `07-踩坑台账`，编程范式进 `14-模组高级编程架构与工程模式`，制作规范进 `20-各类模组制作规范`。
- 反编译产物放 `缓存文件夹\decomp_ws\`，**用完即弃**（已在 `.gitignore` 的缓存目录里），只保留蒸馏档案。
