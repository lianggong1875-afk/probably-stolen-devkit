## 桥接的五个坑（都踩过）

1. **`query_ui` 不要传 `limit`**，传了返回空 `_raw`；要用 `max_nodes`。
2. **`operate_ui` 必须传 `query_ui` 给的 `targetRef`**，`uiRef` 只能读不能点；还要 `world_id` + `action:"click"`。
3. ~~**一个会话只能装一个探针**~~ **这条不准确，已更正**：真实限制是**程序集标识不能重复**（`Assembly name already loaded; rebuild with a unique name`），而且装进去就卸不掉、只能重启游戏。所以做法是「一个探针里放所有命令，要换逻辑就编个新标识的 DLL 再装一份」。详见 [10-开发桥接器能力速查](10-开发桥接器能力速查.md) §5.3。
4. **`close_test_session` 之后 MCP 连续返回空**，要重启游戏才恢复。
5. ~~**`query_items` 在这台机器恒返回空**~~ **这条是用法错，已更正**：`query_items` 必须给 `scope`（`store`/`inspected`/`selected`），`root` 还要求 `store` 作用域 + 已知 root 别名；空结果只代表"这些具名容器里没有"。详见 [10](10-开发桥接器能力速查.md) §8.5。

另外：`open_test_session` 要求游戏已经 `ready`（进了档），所以**探针不能用来首次进档**——鸡生蛋。

- 进档后立刻核 `get_game_status` 的 `saveSlot` / `worldId` / `day`，和台账约定对不上就停手。

```

    /r:mscorlib.dll /r:System.dll /r:System.Core.dll /r:netstandard.dll
    /r:UnityEngine.CoreModule.dll /r:Assembly-CSharp.dll /r:ModDevBridgeNext.dll
```

## ArcSummonProbe —— 真机验收的通用底盘（2026-11-26 起常驻）

源码 `工具库\probes\ps-modbridge\src\ArcSummonProbe.cs`，编译好的丢进 `C:\Users\<你>\AppData\Local\ModDevBridgeNext\modules\`，然后
`load_probe_module(filename=ArcSummonProbe.dll)` → `call_probe(command="…")`。
**换探针不必重启游戏**：`close_test_session` 会把模块卸掉（`Stop()` 被调），再 `open_test_session` → `load_probe_module` 装新的一份即可。**但每次编译必须换程序集标识**（`Assembly name already loaded; rebuild with a unique assembly name`——改文件名不算）；装进去的程序集本身留在内存里直到游戏重启（`assemblies remain loaded`），所以一个探针里尽量多塞命令，别一天编十个。实践入口是 `工具库\probes\ps-modbridge\probe.py`（自动找最大号的 `ArcSummonProbe*.dll`）；撞 `session_mismatch` 才退回重启。
⚠️ 这一节讲的是**探针**。改**模组自己的 C# 代码**另有一条路：`reload_mod` 能热换模组 DLL 不重启游戏，前提是模组实现了 `HotReloadPrepare()` / `HotReloadActivate()` 两个钩子——详见 [10-开发桥接器能力速查](10-开发桥接器能力速查.md) §4。

### 三种验证套路（比截图和拖拽可靠）

1. **打被 patch 的原版 API**。本模组大部分逻辑是 Harmony Postfix/Prefix，找到被 patch 的那个方法直接调、读返回值即可：`TypeHelper.GetTypeDisplayName`、`ItemFeature.GetPublicDisplay/GetExposedString/CreateCustomerConfrontDialog`、`ShowcaseHelper.*`。
   ⚠ **例外**：用 **Transpiler 改 IL** 的缝（如 `ArcMarketPatch` 的 `GameItem.IsTag`）**不能**这样验——它只替换特定调用点的指令，直接调方法走的是原版。
2. **造游离实例做判定**。`ItemSpawner.Spawn(id)` 造一件不放进世界的货，问完就丢，不污染台面：`refuse` / `expose` / `fits` / `tags` 都这么干。
3. **一定要带对照组**。只测目标物会分不清「功能坏了」还是「方法用错了」：验收纳盒拒收硬件时对照原版 `backpack_small` 能装整机；验 `IsTag` 时对照一个确定不存在的 tag 必须为 false。

### 造「贴假标」的货，不需要知道任何 id 字符串

从正版盘上取下「正版条件对象」，塞进盗版盘的 `fakeCondition`：

```csharp
ItemCondition genuineCond = ItemSpawner.Spawn("gd_g_brokenring")
    .FindItemFeatureByCategory("CATEGORY_GAME_LICENSE").fakeCondition;
ItemFeature pf = ItemSpawner.Spawn("gd_p_brokenring")
    .FindItemFeatureByCategory("CATEGORY_GAME_LICENSE");
pf.SetConditions(genuineCond, pf.realCondition);   // real=盗版, fake=正版
```
### 探针做不到的事（2026-11-26 实测，别再重复试）

| 想做的事 | 结果 | 为什么 |
| --- | --- | --- |
| 给 **spawn 出来的游离机器** 装料 | `GraphUtils.EmporiumTryAdd(inv, item)` 会 fallback 到 `backInv`（背包类容器），物品进了 `parentInventory=backInv`，但 `GraphUtils.FindChildrenType<GameItem>(machine)` 仍是 0 | 游离机器不在世界里，没有真实世界归属；六个 `GameInventory.identifier` 全是**空字符串**，没法按名字挑输入槽 |
| 让游离机器跑进度 / 产出 | 跑不了 | `MachineProgressHelper` 依赖机器在场景里被登记 |
| 直接调 Transpiler 改过 IL 的方法验缝 | 走的是原版 | 只替换特定调用点的指令，方法本身没变（见 `ArcMarketPatch` 的 `GameItem.IsTag`） |

**结论**：要验「真刻一次盘 / 真修一次」这类机器闭环，必须先有**玩家真正摆在世界里的机器**，探针只能在这个前提下操作。判断机器是否游离：`FindChildrenType<GameItem>(machine)` 返回 0 且各容器 `identifier` 为空。

⚠ 往游离容器塞东西**不会落盘**（关游戏不存档就没了，已验证 `save_*.es3` mtime 不变），但仍应避免在正式档里这么做。
