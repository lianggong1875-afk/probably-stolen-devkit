# 11 事件系统：怎么接进原版事件池

**什么时候读它**：我们要做自己的空间站事件（限时涨价、突发事件、访客上门、报纸新闻、日历预告）时。这份是读 `Station Events`（工坊 `3833966506`，`local.station-events` v1.4.0）反编译后的提炼——**看清原版事件系统能被怎么扩展**，照着做就不用自己搭框架。

**不重复造轮子的点**：原版已经有事件蓝图、权重抽取、冷却、报纸、日历、预告纸条、访客队列，**这些全都别自己写**。我们只往里塞声明，让原版去调度。

---

## 0 一句话总结

原版事件系统是**可扩展的**，且有两条入池路线：
- **原版托管路线**：往 `StoreEventActionDict.actions` 塞动作 + 往原版蓝图表（如 `threatEventBlueprints`/`normalEventBlueprints`）加 `StoreEventBlueprint`，交由原版抽取；
- **自持蓝图路线（Station Events 1.4.0 真实实现，见 [3833966506-StationEvents](workshop-distill/3833966506-StationEvents.md) §1.4）**：**不写任何原版静态蓝图表**，只写 `StoreEventActionDict.actions` 注册 `:start/:update/:end/:clients` 动作，蓝图保存在自己私有列表，在 `OnDayStart` Postfix 用原版 `RNG.GetOdd` 自建抽取后调 `manager.ActivateEvent(...)` 激活，价格效果直接填 `StoreEvent.negociationDatas`（零价格 Patch），存档时走 `ES3Type.WriteProperties` 浅克隆投影剥离（防卸载坏档）。

两条路线都复用 `ModHelper.GetModData` 存私有状态，**不需要改原版数据结构**。

## 2 声明式事件定义：把内容抽成数据

它的全部事件都写在**一张静态表**里，每个事件只是一个数据对象：

```csharp
internal sealed class EventSpec
{
    internal string Key;            // 唯一键
    internal string Zh, En;         // 标题（中/英，其余 9 语言走翻译表按索引取）
    internal string NewsZh, NewsEn; // 开始时的新闻正文
    internal string EndZh, EndEn;   // 结束时的后续新闻
    internal int MinimumDay;        // 最早第几天能出
    internal int Duration;          // 持续几天
    internal int Cooldown;          // 冷却
    internal int Weight;            // 抽取权重
    internal string[] PriceTags;    // 影响哪些 tag 的价格
    internal string[] BuyingTags;   // 来访者要买哪些 tag
    internal string[] BuyingItemIds;// 或者按具体物品 id
    internal int[] PriceChanges;    // 价格变动幅度
}
```

**为什么这么设计**：

- **内容是数据，行为是代码**。加一个事件 = 在表里加一行，不用写新类。
- **多语言不塞进每个事件**。中日韩法德等 9 种语言放在**独立的并列数组** `TranslationCatalog.Values[langIndex][specIndex]`，靠 `EventSpec` 在表里的位置对齐。好处是加语言只动一个文件，坏处是**表顺序不能乱**（改了顺序所有翻译错位）。
- **标签驱动而不是 id 驱动**。`PriceTags` / `BuyingTags` 让一个事件覆盖一整类货（比如所有含 `alcohol` tag 的），不用枚举物品 id；只有确实要指定单件时才用 `BuyingItemIds`。

## 3 注册：一个事件 = 1 个蓝图 + 4 个动作 id

```csharp
// 每个 spec 造一个原版蓝图：工厂 + odd(权重) + 带命名空间前缀的 id
var blueprint = new StoreEventBlueprint(
    () => CreateEvent(spec.Key),          // 工厂：真被抽中时才造 StoreEvent
    spec.Weight,                          // 对应构造函数的 odd 参数
    "your.modid:" + spec.Key);
StoreEventManager.threatEventBlueprints.Add(blueprint);   // 静态列表，可直接加

// 四个阶段动作，塞进原版的公开静态字典
string text = "your.modid:" + key;
StoreEventActionDict.actions[text + ":start"]   = () => Started(key);
StoreEventActionDict.actions[text + ":update"]  = () => Updated(key);
StoreEventActionDict.actions[text + ":end"]     = () => Ended(key);
StoreEventActionDict.actions[text + ":clients"] = () => QueueClients(key);
```

**关键：造 `StoreEvent` 时必须把四个字段指向上面那四个键**，否则字典里塞了也没人查：

```csharp
var e = new StoreEvent();
e.onActiveActionId           = text + ":start";     // 激活时
e.onUpdateActionId           = text + ":update";    // 每天推进
e.onRemovedActionId          = text + ":end";       // 移除时
e.addClientFromEventActionId = text + ":clients";   // 排来访者
```

后缀名（`start`/`update`/`end`/`clients`）是约定，不是原版强制——原版只认那四个字段里的字符串。但**建议照用这套名字**，别人接手时一眼能看懂。

⚠️ **`identifier` 前缀是你的领地**。它用 `local.station-events:` 作为所有 id 的前缀，再写一个 `Own(id) => id.StartsWith(Prefix)` 判定"是不是我的"。**所有查询、清理、存档过滤都靠这一个判定**，不要散着写字符串比较。

⚠️ **`end` 不是"事件消失"，而是发一条后续新闻**。它的做法是再造一个 `duration=1, cooldown=0, importance=4` 的 `StoreEvent`，id 用 `<原 key>:ended`，正文用 `EndZh/EndEn`。这个"结束也走事件系统"的写法比自己发通知省事。

## 4 调度：三道闸门 + 一套密度系统

原版每天会问"今天要不要出新事件"。它的做法是**加三道闸门**，全过才抽。

### 闸门一：正负两个方向的资格查询

| 方向 | 挂哪儿 | 干什么 |
| --- | --- | --- |
| 正向 | 自己的 `CanStart(key)` | 天数够 + 内容可用 + `!IsEventOnCooldown` + `!IsEventActive` |
| **反向** | `StoreEventManager.IsEventOnCooldown(string)` 的 **HarmonyPostfix**，改 `ref bool __result` | **如果自己的事件"不该出"，就把 result 设成 `true`**（伪装成"在冷却"）来屏蔽它 |

⚠️ 反向那道是反直觉但正确的做法：`IsEventOnCooldown` 返回 `true` 就等于"别选它"。**不要**去改候选池列表，改这个布尔最省事、也不破坏原版其他逻辑。

### 闸门二：密度（五档 × 三种节奏 = 15 个概率值）

```csharp
// 索引 = level * 3 + pulse
EmptyChances = { 0,35,55,  0,45,65,  0,50,75,  0,65,85,  0,75,95 };  // 场上没有活跃事件时
OneEventChances = { 0,0,0,  0,0,0,  0,35,55,  0,50,70,  0,60,80 };   // 场上已有一个时
Cap() = level >= 2 ? 2 : 1        // 同时最多几件
MinimumInterval() = 5 - level     // 5/4/3/2/1 天
```

要点：

- **概率是"通过间隔门槛之后再摇一次"**，不是"到日子就出"。这样玩家感觉是随机的，实际节奏可控。
- **节奏脉冲**（quiet/steady/lively）有独立的持续时间和权重，`ChoosePulse(previous)` 里**把上一次的权重剔掉**（`previous==0 ? 0 : 30`），避免连续抽到同一节奏。
- **脉冲状态要存档**（`DensityPulse` + `PulseUntilDay`），否则读档后节奏跳变。

### 闸门三：一天只抽一次

```csharp
if (state.ScheduledDay >= Day) return false;   // 已经抽过
state.ScheduledDay = Day; WriteState();
```

**为什么需要**：`OnDayStart` 可能在同一天被多个路径触发，没有这道闸门会一天出好几个事件。

### 防重复：把重复事件的权重挪给没见过的

```csharp
// 已出现过的：权重减半（最少留 1）
cut = max(1, weight / 2);
surplus += weight - cut;  weight = cut;
// 减掉的部分按比例分给没出现过的
weight += surplus * weight / remainingTotal;
// 全部都出现过了？那就原样用，恢复正常权重
```

这个做法的好处是**不硬禁用**（玩家还能再遇到），但明显偏向新鲜内容，而且全是整数运算、不需要浮点。

## 5 访客注入：交错，不是追加

原版生成完一批客人后，把"我们的客人"跟原版的交叉排，观感才对（否则我们的客人永远排最后）。

挂法：`StoreClientManager.HandleNormalClient()` 的 **Prefix 记队列长度** + **Postfix 重排**。

```csharp
[HarmonyPrefix]  void Prefix(StoreClientManager __instance, out int __state)
    __state = __instance.clientStack.Count;      // 生成前有多长

[HarmonyPostfix] void Postfix(StoreClientManager __instance, int __state)
    // 1. 本次新增区间 [__state, Count) 就是原版刚生成的客人
    // 2. 把队列里已有的"我们的客人"抽出来放 Queue
    // 3. 重建：每个原版客人后面紧跟一个自己的客人
    // 4. 剩下的自己的客人 append 到末尾
    // 5. clientStack.Clear() + AddRange(list)
```

⚠️ **`out __state` 是 Harmony 的跨前后缀传值手段**（`__state` 命名固定）。比用静态字段安全——静态字段在异常路径下会留脏值。

**判定"这客人是谁的"靠三个字段**：

```csharp
// 我们的客人
client.sourceModId == "your.modid" && Own(client.identifier) && Own(client.eventSourceId)

// 原版普通客人（三个字段都空）
client.attractedItemId == null
  && string.IsNullOrEmpty(client.sourceModId)
  && string.IsNullOrEmpty(client.eventSourceId)
```

`eventSourceId` 很关键——**它记录这个客人是被哪个事件引来的**，用来做过期清理和"本事件只允许一次访问"。

## 6 存档：用自己的 modData，存坏了就降级

```csharp
// 读（同步、随存档走，不用自己开文件）
string raw = ModHelper.GetModData("your.modid", "events-v1", null);
faulted = !EventState.TryRead(raw, out state);
if (faulted) {
    Debug.LogError("[模组] 存档数据损坏，拓展暂停，原版数据保留");
    // 注意：不是抛异常、不是清空存档，是把自己关掉
}

// 写
WriteState();   // 内部就是 ModHelper.SetModData / 等价接口 + JSON

// 换档时先清掉残留
ModHelper.RemoveModData("your.modid", "events-v1");
```

存的内容：

```csharp
class SavedEvent {
    string Key; int FutureDays; int Duration; int TotalDuration;
    int StartDay; int CurrentDay; bool Known;
    string NewsName, NewsDescription, DisplayName;
}
```

**三条值得抄的规矩**：

1. **`TryRead` 返回 bool，失败就 `faulted` 自杀降级**，绝不半死不活地继续跑。玩家最多丢拓展内容，存档本体安全。
2. **`owner` 用 `ReferenceEquals(PlayerStore.Instance, owner)` 判断换档**，换了就重读。不要缓存 `PlayerStore` 实例然后假设它不变。
3. **`BeforeLoad` 里先 `RemoveModData`**，避免旧档数据串到新档。

## 8 最该抄的四个工程习惯

### ① Transpiler 加计数断言，缝变了就炸得响

```csharp
int count = 0;
foreach (var ins in instructions)
    if (ins.Calls(targetMethod)) { ins.opcode = OpCodes.Call; ins.operand = replacement; count++; }
if (count != 3) throw new InvalidOperationException("Native normal-event count boundaries changed.");
return instructions;
```

**我们踩过 Transpiler 静默失效的坑**（`ArcMarketPatch` 的 `IsTag` 改了但没报错，行为悄悄变成原版）。这条断言把"游戏更新后缝位变了"从**静默错乱**变成**启动即报错**。数量就写死预期值，别写成 `count >= 1`。

### ② `ReferenceEquals` 三重保护

```csharp
if (!Active || !ReferenceEquals(manager, Manager) || !EnsureState()) return false;
```

`manager` 参数可能是别的存档的管理器（或者已销毁的）。**只信 `StoreStation.Instance.storeEventManager` 这一个**。

### ③ 配置项的 label/description 用委托，不用字符串

```csharp
.Define("event_density", default, section,
    () => Text("事件叠加密度", "Event density"),      // Func<string>
    choices,
    () => Text("五档……", "The five levels……"),
    false)
```

传 `Func<string>` 而不是 `string`，**切语言时不用重建配置项**，取值那一刻才解析。多语言模组必用。

### ④ 全局开关 + 单一 Active 标志

`StationEventsMod.Active` 是唯一的启用判定，所有补丁第一行都 `if (!Active) return;`，
`OnDisable` 里把 `ModHook` 委托全部 `-=`、`harmony.UnpatchAll(id)`、UI 缓存 `Clear()`。
**注意它的 Harmony id 有两个**（`local.station-events` 和 `mod.local.station-events`），`OnDisable` 都撤——说明存在过被别人/自己另一条路径 patch 的情况，这是防重复 patch 的实际教训。

## 9 我们自己做事件时的最小骨架

```csharp
// 1. 一个 IMod：注册 → 造蓝图 → 塞动作 → patch → 挂 ModHook
public void OnEnable()
{
    if (Active) return;
    Active = true;
    RegisterBlueprints();                 // StoreEventBlueprint + StoreEventActionDict
    new Harmony("your.modid").PatchAll(Assembly);
    ModHook.OnGameLoadedLate += OnLoaded;  // 读自己的 modData
    ModHook.OnNewGameStarted += OnNewGame; // 初始化
}

// 2. 事件就是一张表：Key / 标题 / 新闻 / 起始天 / 持续 / 冷却 / 权重 / 影响哪些 tag
static readonly EventSpec[] Specs = { … };
```
