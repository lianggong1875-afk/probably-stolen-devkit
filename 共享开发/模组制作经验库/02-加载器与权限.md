# 02 加载器与权限

## 模组骨架与能力规则

- `DeepSpaceArcade.dll` 导出 `IMod` 实现（`ArcadeMod`），`manifest.xml` 声明 `<Assemblies><Assembly>DeepSpaceArcade.dll</Assembly></Assemblies>`。
- 开发期 `manifest.xml` 声明 `<Capability>files</Capability>`（用于热重载时从磁盘补读新增 PNG）。
- **正式发布版必须零能力**：用 `-PublicRelease` 编译剔除磁盘代码，manifest 必须保留自闭合 `<Capabilities/>`（缺整个元素会被 ModLoader 直接拒载），并用 `Test-ArcadeLoaderScan.ps1` 验证 `Refused: False` 且 `Capabilities` 为空。

## 为什么会被 ModScanner 判成 `reflection-external`

| 写法 | 是否被判 `reflection-external` |
| --- | --- |
| `Assembly.GetType("Some.Type")` 只取类型 | 不判 |
| `AppDomain.CurrentDomain.GetAssemblies()` 遍历、`Assembly.GetName()` | 不判 |
| 在**运行期动态算出**的类型上调 `Type.GetMethods()` / `GetFields()` / `AccessTools.Method()` | **判（会触发拒载）** |
| 编译期已知类型 `typeof(X)` + `[HarmonyPatch(typeof(X), "Method")]` | 不判 |

结论：兼容第三方模组时不要反射碰其内部成员，改走只读原版公开 API（如 `ArcAppraisalPane` 监听原版 `InspectionUIManager`）。

## 核对游戏实际加载的 DLL

在 `%LOCALAPPDATA%Low\Questing Goose Studio\Probably Stolen\mod-audit.log` 查看对应行：

```
[ModLoader] audit: deepspace_arcade v0.2.0 source=Local ... running=True trust=Updated caps=none hash=<哈希>
```

| trust | 含义 | running |
| --- | --- | --- |
| `Match` | 与信任记录哈希一致 | `true` |
| `Updated` | **零能力**模组内容变更（自动接受，无需重新批准） | `true` |
| `Changed` | **有能力**模组内容变更（需在游戏 Modding 界面人工重批） | `false` |
| `NotChecked` | 首次安装的有能力模组（需人工批准） | `false` |

## 两个常见坑

1. **装机不能只拷 DLL**：`Textures\` 在冷启动时由 ModLoader 扫描进 `LoadedMod.Textures`，公开版无 `files` 能力无法补读，安装必须同步 `Textures\` 和 `Books\`（直接用 `Build-Mod.ps1 -Install`）。
2. **Mods 目录禁放多余可执行备份**：把旧 DLL 改名成 `.dll.prev` 留在 Mods 目录里会被扫成 `payload-file -> executable content` 导致整个模组被拒载。
