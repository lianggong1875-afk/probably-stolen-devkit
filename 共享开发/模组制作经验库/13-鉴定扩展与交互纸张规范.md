# 13 鉴定扩展、自定义放大镜与交互纸张规范

**什么时候读它**：要做自定义鉴定品类、突破鉴定师等级上限、让自定义物品支持原版放大镜细看、做 JSON 驱动的交互式书页/计算器/终端、把模组能力接进游戏内关系网科技树、做鉴定辅助提示、或者零强依赖兼容第三方模组物品时。

**来源**：完整反编译蒸馏工坊鉴定生态四件套——`Appraiser+`（`3843582575`，41 `.cs` + 7 本 JSON 书，零能力）、`AppraisalAssistant`（`3828921912`，52 `.cs`，零能力）、`AppraisalRules`（`3831174434`，14 `.cs`，零能力）、`AppraisalAssistantCompatibility`（`3842921324`，7 `.cs`，零能力）。**四个全都是零能力 `<Capabilities/>` 模组！**

## 一、零能力注册自定义鉴定物品与开局剧本（Appraiser+ 范式）

原版已经提供了一等公民接口，完全不用手魔改鉴定队列：

### 1. 注册自定义鉴定品类
```csharp
// 1) 在 ModHook.OnModItemDirectoryInit 里注册物品基础工厂
GameItem item = dir.Empty();
item.EnableTag("INSPECTABLE_TAG");
AppraisalHelper.InitAppraisalItem(item, defaultEstimate); // 写入原版鉴定必需字段与默认估价

// 2) 在 OnEnable 里注册进官方鉴定注册表
ModHelper.AddAppraisalItem(
    modId,
    typeId,               // 鉴定类型 id
    itemId,               // 对应物品 id
    unlockRank,           // 解锁鉴定师等级（0=见习起）
    () => CreateRandom(), // 随机生成实例（记得 DirectoryMaster.Item(id, isOwned: false)）
    item => CalcValue(item),
    item => IsMyType(item),
    guideItemId,          // 配套图鉴书物品 id
    () => GetLocalizedName()
);
// 停用时清理：ModHelper.RemoveAppraisalItems(modId);
```

### 2. 突破原版鉴定师等级上限（且保持零能力！）
- 原版 `AppraisalRankHelper.Ranks` 是私有静态数组（长度 4，即 Rank 0~3）。
- **超级发现**：游戏内置了官方安全反射工具 **`ModReflect.GetStatic<T>(typeof(Target), "fieldName")`**，读取原版私有成员**不会触发 `reflection-external` 能力**！
- `Appraiser+` 通过 `ModReflect` 备份并扩充 `Ranks` 表（加到 Rank 4~5），再对 `AppraisalRankHelper` 的 `GetRank` / `SetRank` / `CanProgress` / `Promote` / `GetCertificateRank`、`AppraisalItemRegistry.Register`、`StoreClientListAppraisal.CreatePromotionOffer` 打 7 个小补丁，卸载时 `Uninstall()` 完整还原 `masterBackup`。

### 3. 注册自定义开局剧本（StartingScenario）
```csharp
ModHelper.RemoveStartingScenarios(modId);
ModHelper.AddStartingScenario(
    modId, scenarioId,
    () => title, () => body,
    new Func<string>[] { () => gear1, () => gear2, ... },
    OnStartCallback,                 // 开局发钱、发初始装备、设 isAppraisalIntroduced = true
    modId + ":scenario_icon_sprite", // 封面图 key
    () => tagLabel,
    StartingScenario.TagTone.Warning,
    skipIntro: true
);
// 运行期判断是否处于该开局：ModHelper.IsStartingScenario(scenarioId)
```

## 二、让自定义物品接入原版放大镜（双树镜像 + LensFollow）

以前常以为原版放大镜只能看原版硬编码的肋明治/机械手/等离子匣。`Appraiser+` 的 `InspectView.cs` + `LensFollow.cs` 给出了极其干净的零能力方案（已提炼至 `工具库/templates/mod-patterns/CustomInspectLens.cs`）：

1. **切入点**：`[HarmonyPatch(typeof(InspectionUIManager), "OnInspectItem")]` Postfix（关闭时配 `CloseUI` / 重置时清掉）。
2. **借壳挂载**：
   - 底图容器父节点：`InspectionUIManager.Instance.ribwichUISmall.transform.parent`（把自建 900×800 `RectTransform` 的 `SiblingIndex` 插到 `magnifyingGlass.transform.GetSiblingIndex()` 之前，确保放大镜遮罩在上方）；
   - 放大镜镜头内父节点：`InspectionUIManager.Instance.ribwichUILarge.transform.parent`；
   - 复用字体：`instance.ribwichUISmall.barcodeTMP.font`。
3. **同一套绘制代码画两遍**：底图和镜头里各调一次 `BuildInspect(canvas, item)`，把高清单层贴图、动态生成的序列号、划痕/贴纸/防伪标记画上去。
4. **镜头同步公式（`LensFollow.LateUpdate`）**：
   ```csharp
   Vector3 lensPos = lens.position;
   Vector3 zoomedPos = lensPos + zoom * (target.position - lensPos);
   zoomedPos.z = target.position.z;
   transform.position = zoomedPos;
   float parentScale = transform.parent != null ? transform.parent.lossyScale.x : 1f;
   float s = parentScale == 0f ? zoom : zoom * target.lossyScale.x / parentScale;
   transform.localScale = new Vector3(s, s, 1f);
   ```
   其中 `zoom` 直接读取 `ribwichUILarge.transform.localScale.x`（默认回退 `2f`）。

## 三、JSON 驱动的交互式 Paper / 书页应用

原版的 `Books/*.json` 不只是静态图文手册，它内置了完整的**交互按钮 + 动态文本更新**引擎！`Appraiser+` 用它在游戏里零 uGUI 做出了一台能算四则运算、数字和、整除 7 的「袖珍计算器」。

### 1. JSON 声明（`Books/calculator.json`）
```json
{
  "id": "calculator",
  "title": "Pocket calculator",
  "background": "psap_calc_bg",
  "width": 264, "height": 400,
  "draggable": true, "zoomable": false, "sounds": true,
  "chrome": [
    { "type": "button", "id": "close", "action": "close", "x": 113, "y": 6, "w": 10, "h": 10, "sprite": "...", "hoverSprite": "..." }
  ],
  "pages": [{
    "name": "Calculator",
    "elements": [
      { "type": "text", "id": "disp", "text": "0", "align": "right", "x": 12, "y": 37, "w": 106, "h": 24, "fontSize": 17, "color": "#1d2a22", "locked": true },
      { "type": "button", "id": "k_7", "action": "k_7", "x": 9, "y": 98, "w": 26, "h": 20, "sprite": "...", "hoverSprite": "..." }
    ]
  }]
}
```

### 2. C# 事件绑定（零能力、无 Harmony）
```csharp
ModHelper.OnPaperOpened(modId, "calculator", ui =>
{
    ui.OnAction("k_7", () => { HandleDigit("7"); if (ui.IsAlive) ui.SetText("disp", currentText); });
    if (ui.IsAlive) ui.SetText("disp", currentText);
});
```
**适用场景**：任何模组自带的便携终端、解码器、质检单、账本、交互手册，都应该优先走 `Books/*.json` + `ModHelper.OnPaperOpened`，省去全部 Canvas/布局/缩放/音效/拖拽适配工作。

## 四、将模组能力接入原版关系网科技树（AppraisalRules 范式）

与其把强力功能做成一个开关白送给玩家，`AppraisalRules` 展示了如何把功能做成**需要花信用点解锁的原版关系网升级**（零 Harmony、零能力）：

```csharp
// 必须确认不在主菜单（NewGameData.Instance != null && !NewGameData.Instance.isInMainMenu）
ModHelper.SetNetworkTabLabel("MyTab", () => GetTabTitle());
ModHelper.AddNetworkUpgrade(
    modId,
    "MY_UPGRADE_STEP1",
    cost: 300,
    tabId: "MyTab",
    title: () => "...",
    desc: () => "...",
    onUnlock: null,
    category: "MyTab",
    iconSpriteKey: modId + ":upgrade_icon",
    prerequisites: null, // 第二级可写 new[] { "MY_UPGRADE_STEP1" }
    tier: 0,
    subtitle: () => "...",
    boughtText: () => "..."
);
// 运行期检查：ModHelper.IsNetworkUpgradeUnlocked("MY_UPGRADE_STEP1")
// 卸载清理：ModHelper.RemoveNetworkUpgrades(modId); ModHelper.SetNetworkTabLabel("MyTab", null);
```
记得同时挂在 `ModHook.OnGameLoadedNormal`、`ModHook.OnNewGameStarted` 和配置项 `OnChanged` 里刷新。

## 五、鉴定辅助、改造体探测与安全填价（AppraisalAssistant 范式）

### 1. 不靠 Harmony 的安全轮询驱动
- 用 `MonoBehaviour` 0.25s 间隔轮询（`Time.unscaledTime < nextAttempt`），同时监听 `ModHook.OnGameLoadedLate`、`OnNewGameStarted`、`SceneManager.sceneUnloaded`，切档立刻 `ResetSession()`，且延迟 1 帧（`readyAfterFrame = Time.frameCount + 1`）等待 UI 稳定。
- 用 `ConditionalWeakTable<RichTextBuilder, object>` 防止 `ModHook.OnCreateTooltipLate` 重复追加行，无内存泄漏。

### 2. 原版改造体（Augmented）的三大底层线索源
- **动作异常**：`StoreClientMono` 私有字段 `idleAnimator` / `idleSuppressed` / `idleShakeHorizontal`；`IdleAnimator.axis.x > 0.9f && axis.y < 0.01f && amplitude > 0` 表示水平异常微震。
- **立绘池归属**：`SpriteDict` 内部有 34 个立绘池字段（其中 `augLowerMaleEntries` / `augLowerFemaleEntries` / `augUpperMaleEntries` / `augUpperFemaleEntries` / `augBmMaleEntries` / `augBmFemaleEntries` 是专用改造体池）。
- **对话异常**：挂接 `Febucci.UI.Core.TypewriterCore` 打字机事件观察已显示完成的台词文本。

### 3. 安全填入/提交鉴定估价（`PriceInput.cs`）
- 校验链：确认当前在店 → `isClientArrived` 且 `clientIntent == StoreClient.ClientIntent.APPRAISAL_SERVICE` → `InspectionUIManager.Instance.appraisalPanel.activeInHierarchy` → 物品含 `APPRAISAL_ITEM` 与 `APPRAISAL_DEFAULT_VALUE` → `apprisalServiceInputField` 可交互且非只读。
- 填值用 `input.SetTextWithoutNotify(text)`；若要自动提交，先判 `!NegociationUIManager.IsTradeLocked()` 且 `DialogUIManager.Instance.isConversationActiveFlag == 0 && !HasPausedConversation`，再定位持久化监听了 `OnAppraisalServiceEstimated` 的唯一 `Button`。
- 按钮反馈音复用原版：从 `EmporiumAudioPlayer.Instance.audioButton1` 复制 `clip`/`outputAudioMixerGroup`/`volume`/`pitch` 到独立 `AudioSource` 播放。

## 六、零强依赖跨模组兼容范式（AppraisalCompat）

想给第三方模组（或让第三方模组给我们的物品）提供鉴定/辅助兼容，**绝不需要互相引用 DLL 或写编译期强依赖**：

1. **读数据全走原版公共数据面**：
   - `item.identifier` 前缀/精确匹配
   - `item.IsTag(...)` / `item.GetTagReadonly(...).GetInt()`
   - `item.FindItemFeatureByCategory(...)` → 只读 `realCondition.identifier` / `modValue` 与 `fakeCondition` 对比
   - 需要版本核验时查 `ModLoader.Mods.Find(m => m.Manifest?.ID == targetId && m.IsEnabled)?.Manifest.ModVersion` 或 `AppraisalItemRegistry.Get(id)?.source`
2. **输出挂原生低侵入入口**：`ModHook.OnCreateTooltipLate` 追加带配色（`RenderHandler.ColorPalette.LightOrange / LightCyan / Gray`）的只读行，或在 `InspectionUIManager` 打开时同步展示轻量附属浮窗。
3. **异常节流**：出错时按 30 秒冷却记录一次 `Warning`（`Time.unscaledTime < nextWarning`），既不刷爆日志，也不静默隐藏故障。
