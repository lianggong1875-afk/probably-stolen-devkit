# 21. 跨模组冲突案例库（真实症状，不是"方法重叠"）

> 来源：`3832805089` 综合兼容补丁（包内名 `PawnshopBrewingSkillCompat`，1.19 万订阅）—— 一个作者专门写来修别人模组之间冲突的东西。
> **这份文件的价值在于"症状"**：`conflict_scan.py` 只能告诉我们"两个模组都在 Patch `X`"，而这里记的是"实际情况会坏成什么样、玩家看到什么、怎么修"。
> 全部来自源码实证，每条带 `文件:行号`（见 `workshop-distill/3832805089-ElectronicsCompatPatch.md` §1）。

## 0. 怎么读这张表

- **15 条里只有 5 条涉及"电子产品拓展"**（#1/#3/#4/#7/#14）——把它当"电子产品的补丁"读会漏掉三分之二。
- **9 条与电子产品完全无关**（#2/#5/#6/#8/#9/#10/#11/#12/#13），1 条是自己跟旧版自己（#15）。
- **6 条的症状是"功能整块不可用"**（#5/#6/#7/#12/#13/#14），不是数值错乱 —— 这是"两个 Prefix 抢同一入口"的典型后果。

## 2. 从这 15 条能抽出的规律

### 2.1 「整块不可用」几乎总是两个 Prefix 抢同一入口

6 条"功能整块没了"里，5 条是同一个形状：**有人在某个入口的 Prefix 里 `return false`，另一个人的 Prefix 因此根本不执行**；或者 **Transpiler 互相拆对方的指令**（#6 最典型 —— 装机诊断的 Transpiler 把 `EndNight` 的前缀组拆散了，结果工作间与材料箱全不可用）。

对我们：**这是我们在 `20` 第 13 条写"热点上永不抢先 `return false`"的真实证据**。而且它揭示了 Transpiler 的另一半风险：**你的 Transpiler 可能被别人的 Transpiler 拆坏**，修法只能是"优先级最低的那个负责把指令流搬回去"（它用 `Priority.Last=0`）。

### 2.2 存档相关的冲突，症状都是"过不了夜"

#10（行情落后一天 → 过不了夜）、#11（捕获记成逃脱 → 过夜被拒）、#14（暂存期间存不了档）—— 三条全都表现为"卡在过夜/存档"。

对我们：**涉及过夜链的任何写入，都要假设"另一个模组也在写"**。它的修法是"备份 → 改 → 复核 → 失败回滚"，而不是"信自己一次成功"。

### 2.3 主菜单阶段访问 `PlayerStore.Instance` 是最常见的崩

#8、#13 两条都是这个。修法都一样：判 `PlayerStore.HasInstance`。

对我们：`20` 第 3 条已经写了这条，但这里是**两个独立模组各犯一次**的实证 —— 说明它极容易漏。**自检时应该 grep 一遍所有 `PlayerStore.Instance`，逐个确认前面有没有 `HasInstance`。**

### 2.4 自己跟旧版自己也要防

#15：同一个功能的旧版补丁和本补丁同装，会"一份活两份补丁"。它的做法是 `OnEnable` 里直接**抛异常拒绝启动**，并给出人话原因。

对我们：如果我们要并掉某个旧文件/旧模组，**留一个"检测到同装就拒绝启动并提示"的守卫**，比让玩家自己发现"功能双重生效"好。

## 3. 它的"修"为什么全是软的

| 手法 | 说明 |
| --- | --- |
| **零 `HarmonyAfter`/`HarmonyBefore`** | 全库 0 次。只靠两个**数值优先级**：`SleepTrace` 前缀 `priority=800`（=First）；`PcNightDiagnostics` Transpiler `priority=0`（=Last，负责修别人拆坏的指令流） |
| **检测对方只用 `ModLoader.Mods` + 程序集简名** | `IsModRunning` / `ModReflect.FindType` 全库 0 次 |
| **出站能力位** | 4 个 `*CompatibilitySupport` **静态 bool**，语义是"你在管吗？你管我就不挂" |

> ⚠️ 但它自己踩了一个坑：**Harmony owner 写成裸 `Pawnshop.BrewingSkillCompat`（不带 `mod.` 前缀）**，所以第三方写 `[HarmonyAfter("mod.Pawnshop.BrewingSkillCompat")]` **永不命中** —— 与 `mod.GunsmithExpansion`（写成大写驼峰）是同一个坑的镜像。见 `07` 的「Harmony 排序 id 写错不报错，静默失效」。

## 4. 给我们的三条直接指令

1. **自检项加一条**：grep 全部 `PlayerStore.Instance`，逐个确认前面有 `HasInstance` 判断（案例 #8/#13）。
2. **凡是"我加了个新入口"的功能，先问"这个入口会不会被别人的 Prefix 抢掉"**；如果是，考虑把闸门放在**动作位**而不是**判定位**（与 `19` batch-13 的"许可必须挂动作位"是同一条）。
3. **要并掉旧文件/旧模组时，加一个"同装即拒绝启动"的守卫**（案例 #15）。
