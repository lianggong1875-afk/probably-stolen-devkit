# 两套经济系统：金融交易所 Exchange + 公司增强 CorpPresence

> 蒸馏自 `缓存文件夹\decomp_ws\` 下两个大型第三方模组（已反编译源码，非通读，先结构侦察再定点读）：
> **深空金融交易所 Exchange / TradingTerminal**（`3829559307`，157 个 `.cs` / 约 7 万行 / **8 个 ModHook** / 1.9 万订阅）
> **公司增强 CorpPresence**（`3828913695`，162 个 `.cs` / 约 4.1 万行 / **5 个 ModHook** + 自带 Harmony 实例 / 10 万订阅 + 178 张内嵌 PNG）。
>
> 这两个是"经济系统类大模组"的两种极端路线：
> Exchange 是**影子经济**（自己算一整套行情，一根原版价格都不改，只从原版读事件、往原版加钱）；
> CorpPresence 是**内容经济**（不造行情，把公司/档位/订单/品牌叠到原版交易链上，只在最后一步改价）。
> 下面每条结论都标了文件:行号；只写读到的，推断标「（推测）」。

## 一、它们各自加的是什么系统

### 1.1 Exchange（3829559307）—— 店里多了一块行情终端

玩法闭环是一条完整的"钱生钱"链路：店里墙上多一台像素终端（`WallTerminal`，可选 3 个挂点 + 自定义像素坐标，存 `terminalSpot`），打开后是 12 个页签的交易界面。玩家用**保证金 + 杠杆**做多/做空 14 个标的（5 股票 / 4 币 / 5 大宗）、挂限价单、买期权、把闲置资金存进"借贷池"吃 APR；交易所同时提供**贷款**（含 Rina 这条 NPC 剧情线，VIP 阶梯解锁费率、黑卡、章节结局），贷款有清算线，跌破会被强制平仓。大宗商品再接两条实物链路：**矿机**（买矿机放店里，按夜产出矿石）和**配送订单**（用店里真实的矿石按行情价交付，货从你的背包/柜台里扣），把金融数字和原版物品循环焊在一起。另有"盘中币"（Live）用真实时间轴推进的 48 点日内行情、内幕传闻（Rumor，可能被查、罚款）、新闻与情报页、净值曲线、股东特权（把物品放柜台/称重区触发加成）。所有结算发生在**每天开店时**（`StoreEventManager.OnDayStart` postfix），早上给你一份"昨夜报告"通知列表。

### 1.2 CorpPresence（3828913695）—— 九家公司住进了你的店

它不造行情，造的是**买方结构**：九家公司（Pastel / Solana / Carmichael / Spacer / Meridian / Davre + 反叛军 Rebel / 特使 Envoy + Jackson 私人渠道），每家有独立的电话簿条目、立绘 NPC、品牌商品目录（约 100 条 `CatalogEntry`）、**亲密度 `Coop` → 档位 20/50/80 三级**（`Company.TierAt`，`Company.cs:9`）。闭环是：把该公司的品牌货收进店 → 触发"品牌目录收录"（`Brand.Record`）→ 攒 `Coop` → 解锁更高档位的**订购目录**（周限购、按原版估值 × 档位折扣价下单）→ 货以箱子形式送进店 → 交付后公司派人来（`CompanyVisitors`）、给你许可/机器/配方（罐装机、锻造炉、香水流水线、烟草种植、银血水槽）→ 用这些机器生产独家货再卖回去。上层还挂着 6 个人物章节线（`Engine.All`，含 Seline/Rosen/Doreen/Mentor）、记事簿、以及一个**同 DLL 内的可选子模块 `CorpPresence.Malice`**（巨企签约/订阅费/反叛军点数/特使），开关是 `Settings.Malice`。

## 二、经济模型怎么落地的

### 2.1 Exchange：影子账本，一根原版价格都没改

**结论：不是"改 `NegociationData` / 改 `GetCurrentValue`"，是纯影子记账。** 全树对三个高危区的实际行为：

| 高危区 | 行为 | 证据 |
| --- | --- | --- |
| `GameItem.GetCurrentValue` | **只调用，不 Patch**，且只用在配送订单/矿机竞价这种"读原版值"的场合 | `Delivery.cs:339`；全树无 `HarmonyPatch(typeof(GameItem),"GetCurrentValue")` |
| `NegociationData` | **只读**：把原版 `StoreEvent.negociationDatas`（itemType→百分比）翻译成行情冲击 | `ExternalEvents.cs:607`、`Delivery.cs:393/421`、`ProfessionGame.cs:305` |
| `PlayerStore` 存档链 | 只 Patch `SaveGame` 的 **Postfix**，用来 `CommitSharedPool()` 提交跨存档共享池；不改存档格式、不碰 `DecodeSaveItem` | `Scene/SaveGamePatch.cs:15/34` |

数据流（谁产生 → 存哪 → 怎么变成玩家看得见的价格）：

```
原版 StoreEvent(identifier, negociationDatas)          ← 原版/其他模组产生
        │  ExternalEvents.Mods() 把 itemType→% 映射成资产冲击向量
        ▼
daySeed(ulong, 存盘) ──Rng.Mix(runSeed, day)──► MarketData.Simulate(day, seed, ...)
        │                                          │
        │  MarketEvents/MarketEventDef 事件表 ──────┤ Jump / PremiumTarget / VolBoost
        │  Rumor / ImpactRules(玩家自己的成交) ─────┤ Push / Anchor / Fill / Late
        ▼                                          ▼
   AssetSeries.Step(day, seed, ...)  ──►  Candle{Open,High,Low,Close,Volume}  (内存 List)
        │                                          │
        │  Account.Price(asset) = Round(LastClose)  │  Account.MarketScale 影响深度
        ▼                                          ▼
  TerminalWindow / ChartView / WallTerminal（玩家可见的报价与K线）
```

- **产生**：`AssetSeries.Step` / `StepNow`（`AssetSeries.cs:185/325`）——GARCH(0.06/0.9) 方差 + 泊松跳 + 类因子 `classFactor` + 市场因子（β 混合，`MarketData.cs:626`）+ 均值回归锚 `anchor` + 趋势项 + 跳空 `GapFraction` + 事件注入。全部走一个自带的 splitmix64 `Rng`（`Market/Rng.cs`），**没有用 `UnityEngine.Random`**。
- **存哪**：**K线不存盘**。存的是 `daySeeds[]` / `dayEvents[]` / `dayFollow[]` / `dayVol[]` 四个平行数组（`Trading/SaveData.cs:17-23`），K线由 `MarketData.Rebuild()` 从种子重放 360 天预热 + 全部历史日重算出来。
- **怎么影响玩家可见价格**：只在它自己的终端里。真金白银出入走 `ModHelper.AddCredit`（`Core/Game.cs:187`），并且自己处理 `int.MaxValue` 现金上限：溢出额度记 `capOverflow`，落盘/换日时塞进借贷池（`Game.cs:175-242`，`Account.StoreOverflow`）。

**唯一"反向"耦合**是玩家自己的成交影响后续行情：`ImpactRules`（666 行）把成交量按 √ 定律换算成价格推动 `Push`，永久部分占 1/3（`PermanentShare = 1.0/3.0`），并且这笔 `Push` 是**编码进当天事件串**（`=TICKER:push:volume:anchor:fillHigh:fillLow`，`ImpactRules.Token.Encode`）随种子一起重放的——所以"我昨天砸盘"这件事在重放后依然成立。

### 2.2 CorpPresence：拿原版估值当锚，只在自己那一步改价

**结论：以原版 `GetCurrentValue` 为基准价，乘自己的档位倍率；不改价格表本身，仅在 `GameItem.GetNegociatedValue` 的 Postfix 上做"最后一步覆盖"。**

| 高危区 | 行为 | 证据 |
| --- | --- | --- |
| `GameItem.GetCurrentValue` | **只调用**，用来给目录条目取基准价（还会区分"含事件"与"不含事件"两次取值） | `CatalogEntry.cs:270/273`，`Engine.cs:908/1050` |
| `GameItem.GetNegociatedValue` | **Patch 了（Postfix）**——公司货的固定价、品牌买价倍率、持证买家 +10%、反叛军系数，最终覆盖成交价 | `Hooks.cs:228` → `Hooks.cs:2040` |
| `NegociationData` | **写入**：给公司事件挂 `new NegociationData("WEAPON", 25, ...)`，让原版谈判系统认这个折扣/加价 | `CarmichaelCo.cs:220`、`Malice/RebelStory.cs:1034` |
| `PlayerStore` 存档链 | **重度 Patch**：`SaveGame`(Prefix)、`LoadGame`(Prefix/Postfix/Finalizer)、`DecodeSaveItem`、`SaveManager.DecodeNodes`/`EncodeNode`、`ItemDirectory.CreateEmptyItem`、`GraphUtils.DestroyIfUnplaced` | `Hooks.cs:133-190` |

数据流：

```
CatalogEntry(商品定义：Id/Page/MinTier/WeeklyLimit/Bundle/FixedBaseValue)
        │  Make() → 真实 GameItem 样本（临时对象，用后销毁/登记回收）
        ▼
TryValues(): baseline = sample.GetCurrentValue(false,true,false,false,0)
             eventValue = sample.GetCurrentValue(false,true,Settings.OrderEvents,false,标签加价)
        │      （含违禁品 RESTRICTED_1/2/3 → contrabandMarkupLow/Mid/High 的一半，CatalogEntry.cs:206-213）
        ▼
ListValue() = eventValue × Bundle      Quote(rate) = round(ListValue × rate)
        │
        │  rate = Company.PriceRate(tier) = Settings.OrderMarkup − 0.05×(tier−1)     (Company.cs:120)
        │        × [Malice 子模块存在时的 Envoy.OrderFactor()]                        (Company.cs:125)
        ▼
订单 → 箱子送进店 → 玩家收货/付款（CompanyMoney.Pay/DeliverCash → PlayerStore.PayMoney/ModCash）
        │
玩家卖回给公司：GameItem.GetNegociatedValue 的 Postfix 覆盖 __result（固定价 or 倍率）
```

关键差别：**Exchange 拥有一套独立的价格宇宙，CorpPresence 借用原版的价格宇宙并加以标定。**

### 2.3 Exchange 内部其实是七条互相咬合的子经济

从 `SaveData`（205 行）与 `ModEntry` 的结算顺序能反推出它的完整账本结构——这也是它 8249 行 `Account.cs` 的去向：

| 子经济 | 状态字段（`SaveData`） | 咬合方式 |
| --- | --- | --- |
| **现货/保证金** | `positions/orders/history/report/alerts`（+ 各自的 `xxJson`） | 基础层；杠杆上限 `maxLeverage`/`maxCoinLeverage` 由 VIP 特权放宽 |
| **借贷池（内生存贷市场）** | `poolSupply/poolBorrowed/loanInterest/depositInterest/poolDeposit/apr/aprDays/aprValues` | 存款吃 APR、借款付息；**池规模随 `MarketScale` 放大**（`Account.cs:6504`：`poolSupply = 1e8 × marketScaleUsed`）——深度缩放一改，池也跟着改，玩家再有钱也买不穿 |
| **玩家贷款/清算** | `loan/loanCoins/crossDebt/liquidations/loanLiquidations/loanWrittenOff/loanLogJson` | 抵押品就是持仓；`LiquidationLine`/`LoanHealth` 驱动强平，核销走 `loan.notify_writeoff` |
| **期权** | `options`（独立键）+ `OptionMath`(510)/`OptionRecord`/`OptionKind` | 到期强制结算，通知里区分"forced"与普通 |
| **盘中币 Live** | `live`（独立键）+ `LiveBook/LiveImpact/LiveSeries` | 真实时间轴 48 点；`LiveImpact.DepthSource = () => Account.MarketScale` 复用同一深度 |
| **职业三选一** | `profession`（独立键）+ `Operator/Trader/Broker/ProfImpact` | 职业交易有**额外冲击**：`ProfImpact.cs:77` 调 `ImpactRules.AtDepth(num, Account.MarketScale)` |
| **跨存档共享池** | `poolShared/poolSharedBalance/poolSharedSeq/poolSharedEntries/poolLocalEpoch` | `SaveGame` postfix 里 `CommitSharedPool()`——**同一台机器上多个存档共享一个借贷池余额**，靠 seq/epoch 做汇合（具体合并规则未逐行读，标「推测」） |

> 这说明"经济模组做到大"不是靠一个价格公式，而是靠**多条互相供血的账本**：行情给借贷池定价、借贷池给杠杆供血、杠杆放大冲击、冲击反过来改行情。我们要做指数时，**第一条闭环（行情→溢价→现金）就够撑起玩法**，不必一次上全套。

## 四、时间推进

### 4.1 Exchange：游戏日推进 + 第二条真实时间轴

- **日线（主）**：`StoreEventManager.OnDayStart` 的 `Postfix`（`[HarmonyPriority(200)]`，`Scene/DayStartPatch.cs:28`）→ `ModEntry.SettleAfterDayStart()` → `LiveGame.BeginNight` → `Account.SettleNight` → `Options.Settle` → `LiveGame.EndNight`。每段各自 try/catch 记 `Log.Error`，一段炸不掉整个结算（`ModEntry.cs:320-358`）。
- **补算**：进店时若 `MarketData.LastDay < Game.Day - 1`，从存档的 `daySeeds` 逐日补算（`ModEntry.cs:301-305`）——所以"关店好几天再回来"不会漏结算，也不需要在关店时算。
- **盘中（次）**：`Live` 模块用**真实 Unix 秒**：`Clock = () => DateTimeOffset.UtcNow.ToUnixTimeSeconds()`，`Now = Math.Max(ClockNow, Data.seen)`（`Live/LiveBook.cs:28/44-48`）。`Now` 取 max 是**防改系统时钟倒拔**；另有 `ClockBehind` 报警和 `OfflinePass` 离线补算（`LiveGame.Begin`）。
- **随机与复现**：种子只存"每天一个"。`MarketData.Rebuild(runSeed, firstLiveDay, daySeeds, dayEvents, dayFollow, dayVol)`（`MarketData.cs:218`）先重放 360 天预热（`Rng.Mix(runSeed, day)` 派生），再按顺序重放真实日。事件抽取用 `Rng.Mix(seed, FNV1a(eventId@startDay))`，所以**同一事件在同一天永远同一个结果**，与调用顺序无关（`MarketData.cs:343-352/414`）。
- **防 S/L**：读档不重掷——夜间结算发生在 `OnDayStart`，而当天种子在那之前就已经写进 `daySeeds`（`Account.Save` 在结算里调用）。S/L 只能回到"种子已定、结果已定"的状态。K线本身不存盘，也就没有"改存档改价格"的口子。

### 4.2 CorpPresence：纯游戏日，确定性排班

- 挂 `PlayerStore.BeginDay` / `EndDay` 的 Postfix（`Hooks.cs:220/254`）→ `Engine.OnDayStart` / `OnDayEnd`。没有实时轴。
- 推进逻辑是**确定性排班**而非随机：`Engine.ScheduleNext`（`Engine.cs:523`）按 `dayCounter`、`s.LastStoryDay`、`Settings.StoryGap`、声望 `c.Rep()`、现金阈值决定"明天谁来访、来干什么"；每天人数上限 `Settings.DailyCap` 由 `ApplyDailyCap` 顺延（`Engine.cs:504`）。
- 随机部分很弱：`Engine.Pick/Any` 用 `new Random()`（**未播种、不可复现**，`Engine.cs:79-89`），夜间偷窃用原版 `RNG.Roll`（`FufuTheft.cs:32`）。也就是说**它没有针对 S/L 的设计**，靠的是"日结幂等"兜底：`NightSettlement.TryBegin(state, day)` 用 `ConditionalWeakTable<CompanyState, Attempt>` 保证同一天同一家公司只结算一次（`NightSettlement.cs:12-23`）。

### 5.2 CorpPresence 靶点表（约 85 个原版方法，按原版类分组）

### 6.1 Exchange：八个键 + 版本门 + 隔离副本

- **八个独立 `modData` 键**，各自一套 Load/Save，互不牵连（一个键坏掉不拖累其他）：

### 6.2 CorpPresence：两把键 + 写闸 + 指纹 + 结构校验

- **两把键**：`CorpPresence`（公司/人物/医疗/礼物）与 `CorpPresence.Malice`（子模块的巨企合约/特使/反叛军），各自 `SaveBinding` + 各自 `Validate`——**子模块有独立存档位，关掉不脏主档**。
- **键级写闸**（最有价值的一条）：`SaveSlot` 用 `ConditionalWeakTable<Dictionary<string,string>, HashSet<string>>` 记住"这个存档字典里哪个键读坏了"，此后 **`CanWrite(key)` 直接返回 false**——坏键永不被覆盖，玩家原始数据留着可修：

```csharp
// SaveSlot.cs:22-49 / 69-82
public static string Read(string key)
{
    Dictionary<string, string> dictionary = CurrentStore?.modData;
    if (dictionary == null) { return null; }
    if (!dictionary.TryGetValue(key, out var value)) { AcceptRead(key); return null; }
    return value;
}
public static void ProtectUnreadable(string key)
{
    Dictionary<string, string> dictionary = CurrentStore?.modData;
    if (dictionary != null && dictionary.ContainsKey(key))
    {
        Unreadable.GetOrCreateValue(dictionary).Add(key);
    }
}
public static bool CanWrite(string key)
{
    PlayerStore currentStore = CurrentStore;
    if (currentStore == null) { return false; }
    Dictionary<string, string> modData = currentStore.modData;
    if (modData != null && Unreadable.TryGetValue(modData, out var value)) { return !value.Contains(key); }
    return true;
}
```

- **会话指纹**：`SaveBinding` 持 `WeakReference<PlayerStore>` + `WeakReference<modData 字典>` + 上次写回的原始字符串，`Matches()` 三者全对才允许写（`SaveBinding.cs:54-78`）。防的是"静态 `Current` 还指向上一个档，结果把 A 档的公司数据写进 B 档"。
- **结构校验**：`SaveStructure.Validate(state)` 逐字段 `Require`（礼物状态 0~2、各必要集合非空、订单明细非空、`Seline` 旧字段兼容），失败即抛 → 走 `ProtectUnreadable`（`SaveStructure.cs:8-45`）。
- **一致性快照**：`StoreSession`（111 行）把 `(store, runID, CorpState, GameResources.Generation, Revision)` 打进一个 `readonly struct`，`IsCurrent` 五项全等才算"这还是同一个档"（`StoreSession.cs:61-71`）；`Engine.OnDayEnd` 在给每个角色排班之间反复检查 `storeSession.IsCurrent` 和 `SaveSlot.CanWrite`，**中途读档就立刻停手**（`Engine.cs:477-480`）。
- **日结幂等**：`NightSettlement.TryBegin`（上文 4.2）。
- **启动回滚**：`Main.OnEnable` 用 `RuntimeLifetime` 逐项 `Own(install, uninstall)`，任一步抛异常就整批回滚 + `RollbackNotice.Queue()`（`Main.cs:40-56/117-128`）。这是大模组"装坏了不要变成半初始化状态"的工程答案。

### 6.3 两套存档方案的对照

| | Exchange | CorpPresence |
| --- | --- | --- |
| 键的数量 | **8 个**，按子系统切 | **2 个**，按模块切（主模块 + Malice 子模块） |
| 写入 API | `ModHelper.SetModData/GetModData`（官方 API） | **直接写 `PlayerStore.modData[key]`**（自己管 `null` 初始化，`SaveSlot.cs:43-47`） |
| 坏数据处置 | 另存 `<key>.unreadable`，然后**从空开始** | **冻结该键**（`CanWrite=false`），内存里用默认值，**不覆盖原数据** |
| 结构校验 | 无（字段缺失靠 `if (x == null) x = new()` 逐项兜） | 有：`SaveStructure.Validate` / `MaliceState.Validate`，失败即降级为"未读" |
| 写回时机 | `Account.Save()`（结算后、`SaveGame` 前）+ 各子系统自己 `Save()` | `CorpState.Save()` 前必过 `SaveSlot.CanWrite` + `SaveBinding.Matches` |
| 换档检测 | `loadedFor == PlayerStore.Instance` 单条比对 | `SaveBinding`（三方弱引用 + 原始串）+ `StoreSession.IsCurrent`（五项） |
| 列表序列化 | `[NonSerialized]` + 逐元素 JSON 字符串（`JsonUtility` 限制的对策） | `Newtonsoft` 原生嵌套序列化 + `[JsonIgnore]` 挂运行时字段 |
| 版本号 | `SaveData.version = 6` + 7 个 `*FromDay` 门 | `MaliceState.Version = 1`；主模块靠 `RunId` 比对 + 结构校验做"软迁移"（缺字段就当新档补默认） |

> 两种都成立，取决于"你更怕哪一种坏"：Exchange 怕"一个键拖垮整个经济"，所以拆 8 份；CorpPresence 怕"把玩家的公司进度洗掉"，所以宁可冻结。**我们做指数：键少（1~2 个）但要抄 CorpPresence 的冻结策略**——指数序列一旦读坏，覆盖写回是不可逆的。

## 十、对我们的可用点（给《深空电玩》加"二手游戏行情 / 收藏品指数"）

**先说结论：借 Exchange 的"确定性指数引擎 + 影子账本"，借 CorpPresence 的"原版估值做锚 + 写闸存档"，两样拼起来就是我们要的东西。** 具体清单，按能直接搬的优先级排：

1. **【直接抄】确定性日推进 + 种子回放（模式 A）**。二手游戏行情天然是"每天一个价"：把 `daySeeds/dayEvents` 两级数组 + `Rng.Mix(runSeed, day)` 搬过来，K 线不存盘，只存种子。好处三条：存档小、S/L 不重掷、我们改模型不毁老档（配模式 B 的 `*FromDay` 门）。
2. **【直接抄】影子账本，绝不碰 `GetCurrentValue` / `NegociationData`**。收藏品指数是我们的私有数字，玩家看到它在我们的面板里；真实现金只走 `ModHelper.AddCredit`（并抄 `Game.cs:157-242` 的 `capOverflow` 处理，否则玩家一过 `int.MaxValue` 就翻负）。**这条正好符合我们的"持久化只写模组私有键"铁律。**
3. **【直接抄】键级写闸（模式 D）+ 会话指纹（模式 E）**。只要我们的档里存了一个指数序列，就一定会遇到"读坏/读档中途写入"。`SaveSlot` 的 `ConditionalWeakTable` 写闸 20 行就能抄走，比现在各模组自己 `try/catch → 从头开始` 要稳得多；`StoreSession.IsCurrent` 也正好解决我们多个项目都会踩的"静态引用指向上一档"。
4. **【改造后抄】以原版 `GetCurrentValue` 做锚（模式 F）**。我们的"收藏品"是**真实存在的 GameItem**（卡带/手办/限定版），基准价就用 `item.GetCurrentValue(false, true, false, false, 0L)`，指数只记**溢价倍率**而不是绝对价——这样原版事件（`negociationDatas`）对这类物品的涨跌会自动进我们的指数，不用我们自己维护事件表。注意 CorpPresence 的 `TryValues` 还教了一招：**"不含事件"和"含事件"各取一次值**（`CatalogEntry.cs:270-273`），我们就能把"物品本身值多少"和"今天事件加成多少"分开显示。
5. **【借结构】`CatalogEntry` 那套"条目 + 档位 + 周限购 + 窗口天数"**（`Id/Page/MinTier/WeeklyLimit/WindowDays/LabelKey/Bundle/FixedBaseValue`）非常适合做"限量二手货源"：每周上架几件、按玩家收藏等级（对应 `Coop`/`Tier`）解锁更稀的货。`Company.TierAt = {20,50,80}` + `PriceRate = markup − 0.05×(tier−1)` 这套"越熟越便宜"是最省事的声望定价模型。
6. **【借 UI 结论】做小而深，不要做 2 万行。** Exchange 的教训：一个自绘终端吃到 20602 行（`TerminalWindow.cs`）。我们的行情/指数面板应该走 **`CustomUIManager` 窗口 + 一个 `RawImage` 画曲线 + TMP 文字**，把"画"和"排版"分开（`PixelCanvas` 那 230 行 + `ChartView` 1388 行是合理的比例），并且用**版本号脏标记**刷新（`shownMarketVersion`），绝不在 `Update` 里重建 UI。CorpPresence 的 IMGUI 路线**不建议跟**——它的输入隔离要靠 Patch `InputActionManager.Update` + `GraphicRaycaster.Raycast` + `StoreUIManager.CheckRaycast` 四处，代价太高。
7. **【避坑】别学它们的"第三方无法扩展"——但可以抄它们里唯一那个能扩展的容器。** 两个模组的资产表/公司表都焊死在构造函数里；CorpPresence 的 `DefinitionSet<T>`（78 行）却是个例外：`AddRange(source, entries)` 给每个 id 记来源、重复 id 直接抛异常、`Values/Sources` 都是 `ReadOnlyDictionary`（`DefinitionSet.cs:64-95`）。我们把"公司/收藏品标的名册"照这个写一遍，再配一个 `ModHelper.Expose("arcade.index.v1")` 只读查询（照 `MarketService.cs:75-101` 那种"字符串请求 → JSON 回复"的极简协议），以后别的模组想挂自己的限定版进来就不用改我们的源码。
8. **【避坑】"内部子模块"要有自己的存档键。** `CorpPresence.Malice` 用独立键 `CorpPresence.Malice` + 独立 `SaveBinding` + 独立 `Validate`，主模块开关它用 `Ext.Ask(..., fallback)` 软调用（`Company.cs:92/130`）。我们如果做"游戏王卡牌"或"街机联赛"这类可选玩法，照这个结构切，主线数据永远干净。

**不建议借的两点**：① Exchange 的 `GARCH + 泊松跳 + 类因子 + 市场因子` 模型（`AssetSeries.StepNow` 325-615 行）对我们太重——二手游戏行情只要"慢漂移 + 事件跳 + 均值回归"三项就够，参数少反而好调；② CorpPresence 的约 80 处补丁集中在 `Hooks.cs` 一个文件（且含 7 处存档链钩子），我们没有它那种"必须修物品标签"的需求，别为了对齐它的能力去碰 `DecodeSaveItem`。
