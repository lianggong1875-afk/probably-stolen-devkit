### 1.2 它怎么做这件事

调用链只有四跳：`F5Listener.Update` → `SaveKey.Pressed()` → `QuickSave.TrySave()` → `PlayerStore.SaveGame()`。

**入口是原版公开的无参方法 `PlayerStore.SaveGame()`**（`PlayerStore.cs:875`），不是 `InitialSave`（那只给新档用，`PlayerStore.cs:858`），也没有一个字节自己拼 ES3。原版内部做的事：编码 11 个容器 → `SaveFiles.RotateIntoHistory(saveSlotId)` → `WriteSlotFile()` → `SavePreviewData.GenerateData()` + `IndexSave("preview_"+slot)`（`PlayerStore.cs:875-943`）。

### 1.4 踩坑与红线

1. **"没抛异常"≠"存成功"**。`SaveGame` 内部 `catch (IOException)` 之后会 `SaveFiles.RestoreFromHistory(saveSlotId, rotated)` 把刚挪走的历史文件搬回来（`PlayerStore.cs:912-936`）——调用方拿不到任何信号。必须在 `WriteSlotFile` 上取真值。
2. **`frontInvinvElement`（前柜台 18×4）根本不在原版存档里**。`SaveGame` 只编码 `invElement / backInvinvElement / hidden / showcase / sold / hirelingInv / vendingMachine / vendingFountain / trashcan / dossier / cassettePlayer` 这 11 路（`PlayerStore.cs:878-889`）。前柜台上的东西只要不自己 `EncodeSaveItem`，读档就没了——这是 ①必须写 `SaveExtras` 的唯一理由。
3. **客户完全不入档**。`SaveGame` 里没有任何 `storeClientManager` 的编码，所以"客户在场"只能拒绝，不能抢救。
4. **`files` 能力的来源是 `SaveFiles` 这个类，不是文件 IO**。源码里一行 `System.IO` 都没有，但 `SaveFiles` **类级**带 `[ModRestricted("files", "reads, moves or copies files in the save folder")]`（`SaveFiles.cs:12`），而扫描器是这么找的：`FindRestrictionAttribute(method.CustomAttributes) ?? FindRestrictionAttribute(method.DeclaringType?.CustomAttributes)`（`ModScanner.cs:1250`）——**声明在类型上就覆盖全部成员**。`SaveFiles.IndexLoad/IndexSave/Slot/LoadHistory/RegisterSlot` 全中。反过来：`PlayerStore.SaveGame()`、`SaveUIManager.GetPreview` **都不带**限制 → **"按 F5 存档"本身可以做到零能力，只有"存档历史索引/标记"才需要 `files`**。
5. **键位不要硬编码**。三条并行通道：`ModConfig` 里的下拉（`SaveKey.cs:97-100` 用 `Enum.GetValues(typeof(KeyCode))` 过滤）、原版选项里的真键位（`ModHelper.AddGameOptionKeyBind(modId,"keybind","save_key",label,get,set,null)`，`SaveKey.cs:134-141`）、以及轮询时的三重闸 `KeyBindHelper.SuppressHotkeys || StoreUIManager.IsAnyTyping() || Time.unscaledTime < nextAllowedTime`（`F5Listener.cs:68`）。两个 UI 写的是**同一个 `ConfigEntry`**。
6. **别人家键位可以查**。`KeyConflict.With()` 枚举 `GameOptionRegistry.Sections → section.entries`，取 `entry.kind == Kind.KeyBind(3) && entry.source == 对方modId`，再 `entry.getKey() == 你的键`（`KeyConflict.cs:40-54`）；对方 modId 靠 `ModLoader.Mods` 的 `WorkshopId` 反查（只读，零能力）。
7. **读档后卷帘门会挡住点击**：`StoreShutterButton` 关闸时 `blockerMaskObject.SetActive(true)`（`StoreShutterButton.cs:272`），且 `lockShutterButtonFlag > 0` 时按钮直接失锁（`:62`）。①在 `Update` Postfix 里 `lockShutterButtonFlag++` → `ToggleShutterDoor()` → 等 `duration` → `--` 且把 mask 关掉（`ShutterUpdatePatch.cs:45-71`）。
8. **白天存/晚上存的语义不同**：`storeState == 1`（营业中）读档后要重开卷帘门并补回排队客户，`!= 2` 才跳过晨报（`SaveExtras.cs:106-111`）。别用"是不是 F5"当条件。

### 1.5 对我们的可用点

- **"立刻存档"只要 60 行**：`PlayerStore.SaveGame()` + 拒绝表 + `WriteSlotFile` Postfix 取真值。**完全不需要 `SaveFiles`，因此可以零能力发布**（`files` 只有做历史索引才被迫带上）。
- `EncodeSaveItem(id, PixelElement, PixelWindow)` / `DecodeSaveItem(string, GameInventory)`（`PlayerStore.cs:964`）是**原版给单个容器做序列化的公开入口**——想把"我们自己的一个容器"塞进存档而不动原版结构，这是唯一正路。
- 想做"我们模组自己的存档槽/快照"，正确形态是「`ModHelper.SetModData` 存数据 + `ModHelper.RemoveModData` 在 `SaveGame` 后清」这一对，而不是新建 es3 文件。
- 载入界面加信息，靶点是 `LoadGameUI.Bind(Plate, int)` / `BuildExpanded(Plate, List<SaveHistoryEntry>)`（`LoadGameUI.cs:409,549`）：Prefix 里按顺序把待渲染的 `DateTime` 塞进队列、Finalizer 清空，Postfix 里从队列取——**这是"给原版列表逐行配数据"的标准写法**，比反射找 `Info` 文本稳。
- 想给存档分类（手动/自动/我们自己的），①的"时间戳水印"思路可以直接借：`Ticks % 10000000` 的后 7 位二次秒是没人用的位，写进去不会影响排序（`QuickMark.cs:8-18`）。

### 2.4 踩坑与红线

1. **`cancelled = true` 是关键，不是可选**。`EndDrag` 在它之后还有 5 个放置分支（tab 栏、格子、叠放、`MayTarget` 目标交互，`ItemMouseDragHandler.cs:582-643`）；不清字段，物品会被放两次。
2. **`currentRemove != 1` 直接放过**：多选整堆拖拽一次换一堆 = 没人验证过的路径（①也靠这条避开）。
3. **`Eligible` 必须双向判可放**（`incoming.parentInventory.MayHaveValidInventorySlot(old)` 与反向，`SwapLogic.cs:16-19`），单向通过 = 换到一半发现放不下。
4. **液体容器双向排除**（`!incoming.IsTag("LIQUID_CONTAINER_TAG") || !old.IsTag(...)`）：换液体等于偷换成分，涉及真伪面。
5. **`Expel` 会改 `modifiedShape`**，回滚必须 `item.modifiedShape = 原形状` 再 `UncheckedAccept` + `Validate()`（`SwapLogic.cs:114-122`），否则物品永久变形。
6. **`get_childItems` 只改显示顺序**，别当存储顺序用（排序键 `(minY, minX)`，`ChargerDisplayOrder.cs:35-53`）。电池数值全走原版：`power_source_item_energy` / `power_source_item_max_energy` + `PowerHelper.IsPowerSourceFull` / `IsDisposablePowerSource`（`ChargerTargets.cs:7-19`），**没有自己的电量字段**。

### 2.5 对我们的可用点

- **这是"拖放接管"的模板**：`EndDrag` Prefix + 四个字段清零 + `cancelled = true`，零 Transpiler、零能力。任何"A 拖到 B 上做点别的"都照这个骨架。
- `TrySwap` 的五步骨架（**先 Expel 两边 → 用对方腾出的 `GridShape` 当落点提示 → `AcceptUnchecked` 落 → 引用比较校验 → `finally` 全量回滚**）可直接搬到任何 A/B 位置交换。
- 交互提示别等原版：`Drag` Postfix 里 `OverlayHandler.current.ShowTooltip(Input.mousePosition, translation, Text.Build(), 60)`，**松手之前**就把结果写清楚。
- `SwapLogic.Eligible` 那 10 条条件就是"玩家能不能动这两件东西"的完整清单（`IsItemOwned` / `MayRemove` / `MaxNumRemove` / `MayPlayerInsertInto` / `unitCount==1`），抄它比自己想更安全。

### 3.4 踩坑与红线

1. **反射私有字段是唯一脆弱点**：`selectedItems` 一旦改名，功能**静默失效**（返回空列表 + `LogWarning`，不崩、不报错）。这是"零能力"换来的代价——用之前先接受"字段名是契约"。
2. **顺序不能颠倒**：必须 `fakeCondition = picked` 再 `SetExposed(false)`。`SetExposed` 在 `!isFeatureExposed` 时会调 `fakeCondition.HasOnActivateAction()`（`ItemFeature.cs:446-459`），`fakeCondition` 为 null 就 NRE。
3. **批量贴标 = 批量把"已揭示"打回"未揭示"**。`SetExposed(false)` 只清 `isFeatureExposed`（`ItemFeature.cs:167-169`），**不清 `isFeatureDiscovered`**。所以判"我们是否已经查明这件货"必须用 `IsFeatureDiscovered()`，**不能用 `IsExposed()`，更不能看显示名**。
4. **必须自己也补原版的副作用**：音效 `audioLabeler.Play()`、成就 `CheckLowerLevelsSpecial()`、水质重算 `OnWaterLabelUpdated`——这三件都在 `LabelerUIManager`/`LabelerElement` 里，不在 `ItemFeature` 里。
5. **"有没有标签机"要判两处**（`BatchWindow.cs:252-288`）：`PlayerStore.IsPlayerOwnThisItem("labeler")` 或 扫 `EmporiumEntry.GetAllItems()` 找 `LABELER_TAG`；只判前者会漏掉"标签机放在货架上"。
6. **混合值要显式表达**：三个值不一致时插一条"（多种标签）"占位并整体偏移 1（`BatchWindow.cs:82-93,103`），否则下拉会静默显示第一个值，玩家以为已经统一了。
7. 热键解析**必须做白名单校验**：`Enum.TryParse<KeyCode>` + `Enum.IsDefined`，单字符 `'1'` 要转 `Alpha1`（`Settings.cs:56-74`），否则玩家填 `1` 会绑到主区而非小键盘，直接失灵。

### 3.5 对我们的可用点

- **"批量改物品特征"的完整骨架**：反射拿选框 → 按 `identifier` 分组 → 每组每类目一个下拉 → 写原版字段 → 补原版副作用。做"批量改价/批量归类/批量换包装"都能套。
- **只写 `fakeCondition` 是原版设计**：显示面与真值面在 `ItemFeature` 上是两个字段，`GetCurrentItemCondition()` 按 `IsExposed()` 二选一。我们的判定铁律（只认 `realCondition`）在此得到反向验证——**做伪造/贴标系统时改的就是 `fakeCondition`**，那是正路，不是 hack。
- 热键入口 11 行可抄的模板：`InputActionManager.Update` Postfix + `SuppressHotkeys` + `IsAnyTyping` + `Enum.TryParse` 白名单；`LabelerHelper.IsEditableLabelFeature` 现成可用，它已帮我们排掉铁锭纯度/装备成色/酒质三个类目，**别自己再列一遍黑名单**。

### 4.4 踩坑与红线

1. **`ModConfig.Find` 与 `ModConfig.For` 别搞混**：`For` 在配置不存在时会 `new ModConfig(id)` + `Load()` 并**缓存**（`ModConfig.cs:41-58`），相当于替别的模组凭空造一份配置；筛列表只能用 `Find`（`ModConfig.cs:60-67`）。
2. **`ModConfigWindow.Open` 自己会判空并返回 null**（`ModConfigWindow.cs:28-32`，打 `[ModConfig] '…' has no configuration entries`）。先筛再开，否则玩家点了一排没反应的按钮。
3. **父页面不能 `Close`**：原生选项页关掉就丢了"尚未 Apply 的选择"。正确做法是 `CanvasGroup` 假隐藏（4.3 第三段 `PresentationLease`），这也是本模组存在 `PresentationLease` 的唯一理由。
4. **`ModConfigWindow` 的窗口 id 是 `"mod_config:" + modId`**（`ModConfigWindow.cs:7,42`），全局唯一。别的模组会 Patch 它（F5 就在 `Open` Postfix 里塞自己的控件、在 `BuildEntry` Prefix 里换掉自己那一行，见 1.2 靶点表）——**你复用它，就自动继承这些扩展；你在 `Open` 之后往页面里加行，就要自己负责销毁**。
5. **静态窗口引用必须在读档时清**：`Cleanup` 挂在 `ModHook.OnGameLoadedEarly`（`SettingsModRuntime.cs:12`），否则 `_chooser/_config/_notice` 指向已被销毁的窗口，下次进选项页就炸。
6. **Esc 会一帧内被多个窗口收到**，所以 `HandleBack` 用 `_backFrame == Time.frameCount` 去重并直接 `return true`（`SettingsEntry.cs:415-418`）。
7. **插按钮要指定 siblingIndex**：按 `window.Get("apply").Rect.parent.GetSiblingIndex()` 插，否则会掉到页面最底下或被滚动区裁掉（`SettingsEntry.cs:135-140`）。
8. 本地化别依赖游戏 UI 词表：它把 8 语言 JSON 作为**内嵌资源**打进 DLL（`UiText.cs:46`），运行时用 `LocalizationSettings.SelectedLocaleAsync` 拿当前语言码并归一（`zh/ja/de/fr/es/ru/pl`，其余回退 `en`）——**零能力、零外部文件**。

### 4.5 对我们的可用点

- **"游戏内一键进设置"= 40 行**：`GameOptionUIManager.OpenUI` Postfix 插入口 → 列出 `ModLoader.Mods` 里 `ModConfig.Find(id)?.HasEntries` 的 → `ModConfigWindow.Open(mod)`。我们任何一个带 `ModConfig` 的模组都该配一个，能省玩家一次重启找菜单。
- **我们自己的模组要主动配合它**：只要用 `ModHelper.GetConfig(modId).Define(...)` 注册过配置项，`HasEntries` 就为真、设置页就自动出现在它的列表里——**不需要为它写任何适配代码**。反过来，配置项**只在 `Init` 里 `Define`**、别在 `OnGameLoaded` 之后才加，否则列表是在打开瞬间快照的，晚注册的看不到。
- **`PresentationLease` 是通用件**：任何"页面上再开一页、父页不能关"的场景（我们做放大镜/鉴定单/报纸配图全屏页时经常遇到）都能直接抄这 20 行——比 `CanvasGroup` 手写、比 `SetActive(false)` 都安全，因为它在 `Dispose` 里连"自己加的组件"都还原了。
- **`InGameModSettingsApi.ShowNotice(title, message, onContinue)`** 是一个可以借道给玩家看提示的口子（`InGameModSettingsApi.cs:10-18`）；要用它得先确认模组在跑（`ModHelper.IsModRunning("asteroid_in_game_mod_settings")`），**它自己没有 `Expose` 任何服务**（推测：`ModHelper.Expose` 全仓未出现），所以只能反射调静态方法或干脆自己写一个通知框。
- **给我们的启发**：`ModConfig` 的读写面已经足够做"模组间共享设置"（`Find` 只读别人、`Define` 写自己），想把我们的设置暴露给别的模组，正确做法是 `ModHelper.Expose` 一个只读快照，而不是让它们去 `Find` 我们的 `ModConfig` 再乱写。
