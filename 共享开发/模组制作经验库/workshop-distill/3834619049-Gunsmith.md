## 2. 它怎么做这件事

### 2.1 枪械数据结构：**完全复用原版，没有自定义类**

`Guns.Gun()`（`Guns.cs:135-236`）就是一把枪的全部声明，逐条都是原版 API：

```csharp
GameItem val10 = ItemDirectory.CreateEmptyItem(id).SetSpriteAndShapeFromMod("gunsmith_expansion", id).SetContentWindow(val9);
val10.SetGameItemType("WEAPON"); val10.SetGameItemType("FIREARM"); val10.SetGameItemType(tier);
val10.SetValue(value);
if (contraband > 0) ContrabandHelper.InitContrabandItem(val10, contraband);
AudioHelper.InitPistol / InitGun / InitHeavyGun(val10);
GunHelper.InitGun(val10, firepower, style, reliability, recoil, ergonomics, accuracy, caliber, repair, true);
GunModHelper.EnableStockSlot / EnableRailSlot / EnableMagazineSlot / EnableBarrelSlot / EnableUnderbarrelSlot / EnableSpecialSlot(...)
GunHelper.SetEquipmentCondition(val10, (EquipmentCondition)2);
```

槽位是 `GameSlotInventory` + `MachineryPanel` + `GridPixelElement(1,1)` + `MachineryIntake`，通过 `MachineHelper.CreateMachineryWindow(true, panels)` 变成内容窗口（`:148-149, 211-235`）。**没有自定义 `GameItem` 子类、没有自定义存档字段**——所以原版议价、拆解、改装、工具提示、估价全套自动生效。
单个枪的槽位限制也是原版钩子：转轮枪不给消音器、某些枪不给下挂，靠改写 `((GameInventoryFunc)slot).mayInventoryAddItemFunc`（`:124-133`）。
13 把枪 = **11 把致命 + 2 把非致命**（`gsx_ll_pistol` / `gsx_riot_gun`，`contraband` 记 0，`:120-121`）。白名单表 `CALIBER_22 / MAGAZINE_10 / GRIP_GUNS / STOCK_GUNS / SLIDE_GUNS / BAYONET_GUNS / REVOLVERS / BUILT_IN_UNDERBARREL`（`:41-63`）同时喂给 `GunModHelper.AllowOnlyWeapon` 和 `AttachmentInfo.Restrict`。

### 2.2 14 个配件：六维数值走原版 mod 接口，画在枪上走 `ItemSpriteModifier`

`GunMods.Mod()`（`GunMods.cs:65-104`）：`GunModHelper.InitGunModRail/Barrel/UnderRail/Magazine/Stock/Special` 定槽位，`InitGunMod(val, 六维)` 存百分比，`InitGunModBaseStats(val, Base(六维))` 存"原值的 30%"作为基准（`Base()`：`Math.Round(percent * 0.3)`，`:113-116`），`AllowOnlyWeapon(onlyFor, val)` 限枪，`RegisterExclusiveGroup("gsx_finish", {polished_slide, gold_inlay})` 做互斥组（`:62`）。
"14 个配件画在枪上"用原版**叠加图层**接口，不是重新拼贴图：

```csharp
mod.parentItemSpriteModifierForItemFunc = (item, _, _, _, _, gun) => !IsModGun(gun) ? Sprites(item, gun) : null;
mod.parentItemShapeModifierForItemFunc = (item, _, _, _, _, gun) => !IsModGun(gun) ? Shape(item, gun) : null;
```

（`Overlays.cs:286-296`）`Overlays.Sprites()` 拿"锚点名 + 每把枪的偏移"查 `OverlayData.Anchors`（`Overlays.cs:207`），锚点名直接沿用原版（`rds / compensator / silencer2 / mag_10mm_ext / grip_carbine …`，`:24-120`），原版配件走 `RenderHandler.LoadFromAtlas("Items/items_mod", …)`、自家配件走 `LoadedMod.Sprites`（`:235`）。因为 mod 枪的贴图集本身已经把配件画进去了，所以对 mod 枪返回 `null`。

### 2.3 "可打印"这个属性不存枪上，存**卡带物品**上

`Printing` 里两张表：`Metal[6]`（枪 + 框架价值 + 违禁等级 + 卡带价 + 进度 + 材料）与 `Plastic[4]`（`:38-134`）。卡带是这样造出来的（`Printing.cs:214-234`）：

```csharp
GameItem val = ItemDirectory.CreateEmptyItem(ChipId(spec.gun)).SetSpriteAndShape("Items/items_tool", "printer_chip_pistol");
val.EnableTag("PRINTER_CHIP_TAG", false);
val.EnableTag("PRINTER_FRAME_CHIP_TAG", false);
MachineProgressHelper.InitProgressSourceItem(val, spec.progress, FrameId(spec.gun), true, 1, "Metal Printing Module");
MachineProgressHelper.AddRequiredMachineTag(val, "CNC Module");
MachineProgressHelper.SetSingleAdditionalRequiredItem(val, "metal_ingot", 1);   // 或 SetDualAdditionalRequiredItem
```

所以"可打印"= **一个 `gsx_chip_*` 物品 + 原版打印机能读的进度源标签**，模组没有任何"可打印清单"。
**9 把可打印** = 6 张金属**框架**卡带（`GunFrameHelper.InitFrame(frame, gunId, contraband)`，`Printing.cs:210`）+ 3 张塑料**整枪**卡带（`pocket_pistol / compact_smg / ll_pistol`）；另有 1 张"打印零件"卡带（`gsx_printed_part`，可当维修件用）。金属路线印出的是框架，玩家再用**原版 `gun_part` 点框架**合成枪——`GunFrameHelper.CanFinish/Finish` 挂在 `MaterialDirectory` 的 `mayThisTargetItemFunc/canThisTargetItemFunc/onThisTargetItemFunc` 上（原版 `MaterialDirectory.cs:426-432`），**零新 UI**。
打印机的两个 Postfix 只补体验：`FinishPrintingPatch` 支持"批量框架 + 等待帧标记 `GSX_WAITING_FRAMES_INT`"（`:82-110`），`NozzlePatch` 让塑料质量模块 `GunHelper.MultiplyBaseStat` 并给 mod 枪 `SetEquipmentCondition(0)`（`:20-41`）。

- 退货/收钱：三天后同一个买家回来，`Progression.ExtraBuyer(tier, shady, "commission", order)` 复用原版买家、换台词，并挂 `val.OnDismiss` 判断"没交付就扣掉押金"（`:295-353`）；交付成功走 `OrderDeliveredPatch` → `Commission.OnDelivered` 把押金从报酬里扣回（`:321-334`）。
- 单据本身是原版纸张：`SetGameItemType("DOCUMENT")` + 写 `SLIP_TITLE`/`SLIP_BODY` 标签 + `onActivateSlotItemFunc = PaperUIManager.Instance.OpenGeneralSlipUI(item)`（`:367-412`）——**点一下开原版单据 UI，零自绘**。

### 2.7 改造（modify）与"不和原版数值打架"的四道防线

- 装/卸走原版：槽位是原版 `GameSlotInventory`、装的条件是 `mayInventoryAddItemFunc` 白名单、卸下走原版拆解；数值由 `GunModHelper` 的"百分比 + 30% 基准"两层解释，模组不自己算最终值。
- **只写自己前缀**：`Rebalance.Apply()` 遍历全部物品但第一行就 `if (!identifier.StartsWith("gsx_")) continue;`（`Rebalance.cs:58`），改的是自己枪的价值、自己卡带的配方标签、自己机器的 tag（`:62-130`）；`SavedShapesPatch` 同样只处理 `gsx_` 节点的 shape/sprite（`:49`）。
- **扩展原版物品的适用范围，而不是改它的数值**：`ReservedMods` 把 `GunModDirectory.factoryDictionary` 里 13 个**原版**配件（`pistol_switch / barrel / bipod / grip / mag_10mm* / mag_22*`）的工厂包一层，让它们也能装到 mod 枪上（`ReservedMods.cs:170-217`），并把历史上装错位置的配件退回店里（`ReturnUnfit`，`:98-163`）。
- **翻新机是纯原版机器**：`MachineryHelper.InitMachinery(bench, 8, false)` + `MachineHelper.PowerPanel` + `MachineHelper.Panel(label, grid, "input", true)` + `onCycleEndSlotItemFunc`（`Bench.cs:160-202`）；一次循环吃 `gun_part / metal_ingot`，用 `GunHelper.SetEquipmentCondition` 提升一档成色（`:204-265`），只碰成色不碰六维。换口径则 `Caliber.Convert` + `PermitHelper.SetRestrictedClass/RemoveRestrictedClass`（`LessLethal.cs:129-143`）。

### 2.8 "走私"这条线：**没有独立玩法，是"违禁 + 许可 + 暗格 + 黑市"的组合**

源码里能证的全部是原版合规机制，没有第二张地图、没有检查点小游戏：

- 违禁等级：`ContrabandHelper.InitContrabandItem(item, level)`（`Guns.cs:159-162`；金属框架卡带 `contraband` 2~3，转换套件 1）。
- 许可/受限：`PermitHelper.SetRestrictedClass / RemoveRestrictedClass / OnNewItemCreated / ApplyRestrictedFeature`（`LessLethal.cs:129-143, 199-200`；`PermitMarkup.cs:44-50` 在"放进待售容器"时补受限显示）。
- 藏匿：开局直接发一个 `smuggler_bay`（`Perks.cs:87`），原版 `ClearTrash` 对暗格模组网开一面（原版 `PlayerStore.cs:2012-2014`）。
- 经济表达：黑市派系声望 `StoreReputation.ModReputationRaw("FACTION_BLACK_MARKET", …)`、`ShadyBuyer` 系列（黑市买家 +25% 溢价 `ShadyPremiumPatch`）、隐蔽携行订单 `ConcealedCarryOrder()`（`GUN_SIZE_TAG ≤ 9` + 火力 ≥ 44，`Workshop.cs:680-705`）。

（推测）作者把"走私"理解为"合规风险与经济"，而不是"运输/躲避搜查的玩法"。

### 2.9 机器与容器：全部长在原版机器/容器接口上

- 新机器（翻新台 `gsx_refurb_bench`）用 `MachineHelper.CreateMachineryWindow` + `MachineHelper.PowerPanel` + `MachineHelper.Panel(label, grid, "input", true)` + `MachineryHelper.InitMachinery(item, power, …)` + `onCycleEndSlotItemFunc` 组装（`Bench.cs:160-202`）；"输入口只收什么"用 `GameGridInventory.mayInventoryAddItemFunc` 声明（`:169-170`）；放在机上时的贴图切换用 `onSlotAddItemEndFunc/onSlotRemoveItemEndFunc`（`:173-181`）。
- 机器**模块**是普通物品 + tag：`gsx_module_nozzle(SERIAL_CNC_TAG/NOZZLE_TAG)`、`gsx_module_cnc_series`、`gsx_module_ammo_batch`（`Production.cs:22-40`），效果由 `Production.CountModules(machine, TAG)` 数装在模块舱里的数量再乘系数（`NozzlePatch` 里 `Math.Min(40, CountModules * 20)`、`FinishPrintingPatch` 里 `CountModules * 2`）——**不新增机器子类，只加"模块 + tag + 数量系数"**。
- 容器（4 种箱子 `gsx_crate_*`、弹药盒 `gsx_ammo_case*`、枪架 `gsx_gun_rack`、芯片袋 `gsx_chip_pouch`、自动装填器 `gsx_autoloader_kit`）同理：`SetContentWindow` + 网格 + `mayInventoryAddItemFunc` 白名单 + 事件回调；武器/弹药盒还会调 `PermitMarkup.Watch(container, invs)` 在"放进去待售"时补受限标记（`PermitMarkup.cs:7-21`）。
- 配件也能打印：`Production.Chips[7]` 把 7 个配件做成打印卡带（`Production.cs:42-60` 起）。

## 4. 踩坑与红线

| # | 坑 | 证据 | 我们照抄时怎么办 |
| --- | --- | --- | --- |
| 1 | **改私有静态表必须可复原**：`SERVICE_GUNS` 是 `private static readonly`，只能改元素不能换引用；重复调用会重复追加 | `Workshop.cs:318-375` + `serviceGunsAdded` 布尔 | 追加前按 id 去重；`Unregister` 里按前缀过滤还原；用布尔/集合防重入 |
| 2 | **概率换单必须校验"做得到"**，否则玩家拿到无法交付的单 | `ModOrderPatch.cs:36` | 换单/派单前一律跑一遍原版 `IsMet` |
| 3 | **`Cleanup(Exception) => PatchGuard.Skip(...)` 会让"补丁没绑上"也静默降级**（打 `Warning`，功能消失但游戏不崩） | `PatchGuard.cs:11-19`，32 个 patch 类全部带 | 这与我方"边界捕获必须 `LogError` 留堆栈"的规范相反：**建议区分"绑定失败 = Warning + 一次性提示"与"运行异常 = Error + 堆栈"**，并让回归脚本断言"每个 patch 至少成功绑定一次" |
| 4 | **存档里的 shape/sprite 会漂移**：改过贴图尺寸的枪读档会错格 | `SavedShapesPatch.cs:22-29` 维护 `Resized` 名单 | 我们改美术尺寸时必须同时写读档修正（`DecodeNodes` Prefix），且只碰自己前缀 |
| 5 | **价格别改 `unitValue`**：会连锁污染原版估价、议价、报纸行情 | `NightShop.cs:373-458` 全用 `ItemFeature` | 溢价/折扣统一挂 `ItemFeature(FeatureType 6)` + `SetPreExposedValueMod`，并用 `RemoveFeatureByCategory` 清理 |
| 6 | **电话号码是全局唯一资源**，硬编码可能撞车 | `VexPhone.cs:96-100` 撞了就打警告放弃 | 号码要可配置 + 撞车降级，别让模组因此崩 |
| 7 | **每帧/每次生成都全量遍历 `GetAllOwnedItems(false,true)`**（`ModOrderPatch`、`ModGunTierPatch`、`Workshop.CountLooseAttachments`、`Rebalance` …） | 上述各处 | 我们做同类判定要缓存或事件化，别在顾客生成链路上做 O(全部物品) |
| 8 | **跨模组让路**：检测到 `water_seller_english_collection` 就整体跳过清理 | `RemovedItems.cs:22` | 清理/迁移类逻辑一律先判同类模组，宁可不做也不误删 |
| 9 | **红线：只写自己前缀**。它从不改原版枪的六维/价格，只扩"哪些配件能装到哪些枪" | `Rebalance.cs:58`、`ReservedMods.cs:170-217` | 我们要兼容就扩"适用范围/标签"，别动原版数值 |

## 5. 对我们的可用点

1. **（深空电玩）"让原版客人认识新物品"的三件套**：① 反射往原版的品类/权重静态表追加（`SERVICE_GUNS` 那种）② Postfix 原版"取随机单"的方法换单，但先跑原版判定 ③ Postfix 原版"玩家有没有 X 档物品"的判定。我们做"新机型/新品类被原版客人识别"时，按这三步走比新写一套客人逻辑稳得多。
2. **（深空电玩）把内容做成"卡带"交给原版机器**：`MachineProgressHelper.InitProgressSourceItem` + `PRINTER_CHIP_TAG` + `AddRequiredMachineTag` 的组合证明"可刻录内容"完全可以做成物品让原版机器跑。我们的刻录机现在是自管 `STATE_WORKING` 状态机，可评估改成"内容卡带 + 原版进度源"以减少自定义态（或至少让两者并存）。
3. **（两者）溢价/折扣一律挂原版 `ItemFeature`**：`ItemFeature(FeatureType 6)` + `SetPreExposedValueMod` + `RemoveFeatureByCategory`（`NightShop.cs:430-458`）。当铺的"寄售价/黑市加价"、电玩的"情报溢价"都应这样挂，而不是覆写 `unitValue`。
4. **（深空当铺：可能是群友）夜间档口直接接原版外出框架**：`ModHelper.AddAfterhourLocation` 的 `buildPanel: Action<CustomUIBuilder>` + `frontCounterPosition` + `OnAfterhourLeaveLate` 收摊 + "散场把口袋里东西塞回店里、没地方就放前台并 Notify"（`NightShop.cs:212-296`）。做夜市/黑市档口照抄即可，别另开场景。
5. **（两者）读档自愈 + 迁移要成对写**：`SaveManager.DecodeNodes` Prefix 修 shape/sprite（`SavedShapesPatch`）、`OnGameLoadedLate` 跑价值/厂家/配方迁移（`Rebalance`）、`RemovedItems` 清理自己已下线的 id。我们已有的 ES3 写盘剥离只解决"卸载干净"，还缺"旧档升级"这一半。
