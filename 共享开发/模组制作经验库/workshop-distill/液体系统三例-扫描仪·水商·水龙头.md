### 1.2 它改的到底是什么

**不是水质，是"同一份数据的第二种排版"。** 原版 `WaterScannerUIManager.RefreshUI` 把成分拼成每液一行、无对齐的纯文本塞进 `contaminantTMP`（`WaterScannerUIManager.cs:113-130`），`FormatAmount` 又是**先整数除法再除 100**（`currentAmount/10000`、`/10`，`WaterScannerUIManager.cs:142-153`）——末位只会被**截断**、从四舍五入，而且没有任何横向对齐。本模组做的事：

1. 从 `item.modifiedState.dict` 取每个 `Liquid.currentPart`（`CURRENT_PART_*`）的 `valueInt`——**与原版同一个存储位**，只是不再经过 `FormatAmount`（`CompositionSnapshot.cs:22-56`）；
2. 把原版 TMP 直接 `enabled = false` 藏掉，自己在 `owner.panel` 里铺行（`ScannerPanel.cs:522-540`）；
3. 排序/置顶/字号/行距/高度全是纯展示开关（`ScannerPanel.cs:289-299`）；
4. 纯度只用来**选颜色**：`WaterHelper.GetWaterPurity` → `WaterFeatureHelper.GetPurityArrayIndex` → 调色板（`WaterQualityText.cs:156-168`），连写 tag 都没有。

### 1.4 关键机制（点名到字段）

- **置顶跨日 / 跨重启**：存 **`ModConfig`**，不是 `ModData`、不是 ES3。`ModConfig.For("better_liquid_scanner")` 的 `chemical_pins` / `water_pins` 两个字符串项，内容是 `Uri.EscapeDataString(identifier)` 用 `|` 连接（`ScannerPanel.cs:472-478`）。`ModConfig` 落在 `%persistentDataPath%/ModConfigs/<modId>.json`（`ModConfig.cs:35-39`）——**存档之外**，所以换存档不会带走。开关 `persist_pins` **默认 false**（`ScannerPanel.cs:295`）：默认只在本次会话内记着（跨日没问题，因为面板对象不销毁；跨重启要玩家自己开开关）。这是对"置顶跨重启保留"这句简介的**修正**。
- **零含量占位**：`Render` 遍历 `pins`，若本次快照里没有该 identifier，就用记忆的旧行或注册表补一行 `new ComponentRow(id, name, 0, registryIndex, snapshot.TotalUl)`——体积 0、百分比 0，但行还在（`ScannerPanel.cs:781-830`）。所以"置顶"语义是**我让它一直在列表里**，不是"过滤掉零"。
- **排序三级键**（`ScannerPanel.cs:808-830`）：① 在 `pins` 里的按 pin 顺序排最前；② 未置顶的若鼠标正悬停在面板上且不是强制重排，按上一次的 `displayOrder` 冻结（防悬停时行乱跳）；③ 否则按体积降序、并列按注册序。
- **字号/行距/高度**：`component_font_size` 10–18（`ScannerPanel.cs:293`）、`component_row_spacing` 70–150（%，`:321`）、`shell_height` 620–1000 + `fixed_shell_height` 布尔（`:305-307`）。自适应高度 = `451(化学)/549(水) + 行高×行数 + 图例 + 效果区 - 底部按钮预留`，再 `Clamp` 到 `560~744`（化学）/`620~804`（水）；固定模式直接用 `ShellHeight`（水模式额外 `+88`）。脏检查靠一条 `layoutKey` 字符串（含字号、行距、图例文本、字体实例 ID），相等就整段跳过布局（`ScannerPanel.cs:1648-1668`）。
- **面板怎么建**：不是 `PixelWindow`，也不是 `CustomUIManager.Window`——是**在原版面板的 `RectTransform` 上重排**：`vanillaPanel = owner.panel.GetComponent<RectTransform>()`（`ScannerPanel.cs:480-506`），强制 `490.68 × 714` 起算，再把原版设备图**重新切九宫格**：`Sprite.Create(tex, rect, pivot, ppu, 0, FullRect, border(0,65,0,180))` 拉高而不拉花（`ScannerPanel.cs:1545-1571`）。所以它不受 `PixelWindow.Validate()` 用 `widthPixels` 反推尺寸那条规则约束（对照 `03-原版接口速查.md` §UI 第 3 条的教训：**那条只对 `PixelWindow`/`GameGridInventory` 成立**）。
- **延迟打补丁**：`ScannerStartup.Update` 一直等到 `LocalizationSettings` + `Mechanic` 表都就绪才 `PatchAll`，失败就 `UnpatchAll` 并 `LogError`（`ScannerStartup.cs:56-79`）。原因很实在：`L10n` 要靠这张表把 `liquid_water` 翻成人话。

```csharp
// 关键代码：零含量置顶占位 + 三级排序（ScannerPanel.cs:781-830，摘 40 行）
foreach (string id in pins)
{
    if (list.Exists((ComponentRow r) => r.Identifier == id)) continue;
    if (remembered.TryGetValue(id, out var value))                 // 本次快照里没有 → 用记忆行补 0
        list.Add(new ComponentRow(id, value.Name, 0, value.RegistryIndex, snapshot.TotalUl));
    else
    {
        if (!persistPinsSetting.Value) continue;                   // 没开持久化就不补陌生 id
        string name = id; int registryIndex = int.MaxValue;
        var liquids = Liquid.Liquids;                              // 回注册表捞显示名
        if (liquids != null)
            for (int i = 0; i < liquids.Count; i++)
                if (liquids[i]?.identifier == id) { name = L10n.LiquidName(liquids[i]); registryIndex = i; break; }
        list.Add(new ComponentRow(id, name, 0, registryIndex, snapshot.TotalUl));
    }
}
list.Sort((a, b) =>
{
    int pa = pins.IndexOf(a.Identifier), pb = pins.IndexOf(b.Identifier);
    if (pa >= 0 || pb >= 0) return (pa >= 0) ? (pb >= 0 ? pa.CompareTo(pb) : -1) : 1;   // ① 置顶优先
    if (hover.IsHovered && !forceOrder)
    {
        int da = displayOrder.IndexOf(a.Identifier), db = displayOrder.IndexOf(b.Identifier);
        if (da >= 0 || db >= 0) return (da >= 0) ? (db >= 0 ? da.CompareTo(db) : -1) : 1; // ② 悬停冻结
    }
    int byAmount = b.AmountUl.CompareTo(a.AmountUl);                                     // ③ 体积降序
    return (!descending || byAmount == 0) ? a.RegistryIndex.CompareTo(b.RegistryIndex) : byAmount;
```

### 1.5 踩坑与红线

1. **"藏原版"要能原样还回来**：`Dispose` 里逐个 `Restore()` —— `RectState`（原 RectTransform 尺寸/位置）、`TextState`（字号/对齐/自动缩放）、两张原版 `Image.enabled`、两个自建 sliced Sprite 的 `Destroy`、`template.enabled`（`ScannerPanel.cs:2273-2320`）。**这是本档案里最值得抄的一条**：改原版 UI 必须先记账。
2. **风险自限**：`ModEntry.Fail()` 一旦异常就 `faulted = true` + `Restore()` + `LogError`，此后所有 `Refresh` 直接返回——**坏了就退回原版**，不会每帧刷异常（`ModEntry.cs:112-117`）。
3. **无热重载钩子**（透视报告：`HotReloadPrepare/Activate` 否）：只能靠 `OnDisable` 兜底。我们做同类必须补 `HotReloadPrepare/Activate` 成对重置，否则热重载后面板会留一只"半截壳"。
4. `ComponentKind` 是**按 identifier 硬编码**的分类表（`ComponentRow.cs:34-64`，21 个 id）：第三方液体只能落到 `Other` 色。想接第三方液体就改成"读 `Liquid.color`"。
5. 单位写的是 `uL`（`L10n.cs:356`），不是 `μL`；`<0.01%` 用半角尖括号（`L10n.cs:365-368`）。
6. `TotalUl == 0` 走 `EmptySnapshot`，不除零（`CompositionSnapshot.cs:76-79`）——但它同时意味着"全是 0 时一条都不显示"，置顶行除外。

### 1.6 对我们的可用点

- **《深空当铺：可能是群友》塞壬验水**：塞壬现在的验水是台词/标签层（`PROGRESS.md` r3 的"塞壬验水修复"）。①的 `CompositionSnapshot`（读 `modifiedState.dict` + 排序 + 百分比）可以直接抽成一个静态读值工具，让塞壬在对话里报"你这瓶水里 62% 是重金属"，而**不用**引 `WaterHelper` 的任何写入口。
- **《深空电玩》鉴定浮窗 / 扫描类文本**：同款"把一列 TMP 文本换成对齐的行 + 条形"的做法，可以直接用在鉴定浮窗的"成分/参数"段；`PixelPanelGraphic`（圆角 + 2px 描边，`OnPopulateMesh` 画）比九宫格图更省资源，也不怕皮肤模组换图。
- **`ModConfig` 当"跨存档设置"的样板**：设置项声明一行就在游戏原生 Mod 设置窗口里出现（`ModConfig.For` + `Define`），比自建配置文件省事，且**存档之外**不污染玩家进度。

### 2.2 悬浮看水质：挂在哪、怎么判设备

- **不用 `ModHook.OnCreateTooltipLate`**（透视报告：ModHook 0），而是 Patch 三个 tooltip 出口，全部汇到同一个 `AppendScanTooltip`：`WaterHelper.CreateWaterContainerTooltip(RichTextBuilder,GameItem)`、`WaterFeatureHelper.CreateWaterFeatureTooltip(RichTextBuilder,GameItem)`、`GameItemElement.GetTooltipBasic()`（`Core.cs:119-140`）。三条路都走，是因为水容器、水特征、物品元素三种悬停各有各的入口。
- **防重复**：同一帧同一 `builder` 同一 `item` 只画一次（`Hooks.cs:395-411`）；结果再按 `RuntimeHelpers.GetHashCode(item)` + 200 ms TTL 缓存（`Hooks.cs:325-366`）。
- **"手上有扫描仪"其实是"仓库里有"**：`HasWaterScanner()` 读缓存布尔 `_scannerCache`，缓存由 `ScanInventory()` 遍历**自己拥有的所有物品**（`EnumerateOwnedItems` + `GeneralHelper.IsItemOwned`）得到，判定条件是 `identifier` **或 `name`** 等于 `aquascan`/`chemscanner`（`Hooks.cs:643-680`、`1032-1088`）。缓存 30 s 过期、手里那件物品 1 s 校验一次、`GameItem.AddParent/RemoveParent` 一变更就作废重建（`Hooks.cs:307-315`）。**这是"拥有即算"，不是"拿在手上"**，简报里那句"需要扫描仪或光谱仪在手"是玩家视角的说法。

### 2.3 三列条形图：纯渲染，但用了 TMP 的两个内部通道

1. 行文本用 `<pos=NNpx>` 定位三列（列宽靠**实测字宽**，`Hooks.cs:808-861`：给 `TreeNodeRender.InstantiateText()` 造一个离屏 TMP 量 `preferredWidth`，结果进字典缓存）；
2. 条形本身不画，只放一个**链接锚点**：`<link="AquaSenseCompositionBar:<ratio>:<RRGGBB>">\u00a0</link>`（`Hooks.cs:2001-2008`）；
3. `TextMeshProUGUI.GenerateTextMesh` Postfix 里发现文本带这个前缀 → 给该 TMP 挂 `TooltipCompositionBars` 并排队（`Hooks.cs:2015-2031`）；
4. 该组件的 `LateUpdate` 从 `textInfo.linkInfo[i]` 拿到 `linkTextfirstCharacterIndex`，再取 `characterInfo[...]` 的 `origin/ascender/descender`，在字形位置贴两个真 `Image`（深灰轨道 + 彩色填充），填充宽度 = `Clamp(ratio, 0.0125, 0.9875)` —— **极小占比也留一条细线**（`TooltipCompositionBars.cs:88-140`）。

**结论：条形图纯渲染，一个字节的成分数据都没改**；改数据的是另外几处（滤芯、标签）。

### 2.4 单位与 trace

- 体积：`0 < n < 100 → "n uL"`，否则 `x.xxx ml`（`Hooks.cs:910-917`）；读值时先 `currentPart`，为 0 再读 `part`（`Hooks.cs:885-903`）——但 `Liquid.part`（`PART_<ID>`）在**整个原版 `Assembly-CSharp` 里只被赋值、从不读**（`Liquid.cs:533`），所以那行回退是死代码，抄的时候删掉即可。
- 占比：`Math.Round(pct, 2, AwayFromZero) <= 0` → 文本 `‹0.01%`（U+2039，**不是** `<`）；`HideZeroComponents` 文本模式隐藏这行，条形模式**仍画细条**（`Hooks.cs:755-806`、`808-820`）。
- 排序：默认按占比降序（`SortCompositionByAmount`，`Hooks.cs:795-805`）。

### 2.7 踩坑与红线

1. **`9999999 → -1` 是个 no-op**：`AddWater_Prefix` 把水龙头那句 `AddWater(s, 1, 9999999, useRange:true, ...)`（原版 `WaterHelper.cs:155/161`）改成 `-1`。但原版 `AddWater` 自己算 `num5 = (addAmount == -1) ? free : Math.Min(addAmount, free)`（`WaterHelper.cs:977-978`）——`Min(9999999, free)` 本来就等于 `free`。**唯一的实际差异**是容器容量 tag > 9,999,999 μL（≈10 L）时——也就是 0.46D 里几乎不存在。抄这段时要明白：想改"接多少"应该改 `LIQUID_CONTAINER_CAPACITY` 语义或容量，不是改这个哨兵。
2. **`TextMeshProUGUI.GenerateTextMesh` 是 Unity 级的超级热点**：这个 Mod 用"文本里有没有哨兵"做前置判断 + 队列 + `LateUpdate` 才画，已经算克制；我们若照抄，务必保证"没有哨兵时只做一次 `string.IndexOf`"。
3. **`IsWaterScanner` 连显示名一起比**（`Hooks.cs:662-679`）：玩家切语言后显示名变了就可能认不出扫描仪（推测，未真机验证）。正确做法只认 `identifier`，需要兼容时读 `item.name` 的原始字段而不是本地化名。
4. 全库遍地 `catch { }`（`BeforeTransferLiquid` 里 `catch` 后 `return true` 放行是合理边界，其余多处连 `Log.Warning` 都没有）——**抄它的结构，别抄它的异常策略**（按我们的六条硬规范）。
5. `LabelerHelper.HandleLine` 的 Prefix 用 `return false` 顶掉原输出，只在自己上色成功时才拦（`Hooks.cs:546-604`），这点是对的：**拦截前先确认能画**，画不了就放原版走。
6. 它**主动让位**：发现 `chiqingsan.BetterPerformance` 已启用（按 `ModLoader.Mods[i].Manifest.ID` + `IsEnabled` 判）就跳过设置面板补丁（`ConfigPanel.cs:63-72`、`217-235`）——这是"先到者赢"的干净写法。
7. 对外接口走 `AppDomain.SetData("aquasense.composition.v1", Func<GameItem, IReadOnlyList<(string,string,string,float,int)>>)` + 版本槽（`CompositionApi.cs:14-29`），与 `03-原版接口速查.md` §UI 第 1 条记的 Item Details 做法同源，跨模组零引用。

### 3.2 它怎么做到"三段可单独关、矿物分开收、液氯手动补"而不改公式

### 3.5 「容器拖到水龙头上会消失」——根因与三层修法

简介原文（Steam 1.5.4，[工坊页](https://steamcommunity.com/sharedfiles/filedetails/?id=3833421581)）：「Dropping a water container on the faucet while the panel was open could make it disappear for good; the container is now always handed back to you, and if nothing can take it, it stays in the mineral slot instead of being destroyed.」

**根因链（源码可证的部分）**：水龙头窗口被换成了自己的 6 槽 `PixelWindow`，"拖到机器上"这个动作在**面板已打开**时，会让容器被接进 `_slots[3]`（容器/矿物接取槽）；一旦该槽判定放不下（格型不符 / 窗口正在重建 / 面板隐藏），原版就把物品 `Expel` 出去——`GameSlotInventory.Expel`（`GameSlotInventory.cs:539-559`）会解绑并把它交还世界层，**而世界层的那个点此时被打开的机柜面板压着**，于是玩家既看不见也拾不回来 = 永久消失。中间"哪一步触发 Expel"我没逐行追到（推测：窗口重建时槽位被重新 `Validate`），但模组自己的日志把现象钉死了——`NoteFaucetFill` 里写着「**检测到世界投放**（刚入槽就用了龙头），下一帧摘出归还」（`FaucetController.cs:1650-1668`）。

**修法（三层，缺一层都会漏）**：

1. **入口闸门**：`ApplySlotRules` 给每个槽装 `mayInventoryAddItemFunc`（容器必须 `AcceptWaterContainer`、药片盒必须 `AcceptTabletOwned`…），并且**只收玩家自己的东西**——`NoteNonOwnedReject` 的日志写得很直白：「否则会把商店/展示柜里的货物吞掉」（`FaucetController.cs:1571-1577`、`3169-3274`）。
2. **当场识别**：`NoteFaucetFill()` / `NoteFaucetFill(GameItem filling)` 在"刚接水"的 1.5 s 内检查 `_mineralSlot.childItem` 是不是那个刚入槽/正在接水的容器，是就把 `_pendingWorldDrop` 标上、约 0.02 s 后再处理（`1650-1687`）。
3. **兜底归还**：`TickWorldDropEject` → `_mineralSlot.Expel(item)` → `ReturnToPlayerSafe(item, 3)`：先进玩家背包（`StoreInventoryCanAccept` → `ReturnToPlayer` → `GraphUtils.EmporiumTryAdd`）；背包收不下就**留在 3 号槽**，再收不下才交给商店兜底，**任何分支都不 `Destroy`**（`8342-8406`）。

```csharp
// 关键代码：世界投放摘出 + 三段归还（FaucetController.cs:8379-8406 + 8342-8376，摘 34 行）
private void TickWorldDropEject()
{
    if (_pendingWorldDrop == null || Time.unscaledTime < _pendingWorldDropAt) return;
    GameItem drop = _pendingWorldDrop; _pendingWorldDrop = null;
    try
    {
        if (drop != null && _mineralSlot != null && _mineralSlot.childItem == drop)   // 还在槽里才动手
        {
            if (!StoreInventoryCanAccept(drop))                                      // 背包连预检都不过 → 不动它
            { ModEntry.Log("接取槽: 商店库存收不下 " + SafeItemId(drop) + "，容器留在接取槽（不会被销毁）"); return; }
            ((GameInventory)_mineralSlot).Expel(drop);                               // 先摘出槽
            ReturnToPlayerSafe(drop, 3);                                             // 再归还（背包→槽3→商店）
            MarkRecoveryDirty();
            ModEntry.Log("接取槽: 世界投放已摘出并归还: " + SafeItemId(drop));
        }
    }
    catch (Exception ex) { ModEntry.Log("接取槽摘出失败: " + ex.GetType().Name + " " + ex.Message); }
}

private void ReturnToPlayerSafe(GameItem item, int fallbackSlot)
{
    if (item == null) return;
    if (StoreInventoryCanAccept(item)) { ReturnToPlayer(item); return; }             // ① 背包
    if (fallbackSlot >= 0 && fallbackSlot < _slots.Length && _slots[fallbackSlot] != null)
    {
        try { _internalPlacement = true; GraphUtils.TryAcceptAll((GraphNodeStorage)_slots[fallbackSlot], item, -1); }
        catch { }
        finally { _internalPlacement = false; }
        if (SlotHasItem(fallbackSlot, item))                                          // ② 留在原槽
        { ModEntry.Log("接取槽: 商店库存收不下 " + SafeItemId(item) + "，已留在接取槽（不会被销毁）"); return; }
    }
    ReturnToPlayer(item);                                                             // ③ 商店兜底
}
```

### 3.6 踩坑与红线

1. **补丁分 12 个作业、逐个重试**：`PatchJobs` 数组 + `_patchDone[i]` + 失败整体 3 s 后重试，而且要等 `EmporiumEntry.Instance` 出现后再等 0.5 s（`ModEntry.cs:60`、`459-530`）。比"Init 里一次 PatchAll"稳得多，尤其对 `PlayerStore`/`SaveGame` 这类读档后才活的方法。
2. **存档是一整块 JSON**：`ModHelper.SetModData("faucet_filter", "state", JsonConvert.SerializeObject(saveData))`（`FaucetController.cs:8067`、读回 `8443`）。`stateVer 6` 且简介明说"不能回滚版本"。我们做机器状态持久化，**要么学它整块 JSON + 版本号 + 迁移，要么就别碰**。
3. **`_mineralSlot` 一身兼二职**（既是矿物接取槽又是容器落点），这是上面那个 bug 的温床。我们做多槽机器时，**"物品落点槽"和"操作目标槽"必须分开**。
4. 阶段判定靠猜：`ComputeStage` 先看 `RUSTWATER_TAP`/`GUTTERFLOW_TAP` 解锁，猜不出来就读 `EmporiumEntry.Instance.faucet.spritePath` 里有没有 `"faucet1"`（`589-638`）。换皮肤/换贴图的模组会让它误判（推测）。
5. 全库 `catch { }` 与 `catch { return; }` 极多，且很多是"吞掉后静默跳过一段处理"——**抄它的防御布局，别抄它的吞异常**（我们要 `LogError` 留栈）。
6. 它自带 `Stopwatch` 计时日志（`5030-5040` 的"接水处理耗时 / 阶段耗时"），简介也记着"6 L 从 2748 ms 降到 155 ms"。**性能改造要能自证**，这一点值得照抄。
7. `DurabilityHelper.SetDurability` 挂 **Finalizer** 而不是 Postfix：因为它自己批量算耐久、最后一次性写回，Finalizer 才是"不管原版怎么结束都收口"的位置。

### 3.7 对我们的可用点

- **《深空电玩》打印机 / 自检面板**：`MachineHelper.Panel + MachineryPanelRow + MachineryStack.Vertical + new PixelWindow(true,null,(WindowStyle)Machinery) + item.SetContentWindow(...)` 这条链就是"固定尺寸机柜面板"的标准骨架（原版机器面板同款，只是尺寸由我们自己钉死），比再挂一层浮窗更贴原版、天然吃原版拖拽/工具提示。刻录机的双格 + 自检 5 项复选正好能按这个骨架重排。
- **《深空当铺：可能是群友》塞壬的净水设备**：塞壬已经卖了"海渊潮汐分子滤芯"和"螯合净水片"（`PROGRESS.md` §1），但玩家只能往原版净水器里塞。③ 证明了**给一件家具/机器换面板 + 自己跑分段处理链**是可行的，且"三段可关"这种设计正好能变成塞壬的"售后改装"（买了她的滤芯才解锁 UV/氯段）。
- **"分段闸门 + 原版函数"这个模式**：任何"我们想加开关，又不想改数值"的需求（例：刻录机"是否自动退盘"、净水器"是否回收矿物"），都用"`bool` 进存档 + 在调用原版函数前 `if (!flag) skip`"，**不要重写数值**。
- **物品搬运的三段归还**（背包→原槽→商店，绝不 `Destroy`）：直接可用在 `深空电玩` 的整备套件/收纳盒，和 `深空当铺` 的展柜补货上。我们现在多处"投放失败就销毁"的写法（`GraphUtils.DestroyIfUnplaced`）应当改成这条链。
- **`ModConfigWindow.BuildEntry` 一行替换**（③的 `uv_scan_interval`、②的全部滑块）：两个项目要加"带范围的数值设置"，都可照抄 `AddLabel + AddFlexibleSpace + AddSlider + SetFixedWidth(62/224)` 这 6 行。

## 结语：五条最值得带走的结论

1. **只读一层就能拿 25 万订阅**：①证明"把已有数据换个排版"是收益/风险比最高的模组形态，前提是**读值要走同一个存储位**（`modifiedState.dict[CURRENT_PART_*]`），且**改过的原版 UI 全部记账可还原**。
2. **"手上有设备"应该实现成"仓库里拥有"**：②的 `HasWaterScanner` + 30 s 缓存 + parent 变更失效，比每帧扫背包稳，也比真的判"手上"宽容。
3. **要在文本里画图，用 TMP 的 `link` 锚点 + `characterInfo` 取字形位置**，别自己算字符宽度；②的 `TooltipCompositionBars` 是完整范例。
4. **重做机器面板的门是 `GameItem.SetContentWindow`**：`MachineHelper.Panel`/`MachineryStack`/`PixelWindow(Machinery)` 三件套就能搭出原版质感的固定尺寸面板，③ 八成代码花在"安全搬物品 + 安全存状态"，不是画面。
5. **"不改公式"的正确姿势是"改调用次数和顺序"**：③的氯段按 15,000 μL 分块反复调原版 `ChemicalHelper.HandleChlorine`，滤芯段逐字段复刻 `WaterHelper.HandleFilter`——数值一个没动，行为全变了。
