## 1. `3829053332` 声望增加显示 Reputation Pop

**id**：`3829053332`（`<ID>reputation_pop</ID>`，v1.1.0，游戏 0.46D，`<Capabilities />` 自闭合）
**反编译目录**：`缓存文件夹\decomp_ws\3829053332\`
**为什么值得读**：4 文件 559 行、47.5 万订阅（工坊第一梯队）。它把"交易后弹声望"拆成**一处差分 + 一个协程**：
没有公式复刻、没有事件总线、没有 UI 管理器——"弹字管理器"只是一个静态类。

### 1.2 它怎么拿到"实际获得的声望"

**它一个乘法都没算，全靠 Prefix/Postfix 差分读最终字段。** 挂点 `StoreReputation.OnItemTraded`（原版
`StoreReputation.cs:216-255`）这一路把倍率全乘完才落库：`abs(value)` → `×GetTradeRepMultiplier`（`:223`）→
`×GetPreBargainValue`（`:228`）→ `×` 赃物/走私加成（`:233-240`）→ `×0.66` 下层 / `×1.2` 上层 / `×1.33` Diplomatic
（`:241-252`）→ `ModReputation(value / 400.0)`（`:253`）；`ModReputation`（`:88-116`）再乘 消息灵通 ×0.5、谄媚 ×1.25、
黑市负向 ×2、`UL_PETITION` 治安负向 ×2 ＋ `Difficulty.Rules.reputationGain/LossMultiplier`；最后
`CheckReputation()`（`:118-122`）把 `amount` **clamp 到 ±200**。而 `GetReputationExact()` 就是 `return amount;`（`:77-80`）。

所以 Postfix 减出来的差值 = **含难度、含阵营、含 perk、含封顶截断的真实到手值**。差分比"读 `value` 参数"强三处：
参数是 `int`（丢小数）、没乘 perk/难度、而且**封顶后自动为 0**——攒到 200 再赚不会弹一个假的 `+1.2`。

**挂点在数据层，不在 UI 层。** `Pop` 只负责画，位置写死在 `LetterboxManager` 的 GameArea 中央偏上（源码
`Pop.cs:171-179`），与哪个物品/顾客无关。原版调用 `OnItemTraded` 的只有两处：`PlayerStore.cs:2692`（买）、`:2759`（卖）。

**阵营色**是手写 `switch` 比字符串（`Pop.cs:188-202`），来源是原版常量 `FACTION_*`（`:51-65`）：治安红
`(0.93,0.22,0.22)`、黑市近黑 `(0.07,0.07,0.09)`、革命绿 `(0.25,0.82,0.35)`、上层/游客粉 `(1,0.5,0.72)`、`default` 灰
`(0.72,0.74,0.78)`。原版有现成的 `GetFactionColorByID()`（返回 `factionColor3` 十六进制串，`:192-202`），**它没用**。

**"碎光"不是粒子系统、也不是自绘 sprite**：`TreeNodeRender.Instantiate()` 造节点 + `image.sprite = null` 留白板
（UGUI `Image` 无 sprite 即纯色方块）+ 手写抛物线 `v.y -= 120f * s * dt`，`life = 0.6~1.1s`，alpha 线性淡出（`:436-441`）。
**负数不是镜像，是另一套参数**（`:400`、`:418-419`）：主位移方向取反（仍是 30px，缓出 `1-pow(1-t,2.2)`）；
横向抖动 `1.6`（正数 `0.6`）；碎片 6 个（正数 16）；碎片抛射角 200°~340°（正数 15°~165°）、初速 ×0.5。
描边不挂 `Outline`，而是同一串文本做 6 层（暗色 8 层）偏移副本 `(±0.9,-0.9)/(0,-1.7)`（`:352-389`）；
`IsDark()` = 亮度 `r*0.3+g*0.59+b*0.11 < 0.25`（`:204-210`）决定描边反白——黑市黑字靠这条才看得见。
`(TextAlignmentOptions)514` = 居中、`(FontStyles)1` = Bold（`:236-237`）。

**状态只有三个字段**（`Pop.cs:41-47`）：`pending`（按阵营累加）、`nodes`（清场时能全销毁）、`scheduled`。
连续两笔不覆盖靠两件事：`scheduled` 为真即 return 不再起协程（`:89-92`）；唯一的 `Flush()`
`yield WaitForSecondsRealtime(0.12f)` 之后一次取走全部阵营、清空、逐条 `Spawn`（`:106-128`），多阵营按
`start.y += index * 20f * Scale()` 分行（`:142`），每笔弹字是**独立协程 + 独立节点**（`:146`）。
清场只一处 `Clear()`：`StopAllCoroutines` + 清 pending + 逐个 `Destroy`（`:61-79`），由读档/睡觉驱动。

[HarmonyPatch(typeof(StoreReputation), "OnItemTraded")]     // static、6 参，按形参名注入
public static class TradePatch {
    private static void Prefix(string factionId, out double __state) {
        __state = double.NaN;                               // NaN = 没拿到基线，不弹
        try { var r = StoreReputation.GetStoreReputation(factionId);
              if (r != null) __state = r.GetReputationExact(); }
        catch (Exception) { }                               // ← 空吞，见 1.4

    private static void Postfix(string factionId, double __state) {
        try {
            if (!double.IsNaN(__state)) {

                if (r != null) Pop.Record(factionId, r.GetReputationExact() - __state);   // ← 魔法全在这一行
            }
        } catch (Exception ex) { ModEntry.Log?.Error("trade patch failed: " + ex); }
    }
}

public static void Record(string faction, double delta) {
    if (!enabled || string.IsNullOrEmpty(faction) || double.IsNaN(delta)
        || double.IsInfinity(delta) || Math.Abs(delta) < 0.005) return;        // 小于 0.005 不弹

    var list = new List<KeyValuePair<string, double>>(pending);
    pending.Clear(); scheduled = false;                                         // 先清再画，后续交易另起一轮

### 1.4 踩坑与红线

1. **Prefix 空 `catch (Exception) {}`**（`TradePatch.cs:20-22`）——违反"对内暴露"，复刻时至少 `Log.Warn`。
2. **`factionId` 是硬绑定的形参名**：Harmony 按名注入，原版一改名就静默拿不到值（`__state` = NaN，功能无声消失）。
3. **原版 `GetStoreReputation` / `GetFactionNameByID` 内部直接摸 `PlayerStore.Instance` 且不判空**（`:168-178`、`:204-214`），读档空窗期会 NRE；它靠 `StoreUIManager.Instance == null` 早退兜住（`Pop.cs:93-97`），是侥幸不是设计。
4. **只覆盖交易**：议价（`BargainUIManager.cs:855/939/950/1038/1084`）、鉴定（`InspectionUIManager.cs:487`）、机器警报（`MachineAlarm.cs:234-246`）改声望**都不弹**；要全覆盖得挂 `ModReputation` 外层做差分。
5. **单次弹字 ≈ 8 个 TMP + 16 个方块 = 24 个 GameObject**；两笔间隔 > 0.12s 会叠两团（可接受，别再叠层）。
6. **`Scale()` 读 `windowUICanvas.scaleFactor` 做 DPI 补偿**（`Pop.cs:151-169`），所有偏移都乘它，漏乘在高分屏就糊成一团。
7. 本地化在 `Localization\zh.csv`，行格式 `rep_label,声望 · {0}`、`#` 开头为注释；运行时 `ModHelper.GetLocalized("reputation_pop", "rep_label", 阵营名)`（`ModHelper.cs:107`）。

### 1.5 对我们的可用点

- **差分法直接抄**：声望、现金、成色分、拍卖成交价等"原版已算好的最终值"一律不必复刻公式，两行拿到手。
- **`Pop` 可改名成通用飘字服务 `FloatText`**：`Record(键, 数值)` + 0.12s 合并 + 一行 20px 分行；459 行里约
  300 行是表现、逻辑不到 60 行。换颜色表就是"成交价飘字 / 成色判定飘字 / 现金变化飘字"。
- 碎光用 `TreeNodeRender.Instantiate()` + `sprite = null` + 手写抛物线，**比引粒子系统省事**，且与原版同层同序不被遮。

### 2.2 它怎么让"空白/空隙/次级背景"都能起框

**原版本来就有框选**，入口在 `ItemMultiSelectHandler`（`key = KeyCode.Mouse0`、`dragThreshold = 10f`），
`OnEventPress` 的 `State.Idle` 分支只有一个闸门 `!IsPointerOverDragSurface(mousePosition)`（原版 `:123-129`）。
闸门本体是私有静态方法（原版 `:318-345`）：raycast 第一命中若祖先有 `UIDragHandler` → true；否则看该
`TreeNodeRender.eventHandler` 的 `mouseDragFunc` / `mouseBeginDragFunc` 有没有注册 → 有就算 true。
**缺口就在这**：窗口背景、格子空隙、机器次级背景都挂了"拖窗"回调，手指落上去被判成可拖面，拉框永远起不来。

**它改的是命中测试，不是事件冒泡。** 第一刀：`IsPointerOverDragSurface` 的 Postfix 把 `__result` 从 true 翻回 false
（`DragSurfacePatch.cs:9-16`），前提是自己的 `SelectionHit(point)` 认这块地；事件冒泡一层没动，
`ItemMultiSelectHandler` 的算法也没改。第二刀：拖窗的真实动作跑在 `TreeNodeRender.OnBeginDrag` 里
（原版 `:249-256` → `mouseBeginDragFunc`），所以 `BeginDragPatch` Prefix 返回 false 掐掉它，`Drag/End` 用同一本
`blockedDrags` 账本决定放行（`SelectionRegions.cs:318-338`）——**只翻转 bool 会让拖窗和拉框同时发生，两刀必须一起下**。

**什么算"可框背景"**：`SelectionHit` 自己重发一次 `EventSystem.RaycastAll`（`:233-287`），再交 `IsBackground`
（`:169-231`）五级过滤：① 命中必须属于某个可见且已登记的 `PixelWindow`；② 该窗口必须含网格；③ 命中不能是
`Title/Close/Resize` 三个引用（**引用比较，不是名字**）→ 标题栏仍可拖窗；④ 最近父元素是 `GameItem`、或既非
`GameInventory` 也非 `MachineryContainer` → 拒；⑤ `background` 之外的节点若自带 `mouse*Func` → 拒（不抢别人的交互）。
最后是几何双保险 `Contains`（`:152-167`：屏幕点逆变换进节点局部坐标，看是否落在矩形内），三档矩形：

| 场景 | 矩形 | 出处 |
| --- | --- | --- |
| 窗口 `childElement` 自身是网格（桌面） | `(0,-num)~(widthPixels,-heightPixels)`，`num = style==Machinery(1) ? 21 : ((canMove\|\|hasTitle) ? titleHeight+yPadding : 0)` → **挖掉标题条** | `:208-216` |
| 网格套在 `MachineryPanel`（药片罐/水培） | `(0, label!=null ? -18 : 0)~(w,-h)` → **让出标签行** | `:217-224` |
| 其余普通网格 | `(-4, 4)~(w+4, -h-4)` → **四边外扩 4px，吃掉格间空隙** | `:225-228` |

**网格从哪来**：`GraphUtils.FindChildrenType<GameInventory>(window, IsGrid, StopAtInventory)`（`:142`），
`IsGrid = v is GameGridInventory || v is GameGridScrollableInventory`（`:71`）、`StopAtInventory = _ => false`（`:73`，
不剪枝挖到底）；`childElement` 自身是网格时直接收一条（`:132-141`）。
**生命周期三件套（缺一个就泄漏）**：`PixelWindow.Validate` 后置用 `___` 前缀注入 4 个私有字段做登记

### 2.4 踩坑与红线

1. **`entries` 拿 `PixelWindow` 当键，不 `Forget` 就永久泄漏**，`blockedDrags` 还会留下指向已销毁节点的键；
   `Clear(gestures: true)` 才连账本一起清（`OnDisable` 走的就是这条）。
2. **`21 / 18 / 4` 是像素魔法数**（原版 `EmporiumEntry.cs:934-940` 有 960×540 特判，说明原版自己也按分辨率分支）；
   换 UI 缩放或新窗口风格就错，复刻时要跟 `LetterboxManager.GameArea*` 换算。
3. **`Contains` 只看节点矩形、不看 `RectMask2D` 裁剪** → 滚动容器（`GameGridScrollableInventory`）里滚出视野的格子
   仍落在矩形内，可能被判为可起框区（推测，未真机验证）。
4. `hit.eventHandler != null` 之后还得看 4 个 `Func` 列表是否为空——只判 null 会把"挂空处理器"的节点也算进去。
5. **别在 `Validate` 的后置里改布局**：`RefreshVisible → Validate → Bind → Refresh` 已是自触发链，再改会递归。
6. 无热重载钩子（透视报告第 4 行），`Active` 靠 `OnDisable` 复位；我们复刻时补 `HotReloadPrepare/Activate`。
7. `IsPointerOverDragSurface` 是 `private static` 且只有一个重载，补丁才能只写方法名；原版一加重载就必须补参数类型表。

### 2.5 对我们的可用点

- **"翻转原版私有判定"是接管命中测试的最低成本范式**：一个返回 bool 的私有方法 + `ref __result`，就拿到全部上层行为，
  不重写算法。配对原则：**判定位翻 bool，动作位 `return false`**。
- **`___私有字段` 注入**（`WindowLayoutPatch.cs:8`）比反射干净，可用来从原版窗口掏"背景/标题/关闭"引用，
  我们做自定义窗口装饰时直接可用。
- 自家机器面板（药片罐、水培、容器）若也要"空格能起框"，抄 `MachineryPanel` 那段矩形（`:217-224`）即可，不动原版代码。

## 3. `3836661256` 支付宝/微信到账语音

**id**：`3836661256`（`<ID>alipay_voice</ID>`，v1.4.0，游戏 0.46，`<Capabilities />` 自闭合）
**反编译目录**：`缓存文件夹\decomp_ws\3836661256\`
**为什么值得读**：821 行（含 ~130 行中文数字读法）换来 5.3 万订阅。它把三套我们"知道但没用熟"的接口一次用全：
**`Sounds/` 目录协议、`ModConfig` + `GameOptionRegistry` 双通道设置、自建 `AudioSource` 串行队列**；
**144 个音频片段全部由文件命名承载**，代码里没有任何音频表。

### 3.1 规模与结构

### 3.2 音频怎么加载、什么时候播、怎么不叠音

**加载三跳**（原版 `ModLoader.cs:1839-1878` → 源码 `:481-515` → 源码 `:111-126`）：
① 原版加载器自动扫 `<mod>/Sounds/`，只认 `*.wav/*.ogg/*.mp3`，用 `UnityWebRequestMultimedia.GetAudioClip("file://"+file, AudioType)`
读盘，**键 = 去扩展名的文件名**（大小写敏感），存进 `LoadedMod.Sounds`（`LoadedMod.cs:51`）并
`AudioDirectory.RegisterModClip(modId + ":" + key, clip)`；② 这是**协程分帧加载**，加载完才 `ModHook.FireOnModAssetsLoaded(mod)`
（`ModLoader.cs:1877`）→ `OnEnable` 时未必就绪，作者因此懒加载：`GetClip` 首次调用时把 `ModLoader.Mods.Find(...).Sounds`
拷进自己的 `Dictionary<string, AudioClip>`；③ 播放用自建的 `new GameObject("AlipayVoiceAudio")` + `DontDestroyOnLoad` +
`AddComponent<AudioSource>()`（`playOnAwake=false, loop=false, spatialBlend=0`）。
**为什么不用 `ModHelper.PlaySound`**：那三条走原版 `AudioManager` 的共享 source（`ModHelper.cs:157-170` →
`AudioManager.cs:87-121`），新片段会顶掉同 source 上正在播的上一段，音量也不受自己控制；自建 source 才能 `Stop()`、
改 `volume`、读 `clip.length` 算间隔。`PlaySound2` 只作 `audioSource == null` 的兜底（`:275`）。

**什么时候播**：不挂交易/收款事件，改**读现金差分**（`:383-404`）——`playerCash - lastCash > 0` 才 `Enqueue`，首帧只记基线。
心跳不是 MonoBehaviour，而是两个原版 `Update` 的 Postfix（`EmporiumEntry.Update`、`MapUIManager.Update`），
`AlipayVoiceRunner.Update` 只调 `TickAudio()`。**代价：只在店界面或地图界面里检测**——睡觉结算/事件奖励的进账会攒到
下次进店合并播一次（推测，从代码路径可确定）。

**不叠音靠串行队列，不靠限流**：`List<string> pending` + `nextPlayTime`（`:51-53`、`:430-440`），每帧最多吐一个片段，
`nextPlayTime = 播完 + gap`，gap 分两种（开场白后 300ms、数字间 90ms）；队列超 200 条截断（`:422-425`）；
拖音量滑块时先 `Stop()` + 清队列 + 0.28s 后重排试听（`:223-231`）。

**命名协议** `s{80|100|120|150}_[w]{token}`：速度 4 档（`:517-526`）、`w` = 微信（无前导 = 支付宝）、token ∈
`d0`~`d9 / ten / hundred / thousand / wan / yi / yuan / open / wopen / mode_ali|wx|mix`。实测 **4 速度 × 36 token = 144 个 wav**；
换音色、换语言、换口音只换文件名，**代码一字不改**。`ResolveKey` 先试微信变体再退回通用片段（`:596-607`）。
中文读法是标准四级分段（`亿/万/个` + 补零 `d0` + `十` 特例，`:628-730`）；`Describe()` 把 key 串反译成人话进日志
（`:732-779`）——**读法写错日志一眼看出来**，这个自检手段值得照搬。

**设置双通道**：① `ModHelper.GetConfig(manifest.ID)` → `ModConfig.Define(...)` 8 项（`:68-79`），section 名「语音播报」→
自动进 `mod_config:<modId>` 窗口（原版 `ModConfigWindow.cs:7,42`）；`Define` 有 `bool / int(min,max) / float / string(choices) /
DefineEnum<T>` 五款（`ModConfig.cs:84-119`），`ConfigEntry<T>.Set/OnChanged`（`ConfigEntry.cs:93,101,141`）。
② 塞进原版「选项」页：`AddGameOptionSection / AddGameOptionKeyBind / AddGameOptionSlider`（`:291-317`），
`OnDisable` 里 `RemoveGameOptions("alipay_voice")` 成对移除（`:96`），否则重载后残留重复控件；
`GameOptionId(modId, optionId)` = `"alipay_voice:volume"`（`ModHelper.cs:207-210`）。

**"拖滑块实时生效"不是靠回调，是靠每帧偷看控件当前值**（`:172-221`，最值得抄的一招）：原版选项页读
`GameOptionUIManager.Instance.GetFloat(ModHelper.GameOptionId(...))`，模组配置窗口读
`CustomUIManager.Instance.GetWindow("mod_config:alipay_voice").Get("volume").GetFloat()`，差值 > 0.002 就
`ApplyVolume()` + `SchedulePreview()`。

private static AudioClip GetClip(string key) {
    if (clips.Count == 0) RefreshClips();                 // 懒加载；空表下次会自愈重试
    return clips.TryGetValue(key, out var value) ? value : null;
}
private static void RefreshClips() {
    try {
        LoadedMod m = ModLoader.Mods.Find(x => x.Manifest.ID == "alipay_voice");
        if (m == null || m.Sounds == null || m.Sounds.Count == 0) return;
        clips.Clear();
        foreach (KeyValuePair<string, AudioClip> s in m.Sounds)
            if (s.Value != null) clips[s.Key] = s.Value;
    } catch (Exception) { }                               // ← 空吞，见 3.4
}

private static void PumpQueue() {
    if (pending.Count == 0 || Time.unscaledTime < nextPlayTime) return;
    string key = pending[0]; pending.RemoveAt(0);                        // 每帧最多一个
    float gap = IsOpeningKey(key) ? OpenGapSeconds() : GapSeconds();     // 300ms / 90ms
    float len = PlayKey(key);
    nextPlayTime = Time.unscaledTime + len + gap;                        // 播完 + 停顿才轮到下一个
}
private static float PlayKey(string key) {
    AudioClip clip = GetClip(key);
    if (clip == null) return 0.05f;
    if (audioSource != null) { audioSource.Stop(); audioSource.volume = VolumeValue();
                               audioSource.clip = clip; audioSource.Play(); }
    else ModHelper.PlaySound2("alipay_voice", key);                      // 兜底
    return clip.length;
}

### 3.4 踩坑与红线

1. **`Sounds/` 目录名、文件名大小写敏感**，键 = 去扩展名文件名，`wav/ogg/mp3` 之外静默不加载（`ModLoader.cs:1844-1856`）。
2. **音频是协程分帧加载的**，`OnEnable` 时未必就绪。作者的"空表重拉"能自愈空表，但**部分加载完成时会缓存残缺表**；
   稳妥做法挂 `ModHook.OnModAssetsLoaded` 再 `RefreshClips()`。
3. **`catch (Exception) {}` 空吞**（`:512-514`）——违反异常策略，复刻时留 `LogError`。
4. **自建 `AudioSource` 与原版音量通道无关**：游戏"选项→音量"里那条管不到它，音量只认模组自己那 0~100。
5. **现金差分 + 双 UI 心跳**：非店内进账会合并、错时播（见 3.2）；要"任何到账都即时播"，得自己加常驻
   `MonoBehaviour` 或挂 `PlayerStore` 的收款方法，代价是处理"读档首帧基线"。
6. **快捷键三重保护**才敢用：`KeyBindHelper.SuppressHotkeys`、`StoreUIManager.IsTextFieldFocused()`、
   `Application.isFocused` ＋ `Time.frameCount` 去重 ＋ 0.25s 冷却（`:362-381`）——少任何一个都会在打字时误触。
7. **读档/新游戏必须成对重置**：`OnGameLoadedEarly` 与 `OnNewGameStarted` 都做 `initialized=false; pending.Clear();`
   （`:339-349`），否则跨档会播一次假到账。这正是"静态引用成对重置"的活例子。
8. 快捷键存 `PlayerPrefs`（`:43,305,324`），**不往原版存档塞东西**，符合零存档污染底线。

### 3.5 对我们的可用点

- **`Sounds/` + 命名协议是任何"播报类"需求的零成本方案**（到账、事件播报、顾客语音、机器提示音）：文件名即 id，
  `ModLoader` 自动加载并注册进 `AudioDirectory`，连 `ModHelper.PlaySound2` 都能直接用。
- **串行片段队列**（`pending` + `nextPlayTime = 播完 + gap`）比"限流 + 打断"自然，且天然支持拼接句子；
  一句话拆片段，才能换音量/读速/音色而不改代码。
- **"每帧偷看控件值"做实时预览**：不订阅、不反射、不必知道控件实现，两条 `GetFloat` 覆盖原版选项页与模组配置窗口。
- 中文数字读法 `ReadNumber/ReadSection`（~100 行）可直接抄进"单据金额播报""报价播报"。

## 4. 跨例总账：5 条「对我们的可用点」

1. **读最终值，别复算公式**（`3829053332`）：原版已算完的数值，`Prefix` 存 + `Postfix` 差分两行拿到手，难度倍率、perk 修正、封顶截断全自动正确；可替掉我们未来所有"数值镜像"代码。
2. **一个 bool 的翻转就是一次命中测试接管**（`3836727677`）：判定位翻 `ref __result`、动作位 `return false`，上层行为全部复用；两刀必须一起下，只翻 bool 会让拖窗和拉框同时发生。
3. **表现层可以完全无状态**（`3829053332`）："按阵营累加的字典 + 0.12s 去抖 + 每笔一个协程"三件套，足够支撑连续交易不覆盖、多阵营分行、读档/睡觉一键清场；上手就写状态机是过度设计。
4. **音频走 `Sounds/` 目录协议 + 自建 `AudioSource` 串行队列**（`3836661256`）：文件名即 key、144 片段零代码表、播完 + gap 才播下一段；`ModHelper.PlaySound*` 只做兜底，因为它走原版共享 source，会互相打断且音量不受控。
5. **设置永远双通道 + 每帧偷看**（`3836661256`）：`ModConfig.Define`（进 `mod_config:<id>` 窗口，存档外）＋ `AddGameOption{Section,Slider,KeyBind}`（进原版「选项」页，`OnDisable` 必须 `RemoveGameOptions`）；"拖动实时生效"别找控件回调，每帧比 `GetFloat` 差值即可。

> **共同的反面教材**：三例共 3 处 `catch (Exception) { }` 空吞（`TradePatch.cs:20`、`Pop.cs:161`、`AlipayVoiceMod.cs:512`），出问题时只留"功能不生效"一条线索、没有堆栈。我们照抄结构，但必须留 `LogError`。
