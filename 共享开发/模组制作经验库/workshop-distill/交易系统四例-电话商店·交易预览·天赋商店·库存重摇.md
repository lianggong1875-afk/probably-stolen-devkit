### 4 踩坑与红线

1. **`EmporiumTryAdd` 一次都没用**（全库 grep 零命中），这是刻意：六级兜底全满会 `DestroyIfUnplaced`，而"全物品商店"必然把柜台塞爆。它换成 `CanAccept` 预检 → 装箱 → `TryAccept` → `parentInventory == 目标` 复核 → 自己 `DestroyItemSafely` 收尸。与我们 `03` 的三条纪律同向，可直接当范例。
2. **`StorePhoneClient` 每个字段都是 `[ES3Serializable]`**（`StorePhoneClient.cs:28-64`）。往 `PhoneClientDict` 加条目 = 往存档里加条目；模组卸载后再读档，locID 找不到 `DialogFuncs` 就落到 `PhoneDialogList.BugDialog()`。所以必须**在 `WriteSlotFile` 窗口内摘掉**，且 Prefix+Postfix+Finalizer 三件套（异常路径也要摘）。
3. **`GameItem.GetNegociatedValue` 是全库最拥挤的靶点**。它只为"0 元购/售"改返回值，但判据很克制：只在 `CurrentBuyingItem == __instance` / `CurrentSellingItem == __instance`（本次交易那一件）时动手。**抄就抄这个判据**，别对全店物品一概改价。
4. **`TryAcceptOnce` / `UncheckedAccept` 的 Prefix skip 是高风险动作**，拦住的是正常拖拽。它判据三重：`!IsItemOwned(item)` + `parentInventory == backInvinvElement` + `HandleUnownedItemReturningToShelf` 为真，少一个就吞掉玩家的正常操作。
5. **`SanitizeInventoryItems`（`:870-913`）会永久改写玩家已有物品**：`width/height > 6` 就 `SetShape` 成 ≤6×6 实心块，并把 `backpack_medium_military / large_military` 换成 `simple_backpack_*` 贴图。只在"进这个商店"时跑。**我们若抄，只对自己的货架跑，绝不扫玩家背包。**
6. **空 `catch { }` 遍地**（`:3144`、`:3233`、`:657`…），反编译产物里 `catch` 都不带类型，无法判断原文是否有日志。**这是反面教材**：我们的内部逻辑不许静默吞异常，目录枚举失败应 `LogError` 一次再降级。
7. **无 `HotReloadPrepare/Activate`**（透视报告第 4 行「否」），重置散落在 `EndPhoneShopSession`/`OnDisable`。**别学**——我们规范要求读档与热重载成对重置。

### 5 对我们的可用点

1. **「物品大类 = 原版目录名 + 手写例外表」可直接抄成品类表**：`AddFromDirectories(list, "ModuleDirectory", "FurnitureItemDirectory", "ShipSystemDirectory", … "MiscItemDirectory")`（`:3777`）一行给了 22 个原版目录名，比 `GetDictionaryClassNameList` 输出后靠猜靠谱。
2. **`PreBuiltItemHelper` 是"完整造出机器/箱子"的唯一正确入口**：`CreateFurnace/CreateHydroponic/CreatePrinter/FullBeer/Medkit/LootCrateSecurity/RandomPerformanceModule/RealIngotPurity("99.9%")`（`:3955-4096`，30+ 分支）。`DirectoryMaster.Item("printer")` 造出的是**空壳**，只有 `PreBuiltItemHelper.CreatePrinter()` 带全套子件与标签。做"卖成品机器"必须走这里。
3. **「实体货架 + 离线装箱预演分页」是绕开自定义列表 UI 的现成方案**：页尺寸 `14×21`、单页 32 件、行/列优先双网格取并集，全在 `:3481-3527`。做"当铺仓库分页 / 展柜陈列"可零 UI 复用。
4. **`PhoneShopTradeScope`（93 行）是"临时放宽原版顾客参数"的干净模板**：`Begin` 记下 `useClientBudget/GetBudget/isRequireVariety/noAcceptingContraband/refusesHazardousWaterLabel/isMultiBuyDisabled/isBusinessComplete/isRegularSellDisable` 八项，`Apply` 全关，`End` 原样还原（`:16-68`）。做"特殊收购日/清仓日"直接抄。

**怎么保证不刷爆**：不靠次数，靠**四道状态守卫**（`:118-193`）：① 场景/UI 未就绪 → `SceneNotReady`；`NegociationUIManager.IsOpen || BargainUIManager.IsOpen` / `isClientBeingArrested` / `isHandlingShootout || ui.isShootingMode` → `FinishTransactionFirst`（`GetBlockingState:514-529`）。② `MapUIManager.IsInTransit` 直接 return；白天 `IsOutside` 或 `!isClientArrived` → `NoCustomer`。③ **`HasCustomerTransaction(...)` / `HasNightShopTransaction()`** → `TransactionAlreadyOccurred`（`BlockAfterTransaction` 默认 `true`）。④ 重掷 0 件 → `EmptyResult` 并回滚；钱不够 → `InsufficientCredits`。

**随机源一个都没动**：`RNG.random`（`RNG.cs:7` `public static System.Random random`）不碰、不重播种、不替换，`ScavHelper` 不碰。它只是**重新调用**原版摆货函数，于是内部的 `RNG.Roll / RNG.GetRandomInt / TableMaster.Roll / ItemSpawner.SpawnFromTable` 自然再掷一轮。**重摇的正确姿势：让原版自己掷。**

### 3 关键代码摘录

**（a）主流程：摘 → 掷 → 判 → 提交 或 回滚**（`:236-290`，节选）

```csharp
if (!DetachItems(backInvinvElement, list) || !DetachItems(frontInvinvElement, list2))
{ Reject(S.CouldNotDetachStock); return; }
foreach (Action item in actions) item();          // ← 重跑原版摆货函数
num2 = CountUnowned(backInvinvElement);  num3 = CountUnowned(frontInvinvElement);
if (num2 + num3 == 0) { Reject(S.EmptyResult); return; }
committed = TryCommitReroll(current, rerollFee);  // 这里才扣钱 + successfulRerolls++
if (!committed) return;
// finally: 还原 val2.isOfferWholesale / wholesaleDiscount（原版摆货会改这俩）
//          !committed 时 try { RollbackStock(back…); } finally { RollbackStock(front…); }
ItemGraphCleanup.Destroy(list2);  ItemGraphCleanup.Destroy(list);   // 旧货这时才真销毁
current.RefreshCounterItem();  instance.Validate(true);
```

**（b）摘货：临时开 `overrideLockRemove` 强拆**（`:376-401`）

```csharp
bool overrideLockRemove = inventory.overrideLockRemove;
inventory.overrideLockRemove = true;              // 原版字段，GameInventory.cs:11
int num = 0;
try { foreach (GameItem val in items) if (val != null && inventory.Expel(val)) num++; }
finally { inventory.overrideLockRemove = overrideLockRemove; }
return num == items.Count;                        // 差一件就算失败 → 走回滚
```

**（c）回滚：先删新来的，再塞回旧的，塞不进就抛**（`:403-430`）：遍历 `inventory.childItems` 倒序，`!originalItems.Contains(val)` 的一律 `ItemGraphCleanup.Destroy(val)`；再 `RestoreItems`，其中 `val.parentInventory == null && !inventory.UncheckedAccept(val)` 就 `throw new InvalidOperationException("Could not restore detached stock to its original inventory.")`。

**（d）找回"当初是谁摆的货"**（`StockReplay.cs:64-92`）

### 4 踩坑与红线

1. **~140 条反编译 lambda 名是硬编码指纹**（`<CreateJunker>b__19_0`、`StoreClientList+<>c__DisplayClass49_0.<CreateScavGeneral>b__0`，`StockCallbackPolicy.cs:22-44`）。任何一次游戏更新、甚至一次不同的反编译重排编号，这张表就全废，**失效表现是静默的**（该回调被跳过 → 只掷出一部分货；`actions.Count == 0` → `NoSafeStockAction`）。**绝不能抄这套指纹**；若必须识别"某个委托来自原版哪个函数"，只能 `MethodInfo.Name` 前缀 + 白名单双条件，**并把匹配失败打成可见警告**（它这里没有）。
2. **`AddDirectSellingItemToTable(GameItem, …)` 在柜台满时会销毁物品**：原版最终走 `TryAcceptAllOrDestroy`/`DestroyIfUnplaced`（`PlayerStore.cs:2540-2573`）；而 **string 重载有前置 `frontInvinvElement.CanTakeAnything()` 检查，根本不会造出实例**（`:2530-2538`）。`StockSupply.PlaceScavCrateStock` 混用两种（`:120` 传实例，`:83` 传 id）。**重掷成功的前提正是"先把旧货摘空"**——顺序错了就是一片货凭空消失。
3. **`StoreClient` 上的临时字段会被摆货函数改掉**：`isOfferWholesale` / `wholesaleDiscount` 必须记下并在 `finally` 还原（`:260-261`），否则"批发报价"会串到下一次交易。另外重掷中途会弹议价窗，所以 `NegociationUIManager.OpenUI` 的 Prefix 直接 `return !IsRefreshingStock`——窄口用法，只在那极短窗口内为真，可接受。
5. **`overrideLockRemove = true` 是"绕过移除锁"的原版字段**（`GameInventory.cs:11, 237-253`）。拿它强拆玩家锁定物品、再指望 `UncheckedAccept` 塞回去，一旦塞不进就 `throw`（`:414`）——异常冲出 `finally` 时**货架已被清空一半**。它选"崩"而非静默丢货，但依然是洞。**抄这段要加一层：摘货前先 `CanAccept` 预演回程空间。**
6. **`StoreAccess` 用 `AccessTools.Field(typeof(PlayerStore), "instance")` 绕开 `PlayerStore.Instance`**，能读到"未初始化时的 null"而不触发属性逻辑。**这违反"先判 `PlayerStore.HasInstance`"的规范，且这里没有理由。**

### 5 对我们的可用点

1. **夜间店重掷只需两个原版 public 函数**：`StoreClientList.PlaceInventorInventory(bool isVisitingPlayerStore = false)` 与 `PlaceInventorSpecialStock()`（`StoreClientList.cs:578, 490`），配 `AfterhourEvents.IsActive("special_stock")` 选路。**做"杰克逊博士补货/夜间商店刷新"不需要任何 Patch。**
2. **「摘货 → 重跑原版 → 一次性提交或整体回滚」是重掷类功能的通用骨架**（`:236-290`）：`DetachItems`（含 `overrideLockRemove` 存取）+ `actions()` + `committed` 标志 + `try/finally` 双 `RollbackStock`。**只要守住"能否整体成功"，就不会出现半新半旧的货架。**
3. **`TransactionGuard`（90 行）是"本顾客/本晚是否已交易"的现成状态机**，靠 4 个边界补丁喂。凡"交易后就不许再做 X"的功能（退货、重摇、改价）都能直接挂上去。
4. **`ModHelper.Lookup("对方 modId", "key")` 是跨模组扩展点的标准通道**：`better_merchants` 通过它交出 `(generate, rollback, keep)` 三元组（`:156`）。我们若要别人能给我们加"可重摇的来源"，就该提供同形状的 `Lookup` 接口。
5. **`ConfigSectionLocalization`（29 行）教会我们给 `ModConfig` 分区做本地化**：`ModConfig.Find(modId).Sections` + `ModConfigWindow.Open` Postfix 里 `__result.Get("section_" + section).SetText(...)`，且**先判 `mod.Instance.GetType().Assembly == 本程序集`**，不碰别人的配置窗口。这个"只改自己"的门卫，所有 Patch 都该有。
