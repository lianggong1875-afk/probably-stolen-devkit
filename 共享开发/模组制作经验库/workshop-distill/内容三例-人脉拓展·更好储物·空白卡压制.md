### 1.2 "人脉"是什么：原版**关系网**（`NetworkUpgrade`），不是一批新顾客

游戏里统称"关系网"（`03-原版接口速查.md` §关系网节点）：`ModHelper.AddNetworkUpgrade(modId,id,cost,subtitle,title,desc,onUnlock,tab,iconKey,prerequisites,cooldownDays,…)` → `NetworkUpgrade.RegisterModUpgrade`（原版 `NetworkUpgrade.cs:267-289`）把定义塞进 `modDefinitions` 并把 `onUnlock` 记进 `NetworkUpgradeList.UnlockActions[id]`，同时在已有存档里补一条 runtime 记录（`:285-288`）。**37 项里没有一项是"新面孔顾客"**（唯一一次写 `storeClientDict` 是 Pastel 的两只快递员，见第 4 条），它的"人脉"是三层叠加 + 一处例外：

1. **目录条目**：37 条，`Requires` 里挂的是**原版** id（`Upgrades.cs:73` `RUSTWATER_TAP`、`:89` `BREWER_SHAREHOLDER`、`:96` `MINER_SHAREHOLDER`…）。所以"人脉等级"就是原版那套股东/中间人解锁链——**它没造新进度系统，只是挂在原版进度树的下游**。
2. **效果实现**：绝大多数买完即可见的数值型，靠"改原版 tag"或"补一个 Postfix"（`MachineBoost.cs:24-30`、`MilitaryPower.cs`、`WaterTaps.cs`）。
3. **引荐 → 电话 → 快递**：4 条"引荐"类（红小鬼/化学家/药房/矿工）不是新顾客，而是**给原版已有的常客电话加一个下单选项**；跑腿的仍是原版快递员 id（`courrierRedImp`/`courrierChem`/`courrierPharma`/`courrierMining`）。
4. **唯一例外**：`Pastel.cs:120-121` 直接往 `StoreClientListDict.storeClientDict` 写了两只**新**快递员（`courrierPastel` / `courrierPastelFree`），并给 `PhoneClientDict[4614L]` 建了一条电话（`:122-133`）。这是全库仅有的"造顾客"处，也正是 `07-踩坑台账` 标 ERROR 的那个字典。

### 1.5 踩坑与红线

1. **`NetworkUpgrade.IsUnlocked(string)` 不判空**（原版 `NetworkUpgrade.cs:959-966` 直接 `PlayerStore.Instance.networkUpgrade`）。在主菜单/读档前调用必 NRE。它全模组都用 `Ids.On` 的 `try/catch` 兜——这不是防御性垃圾，是**这个 API 的真实缺口**；我们抄就该抄这一层，且注释写明原因。
2. **累加型 tag 只在 `SetInt` 之后加**：`ComputeModuleEffect` 末尾是 `SetInt(total)`（原版 `ModuleHelper.cs:221-232`），所以 Postfix 里 `Bump(+30)` 不会被反复累加。**换成 `ApplyBasicModuleEffect` 或 `MachineBoost.RefreshAll` 自己去加就会越加越多**——`MachineBoost.RefreshAll`（`MachineBoost.cs:52-80`）刻意只做"重算一遍原版两条调用"。
3. **`storeClientDict` 写了不删**：`Pastel.Register` 每次读档/新日都重写（`Pastel.cs:100-121` + `Runtime.cs:33`、`:101`），但 `OnDisable` 只 `RemoveNetworkUpgrades`，**没有把 `courrierPastel*` 摘掉**。热重载/禁用后字典里留着指向死闭包的工厂 → 一旦有人 `QueueFuturClient("courrierPastel")` 就落到 `CreateStoreClient` 的 ERROR 分支（原版 `StoreClientListDict.cs:1118-1129`：找不到就 `LogError` 并塞一只拾荒客）。我们用这个字典必须成对增删。
4. **改原版电话 UI 的气泡数是共享资源**：`DisplayChoice` 只补不删（`PhoneChoiceExpandPatch.cs:34-57`），克隆出来的气泡带 `_modN` 后缀留在场景里。它没做"对话结束后清掉"，靠 `DialogChoiceBubble.index` 复用（推测：原版 `DisplayChoice` 自己按 `choices.Count` 复用，多出来的不会再被读到）。
5. **存盘期改活对象要三件套**：`SaveGame` 的 Prefix 关服务、Postfix **和** Finalizer 都还原（`SaveInertPatch.cs:14-29`）。另配 `Safety.SelfHeal`（`Safety.cs:102-107`）在"没买这个升级"时把残留的 `StoreService` 从 `storeService` 列表里删掉——**模组条目进了存档就要负责清理**。
6. **静默 `catch { }` 遍地**：`MachineBoost`/`WaterTaps`/`Supplier` 大量 `catch (Exception ex)` 只 `Log.Warn` 不抛，反编译产物里还有无类型的空 `catch`（`Press` 那类）。**这是反面教材**，但我们也要承认它的收益：37 个功能里坏一个不影响其余 36 个。折中写法 = 每个功能一个 `Safety.Run(action,"what")` 包裹 + 一条日志（`Safety.cs:32-48` 就这么做的）。
7. **`<GameVersions>` 填错会红字**：`3838830653` 的 manifest 里作者留了一整段注释解释"填了只会显示不适用"，最终留空。同批次三个模组里两个填了、一个留空——**留空是更安全的选择**。

### 1.6 对我们的可用点

- **"加内容"不必造 NPC**：想在当铺里加"中间人/线人/领班"，正确路径是 ① 一条 `AddNetworkUpgrade` ② 一个 `PhoneDialogList.*Regular` Postfix ③ 复用原版快递/访客 id。`SetClientSource` + `OnGenerateCustomerVeryLate` 留给"真的要新面孔"的场合。
- **进度寄存原版**：`NetworkUpgrade.IsUnlocked(id)` 就是存档位，不必自写 `SetModDataInt`。37 个功能零存档代码，卸载后条目自动消失——`deepspace_pawn` 若要加"声望/执照/许可"，优先借这张表。
- **可退开关是产品级设计**：`RevertSetting.cs` 194 行做"改过的原版数值一键还原"，`Runtime.OnConfigApplied` 里分叉（`Runtime.cs:67-77`）。**卖数值的商品必须带退款/回退**，否则差评必来。
- **价格逐项可配**：`Prices.DefineAll` 对 37 条各开一个 `ConfigEntry<int>`，按 `subtitle` 自动分节（`Prices.cs:37-60`）。我们做"目录型商品"照抄这个模式，别把价格写死进代码。
- **跨模组探测的克制写法**：`MduCompat.TryInstall` 只在 `AccessTools.TypeByName("MoreDeviceUpgrades.Engine")` 找得到时挂补丁，且**最多试 3 次就永久放弃**（`MduCompat.cs:21-64`），并在自己算完后再调回对方的方法（`MachineBoostPatch.cs:26-29`）。不引对方 DLL、不 `HarmonyBefore("mod.xxx")`。

### 2.5 踩坑与红线

1. **`RepairVanillaMedBoxes` 会改玩家已有的原版物品**（`PackStore.cs:345-399`）：它扫 `identifier == "med_box"` 且"贴图不是自己的、名字等于自己箱子名"的物品，然后 `item.SetShape(val.shape)` + 覆盖 name/desc/flavor。这是**唯一一处动原版物品形状的地方**，靠"名字 + 贴图"两个弱判据定位，本质上是在打自己上一版留下的脏数据。**我们绝不写这种"按名字猜自己人"的修复**：用自己的 tag 标记归属，永远别用名字。
2. **`NormalizeShape` 只扫自己人**（`PackStore.cs:175-201`：`Packs.Of(item) != null`），这才是读档修复该有的范围。两条并排放，正好是一对正反教材。
3. **扩容失败必须"留着套件"**：`Prefix return false` 意味着原版逻辑完全不跑，销毁权就在你手上。它每条失败分支都 `return false` 且不 `kit.Destroy()`（`:230`、`:246`、`:252`）。**一旦这里误删，玩家损失的是消耗品**——比崩溃更招恨。
4. **面板里的 `content` 不是网格**：`MachineHelper.Panel` 会把内容 `WrapInIntake`（原版 `MachineHelper.cs:70-73`），所以拿页网格必须像 `PackGrids.All`（`:8-50`）那样穿 `MachineryIntake.content` 再 cast；`Press` 那边同样为此写了 4 层循环（`Press.cs:348-367`）。**直接 `as GameGridInventory` 在机器窗口里必然 null。**
5. **`PowerHelper.ChargeBattery` 是共享靶点**：电池舱过夜充电直接调原版三参重载（`BatteryCharge.cs:178`），而同一批的 `3834776998` 正在给这个方法打 Postfix。两模组同时装 = 充电量可能被二次改写。**我们若也要充电，走 `PowerHelper.ChargeBattery` 就必须考虑别人也在改**（推测：谁先谁后取决于 Harmony id 排序）。
6. **卡没有"每件数据"**：`PackUnlock.LockOf` 是拿 `card.identifier`（退化时 `spritePath`）去一个**硬编码 switch** 里查锁 id（`PackUnlock.cs:188-219`：`sec_keycard→LOCK_ID_SEC`…`blank_keycard→""`）。它没读任何 per-item 字段。这和 `3837224174` 的结论一致，是本档案第三例的关键前提。
7. **反编译空 `catch` 不能照抄**：`ExpansionPatch` 20 个、`BatteryCharge` 19 个、`PackStore` 15 个 `catch`。其中相当一部分只 `Log.Warn`，但**扩容/读档这两条主链上的失败必须让玩家看见**（它做到了：`kit kept` 有日志）。我们保留它的"不抛"，但必须补日志字段。
8. **`GameVersions` 留空**：manifest 里作者亲笔注释"填了只会让菜单显示不适用于游戏版本的红字"。核对原版行为：留空 = 显示 `-` 且永不警告（推测：来自 ModLoader 清单解析，未逐行核）。

### 2.6 对我们的可用点

- **"新容器"是零形状风险的路**：4 处 `SetShape` 里 3 处打在自己物品上（`PackItem.cs:61`、`PackStore.cs:189`、`BatteryCharge.cs:227`），唯一的越界是 §2.5-1 那处脏数据修复。`deepspace_pawn` 若要做"票据匣 / 合同箱 / 证物袋"，照 `PackDef` + `PackItem.Create` 这两百行就能起，形状/容量/过滤器全在自己手里。
- **专用容器 = 一个 `mayInventoryAddItemFunc`**：不用新类型、不用新 UI，`(added) => Filter(added)` 一行就把"只收一类"做死了。配合右键 `onToggleSlotItemFunc` 就是完整的"一键收纳"体验，**零 Harmony**。
- **能吃原版扩容套件**：`GetKitTabs`/`CanExpand`/`Expand` 三处 Postfix/Prefix 就把自家箱子接进原版"储物扩容套件"经济（`storage_bay_expansion_kit` / `STORAGE_EXPANSION_KIT_TAG`）。我们若做可升级容器，这套接口比自造升级件省一个物品位。
- **"诊断即功能"**：`BatteryCharge` 里 200 行是 `SkipReason`/`Tally`/`Probe`/`Where`/`Label`（`:52-83`、`:300-530`），把"为什么这颗电池没充上"写进日志。玩家反馈"没生效"时这类日志能省掉一整轮排查——**建议我们每个新机器都配一个 `Diag()`**。
- **读档修复要成体系**：`EnsureGranted → NormalizeShape → Relocalize → PurgeInvalid → RecoverOverflow → RepairAll` 六步固定顺序挂在 `OnGameLoadedLate`（`ModEntry.cs:79-100`）。这是"内容模组 + 老存档"的标准收尾流程，可直接当清单用。

### 3.2 "空白卡"是什么，压制机是什么

- **空白卡是原版物品，不是新物品**：`MiscItemDirectory.cs:66` `Add("blank_keycard", () => BlankKeycard())`，实现就是 `BlankKeycard()` 一个工厂方法、共 11 行（`MiscItemDirectory.cs:1218-1228`：贴图 `Items/items_misc:blank_card`、名称/flavor/描述、`SetGameItemType("ACCESS_CARD")`、`AudioHelper.InitPlasticCard`、`unitValue = 15`）。**没有任何逐件数据**。

- **所以这台机器做的是"原料厂"**：把垃圾换成**空白卡/DNA 盘/空电池**三种原版原料，玩家仍要走原版 desequencer 才能把空白卡变成真卡。**它没有、也不需要每件数据。**
- **它是一台全新机器**，不是原版机器的配方：`ItemDirectory.CreateEmptyItem(null).SetContentWindow(...).SetSpriteAndShapeFromMod("blank_card_press","blank_card_press_icon")`（`Press.cs:120`），`MachineryHelper.InitMachinery(machine, 10, false)`（`Press.cs:130`，即"耗电 10、不可开关"），四个面板 = 电池 / 材料 / 输出 / 控制（`Press.cs:113-119`）。

```csharp
    int slot = Slot;                                  // PlayerStore.saveSlotId，拿不到就 NewGameData.saveSlot
    if (slot < 0) return file;                        // :71-74 都拿不到 → 退回全局文件并提示
    int dot = file.LastIndexOf('.');
    return string.Concat(dot > 0 ? file.Substring(0, dot) : file, "_", slot.ToString(), dot > 0 ? file.Substring(dot) : "");
}
```

### 3.5 踩坑与红线

1. **库存对原版经济完全不可见**：`BCP_STOCK` 是机器自己的 tag，`unitValue` 恒为 350（`Press.cs:124`）。原版读价值只看 `unitValue` + 六个具名修正项（电量/舒适/护甲/液体/器官等），不读自定义 tag——已核 `GameItem.cs:419-421` 的 `GetValue` 与 `:427-462` 的 `ValueModifier`。后果两条：① 玩家把机器卖掉/拆掉，囤的 5000 点库存**一起蒸发**；② 店里的资产、保险、案值统计都看不见这笔钱。我们做"带库存的机器"必须二选一：把库存折进 `unitValue`，或卖出前强制清空并在 tooltip 里写明。
2. **每帧 `Update` 只为一个一次性动作**：`AutoRunner.Update` 每帧调 `RunPendingTick`（`AutoRunner.cs:7-16`），而真正要跑的只是"过夜后 1.5 秒"那一次（`Press.cs:275`、`:287-291`）。**这是可以直接省掉的常驻开销**——用 `ModHook` + 协程/延迟表，或者干脆在 `OnGoingSleepLate` 里同步做完。我们别复制这个 `MonoBehaviour`。
3. **`PlayerStore.instance` 是私有静态字段**：`SlotStorage` 用反射读（`SlotStorage.cs:48`）来避免 `PlayerStore.Instance` 的副作用（推测：`Instance` 的 getter 可能在未初始化时抛/建对象）。我们规范里已有 `PlayerStore.HasInstance`，**优先用它，别反射**。
4. **"待补发"这类状态必须幂等**：`GrantMachine` 三条失败路径都写 `press_pending_delivery = true` 并调 `MarkEntryOwned()` 保持"已购买"外观（`ModEntry.cs:439-466`），`SyncOwnership` 每次开卷帘重试、成功才 `MarkDelivered`（`:490-535`）。**"钱付了东西没到手"是差评第一来源**，这套状态机值得抄，但请写进模组私有键（它用了 `SetModDataBool` + 自建 `flags.txt` 两套，重复了）。
5. **`<GameVersions>` 写了两条**（`1.0.0` + `0.46`），而游戏实际仍报 `0.46D`；同批两个模组一个留空一个写 `0.46D`。**没有统一答案，但"写错版本号"会直接触发红字警告**，见 §1.5-7。
6. **`MOD_VERSION` 常量与 manifest 不同步**（`0.3.1` vs `0.4.11`）。日志里报的版本号会误导排查——我们的 `ModLog(manifest)` 一律取 manifest，不自己写常量。
7. **34 + 27 个 `catch`**：`Press.cs` 与 `ModEntry.cs` 几乎每个方法都整体 `try/catch` 吞掉。好处是"一台机器坏了不炸存档"，坏处是**这台机器为什么不出货，日志里只有一句 `LogLine`**。它的折中是每条失败路径都写一句人话（`"库存不足：blank_keycard"`、`"没有空间：plant_dna_disk"`、`"自动制卡跳过：… 电池槽为空"`）——**这一点值得我们学，`catch` 本身不值得**。
8. **`Print` 里先 `CanAccept` 再三级兜底，最后才 `Destroy`**（`Press.cs:789-825`）。符合 `03` 的"精确投放三件套"；唯一越界的是它把兜底打到了 `EmporiumEntry.Instance.backInvinvElement`（全场背包），**投放范围比机器窗口大得多**，玩家会疑惑"东西跑哪去了"。

### 3.6 对我们的可用点

- **"零 Harmony 造机器"的完整清单**：`GameSlotInventory`/`GameGridInventory` + `mayInventoryAddItemFunc` + `MachineHelper.Panel`（自动包 `MachineryIntake`）+ `MachineHelper.CreateMachineryWindow` + `MachineHelper.PowerPanel` + `MachineHelper.SetupBatterySlot` + `MachineryHelper.InitMachinery` + `ItemDirectory.SetContentWindow`。`deepspace_pawn` 里凡"不想碰补丁"的新机器，照这 9 步就能起。
- **"库存 = 一个 int tag"是最省的机器状态**：`ModifyTag(tag, st => st.Enable().SetInt(v))` + `GetTagReadonly(tag).GetInt()`（`Press.cs:864-892`）。不用自建存档、不用 `SetModData`，跟着物品存档走。**前提是你要接受"库存跟机器走"**（见 §3.5-1）。
- **原料厂 > 成品机**：它不做"打印真卡"，只做空白卡 + DNA 盘 + 空电池三种**原版已存在的中间物**。这解释了 1.26 万订阅：玩家缺的是原料，不是功能。我们若要加"印刷/压制/合成"类内容，优先选原版**已有物品 id** 作产物，兼容性与平衡都更好。
- **人脉商店是发机器的正路**：`AddNetworkUpgrade(..., isRepeatable, onUnlock: GrantMachine)` + `GetNetworkUpgrade(id).IsUnlocked()` 对账（`ModEntry.cs:293-386`、`:490-535`）。比"塞一只顾客卖机器"稳，也比"开局白送"有节奏。
- **按存档槽分文件**：`SlotStorage` 134 行给出"读 A 档看到 B 档标记"的最小解法（文件名拼 `_<slot>`，拿不到槽位就退回全局并提示）。我们任何 `ModData` 文本文件都可套。
