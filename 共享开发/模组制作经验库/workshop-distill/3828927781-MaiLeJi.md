### 3.2 一家门店"从开门到打烊"（一个营业日的完整时序）

1. **开门**（`OnShutterOpenedLate`）→ `Delivery.OnShutterOpened`：若开过局发放，把 1 台快餐加工台摆到交易台、往机器肚子里塞 5 种材料各 2 份（`Delivery.cs:25-60`）。**v0.6.0 起默认不发**——开局什么都不给（`Delivery.cs` 内 `!_on` 分支的日志原文）。
2. **客户生成**（原版 3 类散客之后，`OnGenerateCustomerVeryLate`）→ 三个模组客户各自 `MakeClient()` 后 `mgr.TryAddClient(c, true)` 再 `MoveToFront`。**总部经理**只在「固定日 = 第 3 个星期几（周三）/ 或玩家打过电话的次日 / 或未加盟时的每 7 天」出现（`Franchise.ShouldComeToday`、`Franchise.cs:239`）。
3. **交易**：柜台上的货由玩家拖到交易台 → **原版议价 UI** → 成交时 `PlayerStore.CanSellThisItem` 后置 + `NegociationUIManager.SellMultiple` 前置**双闸门**判"外卖包有没有对单"（`Packager.cs:996-1048`）。
4. **记账**：成交额 `/400` 累加成声望（`Reputation.cs:797-816`，`RepIds.RepPerCredits=400`、`RepMax=200`）；卖错单则 `QueueRefund` 记一笔退款/差评（`mlj_rep_refund` / `mlj_rep_refund_log`）。
5. **过夜**（`OnHandlingNightlyServicesLate`）→ `Machine.OnNight()`：`store.FindAllItem(true)` 扫全店物品 → 命中 3 个 `Spec` 的机器跑 `ProcessOne`（吃电、吃油、吃杯、出成品），失败计数打日志。**同一次过夜也被 `OnGoingSleepLate` 再触发一次**（两个钩子绑同一个 `OnNight`，靠 `_probeLogged`/内部幂等去重）。
6. **夜结报表**：`NightLines.PushAll(marker, lines)` 先按 marker 删旧行再写新行，**保证不重复累积**（`NightLines.cs:90-111`）。
7. **打烊/读档**（`OnGameLoadedLate`）→ `Machine.RebindAll()` 重建窗口绑定 + 清 `_lastDay`/`_deliveredDay` 这类"同日去重"静态标记。

### 3.3 "连锁"的真实闭环（四步，无一步是模拟）

```
名片 mlj_manager_card（document 物品，双击被 3 个 Prefix 拦掉，不弹任何窗）
   └─ 玩家走到店里电话机 → 手敲 9527 → StorePhoneClient.GetCallDialog 后置接通
        └─ 通话日写入 modData → 她「隔天到店」（无 CD，再打一次就顺延）
             └─ 到店 → 说完话（Dialogue.endAction）才把【订过的东西】摆上柜台
                  └─ 玩家拖到交易台 → 原版议价 → 成交 → 声望 += 信用点/400
```

- **订购**：`OrderPanel.Open()`（自绘 UGUI，四页签：整箱 / 散装 / 机器 / 菜单）→ 结果写进一个 `modData` 键 `mlj_hq_order`（管道分隔字符串）。
- **"机器"页签 = `Ids.HqCore` 6 件**（`OrderPanel.cs:MachineList`）：店面 2,400₵ + 可乐机 + 加工台 + 炸锅 + 打包机 + 奶昔机。**"分店"就是从总部订购的一件商品**。
- **加盟**：`Franchise.BuildAsk()` 三个选项（立即加盟 / 再等等 / 拒绝），加盟费 `MlConfig.JoinFee` 默认 **800₵**（`store.PayMoney(JoinFee, true)`，`Franchise.cs:605`）；加盟赠品是名片，只送一次。

### 3.4 "连锁"的数值系统：四项逐一判定

| 问题 | 有没有 | 证据 |
| --- | --- | --- |
| **统一采购** | **有，且是核心** | 自绘订购面板 → `mlj_hq_order` → 经理到店按单摆货。四类货：整箱 / 散装 / 机器 / 菜单 |
| **资源调拨** | **没有** | 只有一个**只读**统计：`CountInBranches(id)` 遍历背包里所有 `mlj_branch_store` 数物品（`Franchise.cs:323-357`）。没有"从 A 店搬到 B 店"的操作，因为分店只是容器，物品本来就在玩家背包里 |
| **品牌声望** | **有，但是全店一份** | 1 个 `StoreReputation` 派系 + **10 档阈值** `{-200,-140,-90,-50,-20,20,50,90,140,200}`（`Ids.cs:1256-1257`），效果：客户预算 +30%、订购件数、订单最少份数、打包售价 ±500bp、退款倍率 ×2 |
| **员工排班** | **没有** | 全库唯一"员工"是"总部经理"这个**客户 NPC**——她不是雇员，是供应商。没有雇佣、没有工资、没有班次 |

## 5. 踩坑与红线

1. **`WriteSlotFile` 前缀改写原版存档对象（§4.6）—— 别学。**它为了"删 mod 后存档零残留"，在写档瞬间**把电话条目和声望派系从活的 `PlayerStore` 上摘掉**，靠 Postfix 放回。一旦 `WriteSlotFile` 中途抛异常、或 Harmony 的 Postfix 因别家补丁跳出不执行，**这一局玩家的热线和声望就永久消失**。作者自己在 catch 里写「扫场会自己补回来」——这是**推测**（本文未能证），不是机制保证。我们的规范是"持久化只写模组私有键，不改原版存档结构"，正是为了不吃这一口。
2. **799 个空 `catch {}`（1,654 个 catch 的 48.3%）**——全库一半的异常处理器**什么都不做**。`catch { return null; }`、`catch { }` 遍布 `Priv`/`Franchise`/`Compat`。这与我们硬规范第 2 条（对内暴露、边界捕获、必须 `LogError` 留堆栈）正面冲突：它把"读不到字段"和"逻辑写错了"统一降级成"返回 null/0"。
3. **配置系统是两套，其中一套是空壳。**`MelonPreferences.cs`（14 行）是 MelonLoader 的**残骸垫片**：`CreateEntry` 只 `new PrefEntry(key, def)`，`MaiLeJiPrefs.Save()` **方法体为空**，`GetBool` **只读环境变量 `MAILEJI_<KEY>`**。⇒ 那 6 个开关（配送加工台/补发/启动物料/开机自检/详细日志/调试出汉堡）在游戏里**既没有 UI、也不落盘**，永远返回默认值。它们的**长文案**（"关掉后不会再往店里摆任何东西"）在当前 DSH 版本是**不成立的**。真正能用的是另一套 `MlConfig`（`ConfigEntry<int/bool>` + 分区 + tooltip + 「应用」按钮，384 行）。
4. **0 处 `UnpatchAll` / 0 处 `HotReload`。**54 个补丁挂上去就不再摘；`OnDisable` 只解绑 4 个 `ModHook` 钩子（`MaiLeJiMod.cs:389-417`）。热重载会**在同一方法上叠第二份补丁**。我们的规范要求静态引用在读档与热重载成对重置——它没有这道工序。
5. **状态放在静态字段里，靠"读档时清"兜底。**`HqManager._lastDay` / `_deliveredDay`、`BranchStore._opened`、`ClickProbe` 的命中表全是 `static`；作者自己在 `HqManager.cs:86` 的日志里承认「读档会经 `SceneLoaded` 清掉这两个标记，**不该再出现这种脏标记**」——即他知道这是隐患。
6. **用日志代替断言。**1,329 行日志里大量 `✗【请把这条日志发我】`。这是一种"故障可见性"策略（值得学），但它同时意味着**没有离线测试**：全库无测试工程，自检（`SelfTest`/`SelfCheck`/`SelfTestFingerprint`/`RecipeSelfTest`/`PriceSelfTest`）都在**运行期**跑，靠人读日志判读。
7. **`ModPaths` 里有一条"能力形"逃逸路径（目前是死代码）。**`ModHelper.GetModDataFolder` 失败后 fallback 到 `%LOCALAPPDATA%\MaiLeJi`——哪天有人把它接上，零能力包就会开始往用户目录写东西。
8. **两处序列化偷懒**：`mlj_branch_keys` 用 `'|'` 存 12 个快捷键，标签含 `|` 就串格，靠 `MaxLabelChars = 4` 缓解、无转义（`BranchKeys.cs:117-227`）；`Sprites.cs:1146` 一条 **2,916 字符**的 `Log.Msg` 把整部美术变更史塞进单行——可维护性为零，却是自检指纹不一致时唯一的线索。
9. **`Machine.OnNight` 只覆盖 3 台机器。**其余 7 台（打包机、农场、孵化机、喂食机、清粪机、可乐机、奶昔机）靠各自的补丁/交互触发。读它时**不要以为"过夜"是全量生产**。
