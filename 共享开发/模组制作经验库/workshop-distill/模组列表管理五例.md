## 1. 模组启用状态的存储真相

### 1.1 位置与格式（硬证据，四源互证）

**不在**游戏目录 `Mods\`（那里只有 DLL 与 `manifest.xml`），**不在** Steam 工坊目录，**不在** PlayerPrefs。
真正的状态文件是 **Easy Save 3 的 JSON 文件 `%persistentDataPath%\SaveFile.es3`**，整个文件是一张**扁平的键 → `{__type, value}` 表**，一行 JSON、无缩进：

```json
{"optionSave":{"__type":"bool","value":true}, …,
 "workshopOwners":{"__type":"string","value":"{\"entries\":[\"3831227725|76561198397880843\",…]}"},
 "modTrustMac":{"__type":"string","value":"f3a12702f619353964ca00fd93f791393757781cc645629ba06f34c0205f6255"},
 "modTrust":{"__type":"string","value":"{\"records\":[{…}],\"stopped\":[]}"},
 "modOrder":{"__type":"System.Collections.Generic.List`1[[System.String, mscorlib, Version=4.0.0.0, Culture=neutral, PublicKeyToken=b77a5c561934e089]],mscorlib",
             "value":["chiqingsan.BetterPerformance","lower_customer_dialogue", …]},
 "modUiWarningAcceptedVersion":{"__type":"int","value":2},
 "locale":{"__type":"string","value":"zh"},
 "welcomeVersion":{"__type":"string","value":"VERSION 100-Rev13"}}
```

> 上面不是编的：这是 `缓存文件夹\save-backup-20261126-0640\SaveFile.es3` 的真实结构（实测 67 个键、`modOrder` 29 项、`modTrust` 29 条 records、`stopped` 为空）。

**交叉证据（同一个结论被多个模组独立实现印证）**

| 结论 | 出处 |
| --- | --- |
| 状态文件 = `%persistentDataPath%\SaveFile.es3` | `ModPresets\TrustForge.cs:53`、`ModPresets\OneClickApply.cs:12,39` 两处硬编码拼路径 |
| 通过 `ES3.*` 读写同名键（等于同一文件） | `ModPresets\ModOrder.cs:9,15`（`ES3.Load("modOrder")`）、`ModPreloader\ModEntry.cs:1217-1231`（`ES3.Load<List<string>>("modOrder")`）、`PawnshopModProfiles\ProfileMenu.cs:2493-2497`（`ES3.KeyExists`/`ES3.Load`） |
| 启用集 = `modOrder` 列表本身 | `ModLoader.cs:403-411`：`_modOrder = ES3.Load<List<string>>("modOrder"); EnabledMods = new HashSet<string>(_modOrder);` |

**字段清单**

| 键 | 类型 | 含义 | 谁写 |
| --- | --- | --- | --- |
| `modOrder` | `List<string>` | **同时表示"启用集"和"顺序"**，未列出的 = 未启用 | 原版 `ModLoader.SetModEnabled/ReorderMods`（`ModLoader.cs:449,490`） |
| `modTrust` | `string`（内嵌 JSON） | `{"records":[ModTrustRecord…],"stopped":[StoppedEntry…]}` | 原版 `ModTrust.Save()`（`ModTrust.cs:102-107`） |
| `modTrustMac` | `string` | 上面那段 JSON 的 HMAC-SHA256，防手改 | 同上 |
| `workshopOwners` | `string` | 工坊项 → 作者 SteamID 缓存（`"<publishedFileId>|<steamId>"`） | 原版 `ModWorkshop` |
| `modUiWarningAcceptedVersion` | `int` | 玩家已接受的模组警告弹窗版本（当前 = 2） | 原版 |

### 1.2 什么时候生效：只能重启，`ModLoader.Awake` 读完就不再看盘

`ModLoader.cs:315-346`（`Awake`）的顺序是全部答案：

```csharp
ModTrust.EnsureLoaded();          // 327  读 modTrust / modTrustMac 进内存
ModTrustList.LoadCache();         // 328  官方信任名单（联网）
LoadModOrder();                   // 333  读 modOrder → EnabledMods（此后不再读盘）
LoadDiscoveredMods();             // 340  逐个摸 manifest、过信任关卡、PatchAll、Init、OnEnable
ApplySavedOrder();                // 341  只按 _modOrder 排 mods 列表
ValidatePrerequisites();          // 342
LoadModAssets();                  // 343
```

- **进程内改 `modOrder` 文件没有用**：`EnabledMods` 是 `Awake` 里一次性快照，之后任何写盘都要等下次 `Awake`（原版自己也是 `RestartRequired = true`，见 `ModLoader.cs:450`）。
- **`modOrder` 的顺序不改变加载时序**：`ApplySavedOrder` 在 `LoadDiscoveredMods` 之后，此时所有 `PatchAll/Init/OnEnable` 已经跑完。真正的加载时序 = ① 本地 `Mods\` 子目录（`Directory.GetDirectories`，NTFS 上即字母序）→ ② 工坊条目 → ③ `<Prerequisites>` 拓扑修正（`ModLoader.cs:1201-1233, 1250-1291`）。`modOrder` 只影响 `ModLoader.Mods` 这个列表的展示顺序。
- 这条正是 Preloader 全套设计的前提（见第 5 节）。

### 1.3 三处"模组清单"别混为一谈

| 清单 | 位置 | 谁维护 |
| --- | --- | --- |
| **启用/顺序清单（唯一真相）** | `SaveFile.es3` → `modOrder` | 游戏 |
| **批准/审批清单** | `SaveFile.es3` → `modTrust` | 游戏（玩家的点击） |
| **"这个存档上次用了哪些模组"** | 原版**根本没有**——存档文件里不存模组表 | 本档案五个模组各建一套（见第 4 节） |

> 第 3 行是本节最值钱的一句：**原版不记录存档↔模组的关系**，所以"读档兼容性检查"必须由模组自己维护基线。五个模组里 4 个都自己存了一份（唯一的例外是纯预载器，它不管存档）。

### 1.4 从模组里"读"是安全的，"写"会被硬拒

- 读：`ES3.Load` / `ES3.KeyExists` / `ModLoader.EnabledMods` / `ModLoader.IsModEnabled(id)` 都不产生任何能力标记。SaveSlot Mod Manager 直接 `ES3.Load<List<string>>("modOrder")`（`ProfileMenu.cs:2495`），Mod Profiles 只用 `ModLoader.IsModEnabled`（`GameModCatalog.cs:57`），两者扫描报告都是"零能力信号"。
- 写：`ModLoader.SetModEnabled` / `ReorderMods` / `ApproveAndEnable` / `ModTrust.Approve` 全部带 `[ModRestricted("loader-target", …)]`（`ModLoader.cs:432,463,749`；`ModTrust.cs:135`），扫描器在 `ModScanner.cs:654,1084-1086` 把它变成 **Hard Flag → `Refused`**；就算绕过扫描，运行时 `RequireNoMod`（`ModLoader.cs:419-430`）也会抛 `UnauthorizedAccessException`。
- 更狠的一条：`ES3.Save("modTrust"/"modOrder"/…, …)` 这种**把加载器键名当字面量传给非 Load 类 ES3 方法**的写法，也在扫描器里被直接 Hard 掉（`ModScanner.cs:69` 的 `TrustKeys` 表 + `ModScanner.cs:701-717`）。
  → 所以"改启用状态"的正路只有两条：**（A）引导玩家在原生 UI 点**（Mod Profiles / SaveSlot / Mod Changes），或**（B）用 `System.IO` 直接重写 `SaveFile.es3`**（Save Mod Check；只会被标 `files` 能力，不会被 Hard）。

### 1.5 运行态一览：`LoadedMod` 里哪些字段能直接读

`LoadedMod`（原版反编译）是本主题的"查询视图"，全部 public、零能力：

| 字段 | 用途 |
| --- | --- |
| `Manifest`（`ID/Name/Author/ModVersion/Assemblies/Capabilities/Prerequisites`） | 清单与声明能力 |
| `IsEnabled` | 本次是否真加载了（`Init/OnEnable` 成功才 true） |
| `Source` / `WorkshopId` / `ShadowedWorkshopId` | 本地还是工坊；`Shadowed*` = 被本地副本顶掉的那份工坊 ID |
| `TrustState` / `TrustNote` / `TrustRecord` | 审批态与原因、原始记录 |
| `ListVerdict` / `LastScan` / `UnlistedDlls` | 官方名单判定、扫描结果、清单外的 DLL |
| `LoadError` | 加载失败原因（非空即没跑起来） |

`ModTrustState` 九态与后果（由 `ModLoader.EvaluateTrust` `ModLoader.cs:500-606` 归纳）：

| 值 | 含义 | 会加载吗 |
| --- | --- | --- |
| `NotChecked` | 还没考 | — |
| `Unknown` | 本机没批准过 | 否 |
| `Match` | 记录与文件完全一致（或 `scannerVersion != 4` 重扫通过） | **是** |
| `Updated` | 内容变了但扫描/能力都通过 | **是**（自动刷新记录） |
| `Changed` | 来源变/工坊项变/能力超出/扫描拒绝 | 否 |
| `DeveloperMode` | 本地模组且开了开发者模式 | 是（即使扫描拒绝） |
| `Blocked` | 官方信任名单封禁；同时 `Revoke` + `DisableSilently` | 否 |
| `Paused` | 官方 Kill Switch 暂停加载 | 否 |
| `Stopped` | 本机因该指纹被"停机"（游戏的安全跳闸） | 否 |

## 2. "批准/审核"机制

### 2.1 存哪、什么形状

`%persistentDataPath%\SaveFile.es3` → 键 `modTrust`（`ModTrust.ES3_KEY`，`ModTrust.cs:31`）+ 键 `modTrustMac`（`ModTrust.cs:37`）。值是 `JsonUtility` 序列化的 `{ records:[…], stopped:[…] }`。每条记录字段（`ModTrustRecord.cs:6-34`）：

| 字段 | 说明 |
| --- | --- |
| `id` | 模组 ID |
| `source` | `Local` / `Workshop`（枚举 `ToString()`） |
| `workshopId` | 工坊 ID 字符串，本地为 `"0"` |
| `manifestHash` | `manifest.xml` 的 SHA256 |
| `files` | `"<相对路径>\|<文件SHA256>"` 数组 |
| `combinedHash` | 全模组指纹（内容变了就变） |
| `folderHash` | 目录级指纹（含未列出的文件） |
| `declared` / `detected` | 声明能力 / 扫描实测能力 |
| `gameVersion` | 批准时的 `Application.version` |
| `approvedAt` / `updatedAt` | ISO-8601 UTC |
| `developerMode` | 仅本地模组可用，开了就"这文件夹怎么变都信" |
| `scannerVersion` | 当前 = 4，**不等于 4 会被当成"需要重新扫描"**（`ModLoader.cs:556`） |

### 2.2 判据与防篡改

`ModTrust.CompareFiles`（`ModTrust.cs:245-268`）→ `ModTrustState`：

- `source` 变了 → `Changed`；`workshopId` 变了 → `Changed`；`combinedHash` 变了 → `Updated`；`folderHash` 变了 → `Updated`；否则 `Match`。
- `Match` 才直接加载；`Updated` 还要过 `ModScanner.Scan` + 能力不许超出 `declared`/`detected`（`ModLoader.cs:556-603`），过了就**自动刷新记录、不打扰玩家**（这就是"更新后不用人工再授权"的实现）；`Changed/Unknown` → 不加载，UI 提示"Review and enable"。
- 篡改检测：`ModTrust.EnsureLoaded`（`ModTrust.cs:59-100`）比对 `modTrustMac`，不一致就 `TamperedOnLoad = true`、`Debug.LogError`、**清空全部 records 再写回**（`stopped` 保留）。HMAC 密钥（`ModTrust.cs:109-115`）：

```csharp
string s = "dse-mod-trust-1|" + SafeDeviceId() + "|" + Application.persistentDataPath + "|" + Application.productName;
// HMACSHA256(key = SHA256(s)) 作用于 modTrust 的 JSON 文本
```

→ 换句话说：**机器绑定**（`SystemInfo.deviceUniqueIdentifier` + 存档目录 + 产品名），换机/换目录即全部审批作废。

### 2.3 两个模组怎么"绕过"，以及一处必须点明的冲突

- **Mod Preloader（可靠路线）**：读现有 `modTrust`，把新记录并进去，用同一个 HMAC 公式**算出正确签名**再 `ES3.Save<string>("modTrust"/"modTrustMac")` 落盘（`ModEntry.cs:629-643` 与 `645-757`，密钥推导在 `773-785`）。它甚至在扫描面前"隐身"：键名不写字面量，而是 `new string(new char[]{'m','o','d','T','r','u','s','t'})`（`ModEntry.cs:759-771`）——因为写字面量会被 `ModScanner.cs:701-717` 判成 `loader-target` 硬拒。
- **Save Mod Check（不可靠路线）**：它改的是**另一个不存在的节点**。`TrustForge.cs:18` 的正则只找 `"modTrustStore"`：

```csharp
private static readonly Regex StoreNode = new Regex("(\"modTrustStore\"\\s*:\\s*\\{\\s*\"__type\"\\s*:\\s*\"string\"\\s*,\\s*\"value\"\\s*:\\s*)(\"(?:[^\"\\\\]|\\\\.)*\")", RegexOptions.CultureInvariant);
```

它假设的形状是 `modTrustStore` → `{ "machines":[ {"machine":…,"json":…,"mac":…,"savedAt":…} ] }`，并给每个节点单独算 MAC（`TrustForge.cs:84-118, 197-201`）。**但我们这台机器上的真存档（`VERSION 100-Rev13`）里只有 `modTrust`/`modTrustMac`，没有 `modTrustStore`，也没有 `machines` 数组**；原版反编译的 `ModTrust.cs` 同样只有扁平 `Store {records, stopped}`。
  结论（有实测反证，不是推测）：在**我们这个版本**上，`TrustForge.Approve` 会在 `TrustForge.cs:60-65` 走 `"存档里没有 modTrustStore 节点"` 分支**安全退出**、一条都不写。它的"写入后回读校验"（`TrustForge.cs:204-220`）校验的也是自己刚写的那个节点，**无法自证游戏真的认了**。这类"自校验通过但游戏不认"的写法是最危险的失败模式，抄它的思路可以，别抄它的节点名。
  （它为什么这么写：推测是针对另一个游戏版本/另一位作者的实现，或纯粹把 `modPreloader` 的键名记错了。）

## 3. 五个模组做法差异与安全性排序

| 维度 | Mod Profiles | SaveSlot Mod Manager | Save Mod Check | Mod Changes | Preloader |
| --- | --- | --- | --- | --- | --- |
| 读启用态 | `ModLoader.IsModEnabled` | `IsModEnabled` + `ES3 modOrder` | `ModLoader.EnabledMods`/`Mods` | `LoadedMod.IsEnabled` | `IsModEnabled` + `ES3 modOrder` |
| 写启用态 | **不写** | **不写** | **重写 `SaveFile.es3` 的 `modOrder` 节点** | **不写** | **只改内存 `ModLoader.EnabledMods`**（当次启动有效） |
| 写审批态 | 不写 | 不写 | 尝试伪造（本版本无效） | 不写 | 伪造（格式正确，真生效） |
| 生效方式 | 玩家手点后游戏自己写盘 → 重启 | 同左 | 写完立刻 `Application.Quit()`（`ApplyWindow.cs:291`） | 提示玩家回主菜单（`QuitToMainMenu`，`ModListLedgerMod.cs:1137-1154`） | 本次启动立刻生效；下次要靠 `selection.txt` |
| 失败时的破坏面 | 无 | 无（只有自己的 `profiles.json`） | 可能写坏全局 `SaveFile.es3` → 全部设置/审批丢失 | 无 | 只影响本次启动的启用集 |
| 备份/回滚 | 无（不需要） | `profiles.prev.json` + `profiles.corrupt-*.json`（`ProfileStorage.cs:108-125`） | `ModData\mod_presets\backups\SaveFile-*.es3`（`OneClickApply.cs:285-304`）、`SaveFile-trust-*.es3`（`TrustForge.cs:374-393`）；写后回读比对，不符就 `File.Copy` 回滚 | 无 | 无（不写全局状态） |

**安全性排序（从最安全到最危险）**：Mod Changes（纯提示）≈ Mod Profiles（纯引导）≈ SaveSlot Mod Manager（引导 + 自己的存档表）> Preloader（改内存 + 可逆）> Save Mod Check（改全局存档设置文件）。

**Save Mod Check 的备份 / 回滚细节**（这是它唯一值得抄的部分）：

1. 备份目录固定为 `%persistentDataPath%\ModData\mod_presets\backups\`，文件名带秒级时间戳（`yyyyMMdd-HHmmss`），`trust` 与 `modOrder` 两路分开命名，不会互相覆盖。
2. **备份失败不阻断写入**（`OneClickApply.cs:295-303` 只 `Warning` 后 `return null`），后续回滚分支判 `text4 != null` 才回滚——也就是说备份失败就等于没有安全网。抄的时候这里应该改成"备份失败即中止"。
3. 回滚 = `File.Copy(backup, path, overwrite: true)`，只回滚"它自己改的那个文件"，不区分其它模组在同一时段写的改动。

## 4. 读档前的比对：存档里到底存了什么

原版不存。三个模组各自建基线，做法差异极具参考价值：

**(a) Mod Changes —— 双写：存档内 + 存档外镜像，互为兜底**

- 存档内：`ModHelper.SetModData("mod_list_ledger", "ledger", …)`（`ModListLedgerMod.cs:96,757`）→ 写进 `PlayerStore.modData`（`PlayerStore.cs:48` 的 `Dictionary<string,string>`，随存档一起序列化），键前缀 `mod_list_ledger:`。
- 存档外：`ModData\mod_list_ledger\slot_<n>.txt`，带 `# file=` / `# time=` / `# slot=` 头部，正文是 `id\tname\tversion` 每行一条（`ModListLedgerMod.cs:783-806`）。
- **抗重命名**：读外部记录时比对 `# file=` 与当前 `NewGameData.saveFile`，不一致就当作"没有基线，重新记录"（`ModListLedgerMod.cs:808-831`）——比单纯按 slotId 认更稳。
- 时机两处：读档后 `ModHook.OnGameLoadedNormal`（存档内可用时优先）+ 读档前 `Patch_LoadGameClick` 打 `LoadGameUI.OnLoadClicked`（只能看外部文件）。
- 版本比较用 `(id, name, version)` 三元组，比较时 `OrdinalIgnoreCase`（`ModListLedgerMod.cs:139-159`）。

**(b) Save Mod Check —— 读档成功后立刻"记账"，下次读档前对账**

- `ModHook.OnGameLoadedInit` → `SaveRecords.RecordCurrentLoad()`（`ModEntry.cs:71-75`）→ 拿到 `NewGameData.Instance.saveSlot / saveFile` 后写 `ModData\mod_presets\save_slot<n>.json`（`SaveRecords.cs:101-137`）。用 `ModHelper.ModDataFileExists/ReadModDataFileText/WriteModDataFileText`，不碰磁盘路径。
- 比对在 `SaveGuard.Intercept`（`SaveGuard.cs:9-43`）：`SaveDiffer.Compute` 拆成 `ToEnable/ToDisable/Missing/Extra/Versions/OrderChanged` 六类，任一非空才拦；三个开关（启用集 / 版本 / 顺序）由 `ModConfig` 控制，默认顺序检查**关**（`SaveSettings.cs:41-51`）。
- 这是全档案里唯一"**读档拦截**"的完整实现：拦 → 弹窗 → 玩家确认 → 用 `SaveGuard.Bypass = true` + `ModReflect.CallStatic(typeof(LoadGameUI), "LoadSlot", …)` **重入**同一个方法（第 6 节范式 4）。

**(c) SaveSlot Mod Manager —— 每个槽位一份"期望模组表"，槽号即键**

- `ModData\pawnshop_mod_profiles\profiles.json`：`Slots[{SlotId, Name, ModIds[], Groups[]}]` + `GlobalProfile`（组设置）+ `KnownInstalledMods`（装过什么）+ `Presets` + `FavoriteModIds`（`ProfileStorage.cs:127-289`）。
- 存档列表来源不是自己扫目录，而是 `SaveUIManager.GetOrderedSlotIds()`（原版 API，`ProfileMenu.cs:882,714`），因此不会漏掉别人新建的槽。
- 槽位 ↔ 模组表的关系靠 `SaveUIManager.UpdateCacheEntry(slotId, SavePreviewData)` 的 `Postfix` 维持（`SaveSlotProfilePatch.cs:5-12`），新档第一次缓存时用当前启用序当默认值（`ProfileMenu.cs:541-568`）。
- 一致性判定用 `SwitchPlan.Compare`（`SwitchPlan.cs:29-93`）：输出 `Enable/Disable/Problems/DependencyWarnings/ChangeOrder`，把"要启用/要停用/依赖缺失/依赖顺序冲突/加载报错"分层——这是本档案里最完整的"兼容性检查"数据结构，直接可以借用。

**(d) Mod Profiles —— 存档维度只存"槽位 → Profile 引用"**

Profile 本体存在 `ModData\kkkvb.mod_profiles\` 的若干 JSON 里（`GameProfileStorage.cs:11-41` 全部走 `ModHelper.ModDataFile*`），存档维度只记"这个槽用哪套"。它对"某模组是否已批准"明确标为 `CapabilityStatus.Prohibited`（`GameModCatalog.cs:92-94`），即**主动放弃读审批态**，只用 `IsModEnabled` + `ModLoader.Mods` + `manifest` 元数据（`GameModCatalog.cs:47-79`）。

**(e) 存档内的键长什么样（做工具时要会用）**

`ModHelper.SetModData` 的键是 `modId + ":" + key`（`ModHelper.cs:938-940`），值一律是 `string`，存进 `PlayerStore.modData`（一个 `Dictionary<string,string>`，随存档 ES3 序列化）。因此：

- 查：`ModHelper.GetModDataKeys(modId)` 返回去掉前缀的键名；`ClearModData(modId)` 按前缀清空。
- 大小：整段清单都塞进存档会让存档变大、且随存档一起坏；Mod Changes 把最多 120 行 × 3 字段的清单塞进一个字符串，等于**每次存档都写一遍整表**——量不大（几十 KB 上限），但这是它的隐性成本。
- 与外部文件的取舍：**存档内 = 天然按档隔离、跟着复制/改名走；存档外 = 存档崩了基线还在**。两边都写（Mod Changes 做法）最稳。
- 存档外路径固定为 `%persistentDataPath%\ModData\<modId>\…`（`ModHelper.GetModDataFolder`，`ModHelper.cs:1442-1447`），文件名要做 `SafeFolderName` 同级别的清洗（该函数会把 modId 里的非法字符换掉），别自己拼路径。

## 5. 加载前干预：Preloader 到底怎么插手

**结论：它没有"在 `ModLoader.Awake` 之前"运行——它做不到，也不需要。**

`ModLoader.LoadModDll`（`ModLoader.cs:1617-1621`）里，每个模组的顺序是 `harmony.PatchAll(assembly)` → `mod.Init(manifest)` → `mod.OnEnable()`，这些都在 `Awake` 内部、`LoadDiscoveredMods` 循环里。所以"抢在加载器读启用表之前"是不可能的；它抢的是**"加载器还没遍历到其它模组之前"**：

1. **抢第一位**：让玩家把自己复制成 `Mods\000_mod_preloader`（本地副本），依据是 `ModLoader.cs:1426-1450` 的重复 ID 规则"**本地副本优先于工坊副本**"（`ShadowedWorkshopId` 记录被顶掉的那份）；本地目录又是 `Directory.GetDirectories` 字母序，`000_` 天然第一。提示文案与实现见 `ModEntry.cs:948-951`（`TipText`）与 `953-1004`（`OnInstallChanged`，手工 `CopyFolder`，逐文件写日志）。
2. **在第一位的 `Init` 里改内存**：`Apply()`（`ModEntry.cs:307-323`）直接 `Clear()` 再填充 `ModLoader.EnabledMods`——而 `EnabledMods` 返回的是那个 `HashSet` 实例（`ModLoader.cs:89`），后续每个模组在 `LoadModFromFolder` 里现算 `IsModEnabled(manifest.ID)`（`ModLoader.cs:1457`），于是**"这一轮别加载"就真的别加载了**，不用重启。
3. **自我降级**：`Init` 一进来先数"已经有多少个模组在我前面加载"，`>0` 就打印"使用原版引导"并直接 `return`（`ModEntry.cs:123-144`）；`Mods` 里只有它自己（`Count <= 1`）也不管（`145-150`）。这条自我约束很值得学：**能力不足时安静退化成空操作，而不是半残地乱改**。
4. **与原生菜单双向同步**：`order.sync` 存"上次我看到的 `modOrder` 指纹"（`Fingerprint = SHA256(id + '\n' …)`，`ModEntry.cs:818-841`），启动时若 `modOrder` 变了就**直接采纳玩家的改动**并改写 `selection.txt`（`184-192`）。选择本身存 `selection.txt`（`id\t0|1` 每行，`907-924`）。
5. **可逃逸**：按住 Shift/Alt 或命令行带 `-nopreloader` 直接跳过（`ModEntry.cs:1321-1348`）；`OnDisable` 为空，激活时只影响当次。

**它需要的能力与风险**

- 权限：`files`（扫描报告标 3 处 File 调用）。它用 `Path.Combine(Application.dataPath, "..", "Mods")` 与 `…/workshop/content/4348910/<id>` 自己扫盘（`ModScan.cs:24-55`、`ModEntry.cs:1165-1178`），读 `manifest.xml` 的 `ID/Name/ModVersion/Author/Assemblies/Capabilities/Prerequisites`（`ModScan.cs:82-137`），并顺手做风险画像（目录里有 `.exe/.bat/.ps1/…`、体积远超中位数，`ModScan.cs:146-171, 227-254`）。
- 风险 1：**只改内存不改盘**。它不写 `modOrder`（写不了，见 1.4），所以如果玩家在游戏里点任何一次启用/停用，原版会用**它自己的 `_modOrder`** 覆盖 `SaveFile.es3`（`ModLoader.cs:449`），Preloader 的当次选择与玩家的点击就会打架。它的 `order.sync` 只是把上一次状态记下来，不能阻止覆盖。
- 风险 2：**伪造审批**。`TryApplyNow`（`ModEntry.cs:552-643`）与 `ForgePendingApprovals`（`645-757`）会为新模组写 `modTrust`/`modTrustMac`。它自己做了把关：跳过 `TrustState` 为 6/7/8（封禁/暂停/停止）、要求 `ModScanner.Scan` 不 Refused、要求不出现未声明能力（`719-724`）。这仍然是在替玩家点"我信任"——**违反原版"审批是玩家的"这一设计**（`ModTrust.Approve` 带 `[ModRestricted("loader-target")]` 正是为此）。我们若做同类工具，只应写进"开发者自用"分支并显式提示。
- 风险 3：`PatchAll` 顺序不可控。它不 Patch 任何东西，但**别的模组 Patch 已生效**（在它前面的那些）无法回滚；它只能决定"要不要加载"。

### 范式 1 · 只读观察 + 引导玩家手点（最安全，零写入）

原理：算出"目标 vs 现状"的差异表，然后在**原版面板**里按 ID 找到那一行，替玩家点一下（或只高亮），让游戏自己写盘。`ProfileMenu.cs:2903-2960`：

```csharp

    SetDependencyNotice(plan);
    List<string> list = (from id in plan.Disable.Concat(plan.Enable)
        where !skippedChanges.Contains(id)
        select id).ToList();
    if (list.Count == 0) { /* 全点完了 → 看顺序 → 出结果 */ EndGuidance(); ShowGuideResult(plan, orderAlreadyMatched: true); return; }
    string next = list[0];
    if (SwitchPlan.Ids.Equals(next, guidedMod) && (Object)(object)guidedRow != (Object)null) return;

        .FirstOrDefault((ModElement element) => SwitchPlan.Ids.Equals(element.ModID, next)));
    if ((Object)(object)val == (Object)null) {
        RestoreGuideAction();
        missingAttempts.TryGetValue(next, out var value); value++;
        missingAttempts[next] = value;
        if (value < 5) { GuideStatus(Text(UiText.StockNotFound, next), AddedColor); return; }
```

## 对我们的可用点

1. **自动化测试里批量切模组（最实用）**：不要写模组去改状态——**在游戏进程外**改 `%persistentDataPath%\SaveFile.es3` 最省事：只改 `modOrder` 的 `value` 数组（保留 `"__type"` 字符串原样），其它键一个字节都别动；改完备份原文件。要做"顺带批准"，必须重算 `modTrustMac`（HMAC 钥 = `"dse-mod-trust-1|" + SystemInfo.deviceUniqueIdentifier + "|" + persistentDataPath + "|" + productName`，再 `SHA256` 当 key），否则 `ModTrust.EnsureLoaded` 会判定篡改、**清空全部审批**——这是最容易踩的坑。
2. **桥接器/开发工具里读运行态**：`ModLoader.Mods`（副本，可安全遍历）、`ModLoader.IsModEnabled(id)`、`LoadedMod.TrustState / TrustRecord / LastScan / ListScan`、`ModLoader.RestartRequired`。全部零成本、不触发能力扫描。**要判"要不要重启"看 `RestartRequired`，不要自己猜。**
3. **做"读档兼容性检查"直接借 SaveSlot 的 `SwitchPlan` 数据结构**（`Enable/Disable/Problems/DependencyWarnings/ChangeOrder`）+ Mod Changes 的"敷衍双写 + `# file=` 校验"，两套合起来就是完整的基线方案；别自己再从 `SaveUIManager.GetOrderedSlotIds()` 之外的表源去推槽位。
4. **禁忌清单（写进我们的模组规范更好）**：
   - 不要在模组里 `ES3.Save("modOrder"/"modTrust"/"modTrustMac"/"workshopOwners"/"modUiWarningAcceptedVersion", …)` → `loader-target` 硬拒（`ModScanner.cs:69,701-717`）；也别学 Preloader 用 `new string(char[])` 绕键名，那是把"可被信任的模组"变成"看起来像木马的模组"。
   - 不要调 `ModLoader.SetModEnabled/ReorderMods/ApproveAndEnable`、`ModTrust.Approve/Revoke`（`[ModRestricted("loader-target")]`，扫描即 Refused，运行即抛 `UnauthorizedAccessException`）。
   - 不要整段替换 `LoadGameUI.LoadSlot` / `OnLoadClicked`：用 `Prefix` 返回 `false` 拦，再用 `ModReflect.CallStatic` + 静态 `Bypass` 标志重入（范式 4），异常一律 `return true` 放行。
   - `modOrder` 的顺序**不改变加载时序**，只改展示顺序；靠它解决"我必须先加载"是无效的，正解是本地 `Mods\000_xxx` 目录名（并接受"本地副本压过工坊副本"这一副作用）。
5. **可复用的"存档内基线"写法**：`ModHelper.SetModData(modId, key, value)` 落进 `PlayerStore.modData`，随存档走、天然按档隔离、零能力；缺点是"存档坏了基线也没了"，所以外部 `ModData\<modId>\` 镜像要保留（范式 3）。
6. **风险提示（供发布评审用）**：本档案里 `Save Mod Check` 与 `Preloader` 都会伪造审批记录，且都可能与游戏自己的写入打架；我们若真的需要"一键对齐"，只做**引导 + 只读比对**（范式 1/4），把"写"留给玩家的一次点击。
