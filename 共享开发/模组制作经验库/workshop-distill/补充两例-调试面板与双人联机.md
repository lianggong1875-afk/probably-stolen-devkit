# 补充两例：调试面板（Debug Console Plus）与双人联机（NextDoor）

> 蒸馏自 `缓存文件夹\decomp_ws\3829432366`（49 个 .cs）与 `3845780921`（68 个 .cs）。
> 前者教"游戏内调试面板怎么做"，后者给了**与 Probably Multiplayer 完全不同的一条联机技术路线**。

---

## 一、调试控制台Plus（工坊 3829432366）

### 1. 它 Patch 了什么（7 处）

| Patch 目标 | 用途 |
| --- | --- |
| `InputActionHandler.UpdateUpdate` | **打开自己面板时屏蔽游戏输入**（第一层） |
| `InputActionManager.UpdateKeys` / `Update` | 同上（另两层，覆盖键盘与整体输入） |
| `PlayerStore.LoadGame` | 读档后重新挂载面板 / 复位状态 |
| `PlayerStore.StartNewGame` | 开新游戏同上 |
| `GameMaster.QuitToMenu` | 退到主菜单时清理 |
| `PlayerStore.GetRentDayCounter` | **改写租金倒计时**（作者注明"倒计时真的驱动房东来访逻辑"） |

外加 `Core.cs` 里一处手动 `Harmony.Patch()`（PatchAll 之外的单点补丁）。

### 2. 三个可学的点

**① 输入隔离靠 Patch 输入管理器，而不是靠"吃掉按键"**

我们是靠模态窗口 + 输入闸门（`ModalInputGate`），它是直接让原版输入管理器在面板打开期间不处理输入。两种都行，但**Patch 全局输入管理器是"多模组高风险区"**——`InputActionHandler` / `InputActionManager` 被好几个模组盯过（NextDoor 的 `MirrorInputGate` 也 Patch 这里 5 个方法）。我们自己的做法（拦截自己的窗口、不碰全局输入）更适合要跟别人共存的场合。

**② 场景切换钩子必须成对**

`LoadGame` / `StartNewGame` / `QuitToMenu` 三处都要挂——不然玩家在控制台开着时退到主菜单，静态引用就悬空了。这跟我们 `OnDisable` + 读档 + 热重载三处成对重置是同一个道理。

**③ 改原版数值要挑"被读取的那一刻"**

它没有去改 `rentDayCounter` 字段，而是 Patch `GetRentDayCounter()` 的返回——**改读取而不是改存储**，这样不污染存档、关掉模组立刻恢复。这条对我们很有用：凡是"显示/判定用"的数值，优先 Patch getter。

### 3. 权限面

透视报告判"无明显高权 API（倾向零能力）"，只用了 `ModReflect.Get/Set`（读私有字段）与 4 个 ModHelper（`GetConfig` / `ReadModFileBytes` / `SetItemOwnerShip` / `SpawnItem`）。**一个功能这么全的调试面板可以做到零能力**，值得记住。

## 二、双人联机 / NextDoor（工坊 3845780921）

### 1. 与 Probably Multiplayer 的技术路线对比（这是本文档最值钱的部分）

| 维度 | Probably Multiplayer（3828909239） | NextDoor（3845780921） |
| --- | --- | --- |
| 传输 | **自写 WebSocket**（TcpClient+SslStream 手写 RFC6455 + permessage-deflate）+ 官方 HTTPS 发现 + 第三方中继 `*.lemoc.icu` | **局域网 TCP 直连**（`TcpListener.AcceptTcpClient`）或 **Steam 好友"加入游戏"**（`SteamLink.cs`，1140 行） |
| 权威 | 服务器权威（`VisitSession` 整份覆盖 + Revision） | 会话内同步（`Session.cs`），双轨存档 `CampaignArchive`（host / guest 各一条轨） |
| 玩家店怎么呈现 | 接管原版顾客流程（把真人变成"顾客"塞进流程，34 个 Patch） | **镜像层**：`MirrorView` / `MirrorNativeView` / `MirrorCollect`（合计 ~4500 行）把对方的店画成本地视图 |
| 输入 | 自制窗口抢输入（`RetiringInputDeactivate`） | `MirrorInputGate` **Patch 5 个输入方法**，在镜像视图里屏蔽本地输入 |
| 过夜 | 各自过夜 | `SleepGate` Patch `EndOfDayUIManager.OnEndDayButtonClick`：**两人都点了才过夜** |
| 经济交互 | 会话议价 + 两阶段提交物品 | `PhoneBank` Patch 电话（`HandleCall`/`PressNumber`/`StopCall`/`OnPhoneDialogEnd`）：拨 `bank_number`（默认 114514）转账，手续费 1% |
| 存档 | 只写私有 ModData | **双轨存档**（`v4=1` 开；`0` 退回老的单轨覆盖流程）+ `CoopSlotHider` Patch `SaveUIManager.GetOrderedSlotIds` 隐藏对方存档槽 |
| 能力 | network（3 文件）+ reflection | **files（9 文件）+ network（1 文件）** |

**结论**：工坊里"联机"至少有两种可行解，门槛差一个数量级。如果哪天要做"两个人各开一家店"，NextDoor 这条路（局域网 TCP + 镜像视图 + 双轨存档）比自建中继服务器现实得多。

### 2. 它的配置文件（现成的设计范本）

`NextDoor.ini` 写在模组目录，字段全是人话 + 注释：

```ini
mode=host            # host=开房 / client=连朋友 / solo=单机不联机
transport=tcp        # tcp=局域网填 IP 直连 / steam=Steam 好友右键「加入游戏」
host=                # tcp 时填主机局域网 IP；steam 时是好友标识
port=                # 两端必须一致
name=                # 显示给朋友看的名字
mirror_offset_x=0    # 镜像层偏移（格）。正常联机留 0；开发自检时可挪开看
mirror_offset_y=0
bank_number=114514   # 电话银行号码
v4=1                 # 双轨存档开关；0=退回老的单轨覆盖流程
```

要点：**每个字段都有"填什么/为什么"的注释**；还把"开发自检用的偏移量"保留在配置里（作者自己调试镜像层用的）；**旧流程开关 `v4`** 让玩家可以退回上一代存档方案——这是给高风险改动的退路。

### 3. 它的 10 个 ModHook 分工（另一种联机的时间轴）

```
OnGameLoadedInit / OnGameLoadedLate      读档后重建镜像与连接
OnNewGameStarted                         开新档
OnShutterOpenedLate / OnShutterClosedLate 营业开始/结束
OnGoingSleepLate / OnWakingUpLate         入睡/起床
OnHandlingNightlyServicesLate             过夜服务后同步
OnLeavingStoreLate / OnReturningStoreLate 出门/回店
```

**几乎全是 `Late`**——说明它做的事依赖原版先完成。我们要做"事后同步/事后修正"类功能，优先挂 `*Late`。

### 4. 风险

- `MirrorInputGate` 一次 Patch 5 个输入方法（`UpdatePress`/`UpdateRelease`/`UpdateMouseMove`/`UpdateMouseScroll`/`UpdateUpdate`）——**与任何"改输入"的模组天然冲突**（调试控制台Plus 也碰了 `UpdateUpdate`）。
- 需要 `files`（9 个文件读写）+ `network`，正式版能力面不小。
- 双轨存档属于"自己管存档"的高风险设计，作者自己都留了 `v4=0` 退路。

## 三、对我们的可用点

1. **调试/开发面板**：照它"Patch getter 而不是改字段"和"三处场景钩子成对"的做法；输入隔离建议仍用我们自己的模态闸门（不碰全局输入管理器），避免与 NextDoor / 调试控制台这类模组抢。
2. **如果将来做"双人各开一店"**：抄 NextDoor 的 局域网 TCP + 镜像视图 + 双轨存档 + 配置文件自带注释，比自建中继现实。
3. **过夜/营业的时间轴**：两种联机模组都只挂 ModHook（`OnGoingSleepLate`/`OnHandlingNightlyServicesLate`/`OnShutterOpenedLate`），没有一个去 Patch `EndNight` 本体——**再次印证"过夜类功能挂钩子不 Patch 主流程"**。
4. 配置项设计：每个字段带注释 + 保留"旧流程开关" + 保留"开发自检参数"，这套习惯值得写进我们的规范。
