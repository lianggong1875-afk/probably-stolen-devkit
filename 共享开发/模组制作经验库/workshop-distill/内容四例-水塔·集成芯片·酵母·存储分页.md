### 1.5 踩坑与红线

1. **`reflection-external` 不是可选项**：`TowerInstance` 全 `object` 字段、`ResolveType("WaterHelper")` 字符串找类型，manifest 必须声明该能力。想抄它的架构但不想要能力，就得把反射换成直接引用（本项目可以，因为我们编译期就有 `Assembly-CSharp`）。
2. **塔的"世代"必须去重**：同一只水箱可能对应多个塔实例（旧档重建/复制），`RunCore` 用 `GenKeyOf(tank)`（uid）与 `TankKey(tank)`（引用哈希）两层去重，重复的 `NightSkip` 掉（`NightSettlement.cs:141-184`）。不去重就是**双倍产水**。
3. **窗口里增删一个元素 = 旧档槽位索引错位**。`SaveLayoutMigration` 469 行只干一件事：把 `MapFrom = {4,5,6,7,8,9,10}` 改成 `MapTo = {5,9,10,11,6,7,8}`（`SaveLayoutMigration.cs:9-10`），并且带"干跑/冲突/歧义"三态日志。**任何给原版机器窗口加槽的改造都会踩这条**。
4. **防套娃要拦三个方向**（塔进塔、背包进工作区、`STORAGE` 船舱进工作区），且要同时挂 `MayHaveValidInventorySlot`（预估）与 `TryInventorySlot`（真落位），只挂一个会出现"预览绿、落位红"。
5. **读档路径会再次执行工厂**（`DirectoryMaster.Item` 重跑 `Build`），工厂里任何"发物品/建槽/锁库存"的动作都要能被重入；它用 `PlayerStore.EncodeSaveItem` 的重入计数 + `SaveManager.IsDecoding` 判据来跳。
6. **夜结要记账**：`SettleOne` 里"盘点台数 ≠ 工作台数"直接 `Log.Error("账本不平（模组缺陷）")`（`NightSettlement.cs:277-279`）。这个自查写进我们任何批量处理的循环里，能省掉一半线上排查。
7. **不要自己造液体 part**：全程只用 `AddXxx(tank, µl)` / `HandleFilter` / `SetChemContentUL`，part 键一律 `Liquid.GetCurrentPartFromId(id)` 取（`NightSettlement.cs:1243-1254`）。

### 1.6 对我们的可用点

- **大容量存储 = 一只标准容器物品 + `UncheckedAccept` + `LockInv`**：当铺的冷藏柜、证物水箱、液体鉴定槽都能这么干，不用新存档键。
- **"中央设备 + 工作区"范式**：`GameGridInventory(w,h).SetMachineryStyle()` + `ContainerHelper.AllowOnlyTaggedItemsOr` 白名单，就是原版认可的"把机器装进机器"。
- **夜结自己算一遍** 而不是复用原版 cycle，是"集中式工厂"（中央锅炉/中央发电机/中央厨房）唯一可行的结构。
- **数值一律读原版**（`GetOutputVolume/GetOutputQuality/ApplySharedAir`）：白拿模块加成，也不会和 `TOTAL_PERCENTAGE_*` 打架。
- **`MachineryButton.OnSelect` Postfix**：机器里加按钮的最省做法，不碰 UI 体系（取水就是 `<50` 行）。

### 2.2 芯片是什么：**不是新模块 tag，是"抢原版芯片槽"**

| 问题 | 答案（源码） |
|---|---|
| 新物品？ | 是。两个：`Pen_mod_integratedchip.chip`（解序器）、`Pen_mod_integratedchip.printer_chip`（打印机），`Ids.cs:7,13` |

**吸收（Add）** 走的是纯委托，零 Patch：

```csharp

((GameItemFunc)val).onThisTargetItemFunc  = (chip, target) => Absorb(chip, target);
((GameItemFunc)val).mayItemTargetThisFunc  = (src, tgt) => CanAbsorb(tgt, src);
```

### 2.5 踩坑与红线（照抄前必读）

1. **千万别往 `TOTAL_PERCENTAGE_*` 加数**。本包证明了一条更稳的路：**"能做什么"用物品标签平面表达，"强多少"交给原版模块**。芯片能改的只有 目标物/消耗/产出数/材料需求 —— 这些是*配方*，不是*加成*。
2. **两个通道不能混**：`TagDiff` 明确忽略协议前缀（`TagDiff.cs:43-50`）。如果把 `PROGRESS_`/`REQUIRED_` 也塞进通用快照，切档时会残留上一档的材料需求，出现"配方都对但印不出来"。
3. **打印中不许切档**：打印机开工时 `GeneralHelper.LockItem(chip)`、完事 `UnlockItem`（`MachinePrinter.cs:149,247`）。`ChipLock` 只判 `IsItemLocked` 就挡住了切换/吸收/配置（`ChipLock.cs:8-29`）—— 这是"用原版锁当互斥量"的漂亮做法。
4. **吸收前必须过 `Evaluate` 黑名单**：机器 / `CONTAINER_TAG` / `DESEQUENCER_STATE_TAG` / 未拥有 / `!canUseOutsideCombat` 一律拒绝（`ChipItem.cs:1121-1194`）。省这一步就能把一台机器吸进芯片里。
5. **档位不挂在物品树上，而是编码进 tag**。`ChipItem.Create()` 末尾直接 `Sync(val)`，读档时工厂重跑一次就把当前档重放出来；再靠 `OnGameLoadedLate → RepairAll` 做旧档迁移（`Legacy` profile → 新键、同源去重、清理已不存在的物品）。**如果要挂在子物品上，就得赌子物品树的恢复顺序。**
6. **`ChipProbe` 的反射式"读原版芯片"要有缓存 + 失效点**：`OnGameLoadedNormal` / `OnNewGameStarted` 都 `Invalidate()`（`PenIntegChipMod.cs:69,116-119`）。否则读档后仍按上一档的物品表算成本。

### 2.6 对我们的可用点

- **"把一条协议序列化进物品 tag"** —— 我们的鉴定台/单据机/证物封装机想"一张卡带多套配方"，直接抄这套（`PEN_*` 前缀 + `TagDiff` 编解码 + 当前档指针）。
- **抢原版槽而不是加新槽**：不动模组舱、不动准入，只让物品"长得像原版芯片"。冲突面接近 0。
- **`ChipKind` 的抽象值得抄**：18 个抽象成员把"两种芯片"统一成一个 `ChipKind.For(item)`（`ChipKind.cs:69-85`），窗口和补丁都只写一遍。
- **`GeneralHelper.IsItemLocked` 当互斥量**，比自制"使用中"标志可靠（原版自己就会锁）。
- **零能力也能做加法**：本包 `<Capabilities />` 空、6 个 Patch、无反射 —— 真正的"重放引擎"只有 `TagDiff.cs` 280 行 + 两个 `Sync`（各约 60 行）。

## ④ 智能存储仓分页 / Smart Storage Tabs（315 行 · 7.2 万订阅）

- **id**：`3834557397` ｜ 包内 ID `smart_storage_tabs`，v1.2，署名 Providence ｜ `<Capabilities />` 自闭合
- **反编译目录**：`缓存文件夹\decomp_ws\3834557397\SmartStorageTabs\`（3 文件 / 315 行：`SmartTabPatch.cs` 276 + `ModEntry.cs` 27 + `AssemblyInfo` 12）
- **为什么值得读**：**名字骗人**。它没有"分页"、没有新 UI、没有筛选列表 —— 它只改"物品该落进哪一页"，315 行、1 个 Postfix、7.2 万订阅

### 4.1 规模与结构

`SmartTabPatch.cs` 276（唯一 Postfix + 排序 + 缓存 + 自限日志）/ `ModEntry.cs` 27（`IMod` + 自带 `ModLog`）/ `AssemblyInfo.cs` 12 = **315 行、1 个特性式 `[HarmonyPatch]`、零能力、零新 UI**。

### 4.2 原版大存储仓的界面怎么组织

- 机器窗口里每个面板是 `MachineryPanel`，带 `role`（`GetPanel("storage")`，`MachineryPanelRow.cs:163-166`）。
- 存储面板的 `content` 可以是 `MachineryTabs`：`count`（页数）、`selected`（当前页）、`GetTabInventory(i)`（该页的 `GameInventory`）—— `MachineryTabs.cs:72-74,244`。
- 投放判定全在 `MachineryPanelRow.TryFindOneValidInventorySlot(item)`（`MachineryPanelRow.cs:334-382`），两条分支：
  - `searchUsingPriority == false`：先试**当前选中页**，再**倒序**遍历其余页 —— 也就是"最后那一页优先"；
  - `searchUsingPriority == true`（默认）：遍历**全部** storage 比 `priority`，平手时优先"当前选中页"，否则保留**后遍历到的**那个。

**问题**：多页大仓里，随便一丢就落在"最后一页/优先级最高的那页"，东西越堆越乱，玩家只能手动分页 —— 这才是它解决的痛点。

### 4.3 它怎么做的：只换"投放目标"，不建 UI

`ComputeRanking`（`SmartTabPatch.cs:169-233`）给每页算三个数：`Exact`（同 `identifier` 的件数）、`Overlap`（与页内物品的最大公共品类数）、`Matching`（有品类交集的物品数），排序键依次是 **有精确同类 > Exact 多 > Overlap 大 > Matching 多 > 页序小**。品类相似度只认 `item.itemTypes`。

### 4.4 关键代码摘录

### 4.7 踩坑与红线

1. **别假设 `panel.content` 是 `MachineryTabs`**：只有大仓类机器才有；`as` 判空后直接 return，才不会把别的机器弄坏。

- **"改落点"比"改界面"便宜两个数量级**：当铺的证物柜/仓库想做"自动归类"，抄这一个 Postfix 就够，不必造分页 UI。

- **拉黑"非品类 tag"** 这条经验：`itemTypes` 里混了稀有度/来源/合规类标签，做相似度前必须剔除（我们自己的 `EnableTag` 品类也一样）。

## 结语：五条对我们最硬的可用点

1. **先问"能不能只改落点/只改一条规则"**：③ 236 行 7.6 万、④ 315 行 7.2 万，都只碰 1–2 个方法；② 5,507 行 3.7 万；① 8,023 行 4.8 万。**订阅数不跟行数走，跟"痛不痛"走。**
2. **大容量存储 = 一只标准容器物品**（`WaterHelper.InitLiquidContainerItem` + `UncheckedAccept` + `LockInv`），不写新存档键、不自造液体 part。
3. **"能做什么"用物品标签平面表达，"强多少"交给原版模块**：② 全程 0 处 `TOTAL_PERCENTAGE_*`，用 `TagDiff` 把协议序列化进 tag，切换时整体重放 —— 这是绕开模块重算冲突的标准答案。
4. **拿原版锁当互斥量**（`GeneralHelper.IsItemLocked`）：打印中/使用中的物品原版自己会锁，我们只需"锁了就拒绝"，不要自造状态机。
5. **集中式设备（水塔/中央锅炉）的骨架**：`GameGridInventory(w,h).SetMachineryStyle()` 工作区 + 白名单 + 夜结自己算一遍 + 数值全读原版公式 + "盘点台数 ≠ 工作台数就报错"的账本自查。
