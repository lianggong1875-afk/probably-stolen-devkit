# 物品贴图自愈 / Sprite Heal（原版标记位 bug 逆向）｜工坊 3845751834

> 蒸馏自反编译源码 `缓存文件夹\decomp_ws\3845751834`（3 个 .cs / 180 行，1 个 Patch，零能力）。
> 价值：**一个极小的模组，换来了原版贴图解析路径的完整真相**。凡是"给物品换贴图"的模组都会踩这个坑。

## 1. 原版 bug（作者逆向出来的结论）

`GameItem` 上有个布尔标记 `useSpriteFromMod`，用于区分"这张图要去模组包里取"还是"这张图在原版图集里"。问题：

| 方法 | 对 `useSpriteFromMod` 的处理 |
| --- | --- |
| `GameItem.SetSpriteAndShapeFromMod(modId, key)` | 置 `true` |
| `GameItem.SetSprite(...)` / `SetSpriteAndShape(...)` | **只改图集路径，从不清回 `false`** |
| 解析函数 `GameItemElement.ResolveSpriteByName(name)` | 按这个标记分流：`true` 时拿 `spriteAtlasPath` 去模组列表里找**同名 ID 的模组**取图，找不到就返回白底问号 |

于是出现"标记只增不减"的粘滞：只要一件模组物品后来切到原版图集（典型触发点是**原版酿酒完成时** `item.SetSpriteAndShape("Items/items_winemaking", "bottle…")`），标记仍是 `true` → 解析时去模组列表里找不到图 → 白底问号。鼠标拖一下又能好，是因为拖拽走了另一条刷新路径。

## 2. 修法：一个 Prefix 做双向纠偏

```csharp
[HarmonyPatch(typeof(GameItemElement), "ResolveSpriteByName")]
internal static class SpriteHealPatch
{
    private static bool Prefix(GameItemElement __instance, string __0, ref Sprite __result)
    {
        var item = (GameItem)__instance;
        string atlas = item.spriteAtlasPath;
        if (string.IsNullOrEmpty(atlas)) return true;              // 没图集路径，交还原版
        bool isBareId = atlas.IndexOf('/') < 0;                    // 图集路径不带 '/' → 它是个模组 ID

        // 方向一：标记说"来自模组"，但图集根本不是任何已加载模组的 ID → 把标记纠正回 false
        if (item.useSpriteFromMod)
        {
            if ((isBareId ? FindMod(atlas) : null) != null) return true;   // 确实是模组，交还原版
            item.useSpriteFromMod = false;
            LogOnce("sticky:" + atlas + "/" + __0, "纠正粘滞标记…");
            return true;
        }

        // 方向二：标记说"来自原版"，但图集其实是模组 ID 且该模组有这张图 → 补上标记并直接返回
        if (isBareId && !string.IsNullOrEmpty(__0))
        {
            var mod = FindMod(atlas);
            if (mod?.Sprites != null && mod.Sprites.TryGetValue(__0, out var sprite) && sprite != null)
            {
                item.useSpriteFromMod = true;
                __result = sprite;
                LogOnce("lost:" + atlas + "/" + __0, "补回丢失标记…");
                return false;                                     // 跳过原版
            }
        }
        return true;
    }

    private static LoadedMod FindMod(string id)
        => ModLoader.Mods?.Find(m => m?.Manifest != null
             && string.Equals(m.Manifest.ID, id, StringComparison.Ordinal));
}
```

## 3. 从代码里挖到的原版字段（可直接用）

| 成员 | 语义 |
| --- | --- |
| `GameItem.useSpriteFromMod` | 贴图是否来自模组包（**只增不减 bug 的根源**） |
| `GameItem.spriteAtlasPath` | 图集路径；**不带 `/` 时它是一个模组 ID**（关键约定） |
| `GameItem.SetSprite(atlasPath, spritePath)` | 改图集/贴图名，不动标记 |
| `GameItem.SetSpriteAndShapeFromMod(modId, key)` | 改图集并置标记 |
| `GameItemElement.ResolveSpriteByName(string)` | 贴图解析总入口（返回 Sprite） |
| `LoadedMod.Manifest.ID` / `LoadedMod.Sprites`（`Dictionary<string, Sprite>`） | 已加载模组的 ID 与贴图表 |
| `ModLoader.Mods`（`List<LoadedMod>`） | 全部已加载模组 |

## 4. 我们的用法

1. **我们给物品换贴图后，如果那张图不在我们模组包里，必须显式把 `useSpriteFromMod` 置回 `false`**，否则玩家读档后会看到白底问号（原版不会帮你清）。
2. 我们自己的物品如果要"多套贴图切换"，把图集路径写成 `模组ID`（不带 `/`）最省事，原版解析器就是按这个约定走的。
3. 给别的模组物品换图时同理；若对方模组未加载，`ResolveSpriteByName` 会返回问号，所以要先判 `LoadedMod` 存在。

## 5. 踩坑

- 该模组的 `catch` 里嵌套 `try/catch` 全吞（连 LogError 都包了一层 try），**违反我们的异常规范**；我们实现同类纠偏时必须 `Debug.LogError` 带堆栈。
- `LogOnce` 用 `HashSet<string>` 去重，但只在 `OnEnable` 清空 → 热重载后日志不再重复，便于排查的同时不刷屏。这个"一次性日志"的技巧值得抄。
