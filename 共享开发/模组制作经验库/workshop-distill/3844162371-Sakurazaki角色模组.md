## 1. 角色是怎么"造"出来的

它加的是**"一类固定脚本顾客"**，不是原版那种带 `StoreClientUniqueList` 编号的剧情 NPC。三条腿同时用：① `StoreClientListDict.storeClientDict["<identifier>"] = Func<StoreClient>` 注册工厂；② 在 `OnGenerateCustomerVeryLate` / `OnWakingUpLate` / `OnGameLoadedLate` 里自己造顾客 → `AddClient` → 从 `clientStack` 摘出来 → `Insert(index)` 插到指定序号；③ `ModHelper.SetClientSource(c, "sakurazaki_ui_clinic")` 打归属。`storeClientDict` 的确切语义未读原版实现，但 key 用 `identifier` 原文、value 是无参工厂、`OnDisable` 里成对 `Remove`，判为「存档里出现该 identifier 时按它重建」（推测）。

| identifier | 出处 | 性质 |
| --- | --- | --- |
| `sakurazaki_ui_clinic.visitor` | `Mod.CreateVisitor`（`Mod.cs:741`） | **羽衣本人来访**；同一 identifier 用 `reason` 分岔成 first / thanks / gift / regular / donation 五条剧情 |
| `sakurazaki_ui_clinic.wednesday_blood` | `FoodHelp.Create`（`FoodHelp.cs:83`） | 引子 NPC：饥饿的拾荒客，拿两袋血换食物（结识羽衣的触发条件） |
| `sakurazaki_ui_clinic.referral_return` | `ReferralReturns.Create`（`ReferralReturns.cs:149`） | 回访 NPC：被你介绍去诊所的客人，几天后带谢礼回来 |
| `sakurazaki_ui_clinic.eleanor_contact` | `EleanorRescue.CreateContact`（`EleanorRescue.cs:160`） | 羽衣以"知情者"身份出场，衔接原版艾莉诺剧情 |
| `milira_gold_chef.customer` | `MiliraChef.Mod.CreateCustomer` | 跨模组彩蛋 NPC，共用同一 DLL |
| `eleanor8` / `eleanor9` | 原版 `StoreClientUniqueList` | **不新建，直接改写原版剧情 NPC 的对话与结局** |

**名字 / 立绘 key / 本地化 key 三者解耦**：displayName 走 `Mod.Name => UiText.Name => Pick(zh,en,ja)` 三语内联（`UiText.cs:5`），不用原版 `LocHelper` key 表；立绘 key 恒为 `"sakurazaki_ui_clinic." + <outfit>`（模组 id 即命名空间）；台词走 `Dialogue/shop.<locale>.txt` 的 `[section].key` 查表，且**代码里每句都带中文兜底字面量**，文本文件缺失只 `warn` 不崩。

立绘入口是硬编码白名单（`Mod.cs:132`），不是前缀匹配；随后按 `tag` 里的 `sakurazaki_ui_clinic.visit.<day>.<reason>` 找剧情强制服装，最后 `client.spriteName = "sakurazaki_ui_clinic." + text`（`Mod.cs:140-148`）。

## 2. 立绘怎么挂

### 2.1 文件放哪 → key 就是文件名（去扩展名）

`Textures/Items/ui_cloak.png → mod.Sprites["ui_cloak"] → SpriteDict["sakurazaki_ui_clinic.ui_cloak"]`（15 张同构）。立绘**全在 `Textures/Items/` 子目录**，代码按裸文件名取值，说明加载器忽略子目录、以文件名去扩展名作 key。

三张大图在 `Textures/` **根目录**，代码取的是 `mod.Textures` 而非 `mod.Sprites`，再手动建 Sprite 写回（`ClinicNightView.cs:102-117`）：

```csharp
if (!mod.Textures.TryGetValue(key, out var value)) { continue; }
((Texture)value).wrapMode = (TextureWrapMode)1;
((Texture)value).filterMode = (FilterMode)1;
sprites[key] = Sprite.Create(value, new Rect(0f, 0f, (float)((Texture)value).width, (float)((Texture)value).height), new Vector2(0.5f, 0.5f), 100f);
mod.Sprites[key] = sprites[key];
```

→ **`Items/` 下的图能自动拿到 Sprite，`Textures/` 根目录的大图只进 `mod.Textures`，必须自己建图再塞 `mod.Sprites`**，否则 `"<modId>:<key>"` 形式的 `ImageKey` 查不到图（与 `afterhour-locations.md` §2 结论一致；"只为 Items/ 生成自动 sprite"是推测）。

### 2.2 png → Sprite 的完整链路（`Mod.cs:247-273`）

```csharp
string[] allKeys = AffinityWardrobe.AllKeys;
foreach (string text in allKeys)
{
	if (assets.Sprites.TryGetValue(text, out var value))
	{
		if (!portraits.TryGetValue(text, out var value2) || (Object)(object)value2.texture != (Object)(object)value.texture)
		{
			Rect rect = value.rect;
			float num = rect.height * 100f / 175f;
			value2 = Sprite.Create(value.texture, value.rect, new Vector2(0.5f, 136f / 175f), num, 0u, (SpriteMeshType)0);
			((Object)value2).name = "sakurazaki_ui_clinic." + text;
			portraits[text] = value2;
		}
		SpriteDict.Instance.spriteDictionary["sakurazaki_ui_clinic." + text] = value2;
	}
}
```

三个要点：直接写 `SpriteDict.Instance.spriteDictionary` 字典（不走 `SetSprite` 封装）；缓存判据是 **`cached.texture != source.texture`**（换图/热重载自愈），不是"key 已存在就跳过"；`Sprite.Create` 六参 = `(texture, rect, pivot=(0.5, 136/175), ppu=height*100/175, extrude=0, FullRect)`。

### 2.3 表情切换：实际上没有表情，只有换装

`AffinityWardrobe.Normalize`（`AffinityWardrobe.cs:72-99`）会剥掉 `_cute` / `_smile` / `_relaxed` 后缀——**这是给表情差分预留的口子，但工坊包里没有任何带这些后缀的图**。真正的差分是 **15 套服装**，门控是好感度阈值：

```csharp
// AffinityWardrobe.cs:42-58
public static string Choose(string reason, long affinity, int visit)
{
	string text = StoryOutfit(reason);          // first→ui_cloak, thanks→ui_casual
	if (text != null) { return text; }
	string[] array = Unlocked(affinity);
	return array[Math.Abs(visit % array.Length)];
}
// AffinityWardrobe.cs:53-58  按 Gate 过滤，ui_casual 恒解锁
public static string[] Unlocked(long affinity)
{
	return (from k in Mod.PortraitKeys.Skip(1).Concat(Added)
		where k == "ui_casual" || affinity >= OutfitMemory.FromOutfit(k).Gate
		select k).ToArray();
}
```

好感度 = `Referrals*5 + Lifetime/100 + 夜班额外值`（`ClinicState.Affinity` + `NightProgress.Affinity`）。

模组**完全没有碰** `Disp…`/表情字段（`SpriteDict` 里没注册任何表情后缀），而是把"换脸"压成**一个字符串 `client.spriteName`**，挂在 `StoreClient.GetSprite` 的 Prefix 上（`PortraitArrivalPatch.cs`）：`Prefix ⇒ Mod.PreparePortrait(__instance)`。每次取立绘前把 `spriteName` 纠正成当前该穿那套。**一处顶八处**（对照 L2 少女当铺的 8 个薄 Patch），代价是必须占住这唯一的缝。

## 3. 对话与剧情怎么组织

三层：**数据结构层** = 原版 `Dialogue` 对象链（不是自定义 JSON/CSV）；**文本层** = `Dialogue/shop.<locale>.txt` / `night.<locale>.txt` 的 INI 风纯文本；**兜底层** = 代码里 `DialogueText.Shop(key, "中文兜底")` 的第二参数。没有 JSON、没有 CSV、也没有 `LocHelper` key 表；三语靠"3 个同名不同后缀 txt + 运行时按 locale 选一份"。

```csharp
// Mod.cs:830-837  —— 初见：4 页线性文本 + 1 个选项 → 收尾页
Dialogue val3 = c.mainDialogue.SetText(Name, DialogueText.Shop("intro.greeting", "打扰了。昨天那位拿血袋换食物的客人……我看见了。")).NextDialogue().SetText(Name, DialogueText.Shop("intro.food", "那袋食物，他抱着走了好远，还回头看了一次。……你多放的那些，他大概没想到。"))
	.NextDialogue()
	.SetText(Name, DialogueText.Shop("intro.clinic", "我叫樱咲羽衣，在下层区开了一间小诊所。看不起病的人来，我不收诊费。"))
	.NextDialogue()
	.SetText(Name, DialogueText.Shop("intro.address", "下次他再来，能不能把诊所的地址告诉他？总这样卖血，我有点担心。"));
string text = DialogueText.Shop("intro.promise", "我记住了。有人需要帮助，我会告诉他们。");
val3.AddChoice(DirectoryMaster.Item("postit", true), text, "", ChoiceLine(text, reply), (Action)null, (Func<bool>)null);
```

- **选项签名（6 参，从调用点反推）**：`AddChoice(GameItem 图标, string 标签, string 说明, Dialogue 回应, Action 选择时执行, Func<bool> 是否可用)`。图标**统一借原版 `postit` 便签**，省掉一整类图标美术。
- **玩家台词用哑节点**：`new Dialogue().SetText("PLAYER", label).SetDummy().SetNextDialogue(reply)`（`Mod.cs:701`）。
- **条件分支不是 if 树，而是第六参 `Func<bool>`**，原版 UI 自己灰掉/隐藏。例：`Mod.cs:665-669` 的两个便签选项，"介绍去诊所"的可用性是 `() => Enabled && Current == c && ReferralRules.CanRefer(...)`。
- **发东西/改状态一律放 `SetStartAction` / `SetEndAction`**，绝不在构造时执行——构造发生在顾客生成期，柜台可能还没准备好。

**文本表解析**（`DialogueText.Load`，`DialogueText.cs:90-142`）：`TrimStart('\ufeff')` 去 BOM → 按 `\n` 切 → 跳过空行与 `#` → `[...]` 更新当前段 → `=` 前半为 key、**后半整段为 value**（值里可再出现 `=`）→ 最终 key = `section + "." + key`。重复 key 只告警、后写胜；坏行/缺文件只 `warn`。`LoadShop` 一次加载 3 个语言（`{"zh-CN","en-US","ja-JP"}`），`LoadNight` 只加载当前语言（旁白少变，省一次 IO）。

## 4. 诊所这个"地点/功能"做成什么

**做成原版夜晚外出地点**，走"全屏 CG / 视觉小说打工"路线（`ClinicVolunteer : AfterhourLocation`），**不是** `ModHelper.AddAfterhourLocation`，也不是店内机器：`Id = "sakurazaki_ui_clinic.volunteer"`、`Source => "sakurazaki_ui_clinic"`、`ImageKey => "sakurazaki_ui_clinic:ui_clinic_room_v1"`、`AmbienceId => "dr_jackson"`、`UsesAfterhourBag => false`、`IsDiscovered() => Mod.State().Met`。注册/卸载用 `AfterhourLocation.Register(instance)` / `AfterhourLocation.RemoveSource("sakurazaki_ui_clinic")`——**按 source 批量摘，不按实例**。

- 舞台是自建 `GameObject`：背景 `SpriteRenderer` `sortingOrder=20`、CG `=22`；`Tick()` 里按 `Camera.main.orthographicSize * 2f` 与 `aspect` 算**背景 Aspect Fill / CG Aspect Fit**，并把底层 `room.color` 染黑当黑边（`ClinicNightView.cs:541-598`）。
- 面板：`BuildPanel` 把原版根节点的 `LayoutGroup`/`Graphic`/`Mask`/`RectMask2D` 全禁用、其余原生子物体 `SetActive(false)`，再在自建 `surface` 上按 `NightLayout` 的绝对坐标摆 6 个控件（`dialogue`/`accent`/`speaker`/`line`/`skip`/`return`）。`NightLayout` 以 **1600×900** 为设计基准整体缩放。
- 时长 8 秒打字机（`maxVisibleCharacters = text.Length * elapsed / 8`），「跳过」= 放弃谢礼（`EarnedGift=false`）。
- **发奖不在 `Leave()` 里塞库**：`VolunteerLedger.Complete` 只记账，真物品在 `OnAfterhourLeaveLate → NightRuntime.Deliver()` 里校验 `playerLocation == 0` 后幂等投递，并按**实际入库数量**回滚。

白天店里那部分靠两个 Patch 成立：

| Patch | 干什么 |
| --- | --- |
| `StoreUIManager.OnNextClientArrived` Prefix → `Mod.Arriving()` | 顾客上台瞬间：清约翰通缉标记、重注册立绘、给艾莉诺第 8 幕补选项、对 `ReferralRules.Cases` 里 22 个原版苦难 NPC **沿对话链走到末尾追加两个便签选项**（"介绍去诊所"/"照常交易"）。选前者 → `Refer` → 记 `ReturnCase`（3~6 天后回访）+ 关谈判 UI |
| `PlayerStore.AcceptBarter` Prefix+Postfix | Prefix 用 `__state` 装 `Mod.Trade`（客户、物品→估值、基准食物件数/最便宜价、捐赠 or 善心）；Postfix **只统计真的进了 `soldElement` 售出区的物品价值**，再判 `IsKind`（食物≥2 件且给的价值 > 最便宜那件）决定是否解锁羽衣；`Committed` 防重复结算 |

## 9. 美术规格

### 9.1 立绘（15 张主角色 + 1 张配角）

| 项 | 实测值 | 来源 |
| --- | --- | --- |
| 像素尺寸 | **约 1466 × 1073**（1464–1466 × 1073–1074，逐张微差） | PNG IHDR 逐个读取 |
| 色彩 | RGBA（colorType 6，8 bit） | 同上 |
| 画风 | **非像素、日系半身立绘**，透明背景；人物居中、头顶留约 60px、左右大片留白 | `read_image` 实看 `ui_casual.png` |
| 长宽比 | 1466/1073 = **1.366**（与主流立绘包 1728×1266 的 1.365 一致） | 计算 |
| PPU | **`rect.height * 100f / 175f`**，1073 高 → **613.1** | `Mod.cs:265` |
| pivot | **`(0.5f, 136f / 175f)` = (0.5, 0.7771)** | `Mod.cs:266` |
| meshType / extrude | `0` = `FullRect` / `0u` | 同上 |
| FilterMode / WrapMode | 立绘**代码未改**（走加载器默认，推测 `Bilinear`）；夜景图另设 `FilterMode(1)`/`TextureWrapMode(1)`=Clamp | `ClinicNightView.cs:112-113` |
| 命名 | `ui_<outfit>.png`，outfit ∈ cloak casual clinic frost hanfu kimono maid miko reader detective mechanic strawberry bunny rain_doll plush_witch | 文件 + `OutfitMemory` |
| SpriteDict key | `sakurazaki_ui_clinic.<outfit>` | `Mod.cs:270` |
| 单张体积 | 1.05–1.48 MB | `Get-ChildItem` |

**`175`/`136` 的含义**：公式让**任意像素分辨率得到同一世界尺寸**——高度恒为 `h/(h*100/175)=1.75` 单位，锚点恒在图高 **77.71%** 处。配角米莉拉 `milira_chef.png`（**288×211**，仅主立绘 1/5 分辨率）套同一公式（`MiliraChef\Mod.cs:153-157`），世界尺寸同样 1.75 → **分辨率只需够清晰，构图只需守住 175:136 的锚点比例**。

> ⚠️ **与既有笔记冲突（须实测核对）**：`afterhour-locations.md` §3 记 `pivot=(0.5, 0.657)`，本模组代码是 **0.7771**，相差约 128px（1073 高时）。本文件记的是代码实测值；0.657 可能来自另一来源。我们自建立绘包时**以 Portrait Studio 口径为准**：`1728×1266 / PPU 600 / pivot (0.5, 0.4976) / Point / 无 mipmap`（见 [美术与角色模组三级形态与立绘包规格.md](美术与角色模组三级形态与立绘包规格.md) §3.2），175/136 只作"自建 SpriteDict 项"的参考。

### 9.2 夜景 / 打工 CG（3 张）

**1672 × 941**（三张一致，16:9 = 1.777），**RGB 无 alpha**（colorType 2）——纯底图，靠黑边裁切。建图参数 `Sprite.Create(tex, (0,0,w,h), pivot=(0.5,0.5), ppu=100f)`，过滤 `Bilinear` + `Clamp`。分工：`ui_clinic_room_v1` = 地点背景（`ImageKey`，Aspect **Fill**，`sortingOrder=20`）；`ui_shift_counter` / `ui_shift_linens` = 打工 CG，每次进场 `RNG.GetRandomInt(0,1)` 二选一（Aspect **Fit**，`sortingOrder=22`，显示时把背景染黑当黑边）。

## 10. 对我们的可用点

1. **"造一个 NPC"的最小闭环 = 四件套**，照 `Mod.cs:197-199`+`741-793`+`398-408` 抄：`storeClientDict[identifier]=工厂` + `new StoreClient{ identifier, displayName, spriteName, clientFaction, clientIntent, arrestable:false, nonShootable:true, CanReturn:false, cooldown:0 }` + `ModHelper.SetClientSource` + `AddClient→Remove→Insert(index,c)`。
2. **立绘挂载别去 Patch 8 个 UI 入口**：挂 `StoreClient.GetSprite` 的 Prefix，把 `spriteName` 纠正成"当前该穿那套"，一处顶八处（对比 L2 少女当铺 8 个薄 Patch）。代价是占住这个唯一缝——目前我们还没人占。
3. **立绘契约固定三行**：图放 `Textures/Items/<key>.png`（**必须在 `Items/` 子目录**）；`Sprite.Create(tex, rect, pivot, ppu, 0, FullRect)` 后写 `SpriteDict.Instance.spriteDictionary["<modId>.<key>"]`；`client.spriteName = "<modId>.<key>"`。缓存判据用 `cached.texture != source.texture`，热重载自动重建。
4. **美术规格**：主立绘 1466×1073 RGBA 非像素画风，PPU `h*100/175`、pivot `(0.5,136/175)`、FullRect；**任意分辨率都成立**（配角 288×211 同样能用），只需守住 1.366 长宽比与"锚点在图高 77.71%"的构图。走 Portrait Studio 口径则用 1728×1266 / PPU 600 / pivot (0.5,0.4976) / Point / 无 mipmap——两套别混用。
5. **对话一律"`Dialogue` 链 + 外部 txt + 代码兜底"**，绝不让任何一句台词只存在于 txt；选项图标统一借 `DirectoryMaster.Item("postit", true)` 省掉一整类图标美术，**用后 `Destroy()`**（`Mod.cs:977` 即此写法）。
6. **`Early` 推进世界状态、`Late` 插队列**，同一套恢复逻辑同时挂 `OnGameLoadedLate`/`OnNewGameStarted`/`OnWakingUpLate`/`OnGenerateCustomerVeryLate`（四处冗余优于一处漏掉），每个恢复函数写成**幂等**。
7. **存档只写自研 `Encode()` 字符串**：首段版本号 + 竖线分隔 + 解码穷举校验抛异常 + 多版本并列解析；字符串字段用 Base64（`ReturnLedger.S`，`ReturnLedger.cs:68-71`）；**绝不改原版 ES3 结构**，要复用原版状态就直接写原版字段（`native.eleanorDriveChoice = 3`）。
8. **改别人原版剧情 NPC**：Postfix 上"沿 `nextDialogue` 找第一个 `choices.Count >= 2` 的节点"再插选项；结局类用 Prefix 短接返回自制顾客。**不要**假定选项在第 1 页，也不要整段替换原方法。
9. **配置项**：`Define` 后一定 `OnChanged += Clamp`，变更后 `RefreshOwned()` **重算已存在实例**（否则只对新物品生效）；旧独立模组的配置值要"先读旧 config、夹值、再 Define 到新分组"。
10. **别学的地方**：`Mod.Safe(Action)` 把入口异常一律吞成 `Debug.LogError`（`Mod.cs:161-171`），按我们的规范只允许出现在 Unity 帧回调与 Harmony 边界；同一个 `DirectoryMaster.Item(string,bool)` 被两个类分别 Prefix/Postfix，我们若也挂这个热点方法必须显式写类型表并考虑 `[HarmonyPriority]`；存档键两套拼法混用，我们只用一种。
