## 1. 生产链怎么建模

### 1.1 酿酒拓展：五级链，只有中间两级是自己的机器

```text
原版种子 ─► 原版水培机（mod 只加 PlantDefinition）─► 果实 ─►[果肉浓缩机]─► 果肉浆（4 次用）
  果肉浆×2 + 空瓶 + 酵母 + 750 mL 水 ─►[大酿酒桶]─► 原版发酵引擎（1 晚/桶）─► 74 种酒瓶
                                                          │
                                    [流年陈化柜] ◄────────┘（每晚 +N 天）─►[瓶装/水灌装机]─► 成品
```

- **第一级（种植）不建机器**：`BrewingHydroponics.Register()` 往原版 `PlantRegistry` 塞 16 条 `PlantDefinition`，让**原版水培机**替你种；只额外 Patch `MachineHydroponic.Hydroponic` 的 Postfix 去改种子格准入与"成长中"贴图（`BrewingHydroponicMachine.cs`）。
- **第二级（果 → 浆）** 是自定义机器 `be_fruit_pulp_concentrator`，按钮触发、即时结算。
- **第三级（浆 → 酒）** 是自定义机器 `be_large_brewing_barrel`，但它**不算发酵**：把两坨果肉浆 + 空瓶 + 酵母 + 750 mL 水塞进瓶子后，直接调原版 `WineHelper.TryStartFermentation(bottle)`，再改写标签 `FERMENTATION_TIME_REMAINING_INT`（普通酒 1、念禾石 4）。
- **第四级（酒的陈化）** 是自定义机器 `be_liunian_ager`：克隆原版 `MachineWineRack.AgeWell()`，把两个网格换成 6×20 / 20×20 的 `LiunianInventory`，每周期按 `MachineWineRack.GetAgingDays(item)` 调 `WineHelper.OnAgeWine()`。
- **第五级（包装/装瓶）** 是两台打印机，玩家按按钮即时出瓶。

> 结论：**"原料→中间品→成品"三级里，mod 只拥有"中间品→成品"这一段**，前后两端都挂在原版机器 / 原版注册表上。

### 1.2 原版化学扩展：链不在物品层，在**液体成分层**

```text
矿石/淀粉/盐/脂肪 ─(原版加热台温度)─► ChemicalHelper.HandleTemperatureReaction ← mod 用 Postfix 挂进来
  ├ ToxinReaction（毒素） ├ OreReactions（煅烧/水玻璃/硅胶） └ Fermentation/Crackine/Lantern（水解/发酵/酯化）
  ▼ 中间液体（starch→sugar→alcohol…）
[电解槽]盐水→H₂/Cl₂ ｜ [蒸馏器]挥发分→冷凝液 ｜ [分离漏斗]油相/水相 ｜ [发酵罐]菌株+热量+电→4 份产物（含变异）
  ▼
[原版化学终整机 ChemFinisher] + mod 的 CanOutput 门禁 ─► 药剂/安瓿
```

- 链的"加工"绝大部分是**液体数量守恒的转化**（`IaLiquids.Get/Move/Set`，单位 μL），不是"槽位配方"。
- 触发点极其省事：整条链挂在**原版过夜化学反应**的 Postfix 上（`TemperatureReactionPatch.cs`、`IaTemperatureReactionPatch.cs`），mod 自己不做遍历。
- 真正需要"机器"的环节才建机器（蒸馏、电解、分离、发酵罐、HPLC、装弹机），其余全靠一个温度阈值 + 比例常数。

### 1.3 水培塔：不造链，**给原版链装一条外挂传送带**

```text
玩家：灌 60 L 水壶 + 左箱放种子 + 自己种下第一颗
  ▼ [水培塔 = 19×20 工作区 + 4 开关 + 2 容器槽 + 1 壶槽]
工作区里的原版水培机照原版逻辑生长（塔不供电、不改机器）
  ▼ 收获瞬间（Patch FinishGrowing）立刻补种 + 分流作物/种子；每晚（Patch EndNight）给每台机补水
```

一句话：这个模组**没有生产链**，它是原版生产链的**物流与调度层**——链条（种子→果实）100% 是原版的。

### 1.4 Station：唯一一条链是能源链

```text
食物（CALORIE_VALUE_TAG）─玩家按"转化"─► 燃料（kcal×0.05，上限 160）
  ▼ 每台 POWER_SOURCE 声明 DST_RW_POWER_OUTPUT
每天收盘（onCycleEndLateSlotItemFunc，按 dayCounter 去重）：Output vs Draw
  → 够：给外置电池充电 + 退还被机器内部吃掉的电 + 扣燃料；不够：全部电源标 OFF
```

这条链只有一级"转化"，其他都是 RimWorld 移植物品（`rw_*`）的电力基础设施。**没有任何多级加工**。

### 1.5 汇总

| 模组 | 链的层级 | 哪一级用原版机器 | 哪一级用自定义机器 | 哪一级靠过夜脚本 |
| --- | --- | --- | --- | --- |
| 酿酒 | 5 级（种植→浆→发酵→陈化→灌装） | 种植（水培机）、发酵（`WineHelper`）、陈化天数（`MachineWineRack`） | 浓缩、发酵桶装填、陈化柜、两台打印机 | 桶装填结算、孵化器批量、陈化柜周期 |
| 化学 | 2 级（液体反应→机器提纯） | 加热台提供温度、化学终整机产品、过夜化学模拟 | 电解槽、蒸馏器、分离漏斗、发酵罐、HPLC、装弹机 | 无（反应挂原版 pass，机器挂 cycle 钩子） |
| 水培塔 | 1 级（原版种植） | 全部 | 0 台真机器（只有 1 个"窗口物品"） | EndNight 补水 + 收获瞬间分流 |
| Station | 1 级（热量→燃料→电） | 无 | 0 台（只有 1 个燃料面板） | 每日电路结算 |

### 2.2 加工逻辑挂在哪：四种挂法，只有一种是"自己的循环"

| 挂法 | 谁在用 | 语义 | 频率 |
| --- | --- | --- | --- |
| **`onCycleEndSlotItemFunc`**（原版物品周期钩子） | 化学发酵罐/电解槽、酿酒流年柜、Station 电源 | 一个"加工周期"结束时跑一次，天然带机器状态/电量/涡轮加成 | 每台机器每周期 1 次 |
| **`onOneSecondItemFunc`** | 化学 HPLC/分离漏斗/蒸馏器（实时模式）、化学发酵罐（补料）、Station 电缆 | 原版每秒心跳；夜里由 `ChemicalHelper.RunNightlyChemicalSimulation` 跑 **360 次**（`Fermentation.NIGHT_TICKS = 360` 印证） | 每秒 1 次，夜里 360 次 |
| **按钮回调**（`MachineryButton`） | 酿酒浓缩机/桶/打印机、化学分离漏斗、Station 燃料转化 | 玩家点一下，当场结算一批 | 玩家驱动 |
| **自家 MonoBehaviour**（`DontDestroyOnLoad` + `LateUpdate`） | 酿酒 `PulpPump` / `LiunianPump` / `ConnectionPump` | **只用来做"延迟刷新 UI/描述"**，不承载加工 | 每帧 |

关键：**没有任何一件是靠"自有每秒 tick"做加工的**。酿酒那三个 Pump 只调 `Drain()` 去刷新界面（避免在回调里递归改窗口），加工全部发生在按钮或原版钩子里。

### 2.3 "没有一件是靠 Patch 原版机器实现的吗"——分清三种

1. **不是 Patch，是"再造"**（占多数）：`ItemDirectory.CreateEmptyItem` / 克隆原版成品机器 / 改造原版容器。  
   - 克隆法代表：`LiunianCabinet.Create()` 第一行 `GameItem item = MachineWineRack.AgeWell();`，然后改 identifier、换网格、覆写 `onCycleEndSlotItemFunc`。  
   - 改造法代表：`BrewingBarrel.Create()` 第一行 `GameItem item = DirectoryMaster.Item("water_jug", false);`。
2. **是 Patch，但只"加挂/闸门"**（没有一处整段替换）：
   - `BrewingHydroponicMachine`：Postfix `MachineHydroponic.Hydroponic` → 在原版返回的机器上**包一层** `mayInventoryAddItemFunc` 与贴图委托（保留原委托并链式调用）。
   - `CrackineEvaporatorCyclePatch`：Postfix `MachineEvaporator.Evaporator` → 把原版 `onCycleEndSlotItemFunc` 存成局部变量，**自己的逻辑不成立时再调原版**。
   - `AmpouleRecipePatch`：Postfix `ChemFinisherRecipe.CanOutput` → 给原版配方加一条纯度门禁（`__result && ...`）。
   - `FormalRecipeFermentation`：Prefix 抓快照 / Postfix 打标签，原版 `WineHelper.StartFermentation` **照跑不误**。
3. **"否决式闸门"仅两处**（`Prefix` 返回 false，但只是禁止某个动作，不重写算法）：
   - `BlendOrePatch`：矿石未粉碎时禁止 `ChemicalHelper.BlendInto`。
   - `BarrelWaterOnly`（挂在 `WaterHelper.TransferLiquid` 上）：只允许把水倒进大红桶，酒/非水一律拒绝。

> 全批次 **0 处** "Prefix return false + 自己重写原版机器加工" —— 这跟工坊里整段替换 `RunNightlyChemicalSimulation` 的做法正好相反。化学模组的 `NightSimulationPatch` 只做 `Fermentation.IsNight = true/false`，**没有拦原版入口**。

### 2.4 进度 / 产出 / 耗材 / 副产物怎么算

| 机器 | 进度怎么记 | 产出怎么定 | 耗材怎么扣 | 副产物 / 废料 |
| --- | --- | --- | --- | --- |
| 化学发酵罐 | **标签计天数**：`VCE_FERMENTER_NIGHTS_TAG`，`NightsNeeded = StrainTraits.BatchNights(strain,2)` | 收成时 `StrainTraits.HarvestCount(strain,4)` 份，每份走 `StrainMutation.Natural()` 变异 | 每晚电 12（`PowerHelper.DrawPowerSource`）+ 饲料卡路里 `StrainTraits.KcalPerNight` | 变异即"非预期产物"，不额外扣 |
| 化学蒸馏器 | 无进度，**蒸汽字典** `VCE_STILL_VAPOUR_STR` 累计 | 冷凝量 `min(可用, 目标)`，受冷却因子 `(purity/10000)²` 限制 | 盘管模式按水量/8×因子扣；蒸发模式扣冷却水；闭环模式扣焦耳额度 `VCE_STILL_KJ_CREDIT_INT` | 冷却水被"用掉"即副产物账 |
| 化学电解槽 | 每晚 1 次，常量：240,000 μL 盐 → 0.3 水 / 1.0 碱 / 0.5 气 | 两种产物槽（H₂、Cl₂） | 24 电 + 24 万 μL 盐水 | 盐水降级为水（副产物） |
| 酿酒浓缩机 | 无（即时） | 4 个同类水果 → 1 个果肉浆（4 次用量） | 8 电 + 4 个水果 `Destroy()` | 果肉浆质量分 = Σ clamp(−2..2) 的 `BERRY_CONDITION_INT` |
| 酿酒大桶 | 无（原版发酵计 1 晚） | 每瓶 1 瓶酒，酒种由**两种水果 id 对**决定（`BarrelWine.Resolve`） | 2 份果肉浆用量 + 1 空瓶 + 1 酵母 + 750 mL 水 | `WINE_SCORE_INT += 两份浆的 berryScore/4`；化学成分整份继承（`WineChemistry.Retain`） |
| 酿酒孵化器 | 无（过夜一次批发） | 每种种子按 `Recipe.Quantity`（多为 2）出 | 12 电 + 每晚**配额**（证书等级 2/5/7/18/24 次） | `RollFruitQuality` 时随机果实品质 |
| 酿酒流年柜 | 无（每周期 +`GetAgingDays` 天） | 陈化天数与 `unitValue` 同步增长 | 每周期耗电 | 用 64 位标签 `BE_WINE_AGE64` 绕过原版 `AGE_INT` 上溢 |
| Station 发电机 | 无 | `DST_RW_POWER_OUTPUT`（每台固定） | 燃料 = kcal×0.05，上限 160 | 电路不足时全员 OFF，不外借电 |

### 2.5 最值得学的一点：**加工事务的"不确定就不许存档"**

酿酒把"多个物品同时增减"当成一笔事务，用三个对象守住它：

- `PulpOperations.Busy`（正在加工的机器集合）+ `PulpOperations.Store`（当前存档实例）；
- `CanSave(store)`：事务没结束 / 当前 store 与记录不符 → 一律返回 false，让存档链**拦住存档**；
- `Protect(store, reason)`：回滚无法确认时，`Debug.LogError` 并把该 store 记进 `WeakReference`，**本局永久禁止存档**。

配合 `SaveManager.DecodeNodes` 的 Prefix 做 id 迁移（§7.5），这套组合拳换来了"读档不会读到半截加工"。代价是：一旦 `Protect` 触发，玩家必须重开本局。

### 3.2 一个配方有哪些字段

**酿酒的孵化器配方**（`IncubatorRecipes.Recipe`，字段最完整的一个）：

| 字段 | 含义 | 例 |
| --- | --- | --- |
| `SeedId` | 投入物 id | `"nutrifruit_seed"` |
| `ProductId` | 产出 id | `"nutrifruit"` |
| `Quantity` | 一批出几个 | `2` |
| `Create` | **产出工厂** `Func<GameItem>`（不是 id 字符串） | `PreBuiltItemHelper.CreateNutrifruitNormal` |
| `RollFruitQuality` | 是否随机品质 | `bloomberry_seed` 为 true |

**酿酒的种植"配方"**（`BrewingHydroponics.Crop` + `Growth[tier]`）：

| 字段 | 含义 |
| --- | --- |
| `SeedId` / `FruitId` / `SmallId` | 由 variety 拼出：`be_<v>_seed` / `_fruit` / `_fruit_small` |
| `Tier` | 1~4，决定成长档与证书门槛 |
| `Calories` | 果实热量 |
| `PlantOffsetX` | 贴图偏移 |
| `Growth[tier] = (Work, Yield, Water, MineralRange, Sensitivity)` | 工时 / 产量 / 耗水 / 矿物区间 / 污染敏感度 |

**化学的反应"配方"**：没有结构体，字段就是函数里的常量——温度阈值（`CALCINE_TEMP=150`）、转化率（`QUICKLIME_YIELD=0.55`）、最小参与量（`*_MIN_UL`）、副产物比例（`GAS_PER_SALT=0.5`）。

**化学的蒸馏"配方"**：不是表，是**模式 × 冷却因子**：`CoolantFactor = (purity/10000)²`，三种模式各一套产量上限公式。

### 3.3 新增一个配方要动几个文件

| 场景 | 要动的地方 | 文件数 |
| --- | --- | --- |
| 酿酒 · 加一种酒 | ① `BarrelWine.All` 加一行 ② `BarrelWine.Resolve` 加 `Pair(...)` 分支（或 `ResolveUnlisted` 兜底） ③ 语言表 `ModText` 加 `_name` ④ 若走水果链再加 `BrewingFruits` / `BrewingSeeds` / `Crops` | **2~5** |
| 酿酒 · 加一种可孵化种子 | ① `BrewingSeeds.All` ② 自动进 `IncubatorRecipes.Find`（无需改表） ③ 语言 | **2** |
| 酿酒 · 加一本配方书章节 | ① `RemainingItems.All` 加 `be_recipe_N` ② `BrewingManualRecipes.Chapters[N]` ③ `ChapterColors[N]` | **2~3** |
| 化学 · 加一条液相反应 | ① `Polarity.Values` 补液体的极性 ② 在对应 `*Reaction.cs` 里加一个 `private static int` 函数并挂到 `Run()` ③ 若产物是新液体，还要在 `IaLiquids` / `Liquid` 注册 | **2~4** |
| 化学 · 给原版配方加门禁 | 只加一个 `CanOutput` Postfix | **1** |
| 水培塔 / Station | 无配方概念 | **0** |

**第三方扩展性**：酿酒是四个里唯一给外部留口的——`ModEntry` 实现 `IServiceProvider`，把 `IncubatorRecipeRegistry.Register(owner, seed, product, quantity, factory)` 暴露成服务；注册带 `IDisposable`（迁出即注销），并显式检查 id 冲突与 `ModLoader.IsModEnabled(owner)`。化学只有 `DeferredPatches.Ready` 这种内部就绪标志，不对外。

### 3.4 有没有"配方发现 / 解锁"机制

有，**三种**，都不是"配方列表里锁着"那种：

1. **证书分级（酿酒）**：拥有 `be_basic/mid/high/top_cert` 决定 `BrewingCertificates.Level()` → `Quotas[level] = 2/5/7/18/24`，即**每晚能孵化几次**；证书本身是柜台物品，会被存进 ModData（`CertificateCounterSave`）。
2. **`returnsSeeds` 开关（酿酒 · 种植）**：`SetUnlocked(crop, NiniCertificates.HasIssued(crop.Tier-1))` 直接改 `PlantDefinition.returnsSeeds`——没证书的作物能长但**不再回收种子**，等于"一次性消耗"。这是很省的解锁实现：不新增物品、不加 UI，只切原版一个 bool。
3. **配方书章节（酿酒）**：`be_recipe_1..8` 是 8 本交互纸张，`Chapters[8]` 里的水果对就是玩家能查到的配方；书之外还有 `ResolveUnlisted` 兜底（未写进书的组合也能酿，只是查不到）。
4. 化学的"解锁"是**知识型**：`GuideBook.GiveChemistStart(scenarioId)` 给开局手册；反应本身不锁，靠玩家自己按温度/极性试（`HPLC` 是"测极性"的工具机）。

## 8. 对我们的可用点（《深空电玩》：光盘刻录 / 整备闭环）

现状（见 [PROGRESS.md](../../../../深空电玩/PROGRESS.md)）：刻录机 8 帧雪碧图、装电池即播、拷贝机 `STATE_WORKING` 24/40 锁盘、`arc_refurb_kit` 翻新、`arc_disc_polish` 抛光、概率维修扣材料。缺的正是"**一条像样的生产链 + 一台会自己干活的机器**"。四个模组各借一条：

3. **从水培塔借「总控终端」**：做一个 `arc_burn_rig`（刻录整备台）：窗口里 19×20 工作区放我们已有的刻录机/整备台，四个开关写进自身 tag（`ARC_AUTO_BURN` / `ARC_AUTO_SORT` / `ARC_AUTO_REFURB` / `ARC_AUTO_STOCK`），`PlayerStore.EndNight` 一个 Postfix 扫全店做结算；首次操作仍由玩家做（第一张母盘），后续全自动。这是 19 文件成本能拿到的最大自动化收益。

### 补 3｜86 种酒的组织：74 条"标签身份" + 12 条"独立物品"

manifest 的"74 款配方酒 + 12 款收藏酒 = 86"在代码里是**两条完全不同的技术路线**：

| 路线 | 数量 | 是什么 | 位置 |
| --- | --- | --- | --- |
| 配方酒 | 74 | **不是独立物品**：原版 `wine_bottle` + 标签 `BE_FORMAL_WINE_<id>` 编码身份；`BarrelWine.All` 每条只有 `(Id, Price)` | `BarrelWine.cs:22-98` |
| 收藏酒 | 12 | 真物品：`RemainingItems` 里 `Kind == "Collector"` 的 12 条（`IsCollector` 就查这个） | `RemainingItems.cs:43`、`138-141` |

**"一个基类 + N 条数据"的答案是：连基类都没有。** 配方酒的全部数据结构就是一张 74 行的 `(id, 价格)` 表和一张"两果 → 酒"的配对表：

- `BarrelWine.Resolve(a,b)` 是**配方本体**：先一串 `if (Pair("be_x_fruit","be_y_fruit")) return "be_zzz_wine"`（对称配对用本地函数 `Pair` 判），再 `a==b` 的单果分支，最后兜底 `ResolveUnlisted` **按果实稀有度** `Rarity.Afterglow/Longing/FromAfar` 返回 4 种"杂酿"之一（`BarrelWine.cs:144-280`）。
- 身份写入 `BarrelWine.Mark`：先 `DisableTag` 掉同一瓶上的其它 `BE_FORMAL_WINE_*`，再 `EnableTag` 本款、改 `identifier`、`ModHelper.SetSource`（`BarrelWine.cs:118-133`）。**一瓶只允许一个配方标签**，这就是它的"唯一约束"。
- 外观/价格靠 `BarrelWine.Refresh`：`SetSpriteAndShapeFromMod("brewing_expansion", text)` + 1×4 形状 + `unitBaseValue/unitValue = definition.Price`（仅当 `AgableHelper.GetAge(item)==0`，陈化过的保留原值）+ 三个 `SetGameItemType("ALCOHOL"/"SUBSTANCE"/"LUXURY_ITEM")`（`BarrelWine.cs:282-322`）。
- 名字：`BrewingWineText.Apply` 只做 `_name`/`_description` 语言键，并**清空 `flavorText`**（`BrewingWineText.cs:57-63`）。

**年份 / 陈化**是原版机制 + 一个 64 位扩展：

```csharp
// BrewingExpansion.Formal\LiunianWineAge.cs:11-18
public static long Age(GameItem wine)
{
    if (!wine.IsTag("BE_WINE_AGE64")) { return AgableHelper.GetAge(wine); }
    return Math.Max(wine.GetTagReadonly("BE_WINE_AGE64").GetLong(), AgableHelper.GetAge(wine));
}
```

- 原版 `AGE_INT` 是 `int`，流年柜每晚 +N 天会撞顶；于是超过 `int.MaxValue` 后**双写** `BE_WINE_AGE64`（long），取值时两者取大（`LiunianWineAge.cs:20-102`）。
- 每天的 `AgableHelper.OnAge` Prefix **只在 `BE_FORMAL_LIUNIAN_AGED` 且已达 int 上界时才接管**，否则原样放行（`LiunianExtendedDailyAge.cs:14-19`）——最小侵入。
- `ResetAge` Postfix 把两个标签都关掉（`LiunianResetAge.cs:8-15`）；价值增长按每酒自带的 `AGE_VALUE_MOD_PER_DAY_INT`（缺省 3/天），整段写入带异常回滚（改前 clone `AGE_INT`/`BE_WINE_AGE64`/`unitValue`，失败原样写回）。

**品质档**不用新表：读原版 `WINE_SCORE_INT`，非 7 分就交还原版 `ItemFeatureList.CreateWineQualityFeature(num)`；**只有 7 分这一档被换成自定义条件** `be_wine_quality_cloud_jade`（云玉），且真假条件同时设成它（`BrewingWineQuality.cs:106-146`）。存档时再补一手：`PlayerStore.WriteSlotFile` 的 Prefix 把云玉**临时换回原版 `ItemConditionList.CreateMasterVintage()`** 再写盘，Finalizer 换回来（`BrewingWineQuality.cs:44-89`）——**"别让自定义条件进原版存档格式"**，这条比品质本身更值得记。

> 一句话优先级：**先把拷贝机升级成"标准机器"（借 2），再加"许可 → 每晚配额"（借 1），最后才考虑整备台总控（借 3）**。借 4 属于经济系统层，等刻录真跑起来再上。
