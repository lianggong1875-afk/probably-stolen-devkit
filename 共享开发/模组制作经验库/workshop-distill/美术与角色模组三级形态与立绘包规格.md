# 美术与角色模组的三级形态 · 立绘包规格

> 蒸馏自第四批（美术/角色方向）：
> **社会王 / GangsterWangAnimated**（3832333084，3 个 .cs）— 单点美术增强
> **少女当铺 / CutePortraits**（3829696854，15 个 .cs / 8.8 万订阅）— 全店立绘替换
> **NPC 手绘肖像 / Non-AI NPC Portraits**（3846193221）— Portrait Studio 提供方包
> **原版风格 NPC 立绘 360+**（3838776570，363 张）— 批量生成包
> 完整角色模组（樱咲羽衣·诊所 3844162371）另见 `3844162371-Sakurazaki角色模组.md`。

---

## 0. 先给结论：美术模组有三级，成本差 20 倍

| 级别 | 代表 | 代码量 | 做法 | 冲突面 |
| --- | --- | --- | --- | --- |
| **L1 单点美术增强** | 社会王（3 文件） | 450 行 | `SceneManager.sceneLoaded` 钩子 + 自建组件挂在某个场景物体上 | 几乎为零（不 Patch、不碰原版系统） |
| **L2 全店立绘替换** | 少女当铺（15 文件） | ~800 行 | 8 个 11 行的薄 Patch + 一个 `PortraitDisplay` 核心，**换渲染器上的 sprite 引用** | 低（不碰 `SpriteDict` 字典，且主动避让别人的贴图） |
| **L3 完整角色模组** | 樱咲羽衣（58 文件） | 数千行 | 自定义 NPC + 立绘 + 剧情 + 功能地点 | 中（20 个 Patch） |
| **另：纯资源包** | 手绘肖像 94 张 / 原版风格 360 张 | 0 逻辑 | 按立绘引擎的 JSON 协议放图，**一行代码都不写** | 零 |

**最值钱的认知**：如果你想做的只是"换掉游戏里的脸"，**别去 Patch `SpriteDict.GetSprite`**。L2 那套"只换渲染器引用"的做法成本一样低、兼容性好一个数量级。

## 1. L2 全店立绘替换：少女当铺的完整机制（重点学这个）

### 1.1 骨架：1 个核心 + 8 个 11 行补丁

```

FixedScenePortraits.cs    87 行   固定场景（博士、保安）的替换 + 卸载还原
AugmentedGuide.cs        254 行   改造体图鉴页（另一个显示入口）
WantedPortraits.cs        66 行   通缉令
TransitPortraits.cs       75 行   运输/行程页
ArrivingClientDisplayPatch.cs      15 行 ┐
NextClientDisplayPatch.cs          11 行 │
WaitingClientDisplayPatch.cs       11 行 │  每个都只有
```

每个薄补丁长这样（全量，11 行）：

```csharp
[HarmonyPatch(typeof(PlayerStore), "GetNextClient")]
[HarmonyPriority(800)]                      // = Priority.High，尽量早跑（别人换完图我们还能纠正）
internal static class NextClientDisplayPatch
```

**8 个挂载点**（做同类替换时照这张表找时机）：

| Patch 目标 | 时机 |
| --- | --- |
| `PlayerStore.GetNextClient` | 下一位顾客上台 |
| `GenericClientMono.StartArrive` | 顾客走进来的动画开始 |
| `MapUIManager.ActivateClientOutsideStore` | 店外场景里的顾客 |
| `TransitUI.ShowPage` | 运输/行程页翻页 |
| `PaperUIManager.OpenAugIdGuide` | 打开改造体识别图鉴 |
| `EmporiumEntry.Start` | 店内场景启动（固定 NPC） |
| `StoreUIManager.OnNextClientArrived` 一类 | 到达完成 |
| （装饰器）`WantedPaper...` | 通缉令纸 |

### 1.2 核心：它是"事后替换渲染器"，不是"接管解析"

```csharp
internal static void Apply(SpriteRenderer renderer)
{
    if (!CutePortraits.Enabled || renderer == null || renderer.sprite == null) return;
    Sprite original = renderer.sprite;
    string key = OriginalKey(original);                  // 反查"这张图是原版哪个 key"
    if (key == null) return;                             // 不是原版图 → 一律不动
    Sprite replacement = CutePortraits.Replacement(key, original);   // 我们有没有 cp_portrait_<key>
    if (replacement != null) FixedScenePortraits.Assign(renderer, original, replacement);
}
```

三个关键判断：

**① 它怎么知道"当前这张图对应原版哪个 key"** —— 反射读 `SpriteDict` 的**私有 `List<SpriteEntry>` 字段**，建一份"原版目录"快照：

```csharp
private static void ReadOriginalCatalog(SpriteDict dict)
{
    if (CatalogOwner == dict) return;
    OriginalCatalog.Clear();
    foreach (FieldInfo f in typeof(SpriteDict).GetFields(BindingFlags.Instance | BindingFlags.Public | BindingFlags.NonPublic))
    {
        if (f.FieldType != typeof(List<SpriteEntry>)) continue;
        if (!(f.GetValue(dict) is List<SpriteEntry> list)) continue;
        foreach (SpriteEntry e in list)
            if (e != null && !string.IsNullOrEmpty(e.key) && e.sprite != null && !OriginalCatalog.ContainsKey(e.key))
                OriginalCatalog.Add(e.key, e.sprite);
    }
    CatalogOwner = dict;
}
```

> 注意它**只读不写**：`SpriteDict` 一个字都不改。这就是它与我们/框架（都去 Patch `GetSprite`）的本质区别。

**② 它怎么不去碰别的模组的图** —— 主动扫全部模组的贴图集合，命中就放弃：

```csharp
internal static bool IsOtherModTexture(Texture2D texture)
{
    if (texture == null || ModLoader.Mods == null) return false;
    foreach (LoadedMod mod in ModLoader.Mods)
    {
        if (mod == null || mod.Manifest == null || mod.Manifest.ID == "cute_portraits") continue;   // 跳过自己
        if (mod.Textures != null)      foreach (Texture2D t in mod.Textures.Values)      if (t == texture) return true;
        if (mod.Sprites != null)       foreach (Sprite s in mod.Sprites.Values)          if (s != null && s.texture == texture) return true;
        if (mod.PaperSprites != null)  foreach (Sprite s in mod.PaperSprites.Values)     if (s != null && s.texture == texture) return true;
    }
    return false;
}
```

**③ 它怎么保证卸载/关模组时不把别人换的图弄回去** —— 只在"当前还是我换的那张"时才还原：

```csharp
internal static void Clear()
{
    foreach (Change c in Changes)
        if (c.Renderer != null && c.Renderer.sprite == c.Replacement)   // ← 关键条件
            c.Renderer.sprite = c.Original;
    Changes.Clear();
}
```

`Assign` 时还会**先清掉同一个 renderer 的旧记录**（`Changes.RemoveAt`），保证记录表不膨胀。

### 1.3 资源命名约定

- 贴图放 `Textures/`，文件名 = key 名：`cp_portrait_femaleLower1.png`、`cp_portrait_maleScav3.png`……
- 命名结构：`<模组前缀>_portrait_<原版立绘 key>`（大小写照抄文件名里的写法，找 key 时是 `"cp_portrait_" + key` **大小写敏感**）
- 覆盖范围：`female/male` × `lower/upper/scav/rev/bm/eng/sec`，另有 `wanted`（通缉令）、`Items/`（道具贴图）子目录
- 实体：226 个文件 / 9.2 MB

### 1.4 它做不到的事（诚实标注）

- 只能替换**已经在画面上、且我们能拿到 `SpriteRenderer` 的**立绘；纯数据层（图鉴缩略图、列表项）要靠额外入口（它为此单独写了 `AugmentedGuide.cs` 254 行）。
- `OriginalKey` 依赖"当前 sprite 仍等于原版 catalog 里的那个引用"；如果别的模组**也**换过这个 renderer，就认不出来（于是它不替换，保持别人的结果——这是可接受的降级）。
- 反射读 `SpriteDict` 私有字段：`ModScanner` 会判 `reflection`（它确实在透视报告里没有高权信号，说明用的是游戏自己的类型、不算 external）。

## 2. L1 单点美术增强：社会王的极简做法

3 个文件、零 Patch、零 ModHelper：

```csharp
public sealed class GangsterWangAnimated : IMod
{
    public void OnEnable()
    {
        active = true;
        SceneManager.sceneLoaded -= SceneLoaded;      // 先退订，再订阅（防重复）
        SceneManager.sceneLoaded += SceneLoaded;
        Apply();
    }

    private static void SceneLoaded(Scene scene, LoadSceneMode mode)
    {
        if (scene.name == "EmporiumMenu") Apply();     // 只在主菜单场景动手
    }

    private static void Apply()
    {
        // 1) 从自己的 LoadedMod 拿 FolderPath 与首帧 Sprite（gw_cover_first_frame）
        // 2) FindObjectsOfType<SpriteRenderer>(true)，找名为 "MenuBackgroundNew" 的那一个
        // 3) 若它下面还没有 "GangsterWangAnimatedCover"，就 new GameObject 挂上去
        // 4) coverVideo.Initialize(target, firstFrameSprite, folderPath + "/cover.mp4", log)
    }
}
```

要点：
- **钩子是 `SceneManager.sceneLoaded`（Unity 原生事件），不是 ModHook 也不是 Harmony** —— 对"只在某个场景做装饰"的需求，这是最轻的接入点。
- 它自己实现了一个 `CoverVideo` 组件（290 行）播 `cover.mp4`，用 `mod.FolderPath` 拼绝对路径。
- 有一个 `Accepted(Sprite)` 判据：只接受 **960×540、PPU 100、且属于本模组（或名为 `bazaar` 的原版封面）** 的图 —— 用"尺寸+PPU+来源"三重判定避免误伤别人的背景图。

> 这套思路适合：主菜单背景、店内海报、招牌、灯牌、封面视频一类"单点装饰"。成本极低，兼容性极好。

### 3.2 立绘规格（照这个做就对得上原版）

| 项 | 值 |
| --- | --- |
| 尺寸 | **1728 × 1266** |
| PPU（pixelsPerUnit） | **600.0** |
| pivot | **(0.5, 0.4976)**（不是 0.5，别四舍五入） |
| Filter | **Point**（像素风；高清包另有做法） |
| Wrap | Clamp / Clamp / Clamp |
| mipmaps | **none** |
| colorSpace | sRGB |
| meshType | FullRect |

> `contentHash` 与 `resourceRevision` 是引擎的缓存键：**素材改了必须让它们变**（这套包用 `frame-<hash前16位>` 命名，天然满足）。

### 3.3 极限形态：连逻辑都可以没有（Portrait Studio Author Kit，3840289739）

反编译这个"作者工具包"（62 MB）后得到的东西很说明问题：

```csharp
// PortraitPackEntry.cs —— 全部逻辑就这些
public sealed class PortraitPackEntry : IMod
{
    public void Init(ModManifest manifest) { }
    public void OnEnable() { }
    public void OnDisable() { }
}
```

**三个方法全空**。而且打包目录里还有一整套 Python 运行时（`python312.dll` / `libcrypto-3-x64` / `libssl-3-x64` / `sqlite3` / `vcruntime140`）——说明它真正的"作者工具"是游戏外跑的 Python 程序，游戏内的 DLL 纯粹是**为了让加载器认得出这个模组**（有 `IMod` 实现 + manifest 才会被加载，`Textures/` 与 `Portraits/` 才会被读）。

推论（对做资源包直接有用）：
1. **纯资源模组只需要"一个实现 `IMod` 的空类 + manifest + 资源"**，不需要任何逻辑；
2. 资源要被立绘引擎读到，靠的是目录约定（`Portraits/` + `portrait-studio-provider.json`）或原版加载器扫 `Textures/`；
3. 想在包里塞"作者工具"，正确做法是**游戏外的独立程序**（它选了 Python），不要把工具链塞进游戏 DLL。

### 3.4 与传统 `Textures/` 包的区别

| | Portrait Studio 提供方 | 传统 `Textures/` 包 |
| --- | --- | --- |
| 谁加载图 | 立绘引擎按 JSON 读 | 原版 ModLoader 扫 `Textures/` 填 `LoadedMod.Sprites` |
| 命名 | 目录 `<key>/` + 固定资源名 `handdrawn.png` | 文件名即 key（`cp_portrait_femaleLower1.png`） |
| 玩家能否切整套 | 能（`portraitSets`） | 不能（装了就是全局替换） |
| 需要写代码 | 几乎不用 | 要一个替换核心 + 若干薄 Patch |

## 4. 批量生成包的命名经验（3838776570，363 张）

```
femaleScav_psrl_scav_f01.png        原版key + 池前缀 + 性别 + 两位序号
femaleUpper_psrl_resident_upper_01.png
augBMFemale_psrl_augBM_f01.png
maleMerc_psrl_upper_merc_m03.png
```

规律：**`<原版立绘 key>_<作者/池前缀>_<子池>_<f|m><NN>`**。
- 保留原版 key 在前缀，读代码时一眼知道覆盖谁；
- 作者前缀（`psrl`）避免与别人的批量包撞名；
- 池 + 性别 + 两位序号保证可无限扩。

## 5. 对我们的可用点

1. **给「可能是群友」做立绘包时，优先用 L2 那套"换渲染器"而不是 Patch `SpriteDict.GetSprite`**：
   - 我们现在在 `SpriteDict.GetSprite` 上有 Prefix（自愈）+ Postfix（兜底），已经和三方（电玩、群友、Extend Framework）在同一个方法上排队；
   - 如果将来要做"整套换脸"，照少女当铺做 **零字典侵入** 的实现，冲突面直接归零。
2. **立绘规格直接照 §3.2**：1728×1266 / PPU 600 / pivot (0.5, 0.4976) / Point / 无 mipmap。这是原版与主流美术包共用的口径。
3. **卸载还原要写成条件式**（`renderer.sprite == 我们换的那张` 才还原），否则会把别人后来换的图还原掉。
4. **主动避让**：替换前先扫 `ModLoader.Mods` 的 `Textures/Sprites/PaperSprites`，命中别人就跳过——比"检测模组是否存在"精确得多。
5. **批量命名带作者前缀**（`<原版key>_<我方前缀>_…`），避免与工坊上其它批量包撞名。
6. **单点装饰走 `SceneManager.sceneLoaded`**，不要为了一张背景图去 Patch 场景类。

## 6. 待验证 / 风险

- `portrait-studio-provider.json` 里 `binding` / `defaultMode` / `candidateResources` 的**语义**我只确定了结构，没读引擎侧实现（Portrait Studio 源码不在本批），标「（推测）」。
- 少女当铺反射读 `SpriteDict` 私有 `List<SpriteEntry>`：字段名/数量可能随游戏版本变；它用"遍历所有同类型字段"的方式规避了字段重命名，但仍依赖 `SpriteEntry` 这个类型存在。
- 社会王播放 `cover.mp4` 依赖 `mod.FolderPath` 的绝对路径；若玩家把模组装在带空格的路径或非 ASCII 路径，`VideoPlayer.url` 需要 URL 编码（未见它处理，标「（推测）」）。
- 立绘总张数（94 / 209 / 363 / 226）只统计了文件数，没有逐张核对尺寸是否都为 1728×1266。
