## 1. 一句话结论

**"60% 事务脚手架"这个判断在这一包上不成立。** 11.6 万行的实际形状是：**24.6% 在一个 28,502 行的静态神类里**（它就是整个"潮汐远征"子玩法，含自己的 IMGUI 布局引擎，其中 19.9% 是纯绘制代码）；**约 18% 在十几个 1,000~2,500 行的子玩法 `*Runtime` 里**（斗鱼引擎 6,000 行是全库唯一算得上原创的东西）；**41% 的文件（335 个 ≤20 行）只占 4.1% 的行**，其中 46 个还是 `Closeout0..30` / `TradingInput0..15` 这类按序号命名的补丁壳。

换句话说：它不是"把 12 万行写成假逻辑"，而是**"一个巨型静态类 + 按文件（而非按类）拆补丁 + 每档 UI 写两遍"**。它把"新玩法接原版"这件事做对了（三档扩展点阶梯，见 §3.1），把"模块边界"这件事做坏了。

## 3. 它怎么做这件事

### 3.1 「钓鱼」接在哪：**三档扩展点阶梯，一档比一档贵**

这是本档案最值钱的一节。同一个玩法作者用了三条**互不相同**的接入路线，成本与侵入度差别巨大：

| 档 | 接入点 | 侵入度 | 需要新 UI？ | 代码位置 |
| --- | --- | --- | --- | --- |
| **① 最便宜** | 开局特性 `gf_simple_fishing`（2 点）+ Prefix 掉 `ScavHelper.GetRandomScavengedItem`，把拾荒 50% 换成鱼 | 极低：只挂 1 个原版方法，失败原版照跑 | **零** | `SimpleFishingRuntime.cs:70-86`、`SimpleFishingGetRandomScavengedItemNativePatch.cs:9-13` |
| **② 中等** | 夜间渔具铺 = **寄生原版 `dr_jackson` 夜间地点**：`MapUIManager.Travel(AfterhourLocation.Get("dr_jackson"))` 进店，再 Postfix 抢 `drjackson2` 背景图 + 改店主名 | 中：复用原版整个 `EmporiumEntry` 货架/结算/离场流程，只换皮 | 零（蹭原版商店 UI） | `Runtime.cs:136-172`、`:182-237`、`WillyShopBackgroundPatch.cs` |
| **③ 最贵** | 潮汐远征 = **自建 `AfterhourLocation` 子类 + 反射伪造 `MapUIManager.Current` + 全屏 `OnGUI` 自绘 16 个页面** | 高：需要自己管场景、输入、音频、存档、货舱 | 是，全套自己画 | `TidalExpeditionRuntime.cs:772-786`、`:12056-12063` |

三档的关键细节：

- **档①**：`StartingPerkList.RegisterModPerk(new StartingPerk{...})` 是原版公开 API（`共享开发/reference/Assembly-CSharp/StartingPerkList.cs:251`），并配 `RemoveModPerks("ps-fishing-gameplay")` 做对称卸载（`SimpleFishingRuntime.cs:90`）。这条路线**连一个新物品栏都不需要**，纯粹用原版"拾荒"当产出管道。透视确认：**它用的是开局特性，不是营业日、不是过夜、不是 `AddAfterhourLocation`**。
- **档②**：作者**没有**调 `AddAfterhourLocation`（全库 0 处）。他直接把玩家传送到**已存在的** `dr_jackson`，然后在 `MapUIManager.ActivateClientOutsideStore` 的 Postfix 里把名叫 `drjackson2` 的 `SpriteRenderer.sprite` 换掉，`LeaveUpgradeMerchant`/`OnReturning` 的 Postfix 里再换回来（`Runtime.cs:190-231`）。货架走 `PlayerStore.AddDirectSellingItemToTable`（原版上架 API）。
- **档③**：`ExpeditionNativeLocation : AfterhourLocation` **只重写 4 个成员**——`Id => "PSFishingGameplay.Expedition"`、`Source => "PSFishingGameplay"`、`UsesAfterhourBag => true`、`CountsDumpedWaste => false`。注册方式是反射直写私有字段：
  ```csharp
  ModReflect.Call(map, "OnGoingOutside", new object[1] { nativeExpeditionLocation });
  ModReflect.Set(map, "Current", nativeExpeditionLocation);
  ```
  也就是说**它根本没有"新地点"**，只是骗过 `MapUIManager` 让它以为玩家出门了，然后把 `InventoryScene` 当成画布盖一层全屏 IMGUI（`TickUi` 里硬校验 `activeScene.name != "InventoryScene"` 就强制关页，`TidalExpeditionRuntime.cs:17112-17118`）。

**结论**：想加一个"打烊后的新去处"，本库的最便宜正解是**档②**（蹭一个已存在的 `AfterhourLocation` 换皮），而不是档③。档③ 只有在"页面超过 5 个、需要自己的地图与战斗"时才划算——而作者为此付了 28,502 行。

### 3.2 鱼的物种数据：**真数据驱动，且是"克隆原版鱼"而非"新建鱼种"**

- **谁读**：`Fishing.Fish.*.json`（8 个）与 `Fishing.Items.*.json`（17 个）都是**嵌入资源**，用 `Assembly.GetManifestResourceStream` 读，不落 `ModData`、不读外部文件（这也是它能保持空 `<Capabilities/>` 的原因）。
- **什么时候读**：
  - 物品定义在 **`Core.Init(ModManifest)` 阶段**一次性读 17 个文件 → `ItemRuntime.Load(_definitions)`（`LocalItemsHost.cs:46-64`）；**这一层不在 `InstallModule` 防火墙内**（`Core.cs:78-83`），抛异常 = 整个模组加载失败。
  - 鱼种（`Fishing.Fish.fish.json` 33 条）在 `FishRegistry` 构造函数里读（`FishRegistry.cs:49`、`:160-165`）。
  - 斗鱼动作目录在 **`FishDuelActions` 的静态字段初始化器**里读（`FishDuelActions.cs:190-191`），即第一次触碰类型时；`LoadSpecies()` 用 `GetManifestResourceNames()` 扫前缀自动发现，**加文件不用改代码**（`FishDuelActions.cs:420-465`）。
- **坏了怎么办：全部 fail-fast 抛 `InvalidDataException`，并在消息里带文件名/物品 id**：
  - `FishDuelActions.Read`：`Version != 1`、`Clips == null`、关键帧时间非递增、`Contact` 越界 → 抛（`FishDuelActions.cs:468-540`）；
  - `LoadSpecies`：检查 **override 指向的 clip 必须存在、行为阶段图必须无环**（`Visit` 里 `visiting.Add` 失败即抛 "Cyclic fish behavior"）、技能阶段必须全部可达（`hashSet.Count != Stages.Count` 抛 "Unreachable"）；
  - `ItemDefinitionLoader`：`MissingMemberHandling.Error`（**JSON 多写一个错键就炸**）+ 重复 ID + 占格/价值/枚举 + 交叉引用（`DryingRecipes` 非空、`StoryPaperNode` 必须是已知节点）逐项校验（`ItemDefinitionLoader.cs:18-51`）。
- **鱼不是新物种**：`NativeTemplate` 字段把 33 种鱼全部映射到原版模板——`Tilapia` 27、`Eel` 3、`ElectricEel` 2、`GutterTilapia` 1；`MeatCuts` 直接把鱼肉映射到原版切件 id（`fish_fillet`/`large_fish_fillet`/`small_fish_fillet`）。所以**做菜、称重、腐败、养殖、图鉴全部免费复用**——这正是它能与 `fishing-cuisine-expansion` 只靠一个反射 API 就联通的原因。

### 4.5 JSON 目录：**先严格校验，再进内存**（`FishDuelActions.cs:468-540` 节选，已删 IL 噪声）

```csharp
private static Catalog Read(string name)
{
    using Stream stream = typeof(FishDuelActions).Assembly.GetManifestResourceStream(name)
        ?? throw new InvalidDataException("Missing fish action catalog " + name + ".");
    using StreamReader streamReader = new StreamReader(stream);
    Catalog catalog = JsonConvert.DeserializeObject<Catalog>(streamReader.ReadToEnd());
    if (catalog == null || catalog.Version != 1 || catalog.Clips == null)
        throw new InvalidDataException("Invalid fish action catalog " + name + ".");
    foreach (KeyValuePair<string, Clip> clip in catalog.Clips)
    {
        Clip value = clip.Value;
        if (value == null || value.Keys.Length < 2 || value.Keys[0].Time != 0f)
            throw new InvalidDataException("Invalid fish action " + clip.Key + " in " + name + ".");
        for (int i = 1; i < value.Keys.Length; i++)
            if (!(value.Keys[i].Time > value.Keys[i - 1].Time))
                throw new InvalidDataException("Out-of-order keys in fish action " + clip.Key + ".");
    }
    return catalog;
}
```
