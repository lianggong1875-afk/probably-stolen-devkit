# Wild's Network API（关系网科技树第三方互操作协议）｜工坊 3842773239

> 蒸馏自反编译源码 `缓存文件夹\decomp_ws\3842773239`（18 个 .cs / 2210 行）。
> 价值：**这是工坊里"多个模组往同一套原版 UI 里塞内容而互不打架"的最佳样本**。它不提供 C# 库，靠"Unity 消息总线 + 原版数据字段约定"实现零硬依赖互操作。

## 1. 它解决的问题

原版"关系网/Wild's Network"科技树只有一条主链。想让几十个模组各自往上加节点、加标签页、加分段，硬依赖会变成地狱（A 引 B 的 dll，B 更新就全炸）。

它的解法：**中心模组广播，订阅者现场交数据，谁也不引用谁的程序集。**

### 2.1 中心侧：广播收集

```csharp
// Registry.Collect()：每次需要刷新时重新收一遍
Clear();
var root = GameObject.Find("danny.wildnet.mailboxes");
if (root != null)
{
    var bag = new List<object>();
    // BroadcastMessage 会调用该 GameObject 上所有组件的 public void WildNetDeliver(List<object>)
    root.BroadcastMessage("WildNetDeliver", bag, SendMessageOptions.DontRequireReceiver);
    int arrival = 0;
    foreach (var item in bag)
        if (item is Dictionary<string, object> d) Add(d, arrival++);
}
foreach (var kv in TabOwner) NetworkUpgrade.RegisterTabLabel(kv.Key, kv.Value.tabLabel);
NetworkUpgrade.InvalidateDefinitions();     // 告诉原版"定义集变了，请重建"
if (SavedSync.InRun()) SavedSync.Run();     // 存档里已有但定义缺失的节点补齐
```

### 2.2 订阅侧：只写一个方法，不引用任何类型

第三方模组要做的全部事情：

```csharp
// 1) 在自己的 IMod.OnEnable 里挂到邮箱根（若根不存在则等待）
var root = GameObject.Find("danny.wildnet.mailboxes");
var mb = root.AddComponent<MyMailbox>();     // 或 new GameObject 挂上去再 parent

// 2) 实现唯一约定方法名，签名固定 List<object>
public sealed class MyMailbox : MonoBehaviour
{
    public void WildNetDeliver(List<object> bag)
    {
        bag.Add(new Dictionary<string, object>
        {
            { "v",          1 },                          // 协议版本，低于 1 会被忽略
            { "modId",      "mymod.id" },
            { "id",         "mymod.upgrade_a" },           // NetworkUpgrade 的 id
            { "tab",        "mymod" },                     // 归属标签页
            { "tabLabel",   (Func<string>)(() => "我的模组") }, // 允许运行时求值（多语言）
            { "tabOrder",   50 },
            { "card",       "line1" },                     // 卡片分组
            { "cardOrder",  10 },
            { "order",      100 },                         // 同卡片内顺序
            { "softPrereqs", new[] { "vanilla.node_x" } },  // 软前置：缺了只提示，不阻塞
            { "visibleWhen", (Func<bool>)(() => SomeCondition()) }, // 运行时可见性
            { "fallbackIcon", "Items/icon_default" },
        });
    }
}
```

**要点**：`Dictionary<string, object>` 里可以放闭包（`Func<string>` / `Func<bool>`），因为交付是**在同一个进程内传对象引用**，不需要序列化。这样多语言与"是否可见"这类动态判断都交给了订阅方自己。

### 2.3 冲突处理策略（重点抄这一节）

| 冲突情形 | 处理 |
| --- | --- |
| 两个模组声明同一个 `id` | `Warn("Upgrade id 'x' is registered by both 'A' and 'B'; keeping the first")`，**保留先到的**，不崩、不覆盖 |
| 多个模组给同一个 `tab` 提供 label | `TabOwner` 只留第一个，其余忽略并 Warn |
| 软前置缺失 | 只在自检里输出 info，不阻塞 |
| 硬前置（原版 `prerequisite`）指向不存在的节点 | 自检 Warn：`requires 'x', which no installed mod defines; it can never be bought. Use a soft prerequisite instead.` |
| 前置成环 | DFS 三色标记找环，把环完整打印成 `a -> b -> c -> a` |
| 有布局数据但没有定义 / 有定义没有布局 | 自检分别 Warn |

自检代码（可直接复用成我们自己的"数据一致性自检"）：

```csharp
// 三色 DFS 找环
void Visit(string id)
{
    state.TryGetValue(id, out var s);
    if (s == 2) return;                                  // 已完成
    if (s == 1) {                                        // 回边 = 有环
        int at = stack.IndexOf(id);
        found.Add(string.Join(" -> ", stack.GetRange(at, stack.Count - at)) + " -> " + id);
        return;
    }
    state[id] = 1; stack.Add(id);
    if (byId.TryGetValue(id, out var def) && def.prerequisite != null)
        foreach (var p in def.prerequisite) if (byId.ContainsKey(p)) Visit(p);
    stack.RemoveAt(stack.Count - 1); state[id] = 2;
}
```

## 3. UI 层：靠 6 个 Patch 接管原版布局，而不是重画

| Patch 目标 | 作用 |
| --- | --- |
| `WildNetworkUI.BuildTabs` | 标签页太多时自动分页（箭头翻页） |
| `WildNetworkUI.BuildCard` | 卡片按 `cardOrder` 排序、按 `visibleWhen` 隐藏 |
| `WildNetworkUI.ResolveIcon` | 图标解析失败时用 `fallbackIcon` 兜底 |
| `NetworkUpgradeLayout.Build` / `PlaceCard` | 长链自动折行：一行放不下就接着往下画，并用连线连接 |
| `NetworkUpgrade.GetDefinitionsInOrder` | 定义顺序按 `order` 字段稳定排序 |
| `NetworkUpgrade.IsHavePrerequisite` / `GetMissingPrerequisite` | 软前置不阻塞购买，只提示"缺 XX" |
| `NetworkUpgrade.IsHiddenForRun` | 某些节点本次周目隐藏 |
| `NetworkUpgrade.AddMissingAfterLoad` | 读档补齐（老存档没有新节点时补上） |

**它 Patch 的全是"原版已经存在的公开/半公开方法"，没有一处重写整个 UI。** 这就是"扩展优先、替换兜底"的范式。

## 6. 对我们的可用点

1. **我们两个模组之间、以及我们与别人的模组之间，都可以照这个协议做互操作**：约定一个 GameObject 名 + 一个方法名 + 一个 Dictionary 协议版本，双方零引用。适合"深空电玩"与"可能是群友"将来要共享数据（例如群友模组的角色出现在电玩街机里）的场景。
2. **自检机制必须抄**：我们自己的数据（自定义物品、事件、剧情节点）也应该在 `OnGameLoadedLate` 跑一次"引用完整性 + 环检测"自检并 Warn，而不是等玩家踩到空引用。
3. **同名 id 保留先到者 + Warn**，永远不要"后到者覆盖"。这条原则写进规范。
4. 做关系网/科技树类扩展时，优先用 `ModHelper.AddNetworkUpgrade` 官方口子，不要自己去改原版定义列表。

## 7. 踩坑记录

- `BroadcastMessage` 传的是 `List<object>`，订阅方必须 `bag.Add(Dictionary<string,object>)`；**如果订阅方抛异常，Unity 会中断整轮广播**，所以订阅方必须自己 try/catch（本模组在 Add 里对每条独立处理）。
- 协议版本 `v < 1` 直接忽略 → 老协议数据不会污染新版本。**我们做协议时一定要带版本号字段并在读的时候校验。**
- 它把 `Func<string>`/`Func<bool>` 塞进 Dictionary 跨模组传递，意味着**订阅方对象生命周期必须长于中心模组的使用期**（否则拿到的闭包指向已销毁对象）。这是这套方案的隐性约束。
