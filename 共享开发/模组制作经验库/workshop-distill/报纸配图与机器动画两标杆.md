# A. Better Newspapers：报纸事件配图（工坊 3839534065）

## A1. 它到底改了什么：**排版 + 配图，两者都做，而且排版是主机**

反编译后的真实结论（`NewspaperMod.cs:10-51` + `NewspaperPages.cs` 1387 行 + `NewspaperTypesetter.cs` 1081 行）：

1. **重排整份报纸**（主功能，占代码量 80%）：它不满足于在原版四套原生排版里选一套，而是**自己决定这一期放几条新闻、怎么分页、每页用哪种版式**。
   - `NewspaperMod.SelectLayoutPatch` 在 `NewsUIManager.SelectLayout` 的 **Prefix** 里，把原版算好的 `List<StoreEvent>`（`__0`）抢过来，交给自己的 `NewspaperPages.Select()` 重新切分，再 `Clear()` + `AddRange()` 塞回去。
   - 于是原版 UI 池（`layout1Elements`/`layout2Elements`/`layout3Elements`/`layout4Elements`）被当成**「1/2/3/4 条新闻的版式容器」**复用：想放 2 条就喂 2 个槽，放 4 条就喂 4 个槽。分页由 `EditionLayout.Paginate` / `PaginateClassic` 试算，「装不下就减一」。
2. **加配图**：在 `PopulateUI` 的 Postfix 里，按算好的矩形把一张 `RawImage` 照片 + 九宫格相框塞进正文旁边/上方/整栏。
3. **加一堆报纸周边 UI 与阅读行为**：日期条 `Newspaper edition date`、页码与翻页折角按钮 `Newspaper page navigation` / `Turn page`、栏间分隔线 `Column rule`、花边栏目 `柜台笑谈`（笑话）/ `街头剪贴`（漫画）、按价格涨跌给标题染色（`ApplyInk`）；卷帘门升起后自动打开报纸并播音效、ESC 关闭后把报纸丢垃圾桶、背包里点报纸也能读（`NewspaperReading.cs`）。

> 一句话：**BN 是「报纸引擎」而不是「贴图器」。** 说它「只做配图」会误导实现——我们若要和它共存，冲突面在**排版**，不在图片。

## A3. 配图怎么「贴」进版面

### 3.1 贴到哪个 UI 元素上：**不替换原版图，自己新建一个兄弟节点**

这是与「换 `Image.sprite`」完全不同的注入法：

- 照片框 = `NewspaperPages.RectChild("Printed photograph", slot.textContent.transform)`：**以正文 TMP 的 `rectTransform` 为父节点**动态 `new GameObject`，挂 `Image`（九宫格相框）+ 内缩 6px 的 `RawImage`（照片本体）。见 `FramedPhoto.cs:20-26`。
- 锚点跟着正文块走：`frame2.anchorMin = frame2.anchorMax = rectTransform.pivot; frame2.pivot = new Vector2(0.5f, 1f)`，位置 `anchoredPosition = new Vector2(Mathf.Round(frame.center.x), Mathf.Floor(frame.yMax))`，尺寸 `Mathf.Floor(frame.width/height)`（`NewspaperPages.cs:994-998`）——**全部取整**，避免半像素糊字。
- 照片本体是 `RawImage` + `uvRect` 做中心裁剪（`FramedPhoto.cs:45-50` + `NewspaperTypesetter.CenterCrop`），不是 `Image` + `preserveAspect`。这样任意栏宽都不会把主体拉变形。
- 双图（`<id>__second` 存在时）：照片框一分为二，上下各一张（`anchorMax = (0.5,1)` + 第二个 `Companion photograph`）。这对应某些事件有「主图 + 次图」。

### 3.2 图片从哪来：**模组自己的 `mod.Textures`，按 key 前缀分派**

`Load()`（`NewspaperMod.cs:402-436`）在 `ModHook.OnModAssetsLoaded` 时遍历 `mod.Textures`：

- key 以 `_ui_comic_` 开头 → 走 `ClippingPress.Print()` 现场做 9 色网点化，结果放入 `pictures[key]` 并登记进 `printedClippings`（供 `OnDisable` 销毁）；
- 其余 key → 原样收下，只设 `filterMode = Point`、`mipmapCount > 1` 时 `mipMapBias = -3f`；
- key 为 `_ui_print_frame` → 额外做成九宫格 `Sprite`（`border = (14,14,14,14)`，`NewspaperMod.cs:429-432`）。

**推论（重要）**：所谓「9 色网点」只作用于 `_ui_comic_*` 这几张漫画图；事件配图（`tag__*` / `edition_*`）是**美术侧预先处理好的成品**，运行时不再网点化。我们做配图时必须自己离线网点化（我们已有 `工具库\img\newsprint-tone.py`，算法与源码 1:1，见 §A4）。

### 3.3 事件 → 配图的映射表：**三层，全在 C# 常量里，没有 JSON**

### 3.4 轮换与去重：`PrintRotation`（`PrintRotation.cs` 106 行）

- 不是随机：`Choices()` 用 `Salt + Day*7919 + edge*31 + 池名+槽位名的字符哈希` 播 `System.Random` 做洗牌，**同一天同一槽位结果稳定**，跨天不重复。
- 已印过的图记进 `Rotation.PrintedPhotos`（一个 `List<string>`），`Mark()` 推进 `Serial` 并为每个池维护 `Boundary`（一轮用完才允许复用）。
- 状态用 `ModHelper.GetModData/SetModData("local.newspaper.illustrations", "print_rotation_v1", json)` 落在**模组私有 ModData**，`JsonConvert` 序列化（这也是它唯一需要 `Newtonsoft.Json` 的原因）。
- 冲突消解：`PreparePictures` 里 `AssignPicture` 跑的是**增广路匹配**（占位冲突就递归让位），保证两篇不同新闻在同一版不会抢同一张图。

### 3.5 缺图怎么退化（四个台阶，全在代码里）

1. 池空 + 无变体 + 无精确同名图 → `editionOptions` 根本不收录这篇 → `Picture(story)` 返回 `null` → `PlacePicture` 第一行 `if (val == null || slot.textContent == null) return;` **干净地不贴图**；
2. 有图但这张已被同版别篇占用 → `PrintablePicture` 尝试换一张；全pool 都被占 → 返回 `null`（同 1）；
3. 双图槽位但 `<id>__second` 不存在 → 单图版式，`aspect` 回到 1.333/2.0 的原定值；
4. 相框算出来宽度 `< 56f` → 直接放弃贴图（`NewspaperPages.cs:962`：`if (!(num10 < 56f)) {...}`）。

排版侧同步退化：`NewspaperTypesetter.FitsColumns` 里 `num2 = (Picture(val2) == null) ? 0f : (...)`，**没图就不预留图高**，正文自然撑满整栏。这就是「不贴图也不会留一块空洞」的实现方式。

## A4. 9 色网点/半色调：完整实现（`ClippingPress.cs`，119 行，全部算法）

核心只有 `Tone()` 一个函数：

- **9 阶油墨色板**（`ClippingPress.cs:8-19`）：`#383631 / #4B473E / #6F6858 / #837B69 / #988F7B / #B5AC90 / #D0C8A7 / #EBE3BD / #F6F2CF`（即 56,54,49 → 246,242,207）。
- **亮度权重**：`(54*r + 183*g + 19*b + 128) >> 8`（整数 BT.601 近似）。
- **量化 + 2×2 网点阈值**：`screen = {32, 160, 224, 96}`，按 `screen[(x & 1) + 2 * (y & 1)]` 取；`if (num3 % 255 > num5) num4++`。
- **`chart` 变体**（我们 16 号文档完全没记）：`chart == true` 时阈值恒为 `128`（不做网点），且先按色相给灰度加一个 `±18 / 20 / 34 / 17 / 10` 的偏置，用来让「图表/证物清单」类图片在 9 色里保住可读性。目前只有 `_ui_comic_counter` 走这个分支（`NewspaperMod.cs:417`）。
- **`Print()`**：`GetPixels32()` → 逐像素 `Tone(pixels[num], j, height - 1 - i, chart)` → 新建 `Texture2D(w,h, RGBA32, mipmap:true)`，`wrapMode=Clamp`、`filterMode=Trilinear(2)`、`Apply(true,true)`。
  - 注意 `y` 传的是 `height - 1 - i`，即**网点矩阵按图像坐标（左下原点）对齐**；我们离线工具若按左上原点算，网点相位会整体错一行——做 1:1 复刻时要对齐这一点（我们 `newsprint-tone.py` 里已是同一写法）。

## A5. 它怎么与「别的报纸类模组」共存：真实机制有三条，**没有 HarmonyAfter**

这是本次核对最重要的一条结论，直接修正 16 号文档的表述。

**事实（grep 全仓 12 处 `[Harmony*]` 属性）**：BN **一处 `HarmonyBefore` / `HarmonyAfter` 都没有**，只有 2 处 `[HarmonyPriority(0)]`。它从没打算"插到别人后面"。它真正用的是三招：

1. **用户级开关 `external_layout`**（`NewspaperReading.cs:226`，默认 `false`）：我在 `SelectLayout` 的 Prefix 里第一句就是 `!NewspaperReading.UseExternalLayout`。**打开它 → BN 不接管排版**（连带 `pages` 组件不会创建，`PopulateUI` 的 Postfix 全程空转，配图一并关掉）。这是 BN 官方给出的"让位"接口——**不是给我方调 API，而是让玩家在设置里关掉它**。它**没有** `ModHelper.Expose`、没有 `IsModRunning` 探测、没有消息总线，与 16 号文档"无第三方注册接口"一致，但**接口是一个设置项，这一点我们漏记了**。
2. **几何自适应，不写死坐标**：所有栏宽/高度/底界都从**当前真实 TMP 网格**反算（`ForceMeshUpdate` 后取 `lineInfo[i].descender`、`panel.rect`、`TransformPoint`→`InverseTransformPoint` 折算回面板坐标），即使别人改了字号/内边距也能重新贴合。
3. **按名字避让自己的产物**：页脚 `Newspaper page navigation`（`NewspaperPages.cs:1257`）、相框 `Printed photograph`（`FramedPhoto.cs:20`）、栏线 `Column rule`（`NewspaperTypesetter.cs:933`）、栏目 `柜台笑谈`/`街头剪贴`（`PaperBrief.cs:176-177`）。**这几个名字就是对外可约定/可避让的锚点**。

顺序层面它的杠杆：两个关键补丁都写 `[HarmonyPriority(0)]`（低优先级），把自己推到"最后一个填页面"的位置；但跨模组真正达到效果的仍是配置开关 + 几何重算。

# B. Vanilla Machine Animations：原版机器运行动画（工坊 3839773708）

## B1. 播放器怎么写：**直接换 `Image.sprite`，永不碰 `spritePath`**

### 1.1 帧序列怎么排（`AnimationData.cs` + `MachineAnimation.cs`）

- `AnimationData` 是一张**硬编码常量表**：`Dictionary<string, (int Width, int Height, int[] Delays)>`，键是雪碧图基名（如 `vanilla__furnace_running`），共 74 条（含 `_rotation_ccw`/`_rotation_cw` 变体）。
- **8 列固定**：`AnimationData.Columns = 8`；切图 `int num3 = num2 % 8 * width; int num4 = ((Texture)sheet).height - (num2 / 8 + 1) * height;`（`MachineAnimation.cs:58-59`）——左上起、行优先、Unity 左下原点补偿。
- **每帧时长**：`int[] Delays` 毫秒，构造时做前缀和 `frameEnds[i] = num + delays[i]`；取值 `FrameAt()` 用 `elapsed % Duration` + `Array.BinarySearch(frameEnds, num + 1)`，O(log N)，**帧率抖动不漂移**。`Duration = frameEnds[^1]`。
- **停顿时长真实存在**：不是全等间隔。例：`vanilla__animal_cage_running` 56 帧里夹 4 个 `180ms`；`vanilla__bottle_printer_running` 有 `160/240ms` 的停顿帧；`vanilla__powerblock_running` 72 帧。
- **加载门槛（硬校验，`MachineAnimationAssets.cs:74-112`）**：只有当 `vanilla.rect.width == 声明帧宽 && vanilla.rect.height == 声明帧高` 才允许加载；再校验纹理 `width == 帧宽*8 && height == ceil(帧数/8)*帧高`，不符就 `return null`（静默不播，不报错）。
- **pivot / PPU 全继承原版**：`pivot = (vanilla.pivot.x / 帧宽, vanilla.pivot.y / 帧高)`，`pixelsPerUnit = vanilla.pixelsPerUnit * 帧宽 / 声明帧宽`（正常路径下就是原 PPU，比值只在冰箱 192px 特例下起作用）。

### 1.2 `Image.sprite` 替换 vs `SetSpriteQuick`

- 全模组**没有一处** `SetSpriteQuick` / `SetSpriteAndShapeFromMod` / 写 `spritePath`。唯一的写入口是 `MachinePlayback.ShowFrame`：

  ```csharp
  internal static void ShowFrame(Image image, Sprite frame)
  {
      if ((Object)(object)image != (Object)null && (Object)(object)image.sprite != (Object)(object)frame)
      {
          image.sprite = frame;
      }
  }
  ```
  （`MachinePlayback.cs:547-553`）
- 目标 `Image` 只有两个：`item.background.image`（实体）与 `item.fakeBackground.image`（拖拽虚影），在 `UpdateItem` 开头取（`MachinePlayback.cs:344-347`）。
- 每次播放/还原都走 `MachineAnimationDisplay`，它保存 `originalSprite` / `originalHitThreshold` / `lastFrame` / `showing`，并在播放期间把 `alphaHitTestMinimumThreshold = 0f`（防不同帧透明区变化导致 tooltip 闪烁）。

### 1.3 状态怎么轮询

- **帧驱动在 `InputActionManager.Update` 的 Postfix**（`AppearanceShortcutPatch.cs:5-12`）→ `MachinePlayback.Update()`，即**每帧**。若开了 `low_frame_rate`，用 `NeedsAnimationUpdate` 把刷新压到 30Hz（33.33ms 累加器），且 `FrameAt` 里 `num2 -= num2 & 1`（隔帧播，节奏不变）。
- **状态判定 150ms 节流**：`ReadAutomaticState` 开头 `if (now < view.NextStateCheck) return view.AutomaticActive;`，随后 `view.NextStateCheck = now + StateCheckIntervalMs(=150)`。
- **但所有"事件点"都会把 `NextStateCheck` 置 0**，实现 0ms 即时启停：`spritePath` 变化（`MachinePlayback.cs:381`）、`RecordCycle`（`:289`）、`RecordHeating`（`:302`）、`TrackInnateLayers` 里充电器/酒架（`:134`、`:144`）、`SetMode`（`:191`）、`SetRotationEnabled`、以及两个配置项 `OnChanged`（`RefreshAutomaticEligibility`）。
- `MACHINE_STATE_TAG` 并不是常量字符串直读，而是走原版助手：`MachineProgressHelper.GetMachineState(item) == "STATE_WORKING"`（`MachineActivity.cs:186`）。「周期型」机器另有门：只有 `CycleStarted >= 0 && now - CycleStarted < clip.Duration` 才播（`MachinePlayback.cs:388`）。

## B3. 供电 / 损坏 / 「要不要播」三套规则

播放决策在 `MachinePlayback.UpdateItem`（`:383-391`）一句话：

```
要播 = clip != null && (mode == Always
        || (mode == Auto && !干缸特例 && (!周期机 || 周期窗口内 && 无 BROKEN) && ReadAutomaticState(...)))
       且 当前 Image.sprite 未被第三方接管
```

- **损坏**：`item.IsTag("BROKEN_MACHINE_TAG")` 一旦为真，周期型机器立即不播（`:388`）；`MachineActivity.IsRunning` 第一行也先判这个 tag（`:65`）。
- **供电**：`MachineActivity.HasPower(item, id)` 是**按机种白名单**，不是无脑 `CanPower`：`chem_finisher / heating_plate / blender / animal_cage` → **直接 true**（不需要电）；`powerblock / recharger` → `PlayerStore.Instance?.isPowerOn`；`makeshift_reactor` → `ReactorHelper.ProvidesPower(item)`；其余 → `MachineHelper.GetBatterySlot(item)?.childItem` 存在且 `PowerHelper.CanDrawPowerSource(battery, 需求量)`，需求量 `bottle_printer` 固定 4、其余 `Math.Max(1, MachineryHelper.GetMachinePowerUsage(item))`。另外 `IsRunning` 里对 `printer / desequencer / hydropower / dna / mirage` 还会再叠一次 `MachineHelper.CanPower(item)`。这个检查可被 `check_power` 设置项关掉（`AutomaticPlayback.CheckPower`）。
- **悬停**：**不参与**播放判定。悬停只用来决定"快捷键按下去改哪台机器"（`AppearanceShortcut.OpenHovered`，靠 `EventSystem` 射线）。这一条直接修正 15 号文档的暗示——不需要为 tooltip 做特殊处理（真正要处理的是 `alphaHitTestMinimumThreshold`）。
- **三套自动规则**（`AutomaticRule`）：`contents`（默认，工作槽里有货就播）/ `vanilla`（跟原版运行状态，并启用上面那批"周期观测"补丁）/ `native_sprite`（跟着原版换 sprite 名走，`MachineNativeSprite.TryGetState`）。规则一换，`ResetAutomaticState()` 全场重置。

## B4. 零存档污染：核对结论 =「贴图零污染，但确实写 tag」

- ✅ **不碰 `spritePath`**：全模组只在 `AnimationWindow.cs` 里**读** `spritePath`（预览用），没有一处写。与 15 号文档「直接改 `Image.sprite`」完全一致。
- ✅ **不调 `SetSpriteQuick`**：确认零调用。
- ✅ **释放完整**：`MachineAnimationAssets.Reset()`（`OnDisable` 调）逐个 `Object.Destroy` 所有帧并清 `OwnedFrames`；`MachinePlayback.ClearScene()`（`SceneManager.sceneUnloaded` 调）释放所有显示并清 `Views`；`Views` 里 `IsDestroyed()` 的元素在 `Update` 中懒清理。
- ⚠️ **但"零存档污染"这个说法要收窄**：VMA 确实往 `item.state` 写 3 个自定义 tag（都是 mod 前缀命名，走原版 `TagSystem`，会随存档序列化）：`sfi.vanillamachineanimations.mode`（`auto` 时**移除**该 tag，`always`/`original` 时写入，`MachinePlayback.cs:180-187`）、`.rotation_disabled`（`:235-240`）、`.fridge_appearance`（`FridgeAppearance.cs:83-90`）。
  正确表述应是：**"贴图/模型状态零污染；玩家选择的播放模式与外观偏好，以 mod 前缀 tag 存进物品状态"**。这恰好符合我们工作区「持久化只写模组私有键」的铁律——它就是这么做的，值得照抄口径。

## B5. 雪碧图放哪、怎么命名、怎么对到机器

- **放哪**：`LoadedMod.Sprites`（我们的 `manifest` 里对应 `Sprites/` 一类资源目录，具体目录名由 `ModLoader` 约定，未取到 manifest →（推测））。代码直接 `loadedMod.Sprites.TryGetValue(sheetName + "__frames", out sprite)`（`MachineAnimationAssets.cs:92`），即**键 = `<基名>__frames`**。
- **命名约定链路**：
  1. 机器 identifier → `MachineCatalog.Machines[id]`；
  2. `MachineDefinition(id, stem, atlas, sprites...)` 用短构造把 `Asset` 拼成 `"vanilla__" + stem + "_running"`（`MachineDefinition.cs:13-16`）；
  3. 需要的纹理键 = `Asset + "__frames"`；
  4. 变体在 `GetSheetName` 里追加后缀：水培按作物/苗期返回不同基名、冰箱按玻璃内容物返回 `vanilla__fridge_glass_<kind>`、净化器空罐返回 `<Asset>_empty`、充电器顶盖返回 `<sheet>_top`；
  5. 旋转变体 = `<基名>_rotation_ccw` / `<基名>_rotation_cw`（`MachineAnimationAssets.cs:126-129`）。
- **对到具体机器还要过两道闸**（`MachineCatalog.TryGet`，`:33-41`）：`item.identifier` 命中目录；`machine.Atlas == item.spriteAtlasPath`（图集路径也必须一致，防同名跨图集误判）；`machine.Sprites` 里含 `item.spritePath`（**只对"静态态" sprite 生效**，如 `printer_off`/`printer_on`；换了第三方美化包的名字就不匹配 → 自动让位）；另外 `!item.useSpriteFromMod` 才接手，`GeneralHelper.IsDisplayOnly` 直接不接，`SpriteAnimationHelper.IsSpriteAnimated`（已被原版自带动画接管）就让位。
- **冰箱特例**：静态图固定按 192×192 处理（`FridgeAppearance.TextureSize = 192`，PPU 乘 4），因为原版 `fridge` 静态图是 48×48、玻璃贴图是 192×192 的大图。

# D. 对我们的可用点

**1. 先改文档，再写代码。** 15 号两处、16 号六处与源码不符（§A6/§B6 表里打了 ❌ 的行）。其中三条会直接害人：
- 16 号说 BN 用 `HarmonyAfter` 避让 → **它没有**。我们要么请玩家关掉它的 `external_layout`，要么自己写 `[HarmonyAfter("mod.local.newspaper.illustrations")]` 并接受"两套排版同时生效"的风险；
- 16 号的 `allElements` 与 `"Newspaper footer"` 两个名字**都不存在**，照抄会读到 null；
- 15 号把 "HotReloadPrepare/Activate 释放" 记成 VMA 的做法 → 那是我们的增强，引用时别挂在标杆头上。

**2. 报纸配图直接改用 BN 的"文件名即映射"三层结构。** 我们 `工具库/templates/mod-patterns/NewspaperArtHelper.cs` 可以简化成：`tag__<标签>__*` 池 + `<事件id>` 精确 + `<事件id>__second` 次图；`eventTags` 只保留我们自己的事件，`firstPictures` 可选。缺图就走"返回 null → 排版不预留高度"这条路（对方 `FitsColumns` 就是这么算的），比"贴占位图"干净得多。

**3. 硬编码美术参数直接用，别再猜。** 相框九宫格 `(14,14,14,14)`、RawImage 内边距 `6px`、最小相框宽 `56px`、多页页脚留白 `96px` / 单页 `24px`、中心裁剪 `uvRect` 公式、网点色板与阈值 `[32,160,224,96]`、亮度权重 `54/183/19`。这七个数字我们是拿实机截图反推的，源码确认无误。

**4. 机器动画模板按 VMA 实测口径改三点**：① 加"`vanilla.rect` 必须等于声明帧尺寸，否则不加载"的硬校验（现在是软约束，坏了只是画面错，很难查）；② PPU 用 `vanilla.pixelsPerUnit * 帧宽 / 声明帧宽` 而不是直接继承；③ 加 `OwnedFrames` 集合 + `HasForeignSprite` 让位（我们现在是"检测到不同就覆盖"，会和美化包打架）。

**5. 状态门照抄"白名单 + 周期窗口"，别一律 `CanPower`。** 尤其 `chem_finisher`/`heating_plate`/`blender`/`animal_cage` 原版根本不吃电，一律检查电力会让它们永远不播。同时把"150ms 兜底 + 事件点置 0"的六个挂点（sprite 变、周期记录、加热记录、innate 层同步、模式变更、设置变更）在模板里收成单一入口 `InvalidateStateCheck()`。

**6. 存档口径分两句写进规范**：
- 贴图/模型：绝不写 `spritePath`，只用 `Image.sprite`（BN 与 VMA 两地一致，可作铁证）；
- 玩家偏好：允许写 `ourmod.*` 前缀 tag 进 `item.state`（VMA 的 `mode` / `rotation_disabled` / `fridge_appearance` 就是范例），但要**像它一样"默认值 = 移除 tag"**（`SetMode(Auto)` → `state.dict.Remove(...)`），保证回到默认态时存档里不留垃圾。

**7. 动态补丁的可卸载写法值得单独沉淀**（`VanillaToggleAppearance.cs:65-119`）：`Harmony.GetPatchInfo(m).Owners.Contains(myId)` 防重复装 → `harmony.Unpatch(m, HarmonyPatchType.All, myId)` 支持"关设置即卸"。我们的热重载/开关型功能可以直接用这套，比 `UnpatchAll()` 精确。

**8. 不要抄的两处**：
- `AccessTools.Method("MachineBlender+<>c__DisplayClass0_0:<Blender>b__2")` 这种按闭包字符串签名打补丁 —— 换版本必挂；

**一句话总结**：BN 教我们「报纸是排版问题，配图是排版的副产品，共存靠让位开关 + 几何重算」；VMA 教我们「机器动画是状态问题，贴图只是最后一毫米，零污染靠只碰 `Image.sprite`，让位靠 `OwnedFrames` 白名单」。两者的共同气质是：**所有"要不要动手"的判定都可被玩家关掉，所有"动手"的痕迹都可被完整还原，所有"读不到"的情况都静默不播并只吵一次日志。**
