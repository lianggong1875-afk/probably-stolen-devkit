## 二、它怎么做这件事

### 2.1 19 作物 / 36 料理 / 10 饮品 / 25 香水：**四种表 + 一表一工厂**

全部内容的数量都能在表的长度上数出来，没有逐条手写物品类：

| 内容 | 表（文件:行） | 长度 | 生成方式 |
| --- | --- | --- | --- |
| 作物 A（原版植物） | `AgriPlants.cs:19-50` | 5 条 `PlantDefinition` | 链式：`Nutriment().Water().ReturnsSeeds().Innate().OnHarvest()` |
| 作物 B（本模组） | `AgriNextCatalog.cs:9` | 11 条 `AgriNextCrop` | 26 字段 DTO（`AgriNextCrop.cs:5-45`），`foreach` 出种子 + 4 档规格产物 |
| 作物 C（超科技） | `AgriSuperCrops.cs:56-67` | 3 条（循环 `AgriSuperRules.Crops`） | 同上 |
| 料理 | `AgriCookingRules.cs:15` | 24 条 | `foreach` 出 `agri_dish_*` + `agri_recipe_*` 一对 |
| 牧场料理 | `AgriLivestockCooking.cs:14` | 12 条 | 并入上表：`AgriCookingRules.cs:41` `.Concat(...)` |
| 饮品 | `AgriDrinkRules.cs:12` | 8 条（+2 条奶饮在牧场料理表） | 同上，`IsDrink=true` 分叉出瓶型/音效 |

| 酒 | `AgriWineCatalog.cs:43-52` | 7 条（6 新 + 原版荧光莓） | 液体 id = `"agri_wine_"+Key`，发酵中 = `"agri_wine_fermenting_"+Key` |

每件内容的成本：`AgriPerfumeCatalog` 48 件 / 51 行 ≈ **1.2 行一件**；`AgriPlants` 5 件 ≈ 5 行一件；最贵的是带中英双描述的家用作物（`AgriNextCatalog` 11 件 / 383 行 ≈ 35 行一件，几乎全是文案）。

**和"酿酒拓展"（3829730904，169 文件 / 17,938 行）比**：
- 两家都靠"id 约定 + 表"生成物品，但酿酒拓展是**一台机器一个类**（`BrewingBarrel` 569、`LiunianCabinet` 589、最大 `MachineConnections` 652 行），FarmStory 是**一台主机七个标签页**（`AgriFarm` 6300 行）。
- 论"加内容"省事：FarmStory 明显更省（表 + 一个工厂函数，19 作物没写 19 个类）；论"改一处不出事"：酿酒拓展更稳（最大文件 652 行）。
- 一句话取舍：**内容用表，交互用代码；FarmStory 把表做到了 4 种，把代码全压进 1 个 UI 类——省的是"加内容"，贵的是"改 UI"。**

### 2.2 三种小型牲畜：**原版物种 + 普通物品，不是独立实体**

一只牲畜 = 一个带 `ANIMAL_ITEM_TAG` 的普通 `GameItem`，身上是原版标签（`ANIMAL_AGE_TAG` / `ANIMAL_WEIGHT_TAG` / `ANIMAL_HEALTH_TAG` / `ANIMAL_SPECIES_TAG` …），**关键动作是把 3 个物种塞进原版注册表**：

- `AgriLivestockItems.RegisterSpecies()`（`:57-109`）构造 `AnimalSpecies` 写进 `AnimalSpecies.All[id]`，填 `growthStages[6]`/`weightStages[6]`/`baseStats`（喂食量、免疫、妊娠期…）→ 之后原版 `HusbandryHelper` / `GeneticHelper` / `MachineAutoButcher` 全都认这只新动物，白拿基因、屠宰分割、饥饿、疾病、拥挤全套。
- 每晚结算 `AgriLivestockRuntime.TickArea()`（`:273-374`）**顺序调用原版 10 个 husbandry 方法**：`HandleHunger→TryFeed→HandleStarvation→CheckHygiene→CheckImmunityDisease→HandleRegen→HandleDisease→HandleHealth→HandleOvercrowding→UpdateFertility`，再 `IngesterHelper.TickIngester` + 自己的 `Grow`，最后才发自己的三类产出计数。
- 产出：**奶只有短角豚**（`MilkYieldMl :129-142`：成年 300 mL，超 1000 g 每 500 g +50；槽上限 1000 mL，`MilkAfterNight :144-149` 封顶）；**蛋** `AdvanceEgg` 3 晚（`EggIncubationNights=3`）、可留 1~2 枚孵化；**毛/羽**（非短角豚）`AdvanceHarvest` 每 3 晚攒 1 件（`:158-171`）。
- 住哪：农场 `Equipment` 里的**原版** `animal_cage` / `ras`（`AgriFarm.cs:277`），面积记在笼子自己的标签 `AGRI_FARM_AREA_CELLS` 上（`:2244` 无标签时按库存形状数格子），扩建用 1 金属锭（`:4798-4842`）。
- 存档格式：**全靠物品标签**（`AGRI_LIVESTOCK_LAST_NIGHT` 防同夜重复结算、`AGRI_LIVESTOCK_MILK_ML`、`AGRI_LIVESTOCK_PENDING_EGGS`、`AGRI_FARM_AREA_CELLS`…）+ 一个 384 格占用位图字符串（`AgriFarmRules.AnimalMask`，`:141-150` 生成 `'0'/'1'` 串）。

### 2.3 可修复扩建的集成农场：**一台机器 + 一组自持容器 + 一套派生等级**

- 农场 = 单个 `MACHINE` 物品 `agri_integrated_farm`（`AgriFarmMachine.cs:107-166`），8×10 格（可配 4×5），带 `CONTAINER_TAG`/`AGRI_FARM_MACHINE`。
- 内部不是"一个区域"，是**一堆被 `item.Own()` 挂到机器下的容器**（`AgriFarm.cs:134-157` + `:4116-4164`）：`Intake` 16×8、`LegacyExport` 10×6（隐藏、`mayInventoryAddItemFunc=>false` 只出不进，`:140`）、`Manual` 槽、`Stock`/`Equipment`/`Water` 三个 `AgriFarmBag`（按件计数的伪 1×1 仓）、`Seeds[10]` 各 10×8、`Queues[24]` 各 10×2、`SeedEdit`、`StorySamples`。
- **"扩建"改的是两套计数器，不是空间**：
  1. 修终端：`REPAIR_<级>_<材料槽>` 四个计数器 vs `AgriFarmRules.TerminalCosts[5][4]`（`:53-60`），四槽全满才 `TERMINAL+1`（`AgriFarm.cs:2187-2222`），允许分次投入；
  2. 捐设备：`WATER_COUNT`/`POWER_COUNT`/`STORAGE_COUNT`/`ANIMAL_COUNT` 计数 → 查阈值表派生 `Level`（`AgriFarmRules.cs:25-51`、`:62-102`）。
- 状态存在哪：**机器的标签**。`Get/Set` 就是对 `AGRI_FARM_<KEY>` 这个 int 标签的读写（`AgriFarm.cs:4173-4184`），所以存档是白送的；`AgriFarm` 实例本身进 `ConditionalWeakTable<GameItem, AgriFarm>`（`AgriFarmMachine.cs:16`）不写盘，读档由 `onLoaded → Loaded() → Ensure()` 重建（`:4202-4233`）。
- 归属判定：`AgriFarmMachine.Owner(node)` 沿 `GraphNodeStorage.parents` 上溯找宿主（`:169-196`），所以任何塞进去的原版机器都能反查"我属于哪台农场"。
- 日结算：`onCycleEndLateSlotItemFunc → farm.Tick()`（`:3604-3677`），顺序 `WATER → PLOTS（按 PRIORITY_ 排序）→ ANIMALS → 回收`，`TICK_DAY` 把关"一天一次"。

### 2.5 九套职业制服：原版没有"穿"，就造一个"当日快照"

- 原版**没有衣服/装备槽**：`EquipmentHelper` 是机器供电与战斗效果（`EQUIPMENT_TAG`/`DRAW_CURRENT`…），不是可穿戴物。所以作者把"穿"拆成两件事：
  1. **制服 = 普通物品**：`HOUSEHOLD_GOOD` + `AGRI_UNIFORM` 标签 + 质量/材料成本/GUID 三标签（`AgriUniformItems.cs:55-89`），2×4 格，不能叠；
  2. **"穿" = 放进衣柜并点选**：衣柜 `agri_wardrobe` 是 10×8 容器（30 件上限，`AgriWardrobe.cs:47-95`），点选时写 `agri.uniform.selected`；
  3. **生效 = 次日起床快照**：`AgriUniformDayRules.Snapshot`（`:7-19`）把当天的 `day / daily（职业号 0..8）/ quality` 三键写进 ModData，**所有效果读取端只读 `daily`**（`AgriWardrobe.Profession` :20-37），白天换装不动当天数值——正好对上"次日起生效"的文案。
- 九套效果是 9 条字符串 + 系数表（`AgriUniformItems.cs:109-141`），每条效果落一个补丁文件（`AgriUniformTheft`/`ScavLoot`/`Energy`/`PlantYield`/`TradePrice`…），强度统一乘 `AgriWardrobe.Scale(profession)`。

### 2.6 和原版作物/水培的关系：**不建种植床，插三个缝**

- 种植区里放的就是**原版 `hydroponic` 机器**（判定写死 `identifier != "hydroponic"` 就放行，`AgriFarmAssociatedPlotPatch.cs:21`）。
- 三个接缝，缺一不可：
  1. `HydroponicHelper.GetAssociatedHydroponic` **Prefix**：原版是拿种子上的 `ASSOCIATED_HYDROPONIC_ID` 走 `EmporiumEntry.FindItemByUniqueID` 全局查那台机器；农场里的水培机挂在容器图里、不在世界图里，这条查找不一定命中，于是补丁直接返回 `parentInventory.GetParentItem()`（推测：这正是它存在的理由）；
  2. `PlantHarvest.Deliver` **Prefix**（原版私有方法）：把产物拦进 `farm.Harvest` 列表，**不落机器输出格**（`AgriFarmHarvestPatch.cs:8-17`）；
  3. 生长仍调 `HydroponicHelper.ContinueGrowing(seed, speed, plot)`（`AgriFarm.cs:3513`），只是"今天给不给这一区跑"由农场算完水/电/液配比再决定（`:3441-3497`）。
- 所以它跟原版 `Plant`/`Grow` 不打架：**原版照跑，农场只当资源闸门 + 收获取向器**。代价是要自己防重入（`AgriFarmPatches.NativeDepth`）和快照回滚（见三.2）。

## 三、关键代码摘录

**1) 一只牲畜怎么造出来：原版物种 + 原版标签（`AgriLivestockItems.cs:111-150`）**

```csharp
internal static GameItem CreateAnimal(string id, bool female, int age)
{
    LivestockDefinition d = AgriLivestockRules.Find(id);
    if (d == null) { throw new ArgumentException("Unknown livestock", "id"); }
    if (!Species.ContainsKey(id)) { RegisterSpecies(d); }
    GameItem item = ItemDirectory.CreateEmptyItem(id);
    item.EnableTag("ANIMAL_ITEM_TAG", false);
    foreach (KeyValuePair<string, float> stat in Species[id].baseStats)
    {
        item.ModifyTag(stat.Key, t => { t.Enable().SetFloat(stat.Value); }, false);
    }
    item.ModifyTag("ANIMAL_SPECIES_TAG", t => { t.Enable().SetString(id); }, false);
    item.ModifyTag("ANIMAL_HEALTH_TAG",  t => { t.Enable().SetFloat(100f); }, false);
    item.ModifyTag("ANIMAL_CURRENT_FERTILITY_TAG", t => { t.Enable().SetFloat(40f); }, false);
    IngesterHelper.InitIngester(item);              // 原版：吃/饿
    MachineAutoButcher.InitDropOnButcher(item);     // 原版：屠宰掉落
    item.mayStackItemFunc = (a, b) => false;        // 活体不可叠
    item.onLoaded += RefreshAnimal;                 // 读档自愈名字/贴图/体重
    InitializeAnimal(item, female ? "FEMALE" : "MALE", age);
    BindMilk(item);
    return item;
}
```

为什么这么写：把"活体"降格成物品 + 原版标签，等于把 `HusbandryHelper` / `GeneticHelper` / `MachineAutoButcher` 三大系统一次性继承下来；`onLoaded` 挂 `RefreshAnimal` 是**读档自愈**，因为贴图/名字是按体重年龄算出来的，不进存档。（原文用 `Delegate.Combine` 拼 `onLoaded`，这里写成 `+=`。）

**2) 农场单区一轮：克隆 + 快照 + 收获取向 + 失败回滚（`AgriFarm.cs:3501-3590`，摘录压缩了日志与 IL 噪声）**

为什么这么写：它要在**别人的机器**上跑一轮会改状态的逻辑，所以先拍两张标签快照 + 克隆种子，失败就整段撤销（`"保护待机"` 而不是"扣了材料什么也没给"）。这是整套模组最值钱的一段工程习惯。

```csharp
    {
        int n = Int(item, l.currentPart);            // 原版液体就是"每个液体一个 CURRENT_PART_* 标签"
        if (n > 0) { kind = (kind == null) ? l.identifier : "agri_wine_tainted"; volume += n; }
    }
    return ReadMetadata(item, kind, volume);         // 质量/年份/进度/回头客另存四个标签
}

internal static void Write(GameItem item, AgriWineBatch batch, bool replaceAllLiquids = false)
{
    AgriSuperEffects.DetachState(item);
    foreach (Liquid l in Liquid.Liquids)
        if (replaceAllLiquids || l.identifier.StartsWith("agri_wine_", StringComparison.Ordinal))
            Set(item, l.currentPart, (l.identifier == batch.Kind) ? batch.Volume : 0);
    Metadata(item, batch);
    item.Validate();
}
```

为什么这么写：注册成 `Liquid` 之后，原版所有液体容器、倾倒、`WaterHelper` 体积统计、瓶/桶 UI 全部免费复用；代价是"哪种酒"只能从 `kind` 反推，混了就退化成 `tainted`（正好也是玩法）。

## 四、踩坑与红线

### 4.1 存档迁移（**重点，我们以后改名/加版本一定会用**）

作者五套手法，都是"读档时一次性、幂等、可重复跑"：

| # | 场景 | 手法 | 代码 |
| --- | --- | --- | --- |
| ① | 物品 id 变了 / 老存档里 id 是空的 | **Patch `SaveManager.DecodeNodes` 的 Prefix**，在反序列化前改 `SaveItemNode`：`identifier = spritePath`，补 `IS_OWNED_TAG`、补 `uniqueId` | `AgriLegacyHarvestRecoveryPatch.cs:6-33` + 判定 `AgriHarvestIdentity.IsLegacyHarvest`（`id` 空且 `atlas=="agri_expansion"` 且 sprite 能查到规格） |
| ② | 主键从 `id` 升级成 `id+sprite` | 新版键 `FEED_CHOICE_<id>\|<spritePath>`，老键 `FEED_DENY_<id>` 逐条翻译，最后写 `FEED_POLICY_VERSION=2` 关闸 | `AgriFarmFeedPolicy.cs:9-48` |
| ③ | 全体物品要补一个新基因/新属性 | 全局迁移键 `agri_expansion.native_genes.1.1`，`FindAllItem(true)` 扫一遍，只补"正 trait 为 0 且反 trait 也为 0"的，最后写 `"1"` | `AgriNativeGenes.cs:7-41` |
| ④ | 容器结构变了（老的独立出货栏 → 共用栏） | 保留旧容器 `LegacyExport`（隐藏、只出不进），每秒 `MergeLegacyExport()` 往新栏搬，搬空即静默 | `AgriFarm.cs:4855-4894`、`AgriFarmMachine.cs:91-94/140/150` |
| ⑤ | 同一份数据从"机器标签"迁到"容器里的液体" | 加权威标记 `AGRI_WINE_TANK_AUTHORITATIVE`：老批次搬到桶里 → 清掉机器上的旧值 → 打标记，之后不再迁 | `AgriWineTerminal.cs:375-397` |

②③ 的写法几乎一样，抄的时候照这个骨架：

```csharp
// AgriFarmFeedPolicy.cs:33-48
internal static void Migrate(IEnumerable<GameItem> existing, Func<string,int> get, Action<string,int> set)
{
    if (get("FEED_POLICY_VERSION") >= 2) return;          // 版本闸门，先判后干
    foreach (GameItem item in existing.Where(i => i != null && i.IsTag("FOOD")))
    {
        string key = Key(item);                            // 新主键
        if (get(key) == 0) set(key, (get("FEED_DENY_" + item.identifier) == 0) ? 1 : -1);  // 老键 → 新键
    }
    set("FEED_POLICY_VERSION", 2);                         // 无论扫到几件，都要落版本
}
```

**红线（血泪顺序）**：
1. **迁移必须挂在"解码之后/读档完成之后"**，且在 `SaveManager.IsDecoding == true` 时**不许写**——`AgriFarmFootprint.Apply`（`AgriFarmFootprint.cs:65`）、`AgriFarm.Ensure`（`:4211`）、`MergeLegacyExport`（`:4857`）、旧过滤器回收 `ReturnLegacyFishFilters`（`:2930`）全都在入口判 `IsDecoding`。解码期间改状态会让写回去的存档错位（README 2.0.12 修的"鼠笼喂食器与屠宰机存档错位"就是这类）。
2. **改 `identifier` 只能在 `DecodeNodes` 之前**：等物品已经按老 id 造出来再改，图/形状/`AnimalSpecies` 已经绑错了。
3. **迁移键要带版本号且写到"最后一句"**：中途 `return` 会导致下次重跑（③ 里若中途抛异常，键没写，下次还会补——这是可以接受的；反过来把键写早了就永久漏迁）。
4. **凡是"能推导出来的"就别存**：体重/贴图/名字按年龄推、格数按形状推（`AnimalArea :2244-2264`）、等级按计数推——存了就要迁，推的不用迁。
5. **改名只改显示名**：这个模组把 `Name` 从"农业扩展"改成"可能是牧场物语"，但 `<ID>agri_expansion</ID>`、`AssemblyName`、命名空间、所有 `agri_*` 物品 id、`AGRI_*` 标签、`agri_expansion.*` ModData 键全部沿用 → 存档零迁移。**要改 id 的话，得同时准备 ①（物品 id）+ ②（键名）+ 一个 `NetworkUpgrade.RemoveModUpgrades(旧source)`**（它 `OnDisable` 里已经这么清了，`ModEntry.cs:170-171`）。

### 4.2 其他红线

- **`TagSystem.Clone()` 是浅克隆**：`AgriSuperEffects.Snapshot` 必须逐个 `TagElement.Clone()`（`AgriSuperEffects.cs:46-60`），否则"快照"会跟着后续 `ModifyTag` 一起变，回滚等于没回滚。
- **机器塞进容器后，原版很多"按唯一 id 全局查"的路径会断**：`HydroponicHelper.GetAssociatedHydroponic` 走 `EmporiumEntry.FindItemByUniqueID`，农场只能 Prefix 改成"返回父亲"（`AgriFarmAssociatedPlotPatch.cs:5-27`）。同理要给塞进容器的原版机器补 `CageRestore`/`RasRestore`/`CycleGetter` 这类复位补丁，否则读档后周期钩子不跑。
- **在容器里塞原版机器，就得接回原版那一堆系统**：光为这台农场就写了 **37 个 `AgriFarm*Patch*.cs`**，分四摊——① 复用原版机器（`AssociatedPlot`/`Harvest`/`PurificationCap`/`RasRestore`/`CageRestore`/`CageContainment`）；② 反作弊与风控（`TheftGuard`/`BurglaryEligibility`/`BurglaryScope`/`InsuranceValue`/`InsuranceScope`/`ContrabandList`/`Flaggable`/`InspectItem`/`BodyDrop`）；③ 停机的语义（`FishAir`/`FishGrowth`/`FishHost`/`FishWeight`、`PausedBreeding`/`PausedLiveStock`/`PausedPrey`/`PausedWaste`）；④ 鼠与屠宰、电力、动画、开局（`ButcherOutput`/`Rat*`/`WorldPower`/`AnimationRender`/`StartReserve`/`ScenarioMenu`）。**少接一个就是一个漏洞**（能被偷、被保险赔、被盘查误判）。
- **`onOneSecondItemFunc` 里别干重活**：农场每秒只做 `Footprint.Apply + MergeLegacyExport`（`AgriFarmMachine.cs:147-151`），真正的日结算在 `onCycleEndLateSlotItemFunc`。逐帧补丁（`GameItemElement.ApplyAnimationFrame`）第一句必须按 `identifier` 早退（`AgriFarmAnimationRenderPatch.cs:17-20`）。
- **自定义 Inventory 要一整套 override**：`AgriFarmBag : GameGridInventory` 只挂 1×1 的壳，但必须同时覆写 `childItems`/`children`/`UncheckedAccept`/`Expel`/`MayHaveValidInventorySlot`（`AgriFarmBag.cs:8-57`），否则原版 `GraphUtils` 判断落点时按 1×1 算，直接塞不进去。
- **运行时改物品形状要先问场地**：`AgriFarmFootprint.Apply` 缩/放之前先 `parentInventory.CheckShapePlacement`，放不下就保持紧凑并给提示（`:62-88`）——否则 8×10 的主机一放大就顶到别人的货架。
- **网络升级/开局剧本用完要能撤**：`OnDisable` 里 `NetworkUpgrade.RemoveModUpgrades("agri_expansion")` + `StartingScenario.RemoveMod("agri_expansion")` + `AgriUniformModuleBreak.Restore()` + `AgriUniformInspectionBribe.Reset()`（`ModEntry.cs:164-173`）。开局剧本是**克隆原版 `hydroponic_farmer`** 再改 id/source/title/onStart（`AgriFarmAccess.cs:51-99`），不是从零造。
- **补丁粒度是"一个靶点一个文件"**：116 个文件 2,502 行，好处是靶点表一眼能列（报告直接抽出来了），坏处是**同一方法被两个补丁打**时没看到 `HarmonyPriority`（如 `PlantHarvest.Deliver` 两处），我们抄结构别抄这个。

## 五、对我们的可用点

1. **`NetworkUpgrade.RegisterModUpgrade` + 幂等 `Grant()`**（`AgriWineAccess.cs:29-84`）→《深空电玩》的"新解锁档位发货"（付费情报、整备套件、银狼周货）和《群友》的"首见发名片/电话"都可以照这个三段式：**先查 ModData 键 → 再查物品上的奖励标签 → 放得下才记账**。放不下就别记，下次还会补发，绝不会重复发。
2. **"当日快照"式身份系统**（`AgriUniformDayRules.Snapshot`）→《深空当铺：可能是群友》要做"今天带着谁的名片/工牌上班"、《深空电玩》要做"今天以审片员/维修工身份营业"，都可以用"容器里选一件 + 次日三键快照 + 效果端只读快照"，避开"原版没有装备槽"这个坑；换装不追溯，正好符合我们"当日账当日结"的调性。
3. **一台总机 + 原版机器当分区 + `Owner()` 上溯**（`AgriFarmMachine.Owner`）→《深空电玩》可以把"整备间/母盘车间"做成一台总机，把原版工作台/刻录机塞进它的容器当分区；定位宿主不用自己维护注册表，沿 `GraphNodeStorage.parents` 走就行。
4. **事务化跑别人的机器**（三.2：快照 + 克隆 + 取向量 + `finally` 回滚）→《深空电玩》的刻录机、"概率维修"、"翻新整备"这类"扣材料→可能失败"的流程，直接用这个骨架，避免"材料扣了、盘没出来"的半成品。
5. **把自定义液体注册进 `Liquid`**（`AgriChemistry.cs:22-36`、`AgriMilkingMachine.cs:181-195`）→《群友》塞壬验水可以加自己的"污染水/纯净水"档位、《深空电玩》的化学/饮品也能白拿原版容器与混合规则；配套只需一个 `Read/Write` 对（三.3）。
6. **`AgriText` 那条"读档时翻译"补丁**（`AgriSavedItemTextPatch` + `AgriText.SavedText`）→ 我们两个模组都有"名字写进存档"的物品（名片、光盘、套装），换语言后同样会留旧语言；这条补丁是现成解法，成本 1 个文件 20 行。
