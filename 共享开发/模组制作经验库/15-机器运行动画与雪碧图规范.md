# 15 机器运行动画与雪碧图规范

**什么时候读它**：要给自定义机器（或原版机器外观扩展）做运行帧动画、设计动画雪碧图排布、或者排查「装电池动画不响 / 拔电池动画不停 / 存档污染贴图」时。

**来源**：反编译蒸馏工坊标杆模组 **原版机器运行动画 | Vanilla Machine Animations**（`sfi.vanillamachineanimations`，工坊 `3839773708`，v1.0.8，zero-cap 零能力），并结合原版 `GameItemElement` / `SpriteAnimationHelper` / `MachineHelper` 源码与《深空电玩》实机踩坑验证。

## 一、美术使用与雪碧图制作规范

### 1. 为什么用单张 8 列雪碧图，不用散装单帧图

- **规范命名与目录**：放到 `Textures/Items/<asset>__frames.png`（例如 `arc_burner_running__frames.png`）。
- **网格排布规则**：
  - 固定 **8 列横向排布**（`Columns = 8`），从**左上角**第 0 帧开始按行从左到右排列；
  - 整张图尺寸必须严格满足：`width = frameWidth * 8`，`height = frameHeight * ceil(frameCount / 8)`；
  - 所有帧必须等尺寸且与静态图标 `vanilla.rect`（通常为 16 的倍数）完全一致；
  - 保留未预乘 RGBA 透明背景，禁用双线性缩放，放入 `Textures/Items/` 后 `ModLoader` 会自动设置 `FilterMode.Point` 与 `TextureWrapMode.Clamp`。
- **与原版像素坐标对齐**：
  Unity `Sprite.Create` 的 `Rect` 原点在**左下角**，而图片排布从左上角起算，所以第 `i` 帧的切图矩形为：
  ```csharp
  int col = i % 8;
  int row = i / 8;
  int x = col * frameWidth;
  int y = sheet.height - (row + 1) * frameHeight;
  ```
- **对齐静态原图锚点与 PPU**：
  切图时直接从当前机器静态 `Sprite vanilla` 读取归一化中心与 `pixelsPerUnit`：
  ```csharp
  Vector2 pivot = new Vector2(vanilla.pivot.x / frameWidth, vanilla.pivot.y / frameHeight);
  Sprite.Create(sheet, new Rect(x, y, frameWidth, frameHeight), pivot, vanilla.pixelsPerUnit, 0u, SpriteMeshType.FullRect);
  ```
- **打包工具**：使用 `工具库\img\pack-spritesheet.py` 一键把散帧拼成标准 8 列雪碧图并做网格尺寸核验。

### 2. 非均匀帧延迟与低帧率模式

- `AnimationData` 用 `int[] Delays`（单位毫秒）控制每帧时长，支持在关键停顿帧拉长耗时（如 `80ms` 常规帧 + `240ms/400ms` 停顿帧），比固定步长累加更真实；
- 构造前缀和数组 `frameEnds[]`，每帧通过 `(Time.unscaledTimeAsDouble * 1000 - startedMs) % totalDuration` + `Array.BinarySearch` O(log N) 定位当前帧，**帧率波动不漂移**。

### 3. 高级外观技巧（VMA 实装手段）

- **旋转变体（如水培仓/RAS）**：通过读取 `item.modifiedShape.orientation`（实体）和 `item.fakeRotator.rectTransform` 的 `localEulerAngles.z` / `localScale.x < 0`（拖拽虚影），在 `_rotation_cw` / `_rotation_ccw` 两套雪碧图间无缝切换；
- **多层叠加机器（如充电器 / 酒架 / 水培仓）**：Patch `GameItemElement.HandleInnateModSprite` 拿到 `innateSpriteMods` 与 `fakeInnateSpriteMods`，只替换顶盖/指示灯对应子层 `Image`，或动画期间将其 `canvasRenderer.SetAlpha(0f)` 暂时隐去、停止时再恢复原 alpha；
- **懒切片与显式释放**：动画帧只在首次播放时才调用 `Sprite.Create` 并记入 `OwnedFrames`，在 `OnDisable` / `HotReloadPrepare` / 场景卸载时调用 `UnityEngine.Object.Destroy` 显式释放，防显存泄漏。

## 二、代码实现规范（为什么绝对不要调 `SetSpriteQuick`）

### 1. 严禁修改 `GameItem.spritePath`

- **错误写法**：在 `Update` 里调用 `machine.SetSpriteAndShapeFromMod` 或 `machine.SetSpriteQuick` 换帧。这会直接改写物品模型的 `spritePath`，**一旦玩家在运行期间存档，工作帧文件名就会被永久写进存档**；且每次换帧都会触发模型状态变更。
- **正确写法（UI 层零污染替换）**：
  1. `[HarmonyPatch(typeof(GameItemElement), "ValidateSelectLocked", new Type[] { typeof(bool) })]` Postfix 自动追踪所有已创建的 `GameItemElement`（记录进 `Dictionary<GameItemElement, ViewState>`），不每帧 `FindAllItem()` 全店扫描；
  2. 只替换 Unity UI 组件 `item.background.image.sprite`（实体显示）和 `item.fakeBackground.image.sprite`（拖拽半透明虚影），**全程不碰 `item.spritePath`**；
  3. 播放前保存 `originalSprite` 与 `originalHitThreshold`，播放期间将 `image.alphaHitTestMinimumThreshold = 0f`（防止不同帧透明区变化导致鼠标悬停 tooltip 闪烁），停止或销毁时精准还原；
  4. **防第三方覆写守卫（`HasForeignSprite`）**：若发现 `image.sprite` 既不是 `Vanilla` / `PreviousVanilla` 也不在 `OwnedFrames` 中，说明已被美化包或其他模组接管外观，立即停止覆盖并让位。

### 2. 对比原版内置 `SpriteAnimationHelper`

原版 0.46D 自带了 `SpriteAnimationHelper`（在 `ValidateSelectLocked` 末尾调用 `SyncSpriteAnimation`）：
- **局限**：① 只能用散装逐帧 key，不支持雪碧图；② 只能等间隔 `frameMs`；③ 动画状态保存在 `TagSystem`（`SPRITE_ANIMATION_TAG` 等 5 个标签会写进存档），且动态启停需要频繁改 tag 触发 `Validate()` 重绘整棵 UI 节点树。
- **结论**：一次性纯装饰小件可用原版 `SpriteAnimationHelper`；凡涉及**受供电/工作状态控制、雪碧图、非均匀帧率或防存档污染的机器**，统一采用 VMA 架构（已沉淀为模板 `工具库/templates/mod-patterns/SpriteSheetMachineAnim.cs`）。

## 三、机器状态与供电判定的核心坑（实战踩过）

1. **为什么「拔电池后动画还在动」**：
   原版进度型机器的 `MACHINE_STATE_TAG` 只有在过夜结算（`onCycleEndSlotItemFunc`）时才会检查并改回 `STATE_READY`，**玩家在白天拔走电池时，`GetMachineState(item)` 依然返回 `"STATE_WORKING"`**！
   因此动画判定绝不能只看 `"STATE_WORKING"`，**必须同时检查 `MachineHelper.CanPower(item)`**（内部验证 `MachineHelper.GetBatterySlot(item)?.childItem != null` 且 `PowerHelper.CanDrawPowerSource(battery, powerUsage)`）。
2. **为什么「装电池后动画不生效」**：
   原版进度型机器（`printer`、`arc_burner` 等）在白天刚摆好放进电池时，`StartProgressTypeMachine` 要到过夜睡觉才触发，白天 `MACHINE_STATE_TAG` 一直是 `"STATE_READY"`。
   应参照机器交互直觉与 VMA 自动规则：在**无故障（`!BROKEN_MACHINE_TAG` 且无模组故障 tag）且供电充足（`MachineHelper.CanPower(item)`）**时驱动运行动画；同时在电池槽/物料槽的 `onSlotAddItemFunc` / `onSlotRemoveItemFunc` 中主动将对应机器 `ViewState.NextStateCheckMs` 置 `0`，实现 0ms 即时启停，其余时刻保持 150ms 轮询节流兜底。
3. **热重载兼容**：
   `HotReloadActivate()` 时场上已存在的 `GameItemElement` 不会重新走 `ValidateSelectLocked`，因此 `HotReloadActivate` / `OnGameLoadedNormal` 中应清理旧 `Sprite[]` 与 `Views`，并对 `PlayerStore.FindAllItem()` 补调一次 `Track()`。
