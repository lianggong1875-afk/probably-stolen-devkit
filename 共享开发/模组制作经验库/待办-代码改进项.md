## P0-1 `ArcShowcase.GetDisplayCaseType` 的 Prefix 抢得太狠

- **证据**：`3830874694` Proper Signboards（21 万订阅）用 19 个 Transpiler 把 `ShowcaseHelper` 里读 `childItems` 的点换成 `DisplayItems`/`PhysicalItems`，其中就包括 `GetDisplayCaseType`（见 `07` 「与 Proper Signboards 的三条真实冲突面」、`workshop-distill/超小功能三例之二…md` §3）
- **我们的现状**：`深空电玩/src/ArcShowcase.cs:259` `ArcShowcaseGetTypesPatch` 是 **Prefix 直接替换 `__result` 并 `return false`** → 整段跳过（已被别人 Transpiler 改写的）方法体
- **后果**：两个模组同装时，**它的展柜类型改写对我们这条路径完全失效**；玩家看到的是"装了招牌模组但招牌不计客流"
- **改法**：降级为 **Postfix 追加** —— 让原版（含它的改写）先跑完，我们只把自己灯牌对应的类型补进 `__result`（去重）
- **风险**：`ComposeTypes` 目前的语义是"用我们的物品列表重建类型列表"，改成追加后要重新确认"没有多余类型""不会重复"
- **验证**：`Build-Mod.ps1` + `Run-Regression.ps1` + 真机 Slot 1 装两个模组看展柜预测

## P1-4 银狼整包货上柜台时，柜台全满会**真的销毁物品**

- **证据**：`3833537477`（357 行，9.1 万订阅）+ 我对照 `reference/Assembly-CSharp/PlayerStore.cs:2525-2560` 逐个核过
- **我们的现状**：`深空电玩/src/ArcDelivery.cs:121-153`
  ```csharp
  GameItem item = DirectoryMaster.Item(id, false);
  GeneralHelper.SetItemOwned(item, false);
  bool placed = store.TryAddDirectSellingItemToTable(item, false);   // ← 传实例的重载
  if (!placed) { ArcLog.Warn("... skipped (counter full): " + id); skippedCount++; continue; }
  ```
- **为什么这是 bug**：传 `GameItem` 实例的重载内部走 `GraphUtils.TryAcceptAllOrDestroy` → **一格都没塞进去就 `DestroyIfUnplaced`**。所以 `:144` 的 `if (!placed)` 只能记一条日志，**物品已经没了**，玩家看到的是"银狼说给我带了货，货不见了"
- **改法**：改用 **identifier 重载** `store.TryAddDirectSellingItemToTable(id, isOwend: false)` —— 它有 `frontInvinvElement.CanTakeAnything()` 前置检查，满了直接 `return false` 且**根本不创建物品实例**；`isOwend` 参数等价于我们手动 `SetItemOwned(item, false)`
- **已核**：`ArcClients.cs:549` 用的是 identifier 重载（`AddDirectSellingItemToTable(identifier, isOwend: false)`），**安全，不用改**
- **风险**：低（等价替换，语义更安全）
- **验证**：回归 + 真机把前台柜台塞满再触发银狼送货，看货是否"留在原位而不是消失"

## P3-3 存档剥离是"手写列模块"，加第四个模块会漏

- **证据**：`3832941698` AI Emporium（`workshop-distill/3832941698-AIEmporium.md`）用 `PlayerStore.WriteSlotFile` 的 Prefix + **Finalizer** 做剥离；它的做法是"机制级"，不靠人记得调用
- **我们的现状**：`深空当铺：可能是群友/src/FreyaLocalization.cs:170-181`
  ```csharp
  Prefix()   { FreyaNightly.DetachForSave(); FreyaPhone.DetachForSave(); DspVisitorPhones.DetachForSave(); }
  Finalizer(){ FreyaNightly.RestoreAfterSave(); FreyaPhone.RestoreAfterSave(); DspVisitorPhones.RestoreAfterSave(); }
  ```
  **手动列三个模块**，加第四个时必须记得改两处，漏一处就污染存档。
- **已核实（重要）**：`WriteSlotFile` 是 `SaveGame` **内部**调用的私有方法（`PlayerStore.cs:917/930`），**不是并列入口** —— 所以我们挂 `SaveGame` 已经覆盖它，**这不是漏洞**。`SaveFiles.IndexSave` 只写 `totalPlayTimeSeconds` 与预览数据，不含实体，也安全。
- **改法**：把"要剥离的模块"收敛成一个列表（`IDspSaveParticipant[] { Detach, Restore }`），Prefix/Finalizer 遍历它。加模块只改一处列表。
- **风险**：低（纯重构，行为不变）
- **验证**：回归 + 真机存读档一次，核对三个模块的状态都恢复

## P2-6 第 ④ 道"真机验证"门禁可以自动化（验收台）

- **证据**：`3830995342` 深空罗德岛（`workshop-distill/3830995342-RhodesPharma.md`）—— 它 19,476 行里有 **6,964 行（35.8%）是自检/验收代码**，`ReleaseGate.cs:274` 是主体
- **现状**：我们第 ④ 道门禁"真机 Slot 1 验证"全靠人肉点，漏了就漏了
- **它的做法**：`SaveFiles.DuplicateSlot` 复制当前档 → **硬钉槽 36**（`:660` 有断言）→ 切 `NewGameData` 重载场景 → 逐条断言 → 落 `release-gate.json`；`manualChecks` 单列 3 条人眼项，`automatedPassed` / `releaseApproved` 双签名
- **改法**：照它做一层"验收台"，但**槽位必须 ≥ 30**（我们的铁律是不碰 Slot 0，也不该碰玩家常用的 1）
- **风险**：中高 —— 涉及复制存档与切档，任何一处判错都可能碰到玩家真实存档。**先在 Slot 36 上做，且断言"当前槽 != 0 && != 1"**
- **验证**：在 Slot 36 上跑一次完整断言，确认它不写 Slot 0/1，且失败时不会污染源档

## P2-7 软依赖探测没过滤 `LoadError`，会把"加载失败"当成"在跑"

- **证据**：`3832805089` 的 `FindEnabledAssembly`（`Core.cs:100-110`）显式过滤三件事：`IsEnabled && LoadError == null && Assembly != null`
- **我们的现状**：`深空电玩/src/ArcAppraisalPane.cs:85`
  ```csharp
  if (m == null || !m.IsEnabled) continue;   // ← 只判了 IsEnabled
  ```
- **后果**：Appraisal Assistant 被启用但**加载失败**（`LoadedMod.LoadError` 非空）时，我们仍判"它在跑"，于是启用依赖它的鉴定面板 → 空引用。原版 `LoadedMod.cs:23` 就是 `public string LoadError;`
- **改法**：判定条件补成 `m.IsEnabled && string.IsNullOrEmpty(m.LoadError)`；同一个判定要覆盖后面三处（id / title / Assembly 简名）
- **风险**：低（一个条件）
- **验证**：故意放一个坏的依赖 DLL 让加载失败，看我们是否禁用自身而不是启用面板
