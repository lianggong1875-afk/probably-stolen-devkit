# AI_GUIDE.md —— 给 AI 助手的阅读协议

> 如果你是一个被要求「给《深空当铺 / Probably Stolen》写模组」的 AI 助手，先读完本页（约 3 分钟），再按任务取用 `docs/`。不要从第一页通读到最后一页：这套文档是为**检索**设计的。

---

## 0. 这个目录是什么

一位模组作者把自己多个已发布模组的实战经验整理成了文档，随一个「空壳模组」发到创意工坊，专门给后来者和他们使用的 AI 阅读。

- 这里**没有**可运行的模组逻辑。`ModdingKnowledge.dll` 不注册任何东西。
- 所有知识都在 `.md` 里。你可以把这些文件当作**项目交接文档**使用。
- 文档里的路径、版本号、ID 都是示例或占位，**不要照抄到用户机器上**。

---

## 1. 你首先要知道的四件事

1. **游戏没有源代码**，只有 `Assembly-CSharp.dll`。查行为要反编译（见 `docs/01`）。**反编译要用当前 DLL 重新跑**，别信旧快照。
2. **官方有 40+ 个模组钩子**。在写 Harmony 补丁之前，先去 `docs/03` 确认官方没提供入口。补丁是最后手段。
3. **存档结构不是 API**。任何「给存档加字段」的想法都要先读完 `docs/04` 第 23、24 条和 `docs/05` 第 6 节。
4. **有一类功能是官方明令禁止的：「信任层」动作**（批准 / 启用 / 停用 / 排序 / 开发者模式 / 取消订阅 / 写信任记录）。需求里出现「一键启用」「一键信任」「批量审阅」之类，**先停下告诉用户官方禁止**，不要实现 —— 调用了会被扫描器 `loader-target` 直接拒绝，运行时还有 `RequireNoMod()` 扫调用栈抛异常。清单见 `docs/10-官方红线清单.md`。

## 3. 检索约定

- **文件命名就是分类**：`01`~`11` 对应「环境 / 结构 / API / 坑 / 配方 / 发布 / 安全 / 调试 / 协作 / 红线 / 性能」。
- **小节编号稳定**：`docs/04` 的条目号（第 1~52 条）在引用时请写「坑 #N」，方便作者对照。
- **代码块语言标记**：`csharp` 可直接用；`powershell` 是 Windows 命令；`text` 是日志或目录结构。
- 文档中 `$GAME` 表示游戏安装目录，`$WS` 表示作者的工作区，`<...>` 表示需要替换的占位符。**不要把 `$GAME`、`$WS` 原样写进代码或命令行。**

---

## 4. 证据等级：你输出结论时必须带

文档里的结论带三种标记：

- `[实测]`：作者在游戏里跑过。
- `[静态]`：从反编译代码或官方文档读出。
- `[待验]`：推断，未验证。

**你回复用户时也要这样标。** 例如：

> 把模组面板追加到末尾是安全的（`[静态]`，官方文档写明新面板只追加），但旧档里的物品会不会错位我没实测过（`[待验]`），建议先备份存档再试。

不要把自己的猜测写成 `[实测]`。不要把「反编译里看到了」说成「游戏里就是这样」。

---

## 5. 输出与改动规范

1. **一次只改一件事**，改完能编译、能加载、能验证，再改下一件。
2. **不要往模组文件夹里写临时文件**（`.bak`、`.orig`、`.zip`、`.ps1`、源码）。扫描器会把未列出的可执行文件判成 payload，导致整个模组不加载。临时文件放工作区或系统临时目录。
3. **不要用文本管道改中文文件**（尤其是 Windows PowerShell 的 `>` / `-replace`）。用能显式指定 UTF-8 的写入方式，否则中文会变乱码。
4. **不要给 `DirectoryMaster.Item` 打 Harmony 补丁**（两个重载会让补丁解析抛 `AmbiguousMatchException`，整个模组 Init 失败）。
5. **不要在模组里调用** `Process.Start`、`System.Diagnostics.Process`、Steamworks API、网络请求、原生库。这些会被扫描器判为高危能力，需要 manifest 声明且会触发玩家信任提示；本项目的做法是**一个都不声明**。
6. **改完写回笔记**：如果你在项目里工作，把新结论追加到项目自己的 `DEV_NOTES.md`，标明证据等级和日期。这是本套文档存在的原因。

## 6. 代码片段的用法

`docs/05-代码配方.md` 里的片段是**从真实模组里摘出来的**，但做了删减：

- 去掉了项目私有的命名空间、日志前缀、辅助函数。
- 保留了对坑的注释（`// 坑：...`），这些注释比代码本身值钱。
- 片段默认你可以直接放进 `IMod` 实现里；类名、命名空间自己改。
- 片段引用的游戏类型（`GameItem`、`MachineHelper`、`RichTextElement`……）都在 `Assembly-CSharp.dll` 里，编译时引用它即可。

---

## 7. 文档自身的信息

- 版本：见 `CHANGELOG.md` 与 `manifest.xml` 的 `<ModVersion>`。
- 完整性：`modding_notes.sha256` 列出了每个文档的 SHA-256。如果某文件哈希对不上，说明它被改动过，请以改动后的内容为准，但要在结论里注明「文档非原始版本」。
- 反馈：在创意工坊页面留言。作者会按「可复现 + 有日志」的标准吸收修正。

---

## 8. 一句话总结

**先查官方入口，再动补丁；先保存档兼容，再谈功能；先实机验证，再写结论。**
