# 01 · 环境与工具链

> 目标：拿到一份能编译、能加载、能调试模组的最小环境。
> 证据等级：本节命令与路径为 `[实测]`（在 Unity 2021.3.45f2 版本上跑通），具体版本号游戏更新后请自己核对。

---

## 1. 运行时

| 项 | 值 |
|---|---|
| 游戏 | Probably Stolen / 深空当铺（Steam AppID **4348910**） |
| Unity | **2021.3.45f2** |
| 脚本后端 | **Mono**（不是 IL2CPP） |
| API 兼容级别 | **.NET 4.x** |
| 游戏托管 DLL | `$GAME/Probably Stolen_Data/Managed/` |
| 已装模组 | `$GAME/Mods/<模组名>/` |
| 存档 | `%USERPROFILE%/AppData/LocalLow/<发行商>/<游戏名>/` 下的 `save_*.es3`（Easy Save 3，**明文 JSON**） |
| 日志 | 同上目录的 `Player.log` |

> `$GAME` 是游戏安装目录的占位符。先从 Steam 库属性里找到「浏览本地文件」。

因为脚本后端是 Mono，所以：
- 模组 DLL 是普通 .NET 程序集，用 Roslyn `csc` 就能编；
- 加载时 DLL 会被**内存映射**：游戏运行时覆盖同名 DLL 会报 `user-mapped section open`（见坑 #7）。

## 2. 反编译：没有源码时唯一的事实来源

游戏逻辑全在 `$GAME/Probably Stolen_Data/Managed/Assembly-CSharp.dll`。用 ILSpy 的命令行版一次性导出：

```powershell
# ilspycmd 需要 .NET 6+ 运行时；用 portable 版放哪都行
ilspycmd -p -o "<输出目录>\Assembly-CSharp" "<$GAME>\Probably Stolen_Data\Managed\Assembly-CSharp.dll"
```

产出是可搜索的 C# 源码。**推荐用法**：

- 不要通读。用编辑器/ripgrep 搜类名或方法名，比如 `rg "class MachineHelper" -g "*.cs"`。
- 先读类声明和 `public` 方法签名，再读调用点。
- 反编译结果里的局部变量名被编译器抹成 `num`、`flag`、`text`，不要依赖它们理解语义。
- 泛型/重载方法（如 `DirectoryMaster.Item`）在反编译里看着正常，但 Harmony 补丁会因重载歧义失败——见坑 #1。

## 3. 编译：csc 命令模板

不需要 Visual Studio。用 Roslyn 的 `csc.exe`（任何 .NET SDK 都带，或单独的 Roslyn 包）即可。

### 3.1 引用清单

最少要引：

```
mscorlib.dll
System.dll
System.Core.dll
System.Xml.dll
System.Xml.Linq.dll
netstandard.dll
Newtonsoft.Json.dll
UnityEngine.CoreModule.dll
Assembly-CSharp.dll
Assembly-CSharp-firstpass.dll
0Harmony.dll
```

按需追加：

| 你要用的东西 | 追加引用 |
|---|---|
| `TextAnchor` / `TextMeshProUGUI` / `Canvas` / UI | `UnityEngine.TextRenderingModule.dll`、`UnityEngine.UIModule.dll`、`UnityEngine.UI.dll`、`Unity.TextMeshPro.dll` |
| `AudioSource` | `UnityEngine.AudioModule.dll` |
| `BoxCollider2D` / `Rigidbody2D` | `UnityEngine.Physics2DModule.dll` |
| `JsonUtility` | `UnityEngine.JSONSerializeModule.dll` |
| `Input`（老输入系统） | `UnityEngine.InputLegacyModule.dll` |

> 报 **CS0012**（类型定义在未引用的程序集里）基本就是少引了某个 `UnityEngine.*Module.dll`。按报错里提到的类型去 `$GAME/.../Managed/` 里找同名模块加上即可。

### 3.2 完整模板（PowerShell）

```powershell
$GAME    = "<游戏安装目录>"   # 例如 Steam 库下的 ...\steamapps\common\Probably Stolen
$managed = Join-Path $GAME "Probably Stolen_Data\Managed"
$csc     = "<你的 csc.exe 路径>"
$out     = "<输出目录>\MyMod.dll"

$refs = @(
  "mscorlib.dll","System.dll","System.Core.dll","System.Xml.dll","System.Xml.Linq.dll",
  "netstandard.dll","Newtonsoft.Json.dll",
  "UnityEngine.CoreModule.dll","UnityEngine.InputLegacyModule.dll",
  "UnityEngine.TextRenderingModule.dll","UnityEngine.AudioModule.dll",
  "UnityEngine.UIModule.dll","UnityEngine.UI.dll","Unity.TextMeshPro.dll",
  "UnityEngine.JSONSerializeModule.dll",
  "Assembly-CSharp.dll","Assembly-CSharp-firstpass.dll","0Harmony.dll"
)

$args = @("/nologo","/target:library","/nostdlib+","/langversion:9.0","/optimize+",
          "/nowarn:1701,1702,1591","/codepage:65001","/out:$out")
foreach ($r in $refs) { $args += "/reference:$managed\$r" }
$args += "<你的源码>.cs"

& $csc @args
```

**两个必须注意的点**：

1. **必须用参数数组 + `@args` 调用**。把 `/reference:"带空格路径"` 拼成一个字符串再交给 `csc` 会被拆坏，报 `CS1504` / `CS2001`。
2. **显式加 `/codepage:65001`**。实测 Roslyn 对无 BOM 的 UTF-8 源码也能正确识别中文，但显式指定更稳。

### 3.3 多文件模组

把多个 `.cs` 一起传给 csc 即可（不要写 `/out` 以外的链接步骤）：

```powershell
$args += "src\Core.cs","src\Hud.cs"
```

## 4. 编码：中文乱码不是 DLL 坏了

Windows 控制台默认 GBK。以下现象**都是显示端问题**，不代表文件/程序集损坏：

- `Get-Content` 读 UTF-8 中文源码显示成「鎵归噺杈撳嚭」；
- csc 输出日志里的中文乱码。

要**确认 DLL 里的字符串确实正确**，用 Python 按 UTF-16LE 在字节里查：

```python
data = open("MyMod.dll", "rb").read()
needle = "你的中文".encode("utf-16-le")
print(needle in data)
```

源码文件本身用 **UTF-8（建议带 BOM）** 保存；写文件时不要用 PowerShell 的 `>` / `-replace`（它会按 GBK 读写，把中文写坏）。

## 5. 加载与调试循环

1. 编译到工作区 `build\` 目录，**不要直接编译进 `Mods\`**。
2. 关闭游戏（或确认该模组尚未被加载）。
3. 复制 `manifest.xml` + DLL（+ `preview.png`）到 `$GAME\Mods\<模组名>\`。
4. 启动游戏 → 主菜单的 Mods 列表里**启用并信任**新模组 → **重启游戏**。
5. 看 `Player.log` 里有没有 `[你的前缀]` 日志。

相关日志关键字（用于确认模组状态）：

```
[ModLoader] Found N mod folder(s)
[ModLoader]   Registered (disabled, Local): <名字> v<版本>
[ModLoader] audit: ... trust=Match
[<模组名>] Changed: scan refused (...)
```

- 新模组默认**禁用**：`modOrder` 里没有它，必须在 Mods 菜单里手动启用/信任，再重启才加载。
- 已信任模组的**版本更新**（`Updated` 状态）会自动加载，不需要重新点信任。

## 6. 部署脚本的小心事项

- 覆盖 DLL 前先查游戏进程是否在跑。游戏运行时 DLL 被映射，`Copy-Item` 会失败。
- **manifest 和 DLL 要作为一个整体更新**：曾经出现过「manifest 先复制成功、DLL 因游戏在跑失败」，结果上传了一个版本号与 DLL 不一致的包。
- 备份 DLL 放到 `Mods\` 之外（例如工作区 `tmp\backup\`）。理由见坑 #16。

## 7. 工具清单（可替换为你自己的）

| 工具 | 用途 |
|---|---|
| ILSpy CLI (`ilspycmd`) | 反编译 `Assembly-CSharp.dll` |
| Roslyn `csc.exe` | 编译模组 DLL |
| Python + Pillow | 生成 `preview.png`（工坊封面，**1280×720**） |
| Python + UnityPy | 读本地化 bundle、提取官方中文物品名 |
| 一个纯文本编辑器 | 改 manifest、写笔记 |

Python 只在做素材/数据提取时需要；编译和运行模组本身不依赖它。
