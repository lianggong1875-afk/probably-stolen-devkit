# 08 · 调试与证据

> 目标：把「不生效」拆成可判定的四层，避免瞎改代码。
> 证据等级：日志格式 `[实测]`；排查顺序为经验总结。

---

## 1. 日志在哪、怎么看

```
%USERPROFILE%\AppData\LocalLow\<发行商>\<游戏名>\Player.log
```

打开后先找这几类行：

| 关键字 | 说明 |
|---|---|
| `[ModLoader] Found N mod folder(s)` | 扫到几个模组目录 |
| `[ModLoader]   Registered (disabled, Local): <名字> v<版本>` | 新模组被识别但**未启用** |
| `[ModLoader] audit: ... trust=Match` | 已加载且指纹匹配 |
| `[<模组名>] Changed: scan refused (...)` | **被扫描器拒绝**，模组没加载 |
| `[ModHook] '...' handler ... threw` | 你订阅的钩子抛异常（框架捕获了，但功能没生效） |
| `[<你的前缀>] ...` | 你自己的日志 |

建议所有模组日志统一前缀 `[模组简称] `，并且：
- 关键路径（Init、读档完成、补丁首次命中）打一条；
- 高频路径（每帧）**不要**打，用计数器每 N 秒汇总一次；
- 打日志本身也会消耗性能，批量循环里用「开始/结束各一条」而不是每次迭代一条。

## 2. 四层排查法

按顺序排除，不要跳层：

### 第 1 层：模组加载了吗
- `Player.log` 有没有你的 Init 日志？
- `audit` 行里 `trust=` 是什么？
- 目录里有没有多余的可执行文件（坑 #16）？

**没加载** → 修 manifest / 清目录 / 在 Mods 菜单重新信任 + 重启。

### 第 2 层：补丁/钩子生效了吗
- Init 日志有没有打出「已打 N 个补丁」？
- 钩子订阅有没有执行到（在处理器里打一条）？
- 补丁目标方法名/签名对不对（重载？private？名字拼错？）
- 补丁异常会不会被外壳吞掉（try/catch 里只 `LogWarning`，没往外抛）？

**没生效** → 用 `AccessTools.Method(typeof(X), "name")` 打印 `null` 检查；确认方法在运行；确认 Harmony ID 唯一。

### 第 3 层：逻辑跑对了吗
- 在关键分支打「输入 → 决策 → 输出」三点日志；
- 对数值型逻辑，打印边界值（0、负数、空集合、满库存）；
- 运行时状态和存档对不上时，直接读存档 JSON 核对。

### 第 4 层：数据/存档对得上吗
- 存档是 **ES3 明文 JSON**，可以直接用文本编辑器读；
- 看 `_keys` 里有没有你写的 tag、值对不对；
- 旧档问题优先怀疑「结构/顺序变了」（坑 #23、#24、#30）。

## 3. 常用命令

### 3.1 看最新日志尾部

```powershell
$log = "$env:USERPROFILE\AppData\LocalLow\<发行商>\<游戏名>\Player.log"
Get-Content $log -Tail 120 -Encoding UTF8
```

### 3.2 筛自己的日志

```powershell
Select-String -Path $log -Pattern "\[MyMod\]" -Encoding UTF8 | Select-Object -Last 40
```

### 3.3 找扫描拒绝 / 加载失败

```powershell
Select-String -Path $log -Pattern "scan refused|Error:|not loaded|Unlisted" -Encoding UTF8
```

### 3.4 对比两版 DLL

```powershell
# 分别反编译到两个目录，再 diff
ilspycmd -p -o out\v1 old\MyMod.dll
ilspycmd -p -o out\v2 new\MyMod.dll
# 用你习惯的 diff 工具比较 out\v1 与 out\v2
```

### 3.5 核对 DLL 里的中文

```python
data = open("MyMod.dll", "rb").read()
print("你的中文".encode("utf-16-le") in data)
```

## 4. 症状 → 原因速查

| 症状 | 最可能的原因 | 先看 |
|---|---|---|
| 模组在列表里，但功能全无 | 被扫描拒绝（`payload-file`） | 坑 #16、`Player.log` 搜 `scan refused` |
| 模组根本没出现在列表 | manifest 解析失败 / 目录不在 `Mods\` / DLL 无 `IMod` | `Player.log` 搜 `Error:` |
| 新模组没反应，旧模组更新直接生效 | 新 ID 默认禁用 | 坑 #8 |
| 读档后整局无法操作 | 每帧补丁里访问了已销毁的 UI 节点并抛异常 | 坑 #10、#14 |
| 读档后仓库全空 / 物品错位 | 读档期间造物品/建 UI | 坑 #2 |
| 读档中断，大量物品没读回 | `LoadUpgrade` 空引用 | 坑 #3 |
| 机器面板加东西后旧档物品消失 | 动了面板顺序（BFS 索引变了） | 坑 #24 |
| 加/改机器后，食材放不进去、电池槽错乱 | 模组区 API 把食材区当模组区改了形状 | 坑 #24、#3 |
| 成品没进成品区、直接掉仓库 | `CanAccept` 预检对新物品不可靠 | 坑 #25 |
| 用完的工具出现在成品格 | 成品区 `mayInventoryAddItemFunc = true` | 坑 #25 |
| 批量生产时界面冻结 | 每次放置都全量 `Validate` | 坑 #17 |
| HUD 挂上去但看不见 | 挂到了 `overlayRoot`（0×0 + mask） | 坑 #26 |
| HUD 位置算错、跑到屏幕最底 | 用了 SpriteRenderer 的整墙 bounds | 坑 #27 |
| 浮窗有框没字 | 手搓 TMP 节点 / 未激活就排版 | 坑 #12 |
| 鼠标移到浮窗，右键菜单收起 | `FindContextMenuNode` 射线命不中 | 坑 #13 |
| 右键菜单加了项但一个像素不画 | 重建了原版菜单格子 | 坑 #11 |
| 自定义液体容器「像没注册」 | 工厂里调了 `InitLiquidContainerItem` → NRE | 坑 #22 |
| 倒空容器后物品掉价 | 用了 `EmptyContainer` | 坑 #20 |
| 写了 tag 但读不到 | `skipValidate:true` 后没同步 | 坑 #19 |
| 自学习模组数值不变 / 负面属性反而涨 | 上限 tag 缺失 / 误用 `OnUsedLearningAlgo` | 03 第 6 节 |
| 自己写的结局弹成房租文案 | 用了 `ExecuteGameOver` | 坑 #28 |
| 上传后工坊还是旧版 | Steam 下载队列延迟 | 坑 #15 |
| 上传报 `k_EResultFail` | 提交太频繁被限流 / 新建物品冷却期 | 06 第 7 节 |
| 自建窗口里点击选不中、命中整体偏移 | 用了 `GameGridInventory.handler` 当矩形（尺寸为 0） | 坑 #32 |
| 自建窗口里出框但选不中 | 用 `PixelWindow.handler` 判矩形，漏判 | 坑 #33 |
| 关闭自建窗口后，它覆盖过的区域框选能选多个、拖只有一个 | `Hide()` 只 SetActive(false)，矩形仍在拦截 press | 坑 #34 |
| 一次拖多件，只有第一件进目标库存 | `TryInventorySlot` 传了源物品的 `modifiedShape` | 坑 #35 |
| 拖到交易区，物品被塞进基础物品栏 | 落点失败后调了 `EmporiumTryAdd` 溢出 | 坑 #36 |
| 自建搜索框空文本点击报 `IndexOutOfRange` | 自建 `TMP_InputField` | 坑 #37 |
| 像素 HUD 的字上下颠倒 | `SetPixels32` 行 0 在底部 | 坑 #38 |
| 卸载模组后物品仍「被隐藏」/ tag 残留 | 用了常驻 `ITEM_HIDDEN_TAG` | 坑 #39 |
| 供应商批发按钮现金不足时仍灰掉 | 补丁 early return 把别的分支一起跳过 | 坑 #40 |
| 原版工具拖不上自建机器 | 目标侧 target 委托是 AND 聚合，一个 false 全否 | 坑 #42 |
| 升级/消耗材料后输入卡住或抛异常 | 提前 `Destroy()` 了拖拽中的材料 | 坑 #43 |
| 100+ 件每日结算/插拔一次卡顿 | 逐件调用了默认 `skipValidate=false` 的 helper | 坑 #44 |
| 所有本地模组突然都要重新信任 | 手改了存档里的 `modTrust`，签名对不上 | 坑 #45 |
| 工坊上版本号还是旧的 | 自动部署只复制 DLL、漏了 manifest | 坑 #46 |
| 拖工具到容器图标没反应，工具被存进容器 | 没挡 `MayHaveValidInventorySlot` | 坑 #47 |
| 光标吸附全部错位 / 总在屏幕右下 | Unity 客户区左下 vs Windows 屏幕左上 | 坑 #48 |
| 满级异形机器打开窗口卡一下 | 非矩形 shape 的 dynamic background 节点 | 坑 #49 |
| 自动投放 ticker 一开就掉帧 | 对每个源物品都调了「全仓库扫描」helper | 坑 #50 |
| 批量输出 71 件连续掉帧，分帧后更卡 | 分帧 + 每帧 `Validate` 重复验证全部成品 | 坑 #51 |
| 商人的大件第一次没买到、之后再也不出现 | 上架找不到位置被 `Destroy`，或排在随机货之后 | 坑 #52 |

## 5. 存档核对

ES3 存档是明文 JSON。典型结构：

```jsonc
{
  "mainInvJSON": "{...}",       // public，主仓库
  "backInvJSON": "{...}",       // 后仓
  "hiddenInvJSON": "{...}",
  "showcaseInvJSON": "{...}",
  "soldInvJSON": "{...}",       // 已售出：补偿时不要用它
  "hirelingInvJSON": "{...}",   // 雇工背包：GetAllOwnedItems 不含它
  "playerCash": -1234           // public int
}
```

查状态时：

```powershell
$save = "路径\save_1.es3"
Select-String -Path $save -Pattern "MY_PREFIX_STATE_INT" -Encoding UTF8
```

看 `_keys` 里的 `modifiedState`，而不是只看 `state`（坑 #19）。

## 6. 性能定位

- 先用「开始/结束两条日志 + `Stopwatch`」确认一次操作的真实耗时，再猜原因。
- 批量操作优先怀疑：`Validate` 全量重排、每次迭代创建 `GameItem`/`GameItemElement`、每帧 `GetAllOwnedItems()`、每帧 `GetTagReadonly()` 里做分配。
- 已知数字（供对比）：批量放 72 个成品，创建实例本身约 1.8 秒（每个约 25 ms）；抑制 `Validate` 只能省掉约 0.6 秒；分帧后冻结消失、总时长不变。
- 「每 N 秒 tick」的任务（角标、液体）务必做缓存，且加 `SaveManager.IsDecoding` 门禁。

## 7. 证据怎么记

写笔记时固定格式：

```
[实测] 2026-11-03 批量输出 21 次全部以「输出区已放满」结束（当时 6×4=24 格）。
[静态] SaveManager.DecodeNodes 按 inventory BFS 索引回填 → 面板顺序不能改。
[待验] 超科技烤架「本体放不进物品栏」疑似与 STANDARD_MACHINE_TAG 有关，未复现。
```

- `[实测]` 必须能指出证据：日志片段、存档字段、界面截图、复现步骤。
- `[静态]` 必须指出文件/方法。
- `[待验]` 要写「怀疑什么、下一步怎么验证」。

**不要把「我改了之后没报错」当成实测通过**——没有日志/行为变化，就等于没验证。

---

## 8. 最小复现

报 bug 或求助时给这三样：
1. **最小复现步骤**（新档还是旧档、第几天、在哪个界面点了什么）；
2. **`Player.log` 相关片段**（从你的第一条日志到异常结束）；
3. **受影响物品的存档字段**（如果涉及数值/存档）。

没有这三样，任何「我这边不生效」都无法定位。
