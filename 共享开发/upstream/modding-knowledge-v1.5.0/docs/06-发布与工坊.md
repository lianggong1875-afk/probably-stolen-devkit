# 06 · 发布到创意工坊

> 官方**禁止游戏内上传**：游戏内调用 `SteamUGC` 会被扫描器拒绝。发布必须在游戏外做。
> 证据等级：命令与返回值为 `[实测]`；Steam 行为为 `[静态]`（Steamworks 文档/日志）。

---

## 1. 发布前的版本管理

每次发布前四件事，缺一不可：

1. **bump `manifest.xml` 的 `<ModVersion>`**（语义化：修 bug 升 PATCH，加功能升 MINOR，改存档结构升 MAJOR）。
2. **重新编译 DLL** 并覆盖到 `Mods\<模组>\`（游戏没开！见坑 #7）。
3. **确认 `preview.png` 是 1280×720**（16:9，见第 5 节）。
4. **准备 `desc.txt`（工坊描述）和 `note.txt`（更新说明）**，UTF-8 无 BOM。

> 版本号与 DLL 必须一致。曾出现「manifest 先复制成功、DLL 因游戏在跑没复制」，结果上传了版本号 0.8.3 + DLL 0.8.2 的不一致包——玩家侧表现是「更新了但功能没变」。

> **自动部署脚本必须把 `manifest.xml` 和 DLL 当成一个整体**。另一次踩坑：后台脚本「等游戏退出 → 复制 DLL → 上传」只写了 DLL 的复制、漏了 manifest，结果工坊上的版本号还是旧的。上传前一定跑 `--validate`，核对输出里的 `version` 是不是你期望的版本（坑 #46）。

> **如果模组申请了能力（`native` / `files` 等）**，工坊描述里必须写清楚为什么需要（例如手柄模组需要 `native` 注入光标），否则玩家启用时会被额外提示吓到。

## 2. 发布工具：无界面驱动

社区有 GUI 上传器（只扫 `Mods\*`，需要 Steam 在线登录，把「本地记忆 → 工坊 key-value → 标题等于 manifest Name」作为匹配顺序）。但它不方便脚本化，也不方便 AI 操作。

更稳的是复用它自带 `SteamUploader` 写的**无界面驱动**（同一套 `SetItemContent` + `SubmitItemUpdate` API）：

```powershell
# 1) 只校验清单，不联 Steam（改完 manifest 先跑这个）
.\PsuUpload.exe --folder "<模组目录>" --validate

# 2) 更新已有物品（note.txt = 工坊更新说明，UTF-8）
.\PsuUpload.exe --folder "<模组目录>" --id <物品ID> --note-file note.txt

# 3) 新建物品（--visibility 0 公开 / 1 仅好友 / 2 隐藏 / 3 未列出）
.\PsuUpload.exe --folder "<模组目录>" --id 0 --visibility 0 `
                --desc-file desc.txt --note-file note.txt --lang schinese
```

`--validate` 会输出：

```
manifest OK
  folder   = ...
  id       = my-mod-id
  name     = 我的模组
  version  = 1.0.0
  asm      = MyMod.dll
  dll size = MyMod.dll -> 12345 bytes
  files    = N (M bytes)
```

**只要 `manifest OK` 且 dll size 合理，就可以提交。** `files`/`bytes` 是内容清单，用来确认没有把临时文件带进去。

### 常用参数

| 参数 | 作用 |
|---|---|
| `--folder` | 模组目录（必须含 manifest.xml） |
| `--id` | 0 = 新建；非 0 = 更新 |
| `--visibility` | 新建必填：0 公开 / 1 仅好友 / 2 隐藏 / 3 未列出 |
| `--desc-file` | 工坊描述文本 |
| `--note-file` | 本次更新说明（显示在更新记录里） |
| `--lang` | `schinese` / `english` / 留空 = 默认语言 |
| `--set-desc` | **默认不覆盖已有描述**；要改描述必须显式加 |
| `--no-content` | 只改页面（标题/描述/封面），不重传文件 |
| `--preview` | 指定封面；**`--no-content` 时必须显式给**才会传图 |

## 3. 标题、描述、语言：三处容易打架的地方

### 3.1 工坊标题 = manifest 的 `<Name>`

上传器每次完整提交都会用 `<Name>` 覆盖工坊标题。所以：

- 想在网页上改标题 → 必须同时改 manifest `<Name>`；
- 否则下次重传会把标题改回去；
- 只改标题、不重传内容时：`--no-content --lang english`，中文界面再跑一次 `--lang schinese`。

### 3.2 描述按语言分开存

- 默认语言（留空）和 `schinese` 是两份独立的描述；
- 只跑 `--lang english`，中文界面看到的是旧描述；
- 改描述要 `--set-desc`，且中文单独跑一轮。

### 3.3 延迟

标题/描述改动在上传工具里**约 1 分钟延迟**才反映到查询结果。查询没变不代表失败，别急着重复提交（重复提交会触发限流）。

## 4. 内容清单校验

`SteamUGC.SetItemContent(folder)` 会**上传整个文件夹**，没有任何扩展名过滤。所以「模组目录里能放什么」完全靠自觉：

- 允许：`manifest.xml`、列出的 `*.dll`、`preview.png`、`Textures/`、`Sounds/`、纯文本（`.md` / `.txt` / `.json` / `.csv`）。
- 禁止：`.bak` / `.orig` / `.zip` / `.ps1` / `.exe` / `.bat` / 源码 `.cs` / 旧版本 DLL。

发布前跑一次目录检查：

```powershell
Get-ChildItem "<模组目录>" -Recurse -File |
  Group-Object Extension |
  Sort-Object Name |
  Format-Table Name, Count
```

只应看到期望的扩展名。任何 `*.bak`、`*.zip`、`*.cs` 都要清掉。

## 5. 封面：必须 16:9（1280×720）

Steam 卡片按 16:9 显示。交 4:3 或方图会被黑底填充，看起来像「黑框里一小块图」。

- 尺寸：**1280×720**；
- 内容：标题 + 一句核心卖点 + 2~3 个图标/示意；
- 生成：Python + Pillow（字体用系统 `msyh.ttc` / `msyhbd.ttc` 即可，注意路径分隔符）；
- 只换封面不必重传内容：`--no-content --preview <png> --lang schinese`（**必须显式给 `--preview`**）。

## 6. 发布前 10 项检查

- [ ] 1. `manifest.xml` 的 `<ID>` 没改（改了就是新模组，玩家要重新信任）。
- [ ] 2. `<ModVersion>` 已 bump，且和 DLL 是同一版次。
- [ ] 3. `<Name>` 与工坊标题一致。
- [ ] 4. `<Capabilities>` 元素存在（没有就写空标签）。
- [ ] 5. `<Assemblies>` 里每个 DLL 都存在，且没有未列出的 DLL。
- [ ] 6. 目录里没有 `.bak` / `.zip` / `.ps1` / `.cs` / 旧 DLL。
- [ ] 7. `preview.png` 是 1280×720。
- [ ] 8. `--validate` 通过。
- [ ] 9. 描述里写清「是否需要新档」「是否会改存档结构」「兼容哪些版本」。
- [ ] 10. 发布后在本地记录一条（日期、版本、物品 ID、变更点、序号），便于下次追溯。

## 7. 返回值与失败处理

| 输出 | 含义 | 处理 |
|---|---|---|
| `RESULT OK: ... id=<ID>` | Steam 已确认提交 | 以它为准，不要立刻用订阅副本比对（见坑 #15） |
| `RESULT FAIL: UNCONFIRMED: ...` | 2 分钟没等到最终确认 | 可能已提交。看 Steam `content_log.txt` 有没有 `Workshop update changed : Running Update,Committing`；有就是已更新 |
| `RESULT FAIL: 提交失败：k_EResultFail` | 常见于**短时间连续提交过多**被限流；新建物品后的第一次更新也可能命中 | 等 60 秒换时间点重试；先 `--validate` 排除清单错误。**新建物品冷却约 5 分钟**：3 分钟内重试两次都失败、5 分钟后同一命令成功；但并非必然——也有模组首发更新直接成功 |
| `CreateItem 失败` | 新建物品失败 | 检查 Steam 是否在线、是否接受了创意工坊法律协议 |
| `Steam 未登录/未连线` | 独立程序的 Steam 会话无效 | 确认 Steam 客户端在线；用 steamcmd 登录过会把客户端顶下线，需要重启 Steam |
| `GetPublishedFileDetails` 返回 `result=9` | 索引延迟（FileNotFound），刚发布的物品还查不到 | 等 10 分钟再查；**以 `RESULT OK` 为准**，不要重复提交 |

> **不要用「订阅副本的哈希」验证刚上传的版本**：Steam 客户端要排下载队列，可能几分钟到几十分钟还是旧版。重启 Steam 或进游戏后副本才会刷新。

## 8. 发布后的本地记录

建议维护一张只在本机可见的表：

| 日期 | 模组 | 序号 | 版本 | 物品 ID | 要点 |
|---|---|---|---|---|---|

- 每个模组**各自独立**编号 `r1`、`r2`……只增不减、不跳号、不复用。
- 序号**不要**写进工坊更新说明、manifest 或任何玩家可见的地方，它只是本地追溯用的。
- 每次提交成功后立刻追加一行。下次接手的人（或 AI）能一眼看出「现在工坊是第几版、上一版改了什么」。

## 9. 发布文案模板

**desc.txt（工坊描述）**：

```
【作者 出品】

一句话卖点。

■ 功能一
· 具体行为（含关键数值）
· 边界条件

■ 功能二
...

■ 兼容性
· 是否需要新档 / 是否会改存档结构
· 与常见模组是否冲突
· 旧版本存档会怎样

■ 说明
· 纯运行时改动 / 新增物品 / 新增职业……
```

**note.txt（更新说明）**：

```
v1.2.0
· 修复：……
· 调整：……（从 X 改为 Y，原因）
· 注意：……
```

更新说明里**写清楚「会不会影响旧档」**，比写功能列表更重要。
