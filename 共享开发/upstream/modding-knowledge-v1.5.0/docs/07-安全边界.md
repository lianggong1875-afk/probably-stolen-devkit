# 07 · 安全边界与扫描器

> 游戏内置了一个**静态扫描器**，在模组启用/更新时读取 DLL 的 IL 与元数据，判定它有没有危险能力；恶意或可疑的包会被**拒绝加载**。
> 证据等级：判定项来自反编译 `ModScanner.cs` `[静态]`；实际拒绝行为在日志里见过 `[实测]`。
>
> **⚠ 还有一类硬禁令不在「能力声明」体系里**：**玩家专属的信任层动作**（批准 / 启用 / 停用 / 排序 / 开发者模式 / 取消订阅 / 写信任记录）。这类调用会被 `loader-target` 直接拒绝，**不能用 `<Capabilities>` 声明换通过**。完整清单见 **[10-官方红线清单](10-官方红线清单.md)**。

---

## 1. 扫描器在查什么

它不运行你的代码，只做静态分析：

| 判定 | 触发条件 | 结果 |
|---|---|---|
| `payload-file` | 目录里有 manifest **没列出**的可执行内容（`.dll` 之外的 exe 等，或额外 DLL） | **拒绝整个模组** |
| `payload-resource` | DLL 内嵌资源以 `MZ` 开头或含 DOS 头（内嵌可执行文件） | 拒绝 |
| `opaque-resource` | DLL 内嵌资源 ≥512 字节且熵 >7.5（可疑加密/打包数据） | 拒绝 |
| `unlisted-reference` | 引用了既不是游戏程序集、也没写进 `<Assemblies>` 的 DLL | 拒绝 |
| `bundled-framework` | 自带 `0Harmony` / `MonoMod` / `Mono.Cecil` | 拒绝 |
| `files` | 调用 `System.IO.File` / `FileStream` / `Directory` / `ES3File` 等「读写任意文件」的 API | 记为能力，需在 manifest 声明 |
| `network` | `System.Net.*` / `UnityWebRequest` / `SteamHTTP` 等 | 记为能力 |
| `process` | `System.Diagnostics.Process` / `ProcessStartInfo` | 记为能力（多数场景直接判恶意） |
| `dynamic-code` | `Reflection.Emit` / `Assembly.Load*` / 序列化器等 | 记为能力 |
| `native` | `Marshal` / `NativeLibrary` / `UnsafeUtility` 等 | 记为能力 |
| `reflection-external` | 用反射去摸系统/引擎内部（`GetMethod(...)` 指向非游戏程序集） | 记为能力 |

对游戏自身程序集（`Assembly-CSharp`、`UnityEngine.*`、`0Harmony`）的反射是**允许**的——`AccessTools` 反射游戏私有字段是正常做法。

### 能力声明的后果

`manifest.xml` 的 `<Capabilities>` 里声明什么，玩家在启用时就会看到对应的中文提示（「读写本机任意文件」「访问互联网」「启动其他程序」……）。而且：

- **新增能力 = 老玩家必须重新信任**（信任状态变 `Changed`）；
- 隐式使用了但没声明 = 直接拒绝（`undeclared`）；
- 声明了也不代表安全——玩家看到提示可能直接不装。

**结论：能不用的能力一个都不要用。** 本项目的所有模组都是 0 声明。

## 2. 模组目录白名单

**只允许**：

```
manifest.xml
<manifest 里列出的>.dll
preview.png
Textures/**            （图片）
Sounds/**              （音频）
*.md / *.txt / *.json / *.csv   （纯文本）
```

**不要放**：`.bak`、`.orig`、`.zip`、`.7z`、`.ps1`、`.bat`、`.exe`、源码 `.cs`、旧版本 DLL。

> 这一条踩过：目录里留了 `MachineTweaks.dll.bak-000143`，扫描器判 `payload-file`，**整个模组不加载**，游戏里表现是「所有功能凭空消失」，而且 `GameLog` 一条相关日志都没有。只有 `Player.log` 里的 `Changed: scan refused (payload-file: ...)` 能看出真相。

## 3. 代码层面的硬规则

### 3.1 不要 `Process.Start`

不启动外部程序、不打开网页。需要跳转链接就让玩家自己点。

### 3.2 不要调用 Steamworks / SteamUGC

游戏内上传/查询工坊都会被扫描器拒绝。发布走游戏外工具（见 06）。

### 3.3 不要联网

不发请求、不上报数据、不做「在线配置」。`UnityWebRequest` / `System.Net.*` 都会被记为 `network`。

### 3.4 不要读写模组目录之外的文件

不写日志文件、不导出配置、不读玩家桌面/文档。需要持久化就用存档（见 05 第 6 节）。

### 3.5 `Unpatch` 必须限定自己的 Harmony ID

```csharp
// 对：只撤自己的
harmony.UnpatchAll(harmony.Id);

// 错：会把别的模组的补丁一起撤掉
harmony.UnpatchAll();
```

卸载时游戏会按模组 ID 调 `UnpatchAll(<该模组 harmony ID>)`，你不需要自己写全局撤销。

### 3.6 不要在模组里收集玩家信息

不读 SteamID、不读用户名、不扫描进程、不读浏览器数据。这些是杀毒软件和扫描器共同的敏感行为。

## 4. 发布前自审（3 分钟）

### 4.1 目录检查

```powershell
Get-ChildItem "<模组目录>" -Recurse -File |
  Where-Object { $_.Extension -notin ".xml",".dll",".png",".jpg",".md",".txt",".json",".csv",".ogg",".wav" } |
  Select-Object FullName
```

输出应为空。

### 4.2 字符串检查

```powershell
$dll = "<模组目录>\MyMod.dll"
$bytes = [IO.File]::ReadAllBytes($dll)
$text = [Text.Encoding]::Unicode.GetString($bytes)
foreach ($k in "System.Diagnostics.Process","ProcessStartInfo","Steamworks","SteamUGC","Application.OpenURL","System.Net.Http") {
  if ($text.Contains($k)) { "FOUND: $k" }
}
```

（UTF-16LE 是 .NET 元数据字符串的编码；上面的 `Unicode` 即 UTF-16LE。UTF-8 字面量再用 `[Text.Encoding]::UTF8.GetString($bytes)` 查一遍。）

### 4.3 反射检查

搜源码/反编译里的 `GetMethod`、`GetField`、`Invoke`：确认目标类型都在 `Assembly-CSharp` 或 `UnityEngine.*` 里。指向 `System.*` / `Microsoft.*` 的反射会被记为 `reflection-external`。

### 4.4 manifest 检查

- `<Capabilities>` 存在；
- 没有多写不该有的能力；
- `<Assemblies>` 与实际 DLL 一一对应；
- 目录里没有未列出的 DLL。

## 5. 信任状态与「开发者模式」

游戏会记录每个模组的**文件指纹**。状态含义：

| 状态 | 含义 | 会不会加载 |
|---|---|---|
| `Unknown` | 第一次见 | 否，等玩家启用/信任 |
| `Match` | 文件未变 | 是 |
| `Updated` | 版本变了、能力没增加 | 是 |
| `Changed` | 来源变了 / 指纹变了 / 扫描拒绝 / 新增能力 | 否，要重新信任 |
| `DeveloperMode` | 本地模组开了开发者模式 | **是，即使扫描拒绝** |

**开发者模式不能代替验收。** 它会让「扫描拒绝」的包也加载，掩盖 `payload-file` 之类的问题。正式发布前应在正常模式下用干净环境再测一次。

> 判断某个版本到底有没有加载：看 `Player.log` 的 `[ModLoader] audit:` 行，`trust=Match` 才正常。

## 6. 给玩家的说明（写进工坊描述）

如果你的模组用了任何一项能力（强烈不建议），必须在描述里写清楚「为什么需要、用来做什么」。0 能力的模组可以在描述里写一句「不读写文件、不联网、不启动外部程序」，这是可信的加分项。

模组不应该要求玩家关闭杀毒软件、不应该引导玩家去下载外部文件、不应该在描述里放可疑链接。
