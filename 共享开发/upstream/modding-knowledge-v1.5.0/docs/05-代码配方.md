## 1. 右键菜单项：独立浮窗（不要改原版菜单）

对应坑 #11、#13、#12。思路：右键菜单弹出时，自己造一个节点挂在**原版菜单窗口的 `handler` 下**（同一棵 UI 树、同一个 Canvas，菜单隐藏时浮窗跟着隐藏）；点击用矩形命中；再给 `FindContextMenuNode` 打后置补丁，防止鼠标移过去菜单就收起。

```csharp
[HarmonyPatch(typeof(ItemContextHandler))]
internal static class Patch_ContextMenu
{
    // 这些补丁都在每帧/每次点击的关键路径上：每个入口都必须 try/catch，
    // 异常冒回去会打断原版输入链（症状：读档后整局无法操作）。
    [HarmonyPostfix, HarmonyPatch("OnEventPress")]
    private static void OnPress(ItemContextHandler __instance) { try { Overlay.Open(__instance); } catch (Exception e) { Log(e); } }

    [HarmonyPostfix, HarmonyPatch("OnEventRelease")]
    private static void OnRelease() { try { Overlay.OnRelease(); } catch (Exception e) { Log(e); } }

    [HarmonyPostfix, HarmonyPatch("OnEventReset")]
    private static void OnReset() { try { Overlay.Hide(); } catch (Exception e) { Log(e); } }

    [HarmonyPostfix, HarmonyPatch("OnEventUpdate")]
    private static void OnUpdate() { try { Overlay.Tick(); } catch (Exception e) { Log(e); } }

    // 坑 #13：原版每帧用 GraphicRaycaster 判断「鼠标还在菜单上」，浮窗命不中。
    // 只改返回值，鼠标在浮窗矩形里就假装还在菜单上。
    [HarmonyPostfix, HarmonyPatch("FindContextMenuNode")]
    private static void FindNode(ref GameObject __result, Vector2 eventDataPosition)
    {
        try
        {
            if (__result != null || !Overlay.Visible) return;
            var rt = Overlay.RootRect;
            if (rt == null || !rt.gameObject.activeInHierarchy) return;
            var r = rt.rect;
            if (r.width <= 0f || r.height <= 0f || r.width > 2000f || r.height > 2000f) return;
            if (RectTransformUtility.RectangleContainsScreenPoint(rt, eventDataPosition, null))
                __result = rt.gameObject;
        }
        catch (Exception e) { Log(e); }
    }
}
```

造节点（关键点：先 `SetActive(true)` 再排版；用 `RichTextElement` 画）：

```csharp
static TreeNodeRender root;
static RichTextElement button;

static bool EnsureNodes(PixelWindow menu)
{
    if (menu == null || menu.handler == null) return false;
    if (root != null && root.gameObject != null && root.rectTransform.parent == menu.handler.rectTransform)
        return true;

    root = TreeNodeRender.Instantiate();
    if (root == null) return false;
    root.gameObject.name = "MyOverlay";
    root.gameObject.tag = "ContextMenuNode";   // 让原版射线能认出「这是菜单」
    root.SetParent(menu.handler);              // 同一棵树 → 菜单 Hide 时自动隐藏

    button = new RichTextElement();            // 坑 #12：别手搓 TMP 节点
    button.handler.gameObject.name = "MyOverlayButton";
    button.handler.SetParent(root);

    root.gameObject.SetActive(false);
    return true;
}

static void Refresh(bool force)
{
    // 坑 #12：TMP 在非激活状态下 preferredWidth 可能为 0，先激活再算尺寸
    root.gameObject.SetActive(true);
    button.SetText("我的操作", 10000, RenderHandler.ColorPalette.LightGray);
    // button.widthPixels / heightPixels 就是排版后的尺寸
    root.rectTransform.sizeDelta = new Vector2(Mathf.Max(48f, button.widthPixels),
                                               Mathf.Max(20f, button.heightPixels));
    // 贴到菜单右侧：坐标是相对菜单的局部坐标；右边放不下就放左边
}
```

## 4. 批量放置：先抑制 Validate，再选「同步」还是「分帧」

对应坑 #17、#51。

### 4.1 规模 ≤100 件：同步一次做完，结束只刷一次（推荐）

实测 71 件时，旧版「每帧 8 个 + 每帧 `Validate`」连续掉 9 帧；改成同步循环后用户确认「流畅度不错」。

```csharp
void BulkOutput()
{
    Bulk.Busy = true;
    int free = CountFreeCells(output);          // 自定义辅助：只算一次
    try
    {
        foreach (var recipe in Batch())
        {
            var product = Produce(recipe);          // 先产出实例（你自己的单件生产流程）
            if (product == null) break;
            int cells = ShapeCells(product);        // 成品实际占格（异形按 Get==1 数）
            if (free - cells < 0) { product.Destroy(); break; }   // 留一格 / 放满都按空格数判断
            int leftover = GraphUtils.TryAcceptAll(output, product);
            if (leftover > 0)
            {
                if (product.parentInventory == null) product.Destroy(); // 避免漂浮泄漏
                break;
            }
            free -= cells;
        }
    }
    finally
    {
        Bulk.Busy = false;
        output.Validate();                      // 只刷这一次
        machine.contentWindow?.Validate();
    }
}
```

### 4.2 必须保持界面响应：分帧，但每帧不要 Validate

```csharp
IEnumerator BulkOutputAsync()
{
    Bulk.Busy = true;
    try
    {
        int n = 0;
        foreach (var recipe in Batch())
        {
            if (!TryProduceOne(recipe)) break;
            if (++n % PER_FRAME == 0) yield return null;   // 每帧 8 个，但不在帧末 Validate
        }
    }
    finally
    {
        Bulk.Busy = false;
        output.Validate();               // 全部结束只刷一次
        machine.contentWindow?.Validate();
    }
}
```

- **「分帧 + 每帧 Validate」是最差组合**：每帧都会把已放好的成品全部重验一遍（71 件累计约 360 次），比同步更卡（坑 #51）。
- 逐件的 `GraphUtils.CanAccept` 也可以去掉：它和 `TryAcceptAll` 做同一套落位搜索，用「空格数」判断即可，`leftover` 兜底。

注意：`finally` 里必须复位静态开关，否则下次整局 `Validate` 都被压掉。

## 8. 拖拽落点：`ItemMouseDragHandler.EndDrag` 前缀

真实签名是 `private void EndDrag(bool cancelled = false)`，按方法名补即可，前缀不必声明 `cancelled` 参数。

```csharp
[HarmonyPatch(typeof(ItemMouseDragHandler), "EndDrag")]
static class Patch_EndDrag
{
    static void Prefix(ItemMouseDragHandler __instance)
    {
        try
        {
            if (__instance == null || !__instance.IsDraggingItem) return;
            GameItem held = __instance.GetCurrentItem();
            if (held == null || !held.IsTag("LIQUID_CONTAINER_TAG")) return;
            if (!MyDropZone.Contains(Input.mousePosition)) return;   // 自己算矩形
            Consume(held);
            // EndDrag 照常把物品放回原处；落点不是 GameItem，不会抢走物品
        }
        catch (Exception e) { Log(e); }
    }
}
```

`OnEventRelease` 和 `OnEventReset` 都可能走到 `EndDrag`；没有额外状态时，最坏情况是取消拖拽时误触发一次，按业务接受度决定要不要加防抖。

## 14. 批量手势：把物品拖到容器图标上执行

对应坑 #47。适用于「拖一个工具到储藏区/机器图标上，对里面所有符合条件的物品批量操作」。

```csharp
// 1) 挡住原版的「插入容器」分支：否则 EndDrag 先把工具存进容器，永远走不到 Target
[HarmonyPatch(typeof(GameItem), "MayHaveValidInventorySlot")]
static class Patch_MayHaveSlot
{
    // 签名按反编译确认；this = 目标容器，item = 被拖的物品
    static bool Prefix(GameItem __instance, GameItem item, ref bool __result)
    {
        if (!IsOurTool(item) || !IsStorageContainer(__instance)) return true;
        if (!HasProcessableItems(__instance)) return true;
        __result = false;   // 强制走 Target
        return false;
    }
}

// 2) 让高亮变绿、显示「使用」
[HarmonyPostfix, HarmonyPatch(typeof(GameItem), "MayTarget")]
static void MayTargetPost(GameItem __instance, GameItem other, ref bool __result) { ... }

// 3) 真正执行批量逻辑
[HarmonyPrefix, HarmonyPatch(typeof(GameItem), "Target")]
static bool TargetPre(GameItem __instance, GameItem other) { return !TryBatch(__instance, other); }
```

要点：
- 判定只认自己的白名单（例如 `itemTypes` 含 `STORAGE` 的 12 个容器），别误伤展示柜/柜台/机器。
- 遍历子物品时：手势判定用**只扫第一层**的 `GraphUtils.FindChildType<GameItem>(container, predicate)`（拖拽每帧都调，别递归）；批量执行时用 `FindAllChildrenType`（可递归到嵌套工具箱）。
- 批量里不要消耗掉「手势物品」本身（反应器/工具留在原处）。

## 15. 词条角标：显示模组效果的第一个字

适用于「给模组/装备在图标上标出它带的词条」，和 tooltip 同源。

// 效果 id 存在这两个 tag 里（值是 MODULE_EFFECT_PREMIUM 之类）

string id2 = item.IsTag("MODULE_EFFECT2_TAG") ? item.GetTagReadonly("MODULE_EFFECT2_TAG").valueString : null;

## 16. 非矩形大 shape：字符串形状图

超过「几张固定尺寸表」的大机器，用 shape 字符串而不是硬编码矩形：

```csharp
// '0' = 可放，'1' = 不可放；width = 每行字符数
machine.SetShape(shapeString, 18);   // 例如 24×18 的图
```

- 矩形（`SetShape(w, h)`）只建 3 个节点；非矩形走 `renderDynamicBackground`，**每格 5 个 `TreeNodeRender`**，400+ 格 = 2000+ 节点，打开窗口时一次性创建（坑 #49）。
- 等级存 `HYPERTECH_AGER_STAGE_INT` 之类的 tag，`onLoaded` 里按等级重建 shape 与电耗，**不要重排**已有物品。
- 升级要重排时：先 `Expel` 全部子物品 → `SetShape` → 按原顺序 `TryAcceptAll` 放回；放不下的 `EmporiumTryAdd` 退仓库，**绝不销毁**。
