# 10 · 官方红线：模组不能替玩家做的事

> **一句话**：游戏的「信任层」（批准、启用、停用、排序、开发者模式、取消订阅）**只能玩家亲手点**，模组一律不许代劳。
> 违反不是「被警告」，而是：**静态扫描直接拒绝加载**，就算绕过去，运行时也会抛异常。
> 证据级别：`[实测]` 2026-11-11 一个「一键全选启用」模组被游戏当场拒绝；`[静态]` 当前 `Managed\Assembly-CSharp.dll` 的 `ModRestrictedAttribute` / `RequireNoMod` / `CallingModId` 实现。

---

## 1. 两道闸门

| 闸门 | 时机 | 做什么 | 结果 |
|---|---|---|---|
| **静态扫描** | 玩家点「审阅并启用」时 | `ModScanner` 读 IL，发现调用了带 `[ModRestricted]` 的成员 | 硬拒（`loader-target`），模组**根本启用不了** |
| **运行时守卫** | 代码真的执行时 | `ModLoader.RequireNoMod()` → `CallingModId()` 遍历整个调用栈 | `Debug.LogError` + 抛 `UnauthorizedAccessException` |

**两道都要过**，所以「绕开扫描器」没有意义：

- 反射调用（`AccessTools` / `Type.GetMethod`）→ IL 里仍然有对目标成员的 `Call`，扫描器看得到；
- 延迟到协程 / 定时器 / `ExecuteEvents.Execute` 派发点击 → 调用栈里照样有模组程序集帧，`CallingModId()` 从栈顶一路找；
- transpiler 伪装 → `CallingModId()` 会用 `Harmony.GetOriginalMethodFromStackframe` 还原原始方法。

设计意图写在守卫的报错里：**"the trust layer is the player's and the game's."**

---

## 2. 已被标注的成员（2026-11-10 版本）

### 2.1 `ModLoader`（游戏内置模组的加载器）

| 成员 | 规则原因（原文） |
|---|---|
| `SetModEnabled(string id, bool enabled)` | enables or disables mods, which only the player does |
| `ReorderMods(List<string>)` | reorders mods, which only the player does |
| `ApproveAndEnable(LoadedMod, ModEnableCheck)` | approves a mod, which only the player does |
| `SetDeveloperMode(LoadedMod, bool)` | turns developer mode on, which only the player does |
| `ForgetMod(string id)` | drops a mod from the list, which only the player does |

> 也就是说：**「审阅并启用」「停用」「自动排序」「开发者模式」「移除模组」全部是玩家专属动作。**

### 2.2 `ModTrust` / `ModTrustList`（信任库）

| 成员 | 原因 |
|---|---|
| `Approve(...)` | writes an approval, which only the player's click does |
| `Refresh(...)` / `StoreFolderHash(...)` | rewrites an approval |
| `MarkStopped(...)` | records a stop, which only the game's tripwire does |
| `Revoke(string)` | revokes an approval, which only the player or the game does |
| `SetDeveloperMode(string, bool)` | turns developer mode on, which only the player does |
| `ModTrustList.Replace(...)` 等 | replaces the trust list |
| `ModTrustList` 的网络阻塞入口 | stalls the game on the network |

> 所以「替玩家写一条信任记录 / 改指纹 / 撤销信任 / 换一份信任列表」全部禁止。
> 附带事实：信任库带 `modTrustMac` 签名，**手改 `SaveFile.es3` 里的 `modTrust` 会让整库作废**（详见 DEVELOP_NOTES 超科技催陈器那节），这条路也不通。

### 2.3 其它被划进红线的 API

| 类别 | 例子 | 规则 |
|---|---|---|
| 取消工坊订阅 | `ModWorkshop.Unsubscribe(...)` | `loader-target` |
| 用 shell 打开东西 | `Process.Start`、`Application.OpenURL`、`ModUIManager.OpenModFolder`、`EscapeUIManager` 的网页入口、`PaperEditorFiles` 打开文件夹/文件 | `process-start` |
| 存档文件夹的文件操作 | `SaveFiles.*`（读/移/复制存档文件） | `files` |
| 任意文件读写 | `System.IO.File` / `FileStream` / `Directory` / `ES3File` 等 | `files`（需声明，且基本不可接受） |

## 3. 我们踩过的真实例子（2026-11-11）

需求：模组页面「已激活」右边加一个「全选」，一键把所有未激活模组审阅并启用。
实现：循环调 `ModLoader.CheckEnable()` + `ModLoader.ApproveAndEnable()`（就是原版「审阅并启用」按钮内部的两步）。
结果：**启用时被扫描器当场拒绝**：

```
loader-target: QuickEnableAll.EnableAll -> ModLoader.ApproveAndEnable
  (approves a mod, which only the player does)
loader-target: QuickEnableAll.DisableAll -> ModLoader.SetModEnabled
  (enables or disables mods, which only the player does)
```

**结论**：错不在实现，而在方向 —— 这类功能一律不做。源码留在 `mod\quickenable\`，`README.md` 写明作废原因，**不要重新部署**。

## 4. 动手前怎么自查（30 秒）

拿到一个 `Assembly-CSharp` API，先确认它有没有被标注：

```powershell
$ws = "C:\Users\Vorty\Documents\deepseek-harness\default-workspace"
$managed = "F:\SteamLibrary\steamapps\common\Probably Stolen\Probably Stolen_Data\Managed"
& "$ws\tools\ilspy\tools\any\win-x64\ilspycmd.exe" -t ModLoader "$managed\Assembly-CSharp.dll" |
  Select-String -Pattern "ModRestricted" -Context 0,2
```

或者反编译整个程序集后直接搜：

```powershell
& "$ws\tools\ilspy\tools\any\win-x64\ilspycmd.exe" -p -o "$ws\tmp\decomp_current" "$managed\Assembly-CSharp.dll"
Select-String -Path "$ws\tmp\decomp_current\*.cs" -Pattern "ModRestricted\(" | Select-Object Filename, Line
```

判断标准：

- 方法上一行有 `[ModRestricted(...)]` → **禁止调用**；
- 方法体第一行有 `RequireNoMod("...")` → **禁止调用**；
- 只有 `IsModEnabled` / `Get` / `Check` 这类**只读**方法才是安全的。

> ⚠ 工作区的 `decompiled\Assembly-CSharp` 是**旧快照**，没有这套机制。涉及 `ModLoader` / `ModTrust` / `ModScanner` 时**必须重新反编译当前 DLL**。

## 5. 正确的替代做法

| 玩家想要的效果 | 不要做 | 该怎么做 |
|---|---|---|
| 一次启用很多模组 | 模组替你调 `ApproveAndEnable` | 告诉玩家：**双击列表行** = 选中 + 审阅并启用；或点详情里的「审阅并启用」 |
| 改完版本不用反复审阅 | 模组调 `SetDeveloperMode` | 告诉玩家：选中本地模组 → 点「开发者模式：开」（之后文件夹任何改动自动信任） |
| 调整加载顺序 | 模组调 `ReorderMods` | 玩家用「自动排序模组」按钮，或直接拖行 |
| 停用/移除模组 | 模组调 `SetModEnabled` / `ForgetMod` | 玩家自己在列表里点 |
| 阻止某个坏模组加载 | 模组调 `ModTrust.Revoke` | 玩家取消订阅 / 自己停用 |

**原则**：需要「信任层动作」的功能，模组只提供**信息与引导**（提示、说明、跳转到哪个按钮），**最后的点击必须由玩家完成**。

---

## 6. 给 AI / 协作者的硬规则

1. 需求里出现「一键启用/停用/信任/排序/开发者模式/取消订阅/替玩家批准」，**先停**，把本清单的结论告诉用户：官方禁止，做不了。
2. 任何要调用 `ModLoader.*`、`ModTrust.*`、`ModTrustList.*`、`ModWorkshop.*`、`SaveFiles.*`、`Process.*` 的方案，先按第 4 节自查。
3. 不要用「模拟鼠标点击 / 键鼠注入」去规避信任闸门。那是故意绕过官方设计，风险和解释成本都高；用户明确要求时也要先说明这一点。
4. 遇到被拒绝：把 `Player.log` 里的 `loader-target: ...` 原文贴给用户，不要试图「换个写法再试一次」——换写法仍会被拒，只是浪费一轮。
