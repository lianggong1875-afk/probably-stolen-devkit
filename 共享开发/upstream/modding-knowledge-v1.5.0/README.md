# 深空当铺 / Probably Stolen 模组开发经验库

> 一个**纯文档模组**：不新增物品、不改玩法、不碰存档。
> 订阅它唯一的目的是把这份经验库下载到你电脑上，给你（和你使用的 AI）读。
>
> 适用游戏：**Probably Stolen / 深空当铺**（Steam AppID 4348910）
> 整理时间：2026-11；对应 Unity 2021.3.45f2 / Mono / .NET 4.x

---

## 1. 这是什么，不是什么

**是**：一份从多个已发布模组（机器改造、液体管理、种子管理、新职业、交易系统、HUD、仓储终端、暗格储藏、批量发酵、手柄支持等）里提炼出来的实战笔记。包含环境搭建、编译命令、官方 API 地图、**52 条**踩坑记录、可直接抄的代码模式、创意工坊发布流程、安全边界、官方红线、性能优化和调试方法。

**不是**：不是教程的替代品，不是官方文档，也不保证对未来游戏版本仍然成立。所有结论都标了证据等级（见下），请按等级采信。

**游戏内没有任何功能**。DLL 只会在日志里打两行字，证明它加载成功。

## 3. 证据等级（全文通用）

| 标记 | 含义 |
|---|---|
| `[实测]` | 在本机游戏里跑过，有日志/存档/界面为证 |
| `[静态]` | 从反编译的 `Assembly-CSharp` 或官方文档读出来的结论，没实机验证 |
| `[待验]` | 推断或社区说法，尚未证实；照做前先自己验证 |

看到 `[静态]` 时请记住：反编译能证明「代码这么写」，不能证明「运行时一定这样」。游戏版本一换就可能失效。

## 4. 30 秒速览：最值钱的 10 条

1. **先查官方有没有入口，再考虑 Harmony。** 官方 `ModHook` 有 40+ 个钩子（`OnGameLoaded*`、`OnGoingSleep*`、`OnCreateTooltip*`、`OnGenerateCustomer*`……）。能用钩子解决的，别打补丁——补丁要维护、要解释「官方缺了什么语义」。见 [03-官方API地图](docs/03-官方API地图.md)。
2. **不要改存档结构。** 官方没有可靠的存档扩展入口；加字段最容易在版本更新后把玩家的档读坏。优先「借」原版已有的 `public` 字段，或把状态挂成物品 tag。见 [05-代码配方](docs/05-代码配方.md) 第 6 节。
3. **机器面板的「顺序」是存档格式的一部分。** 读档回填子物品靠「面板里 inventory 的 BFS 序号」。想加东西只能**追加在末尾**，绝不能重排已有面板。见 [04-踩坑清单](docs/04-踩坑清单.md) 第 24 条。
4. **UI 别手搓 TMP 节点。** 用游戏自己的 `RichTextElement`；挂到 `overlayRoot` 下会被 `RectMask2D` 裁没；自己 `new` 的 TMP 文字会「框在、字没」。**自建窗口还要判可见性**：`Hide()` 只 `SetActive(false)`，矩形仍在，会永久拦截那块屏幕区域的点击。见 [05-代码配方](docs/05-代码配方.md) 第 1、2、13 节。
5. **模组文件夹里不要留备份文件。** 扫描器会把 manifest 没列出的可执行文件判成 `payload-file`，**整个模组直接不加载**，而且症状是「功能全消失」，极难定位。见 [04-踩坑清单](docs/04-踩坑清单.md) 第 16 条。
6. **发布只能游戏外做。** 游戏内调 SteamUGC 会被扫描器拒绝。用无界面驱动 `PsuUpload`；改描述要显式 `--set-desc`，中文要 `--lang schinese`。见 [06-发布与工坊](docs/06-发布与工坊.md)。
7. **改完必须实机验证，并把结论写回笔记。** 反编译读对了不等于跑得起来。每次发布后记录版本号和变更点，下一次能省掉几小时。见 [09-给AI的协作方法](docs/09-给AI的协作方法.md)。
8. **「信任层」动作模组一律不能做。** 批准 / 启用 / 停用 / 排序 / 开发者模式 / 取消订阅 / 写信任记录，全是玩家专属；调用了会被扫描器 `loader-target` 直接拒绝，运行时还有 `RequireNoMod` 抛异常。见 [10-官方红线清单](docs/10-官方红线清单.md)。
9. **大网格别让「每放入一件」触发全网格重算。** 原版 `ComputeAllModuleTempStat` 这类函数会对整张网格逐件 `ValidateShapeState`（还会 `parentInventory.Validate()` + 父链递归），拖动 N 件就是平方级，卡死。合并到帧末、拖拽期间不算、批量 `skipValidate` + `SyncModifiedState`、缓存全图扫描。见 [11-性能优化](docs/11-性能优化-大网格拖拽.md)。
10. **拖拽判定注册在「源物品」一侧，批量结算不要逐件调原版 helper。** `MayTarget` 的委托是 AND 聚合，目标侧一个 false 会把原版工具一起否掉；`OnAgeWine` / `OnAddedModuleToGrid` 这类 helper 每件都做一次全网格 Validate，100+ 件就是灾难。**分帧不等于更快**：分帧 + 每帧 `Validate` 反而比同步一次做完更卡。见 [04 坑 #42～#44、#51](docs/04-踩坑清单.md)。

## 7. 复用与致谢

本知识库的文字与代码片段可以自由用于你自己的模组，不需要署名。如果它帮你省了时间，在工坊页面点个赞就够了。

其中一部分方法论（「先判官方覆盖再打补丁」「安全边界」「证据分级」）来自社区框架的公开实践，这里做了转述与本地化，不包含其原文。

## 8. 免责

- 模组开发有风险：错误的补丁可能让玩家的存档无法读取。发布前务必用**新档 + 旧档各测一遍**。
- 本库记录的是**某个时间点**的游戏行为。游戏更新后，`[静态]` 结论最可能失效。
- 不要在任何模组里收集玩家数据、调用外部程序或联网。扫描器会拦，玩家也不该承担这个风险。
