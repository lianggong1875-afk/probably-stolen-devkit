# 向导

**向导**是一个 bash 脚本，带着人一步步走完一套手工流程：这套流程手动做很繁琐，每次重新给 AI 解释一遍也很繁琐。它逐个打开 URL，说清到底点哪里、复制什么，把值收集下来，写到它们该在的地方（`.env`、GitHub secrets），每个阶段都确认一次，并显示还剩几个阶段。它可能用来配置第三方服务、跑一次性迁移，或者把项目从一种状态搬到另一种状态。

令人愉悦的使用体验已经由 [template.sh](template.sh) 解决：逐阶段的进度、确认关卡、跨平台打开 URL（含 WSL）、密钥的隐藏输入、幂等的 `.env` upsert、`gh secret`/`gh variable` 写入，以及收尾总结。**你只负责界定流程范围、编写它的各个阶段。** `STAGES` 标记以上的那套库在每个向导里都一模一样；这种一致性正是关键：绝不要手工改它。

向导默认是一次性的：为跑一次而建，存到临时路径或 `scripts/` 下，活干完就删。只有用户想要一条可重复、并且应该留在仓库里的搭环境路径时，才提交它。

## 流程

### 1. 界定流程范围

理清人必须走的每一个手动步骤，以及沿途要收集的每一个值。先读仓库，不要什么都没看就问：

- 若是搭环境：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置，以及 `.github/workflows/*`（每一处 `secrets.*` / `vars.*` 引用，都是向导必须产出的一个值）。
- 若是迁移或状态切换：当前状态、目标状态，以及两者之间那些不可逆的操作。

然后把按顺序排好的阶段清单、以及每个阶段产出的值给用户看，并确认：用户可以增加、删除或调整顺序。

**完成标准：**每个阶段都按顺序命名，并且对每个收集到的值你都清楚：(a) 人从哪里拿到它，(b) 它写到哪里（`.env`、某个 GitHub secret、两处都写，还是哪都不写；有些阶段是纯操作），(c) 它是密钥（隐藏输入）还是公开值。

### 2. 画出每个阶段的路径

对每个阶段，写出人要走的确切路径：打开哪个 URL、在那里做什么、值显示在哪儿、填进哪个变量，例如“Dashboard → Developers → API keys → Reveal test key → copy”。哪里你其实并不知道当前的 UI 或确切的命令，就说不知道，去问用户或查文档：绝不要编造可能并不存在的步骤。

**完成标准：**每个阶段都能落到具体指令上，一个陌生人照着就能做。

### 3. 编写向导

把 `template.sh` 复制到目标路径。把示例阶段替换成每个步骤一个 `stage`，按依赖顺序排。使用那套库的辅助函数：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。把 `TOTAL_STAGES` 设成你写出的阶段数量。

守住模板立下的标准：先打开 URL 再问它的值，凡是密钥都用 `ask_secret`，每个要持久化的值都走 `write_env`，`set_secret` 只用于 CI 真正需要的值，任何不可逆操作之前先 `confirm`。每个 `stage` 都会清屏，只让当前这一步可见：一个阶段只放一件专注的事，别让人需要看的东西被滚出屏幕。标记以上的库不要动。

### 4. 验证并交接

- 跑 `bash -n <script>`；有 `shellcheck` 就跑一遍。
- `chmod +x <script>`。
- 不要自己从头到尾跑一遍：它会打开浏览器，并卡在等人输入上。改为静态走查：第 1 步里的每个值都被收集，并落到第 1 步说的位置；每个 `set_secret` 名字都精确对应 CI 里的某处 `secrets.*` 引用。
- 告诉用户怎么运行它。如果这是一条可重复的搭环境路径，就提交它，并在 README 里给出链接，让下一个人直接跑脚本，而不是去问 AI。
