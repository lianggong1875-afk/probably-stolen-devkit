# mattpocock/skills 中文化翻译规范

本目录是 [mattpocock/skills](https://github.com/mattpocock/skills)（MIT）的**中文适配版**。原文逐文件保留为 `*.en.md` 作为对照基底，中文译文写入同名的 `*.md`。翻译时只增不改：不改原文、不改技能名、不改命令。

## 0. 铁律

1. **对应翻译，不是重写**。段落数、列表项数、表格行列数、标题层级必须与原文一一对应。不允许合并、拆分、删减、补充。原文没说的话，译文一个字都不要加。
2. **不加解释、不加例子、不加"译者注"**。读者是执行任务的智能体，任何原文没有的内容都会污染行为。
3. **不删任何限制条件**。原文里 "never / always / only / must not" 这类约束是技能的全部价值所在，漏一句就等于放开了红线。
4. **技能名永远是英文**。`grilling`、`tdd`、`code-review`、`codebase-design` 等既是目录名也是调用标识，任何位置出现都保持英文原样，不加引号变体。
5. **禁止英文破折号 `—`**。中文里改用逗号、冒号、句号、括号或顿号，逐句重写，不要做字符替换。

## 1. frontmatter 处理

```yaml
---
name: tdd                     # 保持英文原样，绝不翻译
description: 中文描述 + 保留英文触发词
disable-model-invocation: true   # 保持原样（未知字段无害）
metadata:                     # 原样保留
  credits: ...
---
```

- `name`：原样。
- `description`：翻成中文，但**必须保留原文里的触发关键词原文**（如 `TDD`、`red-green-refactor`、`grill`、`bug`、`PR`、`GLOSSARY.md`）。触发词翻译成中文会让自动调用失准，所以中英并列。
- 其余字段：原样照抄，顺序不变。

## 2. 必须保持原样的内容

| 类别 | 例子 |
| --- | --- |
| 技能名 | `grilling`、`tdd`、`setup-matt-pocock-skills` |
| Skill 工具调用 | `Call the Skill tool with "grilling"` → 只把 Call the Skill tool 翻成 "调用 Skill 工具加载"，技能名不动 |
| 斜杠命令 | `/setup-matt-pocock-skills`、`/grill-me` 原样保留 |
| 文件与目录名 | `GLOSSARY.md`、`docs/adr/`、`AGENTS.md`、`CLAUDE.md`、`.scratch/`、`SKILL.md` |
| 路径 | 相对路径、绝对路径、`../` 一律不动 |
| 代码块 | 整块不动，包括其中的英文注释和提示词模板 |
| 行内代码 | 命令、字段名、变量名、类型名不动 |
| URL 与链接目标 | `https://...`、`./X.md`、`file.md#anchor` 不动，只翻链接文字 |
| 表格结构 | 行列与对齐方式不动 |
| agent 元数据 | `agents/openai.yaml`、`scripts/*.sh`、`CREDITS.md` 不动 |

## 3. 语言风格

- 技术手册语气：直陈、短句、动作为先。第一句就说做什么，不铺垫。
- **禁止八股**："值得注意的是""综上所述""不仅…而且""在当今""随着…的发展""旨在"这类一律不用。
- 不用敬语客套，不用"我们建议您"。
- 中文全角标点；代码内标点保持原样。中英文之间不加空格。
- 原文的命令式（"Do X / Never do Y"）译成中文命令式（"做 X"、"绝不要做 Y"），不要软化成"可以考虑"。
- 原文的 `Done when` / `It's working if` 这类验收小节，译成"完成标准""生效表现"，保持条目化。

## 4. 术语

严格按 `_术语对照.md` 执行。表里没有的词：首次出现给中文（英文原词），之后只用中文；同一个词全文只用一个译法，不允许同义词轮换。

## 5. 参考文档

技能目录里除 `SKILL.md` 之外的 `.md`（如 `tests.md`、`DEEPENING.md`、`ADR-FORMAT.md`）同样翻译，规则完全一致：读 `X.en.md`，写 `X.md`。
