你已经拿到一份规格说明。这份规格说明应当关联着工单，描述如何实现该规格说明。

工单系统应当已经提供给你。如果没有，让用户运行 `/setup-matt-pocock-skills`。

目标是在单条**集成分支**上把整份规格说明实现完，并让每张工单都按工单系统关单的方式得到解决。

工单不是一串步骤。它们是一张**任务图**，彼此之间存在阻塞关系。这意味着总有一批**前沿**工单可以立刻抓走。

每派一个子智能体，都给它一个全新上下文窗口。

与子智能体之间的通信要稀疏。主要靠**上下文指针**通信：指向规格说明、工单、调研笔记和此前的提交。指针已经能拿到的东西不要重复转述。

**实现子智能体**应尽量放到后台运行，以取得最大并发。

## 步骤

1. 读规格说明和工单，弄清任务图。

2. （可选）用**探索子智能体（exploration subagent）**做那些工单要求的探索：相关代码库文件或外部文档。确保该探索子智能体能存文件，它应当把 markdown 笔记存到仓库之外的目录，且所有后续子智能体都能读到。这样**实现子智能体**就能专注实现，不必自己去探索。

3. 创建集成分支。如果工单系统通过拉取请求（PR）关单，或者用户要一个 PR，就在第 5 步第一次合并之后开一个草稿 PR，并标记为关闭该规格说明与相关工单（分支在 main 上还没有提交时开不出来）。

4. 每张工单都用一个全新的**实现子智能体**，各自在自己的工作树（worktree）、自己的分支上干活。每个实现子智能体：
   - 开始前确认自己的工作树基于集成分支，若不是就重置到该分支上；
   - 调用 Skill 工具加载 `tdd` 来构建这张工单；
   - 报告完成前，把集成分支的最新提交合入自己的分支

5. 一个**实现子智能体**完成后，用**合并子智能体**把它的成果合并到集成分支。

6. 如果这改变了可动工单的**前沿**，就再启动更多**实现子智能体**去做新露出的工单。这样能取得最大并发。

7. 所有工单完成后，在集成分支上调用 Skill 工具加载 `code-review`。由一个全新的**实现子智能体**修掉代码评审提出的全部问题。

8. 如果存在草稿 PR，把它标记为可评审。否则按工单系统关单的方式逐张解决工单，并汇报集成分支。

9. 清理所有**实现子智能体**的工作树。
