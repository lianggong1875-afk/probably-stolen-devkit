# 这套技能怎么接到本工作区

上游技能默认假设你在一个 TypeScript 仓库里：有 GitHub issue tracker、有 `pnpm test`、有 tsc 类型检查。本工作区是 Unity/Mono C# 模组 + 本地 Git + PowerShell 构建脚本，所以需要一个落地映射。**技能里的流程与判断标准照用，命令和落点换成下表。**

## 0. 优先级

任何技能流程与本工作区硬底线冲突时，硬底线优先：

- Slot 0 主档禁碰，真机测试只进 Slot 1
- 付费 OpenAI 调用先经用户同意
- 工坊正式发布前须用户确认

技能是方法，不是授权。

## 1. 斜杠命令 → DSH 里的对应做法

上游写作 `/grill-me`、`/tdd` 这类斜杠命令。DSH 原生支持同样的手势：**在输入框里打 `/技能名`**（要用空格和其它文字隔开，是一个独立的 token），宿主会把那个技能的完整正文作为指令注入当轮。输入 `/` 会弹出补全菜单，名字带「仅限用户」标记的就是下面这类技能。

这套技能里有两类，在 DSH 里的可见性完全不同：

| 类型 | 数量 | 表现 |
| --- | --- | --- |
| 模型触发（无 `disable-model-invocation`） | 11 个 | 出现在我的技能清单里，我可以自己按描述调用；你也可以用 `/名字` 手动触发 |
| 用户触发（`disable-model-invocation: true`） | 16 个 | **不出现在我的技能清单里**，我永远不会自动调用。唯一入口就是你打 `/名字` |

所以下面这 16 个必须由你亲手打出来：`/ask-matt`、`/grill-me`、`/grill-with-docs`、`/handoff`、`/implement`、`/implement-spec`、`/improve-codebase-architecture`、`/retro`、`/setup-matt-pocock-skills`、`/teach`、`/to-questionnaire`、`/to-spec`、`/to-tickets`、`/triage`、`/wait-what`、`/wayfinder`。

其余命令：

| 上游写法 | 本环境做法 |
| --- | --- |
| `/clear` | DSH 没有这个命令。开一个新会话（旧会话仍可回看） |
| `/compact` | DSH 有同名原生命令，直接用。压缩前先 `/handoff` 落一份文件更稳 |
| `/handoff` | 打 `/handoff`，产出文件放 `缓存文件夹\handoff\` |
| `/setup-matt-pocock-skills` | 不用跑：本文件就是它的等价配置结论 |

## 2. 工单系统

上游支持"本地 markdown 工单"。本工作区落点为各项目自己的目录，保持两款模组互不引用：

```
深空当铺：可能是群友/工单/<feature>/001-<slug>.md
深空电玩/工单/<feature>/001-<slug>.md
```

每张工单一个文件，文件头写阻塞关系：

```markdown
---
id: 001
title: 鉴定台的纸张交互
blocked_by: []
---

## 要做什么
## 完成标准
```

- 只有**跨多个会话**的功能才值得拆工单。单文件改动、文案调整、数值微调，直接改，不要走这套流程。
- 已有 `PROGRESS.md` 继续承担"项目当前状态"，工单只管"这次要做的一批活"。完工后把结论写回 `PROGRESS.md`，工单文件可留可删。
- 分诊（`triage`）技能对我们基本用不上：我们没有外部缺陷报告流。跳过它不影响主流程。

## 3. 领域文档

| 上游约定 | 本工作区落点 |
| --- | --- |
| `GLOSSARY.md`（仓库根） | `共享开发\GLOSSARY.md`：全工作区共用的领域术语（原生 API 名、判定规则、状态机叫法） |
| `docs/adr/` | `共享开发\adr\`：难回退的决策各写一份，例如"为什么禁用 IL Transpiler""为什么只用 EnableTag" |

建 `GLOSSARY.md` 的收益很直接：技能（以及任何模型）读代码时先读它，命名和判定就不会各说各话。**但它是活的**，只有真的被拷问、被修改才有价值，摆在仓库里发霉不如不建。

## 4. 工具链映射

技能里凡是出现下面这些动作，换成对应命令：

| 上游说法 | 本工作区命令 |
| --- | --- |
| typecheck / build | `Build-Mod.ps1`（开发版）；发布候选加 `-PublicRelease` 走零能力校验 |
| test suite / run tests | `Run-Regression.ps1` |
| 单元测试文件 | 回归脚本里的真实断言（文案、判定、定价等核心不变量） |
| 装进环境验证 | 直接装机 + 热重载 |
| e2e / 浏览器验证 | 真机 Slot 1 验证，必要时用桥接工具、探针、`native-input.ps1` 键鼠模拟 |
| CI 检查 | 无。`Build-Mod.ps1` + `Run-Regression.ps1` 就是我们的门禁 |

`tdd` 技能的红-绿循环照样成立：先写一条会红的回归断言（比如"成色判定必须只认 realCondition"），再改代码让它变绿。**不要**为了让测试跑起来去拆出假的策略层，那正是 `AGENTS.md` 明令禁止的套娃。

## 5. 子智能体

技能里说"派一个带全新上下文窗口的子智能体"，在本环境用 `subagent` 工具，等价。多模型分工（主模型定方案 + `deepseek-v4.1-flash` 执行）照旧，技能只规定任务边界，不规定谁来干。

## 6. 哪些技能对本项目基本无用

省得白试：

| 技能 | 判断 |
| --- | --- |
| `triage` | 没有外部工单来源，用不上 |
| `wayfinder` | 单人开发、一个玩法系统的规模够不上"一个会话装不下" |
| `pr` | 不做 PR，本地 Git 直接提交 |
| `wizard` | 生成 bash 交互向导，Windows 上跑不了；真需要就手写 PowerShell |
| `to-questionnaire` | 没有"别人"可问 |
| `research` | 我们的"一手来源"是反编译产物，技能默认对着在线文档；思路可用，落点要改 |
| `implement-spec` | 并行前沿那套要求工单图 + 多个实现子智能体，收益主要在超大批量；小项目不如直接干 |

真正会天天用到的见 `评估-对深空当铺模组开发.md`。
