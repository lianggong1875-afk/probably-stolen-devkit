一个粗糙的想法到来了，大到单个智能体会话装不下，还裹在迷雾里：从这里通往 **目的地** 的路还看不见。探路要的是找出这条路，不是朝目的地硬冲。本技能在仓库的工单系统上把这条路画成一张 **共享地图**，然后逐个处理它的 **决策工单**（那些答案是决策、而不是一段待执行构建的问题），直到路线清晰。

目的地因任务而异，而给它命名是绘图的第一件事：它塑造每一张工单。目的地可能是一份要交接出去反复迭代的规格说明，一个要在规划开始前锁定的决策，或者一项就地完成的改动，比如数据结构迁移。地图与领域无关：工程工作、课程内容，只要形状对得上都行。

## 只做规划，不动手

wayfinder 默认做的是 **规划**：每张工单了结一个决策，路一清晰地图就算完成，在有人去动手之前不再剩下任何要决定的事。忍不住想直接干活，通常正是已经走到地图边缘、该交接了的信号。某项任务可以在它的 **Notes**（备注）里覆盖这条，把执行也纳入地图本身，但没有这项声明时，产出的是决策，不是交付物。

## 用名字指代

每张地图、每张工单都是工单系统里的一个条目，所以都有一个 **名字**：它的标题。在人会读到的一切地方（叙述、地图里的 Decisions so far），都用那个名字指代它，绝不要用一个裸 id、编号或 slug。一整屏 `#42, #43, #44` 根本读不下去；名字一眼就读得懂。id 和 URL 并没有消失；由名字包住链接，它们待在名字 _里面_，绝不代替名字。

## 地图

地图是本仓库工单系统上的单个工单，带 `wayfinder:map` 标签，是唯一权威产物。它的工单都是地图的子工单。

地图是 **索引**，不是存储。它列出已经做出的决策，并指向持有细节的工单；一个决策只存在于一个地方，也就是它的工单，因此地图绝不重述它，只给一句要点加链接。

**地图、它的子工单、阻塞关系与前沿查询具体落在哪里，由工单系统决定。** 工单系统本应已经提供给你。如果没有，让用户运行 `/setup-matt-pocock-skills`。查工单系统文档里 “Wayfinding operations” 一节，看 _这个_ 仓库是怎么表达的。如果确实没有提供任何工单系统，默认用 local-markdown 工单系统。

### 地图正文

低分辨率下的整张地图，每个会话加载一次。未关闭的工单 **不** 列出来：它们是未关闭的子工单，靠查询找到。

```markdown
## Destination

<what reaching the end of this map looks like: the spec, decision, or change this effort is finding its way to. One or two lines; every session orients to it before choosing a ticket.>

## Notes

<domain; skills every session should consult; standing preferences for this effort>

## Decisions so far

<!-- the index: one line per closed ticket, enough to judge relevance, then zoom the link for the detail the ticket holds -->

- [<closed ticket title>](link): <one-line gist of the answer>

## Not yet specified

<!-- see "Fog of war": in-scope fog you can't ticket yet; graduates as the frontier advances -->

## Out of scope

<!-- see "Out of scope": work ruled beyond the destination; closed, never graduates -->
```

### 工单

每张工单都是地图的 **子工单**；工单系统里的 issue id 就是它的身份。它的正文是那个问题，篇幅控制在一个 100K token 的智能体会话之内：

```markdown
## Question

<the decision or investigation this ticket resolves>
```

每张工单都带一个 `wayfinder:<type>` 标签，取值是 `research`、`prototype`、`grilling`、`task` 之一（见 [工单类型](#工单类型)）。`wayfinder:` 标签是地图和它的工单唯一会带的标签，绝不要带 `ready-for-agent` 这类分诊标签：它们是决策，不是实现工作。

会话 **认领** 一张工单的办法，是在任何工作开始之前 **先** 把它指派给驱动这张地图的开发者，这样并发的会话就会跳过它。那个指派对象 _就是_ 认领本身：未关闭且未指派的工单就是没被认领的。

阻塞关系用工单系统的 **原生** 依赖关系表达：这一点不可省，因为它让前沿在工单系统自己的界面里 _可视化_ 呈现，人不用打开地图就能看到哪些能动手。只有缺少原生阻塞能力的工单系统才退回正文里的约定写法。当阻塞它的每一张工单都已关闭，这张工单就是 **已解除阻塞**；**前沿** 则是未关闭、已解除阻塞、未被认领的子工单，也就是已知范围的边缘。

答案不属于正文；它在有结论时记录（见 [顺着地图推进](#顺着地图推进)）。了结工单过程中产生的产物从工单里链过去，不要粘进来。

## 工单类型

每张工单要么是 **HITL**（人在环路中，要和一个能自己表态的人 _一起_ 推进），要么是 **无人值守**（AFK），由智能体独立驱动。HITL 工单只能通过那次实时交流了结；智能体绝不替人站在人那一侧（一个自己回答自己问题的 grilling 智能体已经破坏了这条）。

- **Research**（无人值守）：读文档、第三方 API，或知识库这类本地资源，把某个决策在等的事实挖出来。由子智能体调用 Skill 工具加载 research 来了结。需要当前工作目录以外的知识时用它。
- **Prototype**（人在环路中）：通过调用 Skill 工具加载 prototype，做一个便宜、粗糙、具体的东西让人有得反应（一份大纲、一个粗版方案、一个桩，或 UI/逻辑代码），以此提高讨论的保真度。把原型作为产物链接进去。当“它该长什么样”或“它该怎么表现”是核心问题时用它。
- **Grilling**（人在环路中）：对话。默认情况。始终调用 Skill 工具两次，分别加载 grilling 和 domain-modeling。
- **Task**（人在环路中或无人值守）：在能做 _决策_ 之前必须完成的手工活：没有可决策、可原型、可研究的内容，但讨论在它完成前卡住。注册某个服务以便评判它的 API，开通访问权限，搬一遍数据好让人看清它的形状。这是唯一 _动手_ 而不是决策的类型，它靠解除某个决策的阻塞来立足，而不是靠交付目的地。智能体自己能干的就独立干（无人值守）；干不了的，交给人一份精确的清单（人在环路中）。工作完成即了结；答案里记录做了什么，以及后续工单依赖的派生事实（凭据位置、新 URL、行数）。

## 战争迷雾

地图是 _故意_ 不完整的：看不见的东西不要画上去。已开出的工单之外是 **战争迷雾**（fog of war）：那些你判断得到要来、却还定不下来的决策与调查，只有模糊的轮廓，因为它们挂在尚未有答案的问题上。了结一张工单，就清掉它前方的雾，把此刻已能明确的部分升格成新工单，一次一块，直到通往目的地的路清晰、不再剩任何工单。

地图的 **Not yet specified**（尚未明确）小节就是写下这份模糊轮廓的地方：怀疑要问的问题、以后要回来处理的范围。它是 _通向_ 目的地、还没被探明的那段前沿：这里的一切都在范围内，只是还不够清晰，开不出工单。怎么写都行，看得多清就写多全；它同时是给协作者的指路牌，让人读到这项任务正往哪去。

**写进迷雾还是开工单？** 判据是此刻能不能把问题精确说出来，_而不是_ 此刻能不能回答它。

- 问题已经足够清晰时就 **开工单**，哪怕它被阻塞、此刻动不了。
- 还说不那么清楚时就写进 **尚未明确**。不要把迷雾预先切成工单大小的碎块：它比一张工单更粗，等前沿推过去，一块可能升格成好几张工单，也可能一张都不出。

**尚未明确** 不包含已经决定的事（Decisions so far）、已经开出的工单，以及超出范围的内容（下一节）。

## 超出范围

迷雾只会 _朝_ 目的地聚拢。目的地划定范围，因此目的地之外的工作就是 **超出范围**：它不是迷雾，也不该放进 **Not yet specified**。它在地图上拿到自己的一节 **Out of scope**（超出范围）：你已经有意识排除在 _这项_ 任务之外的工作。决定它落在这里的是范围，不是清晰度。

超出范围的工作永不升格（前沿到目的地为止），所以只有目的地被重画时它才会回来，而且是作为一项新任务回来，不是接着干。

把某件事判为超出范围是一次划定范围的动作，不是路线上的一个步骤。当一张已存在的工单被发现落在目的地之外（绘图时错划进来，或被某次结论暴露出来），**关掉它**（已关闭的工单毫无疑问地不在前沿上），并在 **Out of scope** 小节留一行：要点，加上它为什么超出范围，附上那张已关闭工单的链接。它不进 **Decisions so far**，那一节记录的是实际走过的路线；范围边界不是路线上的步骤。

## 调用方式

两种模式。无论哪种，**每个会话绝不要了结超过一张工单**，research 工单除外。

### 画地图

用户带着一个粗糙的想法调用。

1. **给目的地命名。** 调用 Skill 工具两次，分别加载 grilling 和 domain-modeling，把这张地图要通往的东西钉死：那份规格说明、那个决策，或那项改动。目的地划定范围，所以先把它定下来。
2. **摸清前沿。** 再拷问一轮，这次用 **广度优先**：在整个空间里铺开，而不是在某一根线索上挖深，把尚未解决的决策和此刻就能迈的第一步摆出来。**如果这一轮没探出迷雾**（通往目的地的路已经清楚，整段行程小到一个会话就够），你不需要地图。停下来问用户想怎么继续。
3. **创建地图**（标签 `wayfinder:map`）：填好 Destination 和 Notes，Decisions so far 留空，把迷雾勾进 **Not yet specified**。
4. **把此刻能明确的工单开出来**，作为地图的子工单，然后在 **第二遍** 里连阻塞边（工单要先有 id 才能互相引用）。交叉引用也在这一遍里写，用真实 id：占位符 `#<n>` 会自动链到一张不相干的工单上。连完之后，它们自然分成前沿和受阻两堆；还明确不了的一切留在迷雾里，也就是 **Not yet specified** 小节。
5. **把 research 子智能体发出去。** 对你刚创建的每张 `research` 工单，起一个带全新上下文窗口的子智能体，调用 Skill 工具加载 research 去并行了结它，把它的发现落在一条用完即弃的 `research/<name>` 分支上，并由工单给出一个上下文指针。推这条分支，但不开 PR：它永远不会被合并。
6. 停下：绘图是一个会话的工作量；它不亲手了结任何工单。

### 顺着地图推进

用户带着一张地图（URL 或编号）调用。工单是 **可选的**：没指定工单时，由你挑下一个决策，而不是用户挑。

1. 加载 **地图**：低分辨率视图，不是每张工单的正文。
2. 选工单。用户点了名就用那张。否则按顺序取第一张前沿工单。**认领它**：在任何工作之前把它指派给自己。
3. 按它 `wayfinder:<type>` 标签指名的类型了结它（见 [工单类型](#工单类型)）。读标签，不要只看正文：正文从不写类型。**按需拉近**：随取随读任何相关工单或已关闭工单的完整正文；`## Notes` 块里点名的技能，用 Skill 工具加载。拿不准时，调用 Skill 工具两次，分别加载 grilling 和 domain-modeling。
4. 记录结论：把答案作为 **结论评论** 发出，**关闭** 工单，并在地图的 Decisions so far 里 **追加一个上下文指针**。
5. 补上这轮新冒出来的工单（先建后连）；把答案已经能明确的部分从迷雾里升格出来，把每一块升格过的内容从 **Not yet specified** 里清掉，让它只以新工单的形式存在。如果答案揭示某张工单（这张或别的）落在目的地之外，**把它判为超出范围**，不要在路线上把它了结掉。如果这个决策让地图的其他部分失效，就更新或删除那些工单。

用户可能会并行跑已解除阻塞的工单，所以要预期别的会话同时在改工单系统。
