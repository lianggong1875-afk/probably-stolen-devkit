# 技能机制

[`writing-for-agents`](SKILL.md) 里技能专属的那一支：当文档是技能时，哪些东西变了（frontmatter、调用方式的选择、路由技能）。除此之外的写法，全在 `SKILL.md` 里的通用参考中。

## 调用方式

两种选择，互相交换两种负载：

- **模型触发**的技能保留 `description`，这样智能体能自主触发它，其他技能也能抵达它。你依然可以敲它的名字：模型触发永远_包含_人的触达；description 只增加智能体侧的发现能力，绝不剥夺人的那一侧。description 是这个技能的顶层上下文指针，被强制永久加载：用常驻的上下文负载换可被发现。内容全是参考的模型触发技能，也是共享参考的一个落脚处：别的技能可以调用它，于是多个技能都需要的参考只住一处。做法：不写 `disable-model-invocation`，并写一段面向模型的 description，把触发分支都带上（`SKILL.md` 里写指针的规则完全适用）。
- **用户触发**的技能把 description 从智能体可及的范围内拿掉：只有人敲它的名字才能调用它，其他技能都不能。上下文负载为零，但它花认知负载：你就是那个必须记住它存在的索引。做法：设 `disable-model-invocation: true`；`description` 转为面向人：一行摘要，把触发清单剥掉。

只有当智能体必须自己抵达该技能，或另一个技能必须抵达它时，才选模型触发。如果它只靠手敲触发，就做成用户触发，一分上下文负载都不付。

两个用户触发的技能都需要的共享参考，两边都住不了：没有 description，谁也触发不了谁。把它推到技能系统之外的普通文件里：外部参考，任何技能都能指向它。

## 按调用方式拆分

拆分里的调用切法（顺序切法在 `SKILL.md` 里）：当你有一个独立到该由它自己触发的引导词（一个你真的会在提示词里用的触发词），或另一个技能必须抵达它时，就把这个模型触发的技能拆出去。你要为新增的常驻 description 付上下文负载，所以那份独立触达必须值这个价。

## 路由技能

当用户触发的技能多到超出你能记住的数量，堆积起来的认知负载由**路由技能**来治：一个用户触发的技能，点名其他技能以及各自何时该去取，这样人只需要记住一个技能，而不是许多个。它只能提示，绝不能触发它们：用户触发的技能没有 description，除了人，什么都抵达不了它们。
