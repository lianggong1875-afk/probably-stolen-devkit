# 工坊模组蒸馏 SOP（长期任务的自动化流水线）

> 这是一份**自足**的作业书：任何一个新会话、子代理或定时任务拿到它，都能从零接着干。
> 状态不靠记忆，靠 `共享开发\模组制作经验库\蒸馏台账.json`（唯一事实源）。

## 0. 这个长期任务在干什么

把 Steam 创意工坊里别人做的《深空当铺》模组**读懂、拆透、沉淀**，产出四样东西：

| 产出 | 落在哪 | 判据 |
| --- | --- | --- |
| **技能** | `工具库\skills\probably-stolen-moddev\` | 下次做同类功能，照技能就能做出来 |
| **经验** | `共享开发\模组制作经验库\*.md`（接口进 `03`、坑进 `07`、范式进 `14`、规范进 `20`） | 能被检索到，且是**验真过**的（对着 `Assembly-CSharp` 或真机日志） |
| **工具** | `工具库\` 下可直接跑的东西 | 跑一次能出结论，不是文档 |
| **规范** | `共享开发\模组制作经验库\20-各类模组制作规范.md` | 按类型给出"要做哪些东西、美术需求多大、代码骨架长什么样" |

**不产出**：对模组的评价、作者八卦、与我们无关的功能罗列。每份档案结尾必须有「对我们的可用点」，点名到 `深空电玩` 或 `深空当铺：可能是群友` 的**具体功能**。

## 1. 选批纪律（用户的排序，别自己发明）

1. **优先大型扩展**：整块新产业/新区域/新玩法（订阅 >2 万且体积 >5 MB，或简介里出现 200 items / 新职业 / 新机器群）。
2. **其次有特色的中型扩展**：单一机制做到极致（声望系统、升级路径、鉴定三件套）。
3. **再次有意思的小功能**：几十 KB 但手法巧妙（截图/贴纸入口/一键投料）。
4. **热门优先**：订阅量是第一权重，但**大型 > 热门 > 新颖**。
5. **美术类只看实现方式与美术需求**：立绘/贴图怎么接、要多少张、多大分辨率、pivot/PPU 多少。
   **重新绘制的纯美术资源包一律跳过**（台账 `skip` 里记原因），不读它的几千张贴图。
6. 已蒸馏的**绝不重做**：台账里有就是有。
7. **热度扫完之后改"按缺口选"**（batch-16 起的策略）：不再只看订阅量，而是列出"我们还没系统接触过的主题"
   （保险/索赔、物流/委托链、天气/环境、本地化框架、音频系统…），按主题去池子里搜关键词。
   **搜不到本身就是结论** —— 说明这块工坊里没人做，我们得自己设计，那就更值得先读所有相关的东西。
   搜法见 `distill_queue.py` 的思路：把 `title + description` 拼起来匹配主题词，按订阅降序看。

## 2. 一条命令的流水线

```powershell
# 0) 体检：池子多大、还剩多少、有没有欠账
python 工具库\workshop-tools\distill_queue.py status --top 20
python 工具库\workshop-tools\distill_queue.py pend      # 上一批有没有忘记退订的

# 1) 刷新工坊池（约 1 分钟；台账/列表快照落在 缓存文件夹\workshop-scan\）
python 工具库\workshop-tools\distill_queue.py refresh

# 2) 选批：打分 = 订阅量 × 体积档 × 扩展关键词，纯美术重绘自动沉底
python 工具库\workshop-tools\distill_queue.py next --n 10
#    输出 queue-batchN.json；把选中的 id 记下来

# 3) 订阅 + 触发下载（必须等状态变成「已安装」再反编译）
# 工坊工具位置（2026-11-28 实测在 缓存文件夹\workshop-uploader\bin；若被移动，用 dir /s /b WorkshopUploader.exe 定位）
cd 缓存文件夹\workshop-uploader\bin
.\WorkshopUploader.exe --sub 3829730904,3832840208
.\WorkshopUploader.exe --list-subs | findstr /C:"已安装"

# 4) 反编译 + 架构透视
python 工具库\workshop-tools\distill_prep.py 3829730904 3832840208
#    源码在 缓存文件夹\decomp_ws\<id>\，透视报告在 缓存文件夹\decomp_ws\_reports\<id>.txt

# 5) 分工读源码、写档案（见第 3 节）
#    并行子代理，一个子代理 1~2 个模组，禁止一个子代理吃 5 个大型模组

# 6) 记账 + 清账
python 工具库\workshop-tools\distill_queue.py mark --batch 8 --ids 3829730904,3832840208 --archive-map 3829730904=BrewingExpansion
# 工坊工具位置（2026-11-28 实测在 缓存文件夹\workshop-uploader\bin；若被移动，用 dir /s /b WorkshopUploader.exe 定位）
cd 缓存文件夹\workshop-uploader\bin
.\WorkshopUploader.exe --unsub 3829730904,3832840208
python 工具库\workshop-tools\distill_queue.py unsubbed 3829730904,3832840208

# 7) 清缓存（反编译产物用完即弃，只留 _reports）
rm -rf 缓存文件夹\decomp_ws\<id>

# 8) 沉淀与同步
python 工具库\kb-tools\kb_pipeline.py build
powershell -NoProfile -ExecutionPolicy Bypass -File 工具库\kb-tools\Sync-ModdevSkill.ps1
```

**只有用户本来就订阅着的模组**（不是为蒸馏订阅的）才用 `mark --no-unsub`，其余一律退订。
`pend` 非空 = 上一批欠了退订，先清再开新批。

## 3. 分工与档案规格

- 一个子代理负责 1~2 个模组；大型模组（>2 万行）单独一个。
- 子代理必须**先看透视报告再决定读哪几个文件**（`_reports\<id>.txt` 有类型/方法/Harmony 补丁/资源清单）。
- 档案路径：`共享开发\模组制作经验库\workshop-distill\<工坊id>-<英文短名>.md`；同一批里同类小模组可合并成一份（如 `生产链与自动化四例.md`），但**每个模组都要有独立小节 + 独立 id**。
- 档案骨架（不许缺项）：
  1. 头三行：工坊 id、反编译目录、**这个模组为什么值得读**。
  2. 规模与结构：文件数/行数/最大的文件/有没有冻结副本。
  3. 它怎么做这件事：**调用的是哪些原版接口**（点名到类与方法），哪些地方非 Patch 不可。
  4. 关键代码摘录（≤60 行，带文件与行号），说明**为什么这么写**。
  5. 踩坑与红线（作者绕过了什么、我们别学什么）。
  6. **对我们的可用点**：给 `深空电玩` / `深空当铺：可能是群友` 的具体功能，能落地的写法。
- 跨模组结论**必须往上一级沉淀**，别只躺在档案里：接口 → `03`、坑 → `07`、范式 → `14`、规范 → `20`、立绘 → `08`。
- 结论落库前**必须看包内 `manifest.xml` 原文**（ID 与 Name 可能不一致，作者改过名没换 ID——踩过）。

## 4. 收尾（每批必做，缺一项算没做完）

1. `19-工坊模组逆向与蒸馏.md` 加一节批次索引表（id/模组/档案/核心收获），并把合计数字改对。
2. `蒸馏台账.json` 已由 `mark` 写好；`status` 复查"待退订 = 0"。
3. `kb_pipeline.py build` 重建 `CATALOG.json` / `DISTILL_DIGEST.md`；`Sync-ModdevSkill.ps1` 同步技能。
4. 缓存：`缓存文件夹\decomp_ws` 只剩 `_reports`（几十 MB 以内）。
5. **提交落盘**（2026-11-28 补：前六批就是因为缺这一步，59 个文件在工作区裸奔了很久）：
   ```powershell
   git add 共享开发/模组制作经验库 工具库/README.md 工具库/workshop-tools 工具库/skills
   git commit -m "docs(kb): 蒸馏 batch-N ..."
   ```
   - **只 add 这两个目录**，别 `git add -A`（工作区里常有别的窗口的代码/美术改动）；
   - **不要切分支**：蒸馏产出是共享资产，不属于任何功能分支。真要单独成支，事后 `git cherry-pick`；
   - 提交是备份的前提 —— 没提交的档案在 `Backup-All.ps1` 眼里不属于仓库内容，只有资产包会捞到。
6. 给用户一份**阶段性报告**：这批读了什么、最大收获三条、沉淀到哪、下一批候选；然后继续下一批。

## 5. 红线（踩过的，别再踩）

- **不动 Slot 0**；真机只进 Slot 1。蒸馏本身不需要进游戏。
- **不发布任何东西到工坊**（`--sub/--unsub` 之外的上传动作要用户明确同意）。
- 工坊工具**每个分支都要 `return`**：`--sub/--unsub` 少一个 `return` 会一路走到 `CreateItem`，
  在工坊里建出空物品（实测踩过 4 次，见 `07-踩坑台账`）。
- 另一个 AI 窗口会在同一工作区切分支；动 git 前先 `git status`，**别提交别人未提交的文件**。
- 反编译目录里有 `CON`/`PRN` 之类 Windows 保留名会让 `git add -A` 失败；反编译产物本来就不入库。
- 报告里凡是没真机验证的，写"未真机验证"，不要暗示已验证。
