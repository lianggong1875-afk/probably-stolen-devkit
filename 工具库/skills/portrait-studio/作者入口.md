# 立绘作者工具

需要调整图片时，双击本目录的「启动立绘调整工具.cmd」。支持拖动位置、四角缩放、保存进度、导出 PNG 和管理器包，自带运行环境。操作说明见[立绘调整工具说明](tools/portrait-editor/使用说明.md)。

原版顾客可按职业单独换图，也可按共用图片替换。告诉 AI“只换这个职业”或“所有用这张图的人一起换”；详见 [职业与图片键](protocol/原版职业与图片键.md)。

先选适合你的路线，把对应的整个 skill 文件夹交给 AI：

| 你的情况 | 使用哪套工具 | 会怎样处理 |
| --- | --- | --- |
| 愿意依赖管理器，把显示和调整全交出去 | `skills/portrait-studio-managed` | 整理静态资源，停止已托管位置的原换图，由管理器负责显示 |
| 已经有能换图的模组，想保留自己的显示系统 | `skills/portrait-studio-adapter` | 保留现有功能和调整方式，在原工程加接口 |
| 有图片，要从头制作模组 | `skills/portrait-studio-pack` | 制作能独立换图、也能提供管理器接口的包 |
| 自动变表情、播放动作或按剧情换图 | `skills/portrait-studio-dynamic` | 保留作者动画和独立设置，增加动态显示交接接口 |

不清楚怎么选时，可以直接告诉 AI：“我想全部交给管理器”“我已经有模组”或“我只有图片”。AI 会先推荐路线；工程里能查清的内容直接读取，需要你决定时再用简单的话询问。

原工程接口接入会保留已有大小、位置和配置。托管路线将静态图片的大小位置调整入口移到管理器，保留 NPC、剧情、语音等功能。新包按图片尺寸、锚点和显示布局准备；有特殊缩放或偏移需求时再确认。交付时会写清采用的方式和调整入口。

前三条路线只接静态图片，人物、通缉照片、场景、自定义 NPC 都可以提供多张候选。动态路线用于动画、表情和随剧情变图，仍由作者模组负责播放。混合模组分别声明静态和动态范围；同一显示位置只接一套写图接口。自定义 NPC 由原模组负责创建、剧情和语音。

动态接入的源码与范例已经提供，管理器完成 `dynamic-display-control/1` 接线后才能通过新接口控制动画。已有动态模组在当前管理器中仍使用各自的专用适配。详见[动态接入协议](protocol/动态立绘接入协议.md)。

协作接口由作者端最终写图，管理器按位置让位；托管路线由管理器最终写图，作者退出声明范围。原生托管图片包不逐帧运行，自定义 NPC 仍须创建者登记实际表面。协作需要管理器支持 `static-display-transaction/1`，托管需要支持 `portrait-studio-managed/1`。独立新包不依赖管理器即可换图和切换套装。

给 AI 的请求示例：

> 我想把静态立绘全部交给管理器。请读取 portrait-studio-managed/SKILL.md，保留 NPC、剧情和语音，整理图片并移除已托管位置的原换图和大小位置控制。

> 我已经有能换图的模组。请读取 portrait-studio-adapter/SKILL.md，保留原来的功能和大小位置设置，加上静态资源接口。只修改我的工程。

> 我只有图片。请读取 portrait-studio-pack/SKILL.md，制作独立立绘包，房东和导师各有多个候选，另有通缉照片与场景背景。请推荐默认的大小位置处理方式。

> 我的模组有自动表情和两套服装。请读取 portrait-studio-dynamic/SKILL.md，保留原动画和独立设置，增加动态接口，只修改我的工程。

开发说明见 [静态资源协议](protocol/静态资源公开协议.md) 、[托管显示协议](protocol/托管显示协议.md) 和 [管理器接入说明](protocol/管理器接入说明.md)。新包构建需要 Python 3.10+、.NET SDK 和目标游戏目录。每套 skill 自带所需代码与文档，可单独分发。

先看 [范例入口](examples/范例入口.md)：提供可构建的独立包、托管包，以及原工程和自定义 NPC 的接入代码。范例可在新目录生成源码与成品；普通制作从这些工程开始，保留入口与 SDK，按自己的资源和构图修改。

查看工具自带演示见 [使用说明](使用说明.md)。工具代码、协议和原创几何示例可复制、修改和分发；图片使用权由作者自行确认，游戏程序集不随包分发。
