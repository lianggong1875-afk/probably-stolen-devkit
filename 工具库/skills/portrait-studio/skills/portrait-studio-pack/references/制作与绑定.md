# 制作与绑定

原版职业与共用图片分开声明，填写前读 [职业与图片键](原版职业与图片键.md)，身份见 [职业表](vanilla-client-roles.tsv) 或 [图片键表](characters.tsv)。

先用 scripts/new_pack.py 创建独立工程，保留自己的 mod ID、作者和游戏版本。没有管理器前置；template 的 Entry.cs 自带桥、原生绑定和生命周期驱动。

保留模板在首帧初始化的入口。游戏在 OnEnable 返回后才登记自身目录，不能把 StaticBridge 构造移进 OnEnable。首帧前停用会取消初始化；初始化失败只记录一次并清理，重新启用才重新尝试。

首帧只代表模组目录已登记，存档和显示对象仍可能未创建。保留 SDK 的 `PlayerStore.HasInstance` 检查；`PlayerStore.Instance` 会自动创建背包等对象，不能用它判空。原生绑定等待实际对象和可信原图，游戏载入后继续工作；自定义绑定跟随创建者的对象就绪事件。Image 以有效的 overrideSprite 判断实际图片，停用先还原自己仍拥有的显示，再释放自建资源。

每个 target 是一个明确静态显示位置；原生人物、wanted1..9 的 photo、场景背景/旅行卡分别登记。每个 resourceSet 与一个完整身份对应，resources 可列多张图及各自不可变 resourceRevision。target.candidateResources 列引用，defaultMode=resource/defaultResource 选择独立默认图。更换内容创建新 resourceRevision，清单更新 catalogRevision；只有 writer 范围变化才更新 revision。

填写完整 texture、SHA256、geometry.rect/PPU/pivot/border。16:9 限制适用于原生场景的 Sprite rect。

## 构图、大小与位置

原图像素尺寸、Sprite 在场景中的大小和实际裁切区域是三件事。原图宽高及 Sprite bounds 只作为几何参考；是否存在固定框，须检查实际 SpriteRenderer/Image、Mask/RectMask2D、布局和遮挡。没有运行画面时，说明哪些结论来自代码、哪些效果待查看，不凭尺寸断言一定溢出或被裁掉。

按作者想要的构图确定显示。未说明时，保留新图完整构图和比例，以实际场景位置设置合理的默认大小和锚点，保留调整入口。人物可根据脸部、身体和站位选锚点，不强行按原图宽或高二选一。确需澄清时问完整人物、突出半身或参考效果；由 AI 换算 PPU、pivot 和位置，避免让作者选择这些参数。作者已说明构图时直接执行。

裁切或改变 geometry.rect 会影响可见内容，按作者要求采用；不默认裁成半身，也不为迁就原图尺寸拉伸、补边或重采样。若确有遮罩或现有绑定无法满足构图，说明具体限制，再在该包可控制的范围内处理；改变共用布局前须确认不会影响其他角色或界面。不要把未经检查的多套构图分别塞给不同角色作为默认成品。

资源几何记录默认比例与锚点，pivot 可越界；对象布局记录显示位置。管理器的 scale/x/y 只追加一次，避免把同一缩放或偏移同时写进资源几何和对象布局。已有工程默认保留原有构图及调整入口。

默认保留 PNG 原分辨率，PPU 负责换算显示大小，不据此烘焙固定分辨率的图片。去背、裁切和降低分辨率分别按作者要求处理；转换与内存判断见 [图片处理与预算](图片处理与预算.md)。

调整默认构图用 `scripts/framing.py`，可拖动、缩放和选锚点，直接保存到清单。用法与去像素化选项见 [构图与显示](构图与高清显示.md)。先给可调整的初始效果，按预览校准；不按角色名前缀硬套不同构图。

StaticBindings 原生人物跟踪共享顾客对象的真实角色，换人先解绑，未知角色不使用上个人物图片。隐藏保持 visit，重新显示递增 epoch；新登场更新 visit。原图从游戏序列化入口保全。场景资产无法唯一确认时，改在创建处显式绑定并提供可信原图，不能抓当前已美化 renderer 当原图。

自定义 NPC 由原作者创建，清单只声明显示。调用 BindSprite(targetId, renderer, original, visitId, originDisplayId, originVisitId)，Image 同理。originDisplayId 来自创建者，稳定表示实际表面；visit 表示一次登场。同对象换人物再次绑定；未知人物用 Unbind。批量绑定 BeginBatch/EndBatch；Tick 仅检查已知对象。

先运行 validate.py 检查源码清单/图片，再用 build.py 在 Mods 外构建严格运行白名单。交付前集中检查启停/还原、多个候选、同对象换人、照片赏金、场景、custom、silent 与事务失败恢复。完整字段见公开协议和 Schema。

多套图片使用 portraitSets，规则见公开协议“套装声明与切换”。保留 Standalone/PortraitSets.cs 及入口创建、Tick、Dispose；套装设置保存稳定ID，显示名称可自定义。不要改写磁盘 defaultResource 来切换套装。

保留 StaticBridge 的生命周期即可自动提供活跃位置查询，无需单独注册服务。自定义位置须在真实显示时 Show、隐藏或复用前 Hide；仅列入清单不会被当作正在显示。
