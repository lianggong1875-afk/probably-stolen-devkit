# 原版职业与图片键

想只换某个职业，查 [职业表](vanilla-client-roles.tsv)；想替换所有使用同一原图的原版人物，查 [图片键表](characters.tsv)。需求不清楚时问：“只替换这个职业，还是所有用这张原图的人？”已经说清就直接制作。

原版会让多个职业共用图片，也会随机选图。职业身份按顾客 `identifier` 精确匹配，不能从图片、文件名或显示名称推断。

| 用途 | subject.owner | subject.key / binding.key | binding.type |
| --- | --- | --- | --- |
| 只换下层区医生 | game | vanilla_client_lowLevelDoctor | sprite-key |
| 只换中层区护士 | game | vanilla_client_nurseMinor | sprite-key |
| 换使用某张科学家图的原版人物 | game | maleSci1 | sprite-key |

以上均为 `kind: character`、`slot: main`。资源组和 target 使用相同身份，候选、套装仍按资源引用填写。`vanilla_client_` 是职业身份前缀，不是游戏 SpriteDict 的图片键，不向字典添加它。

职业表每行一个主 key，`identifiers` 包括游戏分支别名，例如 `junker,junker2` 共用 `vanilla_client_junker`。声明统一使用表中 key；不要拼 `vanilla_client_junker2`。`previewSpriteKey` 只用于目录预览，不能当作来访时的原图。

## 独立包

保留模板 `StaticBindings`，它在主顾客显示处先找本包声明的职业目标；没有职业目标才找本次实际图片键目标。职业声明即使选择原图也优先，不退回共享图片替换。

原图来自本次 `spriteName` 对应的游戏序列化资源；无有效图片键时，仅接受显示处实际出现的可信原版图。无法确认就等待，不拿预览图或第三方替换图当原图。同一来访换原图保持 visit，换顾客则解绑旧目标；顾客引用清空时保留离场显示到隐藏。

`sourceModId` 非空的顾客交给创建者的自定义接入。`isAug` 伪装顾客保留身体图路径，不使用职业替换。职业映射和原图缓存只在内存查询，空闲帧不扫描目录或遍历职业表。

## 既有模组接接口

先确认作者想保留按职业还是按图片替换。按职业公开 writer 时，在真实顾客入口读取 identifier、sourceModId、isAug，并按本表选目标；调用 `StaticContract.cs` 内的 `NativeClientRoles.SelectionKey(identifier, sourceModId, isAug)`。返回空时沿用身体图或自定义来源路径。共用图片字典中的 Sprite 不能提供职业身份。

只加接口默认保留已有替换范围。原工程无法区分实际顾客时，可按图片键公开资源；改为职业替换需要补实际显示入口，再登记 writer。自定义 NPC 使用创建者 ID 与稳定 key，即使借用了原版图片或 identifier 也保持独立身份。

## 托管包与管理器协作

托管包按同一职业表填写两份清单，无需作者增加写图循环。管理器应按真实顾客身份识别职业，保持来源隔离、伪装身体图和当次原图；共享图片选择只用于没有职业选择的情况。多套选择继续使用 `portraitSets`。

协议沿用现有四项身份和消息。独立包自行按职业或图片键绑定；与管理器一起使用时，由支持对应协议的管理器协调显示。
