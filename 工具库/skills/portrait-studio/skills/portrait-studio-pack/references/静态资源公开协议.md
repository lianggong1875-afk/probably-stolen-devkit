# Portrait Studio 静态资源与显示协议

原版顾客支持按职业身份或共用图片声明，见 [职业与图片键](原版职业与图片键.md)。`vanilla_client_` 职业沿用 character/game/key/main 与 sprite-key binding，按 identifier 精确识别，别名合槽；保留 sourceModId 来源隔离、isAug 身体图及当次可信原图。

协议 `portrait-studio-static/1`，能力标识 `static-display-transaction/1`。清单入口 `portrait-studio-provider.json`，官方消息通道 `static-v1`。字段定义见 [清单 Schema](portrait-studio-static-v1.schema.json)、[消息 Schema](portrait-studio-wire.schema.json) 和 [完整示例](static-examples.json)。

## 1. 身份、角色与入口

protocol 固定 `portrait-studio-static/1`，本组能力的 contract 固定 `static-display-transaction/1`。两者及 `renderMode: static` 都必须精确匹配。通道仍为官方 `static-v1`，实际 sender 必须与声明身份一致。管理器 caller ID 为 `PortraitStudio`。

全局显示身份是 `[kind, subject.owner, subject.key, slot]`。人物 main、通缉 photo、场景 background/travel-card 和自定义槽位独立；owner 为实际创建者 ID，原生为 game。字符串精确匹配，不按人物显示名或文件名猜测。

固定入口仍是提供者根目录 `portrait-studio-provider.json`，不接收消息指定的清单路径。实际根目录只经游戏官方 API 按 providerId 获取。

根字段为 `format`、`contract`、`providerId`、`renderMode`、`role`、`catalogRevision`、`resourceSets`。role 为 `writer`、`resources` 或 `both`。

- writer/both 另有非空 `revision` 与 `targets`。revision 仅标识 writer 的身份/接入范围/行为契约；变更须重建 instance 并重新协商。
- resources 根没有 revision、targets 或 binding，不发 writer hello、不 acquire、不声明接管范围。目录存在只表示可供图。
- `catalogRevision` 只标识清单快照，新增资源会改变它，不改变 writer revision 或已有资源引用。
- 每个 resourceSet 含 `id`、`kind`、`subject`、`slot`、`renderMode: static`、`resources`。没有显示 binding/default。set 内每个资源含 `id`、不可变 `resourceRevision`、`renderMode: static`、path、texture、geometry。
- writer 的每个 target 含 `id`、`kind`、`subject`、`slot`、`renderMode: static`、binding、defaultMode。defaultMode=source 表示原工程提供现有静态默认图；defaultMode=resource 须附 `defaultResource`。`candidateResources` 是可为空的资源引用数组。新纯图片包用 resource 默认；旧工程可用 source 默认。
- 资源引用统一为 `{"providerId":"...","setId":"...","id":"...","revision":"资源修订值"}`。候选无论来自何处，其资源集合四项显示身份必须与目标一致。defaultResource/candidateResources 引用也遵守此规则。

管理器自有出口使用 providerId=PortraitStudio、role=resources。跨角色图片按目标身份另建资源集合并映射到相同底层文件；引用不冒用原作者 target/ID。UI 与原路径配置保持，新增内部 opaque ID 映射。导出缓存和用户主动登记备份分别保存，清理时保护当前租用的资源及文件。

每份清单以完整临时文件校验后原子替换。新文件先就位，再提交清单。资源路径在该提供者根内，用 `/`，拒绝绝对路径、链接、空段、`.`、`..`、反斜杠和冒号。资源 ID+revision 指定内容、采样和几何的不可变快照；变更产生新 revision，旧版本留到没有任何显示/准备/回滚引用后清理。同一资源在清单中可保留多个 revision；完整键是 setId+id+resourceRevision。文件元数据只用于失效检测，不代替内容校验。

## 2. 静态资源的几何与纹理

资源 path 是完整基础纹理的静态 PNG，不强制裁为 sprite rect；geometry.rect 指定实际使用区域。PNG/APNG、长度、尺寸和路径检查保持严格。每文件≤32MiB、每边≤8192、基础层总像素≤16,777,216，清单≤1MiB。超过上限拒绝该资源，保留旧选择。

texture 字段：width、height（正整数），filter（Point/Bilinear/Trilinear），wrapU/wrapV/wrapW（Clamp/Repeat/Mirror/MirrorOnce），anisoLevel（0..16），mipMapBias（有限数），colorSpace（sRGB/linear），mipmaps。

- mipmaps.mode=none：仅基础层。
- mipmaps.mode=generate：按基础层生成完整 mip 链，只在原来源本身使用同等自动生成链时选用。
- mipmaps.mode=provided：levels 按 level=1..N 连续列出 path、width、height、sha256，直至 1×1；每级尺寸为 max(1, floor(上级/2))。精确保留已有 mip 时导出全部实际层，不重新生成。所有层均为静态 PNG，完整像素链参与资源修订和预算。
- texture.contentHash 是基础 PNG 文件 SHA256；levels 各自有 SHA256。读取时核对声明尺寸、长度和内容哈希。重建 RGBA32 纹理，保留解码后的颜色/透明度和色彩空间；GPU 压缩格式本身不保留，预算按重建后的格式计算。

geometry 字段：rect={x,y,width,height}（底部为原点的整数像素框，完全位于纹理内），pixelsPerUnit>0，pivotX/Y 为相对 rect 的有限数（允许越界），border={left,bottom,right,top}（非负有限数，横/纵边框和不超过相应 rect 尺寸），meshType=FullRect。

完整纹理、rect、PPU、pivot、border、filter、wrap、色彩空间与 mip 行为分开保真。原生完整资源、旧工厂静态输出、登记备份均遵守此结构，不把已有几何压扁为普通 PNG 默认值。布局派生 Sprite 共享原纹理，不复制纹理，不更改采样状态。

静态接口只支持 FullRect 静态 Sprite。需要 tight/custom mesh、独立 alpha 纹理或特殊材质才能保真的位置，writer 不公开该位置，管理器保留原显示兼容；不静默丢弃这些属性。动态位置不得借导出资源声明为静态 writer。管理器允许用户将动态来源的一帧主动登记为静态候选，候选只声明已导出的固定图片。

照片候选仍保留赏金/姓名等纸面元素；赏金留位是显示准备派生处理的一部分，不修改资源文件。缓存键包含槽位和处理参数，不能把处理后的照片当作未处理的人物资源复用；provided mip 链的照片处理逐层使用相同归一化区域。

## 3. 布局字段与应用顺序

select 的 layout 为完整值对象 `{"scale":1,"x":0,"y":0}`，省略表示本次选择使用该默认值，不能继承上次布局。三个字段须同时提供，scale∈[0.25,3]，x/y∈[-1,1]，非有限或超范围值返回 invalid-layout，不清空旧选择。

follow、original、selected 都接受 layout。先取得模式对应的最终基础 Sprite（follow 包含作者自己的大小位置设置），再且只再应用一次：

```
result.pixelsPerUnit = base.pixelsPerUnit / scale
result.normalizedPivotX = base.pivot.x / base.rect.width  - x / scale
result.normalizedPivotY = base.pivot.y / base.rect.height - y / scale
result.texture/rect/border = base.texture/rect/border
```

不改 Transform/RectTransform，不按透明区域裁出的可见框计算偏移。identity layout 直接复用基础 Sprite。反复应用始终从同一个未加管理器布局的 base 计算，不能用上一次布局结果再叠加。模式或用户参数变更创建新 choiceId，经准备事务成功后切换。来源自行改变默认图的几何时保持该 visit，不触发随机重抽，但重新计划和准备派生 Sprite。

管理器继续按现有角色+图片 slot（file:/vanilla/source-default）读取配置与预设；performance 模式发送 live 快照，草稿与实时预览沿用现有规则。重启应用语义不会因接入改变。

## 4. 消息公共字段

所有消息含 protocol、contract、renderMode、op、providerId（writer ID）。discover 除外，其余来源消息含 revision、instance；会话消息另有 session。instance 每次 writer 启用生成，session 每次管理器 acquire 生成，不复用已退休值。来源 actual sender=providerId，管理器 actual sender=PortraitStudio。来源通过 ModHelper.OnMessage(providerId, "PortraitStudio:static-v1", callback) 监听，通过 ModHelper.SendMessage(providerId, "static-v1", json) 回复。

管理器请求带递增正整数 seq；响应回显 seq 和 requestOp。seq 只在请求成功接受时推进，错误回显失败请求值。相同 seq+相同完整请求可重发并获得相同结果，不重解码/重复赋图；相同 seq 不同内容拒绝。旧 seq 除仍保留的幂等响应外拒绝。来源主动事件 seq=0，另带从1递增 eventSeq；管理器丢弃重复/较旧事件。来源在 commit/rollback/finish 消息处理器内完成无 IO 动作并同步 SendMessage 返回响应；管理器的响应 handler 只把响应入队，不递归发命令。外层管理器 SendMessage 返回后消费响应，发送下一条，完整提交组由同一个管理器 drain 在一次主线程调用内跑完。不得等来源下一次 Update 才返回提交响应。prepare 可异步；commit 缺同步响应立即失败并回滚，不让出帧等待。

hello 必须宣告本 contract、writer targets、instance、revision，以及 memory 快照；旧 SDK 无本 contract 不进入新协作。acquire 只建立静态位置会话，不代表任何图片已加载、旧覆盖已停或显示已提交。租约仍10秒，heartbeat 每3秒；每个成功命令续租，Tick 用实际游戏运行时间检查，暂停随主线程暂停。

acquire 的 targets 数组和 ready 的 targets 回显只表示允许协商的 target 范围，不表示所有表面已协调。角色在每个实际显示事务的 plan 中协商：surfaceId、encounterId、groupId、presentationRole（presenter/silent）、presenterProviderId。唯一 presenter 限定在 [全局显示身份,surfaceId,encounterId]；相同 target 的不同表面各选自己的 presenter。同一组全部 writer 的 presenterProviderId 与 groupId 必须一致，planned 精确回显；不能以 target 级 acquire 静默该角色所有表面。

acquire/prepare 阶段 silent 仍保持旧行为，commit 时才停止该表面所有最终写图、overlay/照片层及可覆盖呈现者的副作用；来源其他剧情/语音/生命周期照常运行。silent 不准备管理器选图；已有恢复默认时预算增量为0，恢复默认尚未就绪时将其纳入计划并按授权准备，期间不赋图。silent SDK 必须返回明确的 shouldWrite=false（或等价显式分支），不能返回 null 或原图再由作者赋值。共享字典、全局 LoopPrefix/AtlasScanPrefix 等跨表面副作用必须在仍受影响的全部表面间协调；不能让一个 silent 表面恢复字典后破坏另一 presenter 表面。无法局部隔离且未覆盖全部影响表面时拒绝协商，保留旧路径。

组提交先让所有 silent writer commit 到不写图状态，再提交唯一 presenter。prepared 到全部 applied 之间管理器同时退出该身份自己的旧写入口，包含共享字典、全局钩子的局部分支和 wanted overlay。rollback 时先撤销 presenter 的本事务显示，再恢复 silent 的旧写入权及管理器原控制；在同一提交段完成，中间不渲染。回滚只触及匹配的显示实例/本事务拥有的改动，不覆盖第三方之后写入的内容。失联时恢复自己的原状态并主动报告，管理器撤销整组协作，不能让幸存 silent 永久失声。

最长单消息65,536字符；targets/display 快照分页为每批≤32条，源事件逐条发。budget 的 texture 列表单计划≤32项；超出拒绝该次资源表示。所有 ID 为≤160字符非空字符串；seq/eventSeq 为1..2^53-1 的整数，主动事件 seq=0。丢失事件后用 query-state 取得当前显示元数据与 memory，不借心跳重选或重抽。

## 5. 选择意图、显示与登场

select 请求字段：targetId、choiceId、mode、setDefault、可选 layout、selected 模式必需的 resource；其他模式不带 resource。choiceId 是会话内不可变意图表的主键，值包含 target、mode、完整 layout 和资源引用。相同 ID 相同值可幂等提交，相同 ID 不同值拒绝。setDefault=true 只更新 target 的默认意图映射用于 UI/后续显示；false 用于某次 encounter 的独立选择。更新默认映射不使已有 choice、plan 或显示失效。stored 只确认意图已接受，不读 PNG、不分配纹理、不更改当前可见图；UI 区分已保存与已应用。

plan 显式引用任一仍保留且 target 匹配的 choiceId，不要求等于默认映射；同 target 的多个 display/encounter 可同时引用不同 choice。只有不再被默认映射、计划、准备、显示或回滚引用的 choice 才可通过 forget-choice（choiceIds 数组）删除；来源按会话保存意图，关闭会话时统一清理。新选择/布局编辑创建新 choice，不就地改变旧意图。show 不自动使用默认意图加载，等待管理器为该实际显示发 plan。

follow 表示本表面唯一 presenter 的来源默认。管理器选择 presenter 时沿用接入前该表面的默认来源优先级/用户来源设置，不按扫描/hello 到达顺序挑选。所需默认来源不能在该表面作为合规 presenter 时，该组继续旧路径并报告未协作；不能让未手选人物悄悄换成另一包默认。手选其他包图片通过 selected 的资源引用实现，不必更换 presenter。original 必须来自首次替换前的可信原图入口，不抓已被其他 writer 覆盖的当前 renderer.sprite。

来源在即将显示之前发 show：targetId、displayId、visitId、eventSeq。displayId 在当前 instance 内唯一标识一个显示对象的整个寿命，复用对象时保持；visitId 在同一个实际登场期间保持，同对象换成另一人物或再次登场必须换值。目标身份由 writer target 确认，不从已经替换过的 Sprite 猜测。相同 target 可同时有多个 displayId，分别持引用。

每个 show 还必须携带正整数 displayEpoch：在同一 displayId 内每次 hide 后再 show 都递增，即使 displayId/visitId/targetId 相同。hide、事务和所有关联响应均回显该 epoch。旧 epoch 永久退休，重新显示不复活旧计划/事务；管理器另保留本地代次以隔离会话变化。

show 另含 surfaceId，用于核对多个 writer 是否作用在同一实际呈现表面。原生格式为 game:SpriteRenderer:<Unity实例ID> 或 game:Image:<Unity实例ID>，只在当前游戏进程/对象寿命内使用，不持久化为角色键。自定义表面由创建者提供稳定 originDisplayId，surfaceId=创建者ID+冒号+originDisplayId；不能确认同一表面时报告冲突，不仅凭 target 就合并两个对象。silent 同样报告 show/hide，但不取得呈现权。

离场时即使游戏 currentClientInstance 已清空也保留最后 target/visit；直到对应 renderer 真正隐藏或销毁才发 hide，字段含完整三元组和 reason。对象直接复用先 hide 旧三元组，再 show 新三元组；未公开人物只 hide 旧绑定，不把旧角色图写给新角色。隐藏再出现属新显示周期，若还是同一次实际登场，visitId 保持、displayId 保持；若已结束再来，visitId 更新。

visitId 是 writer 对本地显示生命周期的标识，不要求不同 writer 猜出相同字符串。原生角色由管理器依照当前游戏实际顾客实例把各 writer 的本地 visit 映射到同一 encounter；custom 创建者可提供 `originVisitId`（创建者 ID 命名空间）用于多 writer 一致映射。无法确认归属时报告冲突，不按人名或时间窗口合并登场。管理器只在确定的新 encounter 抽一次随机；hide/show、同 visit 重试、对话、离场、心跳、资源重载都不重抽。

custom writer 通过清单和 show 报告显示身份及生命周期，由来源的注册回调呈现管理器的选择、原图和布局，无需向管理器公开 Unity 组件。单 writer 无 originVisitId 时，以 providerId、instance、visitId 区分本地登场；跨 writer 合并须有创建者提供的一致关联。第三方图片包使用创建者公开的身份和表面入口。托管路线的实际组件登记另见托管显示协议。


hide 撤销该显示代次全部计划/待准备/已准备/已应用引用；不删除选择意图，也不影响同 target 的其他显示。所有 plan/prepare/commit/rollback/finish/响应都携带 targetId+displayId+visitId+displayEpoch+choiceId+transactionId、surfaceId+encounterId+groupId+presentationRole+presenterProviderId，任一不匹配则 stale-display，旧回复不得作用到复用后的对象。一个 display 同时只允许一个未完成切换事务，finish/rollback 后可为同 visit 再发新事务；选择意图表中其他条目不受影响。

## 6. 先预算、再加载、再提交

每次实际显示或换图执行下列事务。事务只在本 instance/session 和完整显示代次内有效；ID 不复用。

| 请求 → 响应 | 必需字段与行为 |
| --- | --- |
| plan → planned | 完整事务字段。按当前 choice 检查资源身份、修订、文件头、路径及基础 Sprite，给 planId 与 budget，不解码图像。把来源默认图/所选图、布局派生和照片处理都算入计划。 |
| prepare → prepared | 另带 planId、reservationId、grant。核对计划仍有效且授权覆盖 residentDeltaBytes、peakAdditionalBytes。先校验预算再分配/解码；冻结待显示结果，旧图保持，返回实际 memory、heldResources。 |
| commit → applied | 另带 planId、reservationId。只把已准备结果提交到仍匹配的显示对象，不能临时读盘/解码；回显 memory。赋图或来源回调失败须 error，不能吞掉异常后 ack。保留本事务之前的已提交图供 rollback。 |
| rollback → rolled-back | 放弃未提交准备或恢复本事务的上一幅已提交图，释放新引用；隐藏或对象复用后只清事务，不再写旧对象。不撤回更晚事务的结果。 |
| finish → finished | 所有 writer 已 applied 后关闭回滚窗口，释放被替代旧引用。已完成的请求幂等，不重新解码或切图。 |
| cancel → cancelled | 仅放弃未 commit 事务的计划/准备，已 commit 用 rollback。 |

planned 的 budget={residentDeltaBytes,peakAdditionalBytes,textures}；每个 textures 项含 textureKey、residentBytes、alreadyResident。textureKey 在 writer instance 内唯一，代表实际纹理分配与处理变体；多个 Sprite/rect/layout 共用同一纹理只列一次。不同 writer 的相同图片若各自解码，属于两份实际分配，管理器分别计数。计划把旧图继续占用的空间算在当前 resident，不假设换图先释放旧图。

grant={residentDeltaBytes,peakAdditionalBytes} 必须大于等于计划且由管理器绑定该 planId/reservationId；不能拿另一计划授权使用。来源本地预算不足或资源在计划后变化，返回 budget-exceeded/resource-changed，不偷偷扩大授权。未提交计划/准备的有效期为2秒（游戏运行时间）；超时释放准备、发 transaction-expired 与 memory。commit 后若未 finish，回滚窗口保持到 finish/rollback、hide、release 或租约超时，不在任意2秒后擅自把已显示图回滚。

管理器先为全组 writer 预留 residentDeltaBytes 与同时发生的 peakAdditionalBytes，再逐个 prepare。全部 prepared 才在同一不让出帧的主线程提交段中暂停相应旧门控/覆盖并逐个 commit；有失败立即 rollback 全组并恢复旧控制。全部 applied 后标记这组成功，逐个 finish。finish 只释放旧引用，不调用作者写图或读盘；丢失响应重试，不能因超时拿新 choice 覆盖。对象在提交过程中变化则本组失败。

这是同一主线程帧内的逐组提交，不承诺跨进程事务。来源失联/禁用/租约超时恢复本地来源默认，管理器按实际存活 writer 回滚并报告冲突。未公开/动态范围照常走旧策略。不能只协调一个 writer 就声称全范围让位。

## 7. 内存与资源租用报告

hello、planned/prepared/applied、隐藏释放及预算变化都提供 memory={residentBytes,pinnedBytes,warmBytes,pendingDestroyBytes,borrowedBytes,decodeReservedBytes}。所有值是非负整数估算字节数，计数单位为每 instance 去重后的纹理实际分配，而不是每个 target 引用数。

- residentBytes=pinnedBytes+warmBytes+pendingDestroyBytes。pendingDestroy 在 Unity 延迟销毁阶段仍计入 resident，不能发送释放命令即从总账扣除。执行销毁并跨过对应帧销毁阶段后才移除此估算条目；不声称已测得 GPU 物理释放。
- borrowedBytes 是作者原系统/游戏原图已经持有、桥未创建的纹理，仅报告不释放，不与 owned resident 重复计数。修改布局只创建 Sprite，不把共享纹理再次计费。
- decodeReservedBytes 是当前同时在解码/准备的临时预算；peakAdditionalBytes 计入额外 RGBA CPU/GPU副本、编码文件缓冲、照片处理及 mip 临时缓冲，包含本次 resident 增量，不能 residentDelta+peakAdditional 重复相加当峰值。
- 管理器全局账本按 instance 汇总 resident，并在其上预留本轮 peakAdditional；使用统一配置上限与来源本地预算的较小可用额度。每桥128MiB/32MiB只是本地估算限制。
- 源默认图为桥自建时同样先计划/授权；原工程已经创建的默认图作为 borrowed。初始独立运行已存在的 owned 图在 hello 全量报告，管理器不能事后撤销已分配内存，只能限制后续准备/要求释放空闲缓存。
- `trim` 请求带 warmLimitBytes，仅清空闲 owned 缓存，不能销毁 pinned、回滚备用或 borrowed。返回 trimmed 与 memory。来源独立模式无管理器时按自己的本地预算正常显示。

prepared/applied 和 memory-changed 另带完整 heldResources 数组，项为 resource 引用+refCount；包括准备、显示、回滚和 warm 缓存对磁盘快照的保护引用。refCount 减到0才可清理对应缓存文件。超过单消息限制分批完整快照（snapshotId、page、last），管理器收完才替换旧保护集合；分片期间按旧/新并集保护。来源掉线后至少保留到已知租约截止和本地销毁宽限，不仅凭窗口不可见就删文件。

内存上限是协议资源的保守估算账本，不是整个游戏/驱动硬上限；Unity内部解码开销、原工程主动分配和渲染驱动额外开销无精确控制。预算不足保留旧显示并报告，不循环尝试解码。

## 8. 查询、错误与停用

writer 的 `StaticBridge` 自动通过官方 `ModHelper.Expose` 发布 `portrait-studio-static-active/1` 只读服务，类型为 `Func<string>`，在会话内外均可查询。返回紧凑 JSON，字段精确为 protocol、contract、renderMode=static、providerId、instance、revision、targets；revision 是 writer 修订，与 hello 和清单 revision 一致。targets 是已成功 Show 且未 Hide 的位置 ID 去重列表，包含 silent 表面；仅注册、隐藏或显示失败的位置不列入。来源负责及时报告真实显示生命周期。

查询只读取缓存元数据，不发消息、不读图、不改变显示；列表变化后首次查询重建缓存。无活跃位置返回空数组。JSON 不超过65,536字符及65,536 UTF-8字节，超限返回 null，不截断列表；停用后已缓存的委托也返回 null。Schema 见 [活跃位置查询](portrait-studio-active.schema.json)。服务由桥创建和清理，作者无需重复注册。

管理器缓存通过官方 `Lookup<Func<string>>` 取得的委托，在维护阶段最多每0.25秒查询一次，核对运行提供者、已认证 hello 的 instance、writer revision 和声明位置。按真实活跃位置及原生/托管需求 acquire，再接收 show；服务本身不授予显示权。会话最多32个位置，实际同时需求超过上限时保留已有协作并提示未接入范围，不轮询抢占、截断或静默忽略。查询不可用或校验失败时保留已有有效显示，照常检查会话租约及来源启停；不按名称猜组件。Lookup 仍受官方能力检查约束，返回 null 时不绕过。

discover→hello，acquire→ready，heartbeat→ack，release→released 保留。ready 只确认 targets 范围和 contract；成功后来源为当前活跃对象逐个补 show。query-state→state 分页返回活跃显示、当前 choice、准备/提交状态及 memory；不加载图片。hide 是来源事件，释放后通过 display-released 回报 memory 与 heldResources。memory-changed 可独立报告 cache/延迟销毁变化。

state 的每条显示含 targetId、displayId、visitId、displayEpoch、surfaceId、phase，可附 choiceId；show 提供 originVisitId 时，快照也带相同值。管理器收齐当前快照后核对显示代次并恢复关联，不把查询当作新登场或重新抽图。

error 含 requestOp、请求 seq、code、message 和能确认的事务关联字段；成功/失败响应不得用 seq=0 代替请求关联。code 包括 invalid-message、invalid-layout、stale-session、stale-display、stale-plan、identity-mismatch、resource-missing、resource-changed、unsupported-geometry、budget-exceeded、apply-failed、transaction-expired。错误保留已有 choice 与旧显示；select 的存意图与显示事务失败状态分别报告。

release、租约超时或 writer 停用取消所有事务，恢复作者默认与原有调节设置，解绑时只恢复仍属于自己的写图结果；清理不写到已经复用的对象。每个显示自己的 immutableOriginal 在首次替换前从可信原图入口取得。custom 由创建者显式绑定并提供原图、show/hide 和 visit，清单不创建 NPC。

## SDK 接入

将 assets/SDK（新包为 assets/template/SDK）中的 StaticContract、StaticSession、StaticWire、StaticResources、StaticBridge 编入自己的程序集。新包另外编入 StaticBindings。仅依赖游戏程序集和 Newtonsoft.Json；没有管理器前置。Catalog.Read(root, expectedId) 是不带 Unity/消息副作用的清单解析入口。

游戏在 OnEnable 返回后才登记模组目录。StaticBridge 应在首帧或之后的对象创建事件中构造；OnEnable 只安装生命周期驱动，新包保留模板的延迟入口。初始化失败记录原因并清理，不逐帧重试；启用后首帧前停用也应取消初始化。

每个表面注册一个 StaticDisplay，回调统一控制该表面的所有最终写图分支：

```csharp
var display = bridge.RegisterDisplay(targetId, displayId, surfaceId,
    () => renderer.sprite, () => authorDefault,
    decision => {
        if (decision.shouldWrite && renderer.sprite != decision.sprite)
            renderer.sprite = decision.sprite;
    });
display.Show(visitId, immutableOriginal);
```

silent 回调的 shouldWrite=false，所有写图和附加层都要跳过。持续写图处使用 display.Resolve() 返回的同一决策；它只读内存。defaultMode=source 的原工程主动改变已持有的静态基础图时调用 SourceChanged()，保持 visit 并重新报告 show，管理器需为该 epoch 重新准备选择。Hide() 报告隐藏；换人必须先 Hide("rebound")，再以新目标、相同 displayId 和新 visit 绑定。销毁调用 UnregisterDisplay；每帧调用 bridge.Tick()，停用 Dispose。

新包 StaticBindings 使用官方 ModReflect 读取游戏序列化原图列表，固定字段按实例索引；不从已经换图的 renderer 或字典猜原图。原生人物依据实际 currentClientInstance，离场身份保留到 renderer 隐藏。场景按已加载的同名 Sprite/Texture 资产匹配；发现资产歧义时不自动绑定，作者应在创建入口提供可信原图。自定义对象显式调用 BindSprite/BindImage，提供目标、原图、visitId 和创建者 originDisplayId；originVisitId 可选。同对象换人重新绑定，原身份先解绑。多对象用 BeginBatch/EndBatch，新增原生对象用 RefreshNewObjects。模板 LateUpdate 只检查已知对象和共享顾客入口，不每帧全场搜索或读取图片。

独立运行时仅为可见位置准备默认资源；有会话时 show 只报告显示，不自动读取管理器的默认选择。新候选必须先 plan、获预算再 prepare，commit 不做 IO。图片哈希、路径、静态声明或预算校验失败时保留旧图。资源发布到临时文件后原子替换，旧修订保留至引用释放。

作者完整检查无管理器时独立换图与还原、共享对象换人、同目标多显示、隐藏再出现、失联恢复、silent、回滚、布局三模式、照片留位、场景和自定义 NPC。运行包只包含原工程需要的运行文件和声明资源；纯图片模板另用严格白名单检查。

会话先于新表面出现时，资源型默认图也等待预算授权。presenter 和 silent 的计划均包含尚未准备的独立恢复默认；prepare 只准备并保护引用，commit 成功后将其保留为本地恢复图，finish/trim 不提前释放。silent 不临时取得显示权或写入原图，取消和回滚只撤回本事务持有的改动；release/失联恢复使用已准备默认，不临时读盘或解码。


另有 [管理器托管路线](托管显示协议.md)：资源清单保持 role=resources，另用显式托管声明授权管理器最终写图。只发布资源不会自动交出显示权。希望保留作者独立显示功能时继续采用本文 StaticBridge 协作接口。

## 套装声明与切换

多角色整套换图使用可选根字段 `portraitSets`。`resourceSets` 继续表示单个目标身份；套装是跨目标的图片映射。每套有稳定 `id`、供人阅读的 `name`、`renderMode: static` 和 `entries`。每个 entry 是既有四字段资源引用，目标身份从对应资源组的 kind、subject、slot 取得。

```json
"portraitSets": [
  {"id":"set-one","name":"立绘1","renderMode":"static","entries":[
    {"providerId":"author.pack","setId":"mentor-main","id":"day","revision":"1"},
    {"providerId":"author.pack","setId":"wanted4-photo","id":"day-photo","revision":"1"}
  ]},
  {"id":"set-two","name":"立绘2","renderMode":"static","entries":[
    {"providerId":"author.pack","setId":"mentor-main","id":"night","revision":"1"}
  ]}
]
```

套装最多128套、每套1..4096个引用。套装ID在本提供者内唯一，每套对同一个完整显示身份最多选一张图；图片须在本提供者发布，引用精确到不可变修订。writer/both及托管声明的套装图片须属于对应位置的 candidateResources。纯供图清单无须提供 target。人物、通缉照片、场景和自定义身份使用相同规则。未填写 portraitSets 时保持普通候选包行为。

列表顺序只决定选项展示和独立模板的首次默认套装，不表示不同角色的第N张图属于第N套。默认套装应列全作者想统一替换的位置。缺图时跳过该目标、保留当前图片；首次加载时缺图使用 target.defaultResource。套装信息更改更新 catalogRevision，改图仍更新 resourceRevision。构图工具保存会同步套装引用。

独立模板在游戏设置中提供“立绘套装”下拉框，以稳定ID保存选择，并按需加载已出现的资源。用户主动切换固定图片属于静态；自动动画、表情和剧情变图仍不进入静态声明。已有模组保留自己的套装设置，只把静态候选对应关系公开。

管理器按来源读取 portraitSets，批量选择来源后显示套装名称和本次筛选范围内的覆盖数量。仅切换下拉框不写用户选择，点击应用后才按 entries 提交明确资源引用；缺图跳过，已有布局、原版筛选和随机池规则保留。人物页面只操作 character，照片/场景页面按自己的 kind 与 slot 筛选，不串到人物目标。

来源自身套装设置不覆盖管理器的显式选图、原图选择或 silent 控制。当前 SDK 在整个管理器会话期间暂存来源端套装变化，不加载新套装或改写画面；会话释放或租约结束后应用。需要在会话内更新 follow 的来源，另按既有 source 默认与 SourceChanged 协作，不能由独立模板强行刷新。套装分组不新增消息操作，也不要求管理器反射调用来源切换函数。

管理器使用同版 Catalog 读取器并接通 portraitSets 后才会出现通用套装下拉框；现有特定模组识别不等于已支持本声明。旧严格读取器无法识别带此字段的清单，需更新读取器；不发布含未知字段却宣称旧管理器可识别的成品。

### 设置与保存

独立包保存本提供者内的套装 ID，显示名称可改。管理器的套装下拉只筛选本次批量操作，应用后保存各目标的明确资源引用；不回写作者设置，不为切换套装复制图片或新增登记。普通应用替换套装覆盖的目标，“应用到原版”只改当前使用原版的位置；加入随机池沿用管理器已有的角色随机功能，增量添加，不清除原池。照片和场景的套装声明不增加随机播放功能。

同一 providerId 和 catalogRevision 下的套装映射保持不变。清单更新后按稳定套装 ID 重新解析；所选 ID 已删除时提示重新选择，不自动应用第一套。每份清单总大小仍不得超过 1MiB，套装数量和条数上限同时生效。

### 设置边界

- 套装统一使用 portraitSets；已有模组的专用兼容映射由管理器转换为内部套装，不增加作者文件或第二种公开字段。
- 目标按完整显示身份区分。普通与增强角色使用各自的真实身份；自定义 NPC 通过 subject.owner 和 binding 等字段识别，不新增 custom kind。
- 图片默认构图写在资源 geometry 中，变更产生新资源修订；用户的缩放和偏移由管理器现有参数处理。套装不另存布局。mipmaps.levels 是同一张图的纹理层级，不作为套装。
- 高清、像素相机、分辨率档位及来源自身的自动换肤设置沿用对应显示系统；自动表情、动作和剧情换装走动态适配。随机、性能模式和快捷键由管理器管理。
