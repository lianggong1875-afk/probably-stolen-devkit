# 管理器托管静态显示

原版顾客支持按职业身份或共用图片声明，见 [职业与图片键](原版职业与图片键.md)。`vanilla_client_` 职业沿用 character/game/key/main 与 sprite-key binding，按 identifier 精确识别，别名合槽；保留 sourceModId 来源隔离、isAug 身体图及当次可信原图。

作者把声明位置的显示、大小位置调整和选图交给 Portrait Studio，停止自行写入这些位置。协议标识 `portrait-studio-managed/1`，能力 `static-manager-rendering/1`。元数据见 [托管清单 Schema](portrait-studio-managed.schema.json)，登记头、行及通知见 [登记 Schema](portrait-studio-managed-wire.schema.json)。托管包依赖支持该能力的管理器显示。

## 入口和资源

固定入口为提供者根目录 `portrait-studio-managed.json`。根字段 format、contract、providerId、revision、renderMode=static、renderOwner=PortraitStudio、targets 均必填。providerId 与实际 manifest ID 匹配，包依赖 PortraitStudio。revision 标识托管范围/行为，改变后销毁旧登记服务并重建 instance。每份清单至多 1MiB、4096 个位置；字符串身份最多 160 字符。

每个 target 必填 id、kind、subject、slot、renderMode=static、binding、defaultResource、candidateResources。四元身份与 binding 遵守 [静态资源协议](静态资源公开协议.md)；没有 source 默认或来源 writer。候选非空、引用不重复，默认必须属于候选。同一提供者不能重复位置 ID 或四元身份。

资源仍由 `portrait-studio-provider.json` 发布，role=resources；根、资源组、图片显式 static。资源清单没有 writer revision/targets，不创建 StaticBridge，不发送 static-v1 hello/acquire。托管声明不改变供图角色：没有托管声明的 resources 仅供图，不授权接管。托管目标的全部引用必须在本提供者的资源清单内，资源组四元身份一致。资源清单与托管声明分开维护修订；资源先就位，再原子更新清单与声明，管理器整套校验通过才采用。

图片、哈希、尺寸、几何、采样、mip、照片留位、路径及链接限制与静态资源协议一致。Native scene 的 rect 为 16:9。ManagedCatalog.Read(root,expectedId) 联合校验两份清单，不加载 PNG 或改变显示；运行启用状态、manifest 前置及实际图片完整性由管理器扫描阶段另验。

## 显示权和默认

只有实际已启用且正常加载、声明完整并通过资源/权限检查的提供者进入托管显示。不能仅凭文件存在替换图片或退出其他 writer。作者永久退出声明范围内的原换图补丁、字典替换、持续赋图、缩放偏移及附加层写入；只保留创建基础对象所需的原始布局。托管位置不得同帧再走作者独立显示端。未声明的动态/其他功能继续原实现。

管理器负责唯一呈现者、其他 writer 的静默/旧覆盖协调、图片准备和全局预算、布局应用、随机及失联/停用恢复。管理器仍须完成整个表面的协商，不能把托管文件当作其他模组已让位。已有用户选择、布局、预设和默认来源优先级保留；托管 defaultResource 只补没有用户设置时的来源默认，多提供者按管理器现有优先级处理，不按扫描先后抢写。

资源几何承载作者默认比例/锚点，用户大小位置由管理器应用一次。无支持的管理器、资源无效或预算不足时保持现有基础/成功显示，不启动作者备用写入。包不提供无管理器时的图片替换。停用来源或管理器时，只恢复仍由管理器持有且身份未变的表面，释放缓存引用；不能把旧角色图写回已复用对象。

## 原生和自定义表面

sprite-key、wanted-photo、scene-key 由管理器现有原生入口发现，采用可信原图和真实登场身份，不按角色显示名猜 key。纯原生包没有逐帧代码，也不创建图片纹理。

custom 的基础对象、NPC、剧情、语音由创建者保留。只有 subject.owner 与提供者 ID 相同的创建者可用 ManagedSurfaces 登记自己的表面；第三方图片包复用创建者登记的四元身份，不能冒名操作其对象。管理器不能发现自定义表面时，该位置保持未接入，不在全场按名称猜测。

创建者通过官方 `ModHelper.Expose(providerId,"portrait-studio-managed-surfaces/1",service)` 发布 `Func<object[]>`。管理器只用官方 `Lookup<Func<object[]>>` 获取，不反射其他程序集。Lookup 仍受双方声明能力覆盖约束，返回 null 时不绕过；原工程不合规的其他权限也不会因托管自动获准。

调用 service() 返回只读快照：`object[] { headerJson, row1, row2, ... }`。每行是 `object[] { metadataJson, component, immutableOriginal }`；component 只允许实际 Unity SpriteRenderer 或 UnityEngine.UI.Image，immutableOriginal 是创建者保全的 Sprite。所有 JSON 头/行由配套 Schema 严格检查；不得返回来源自定义类或待反射成员。最多 4096 行，创建者只在变动时生成快照，读取同一快照不分配。

header 字段为 protocol、contract、providerId、revision、instance、renderMode=static、generation、enabled。instance 每次创建新 GUID，generation 从 0 起随快照变动递增。行字段为 targetId、displayId、visitId、displayEpoch、surfaceId、surfaceType，以及可选 originVisitId。displayId 是创建者稳定表面槽，surfaceId=providerId+":"+displayId；surfaceType 为 SpriteRenderer 或 Image。displayEpoch 每次该槽重新 Show 增加，包括相同 visit 隐藏再现；同一 component 不能登记为两个槽。originVisitId 可将同一登场的多个表面关联。

管理器收集快照后按实际引用类型检查 component/原图，解析 targetId 并匹配身份，记录 instance、displayId、visit、epoch 和对象引用。写图或提交前重新取得当前快照，确认服务仍为当前 instance、enabled=true、相同行/引用仍有效，检查 component 活动/enabled 和实际 subject 生命周期；有变化取消旧准备，保持本次登场的选择。不要直接修改快照数组，也不要把对象句柄持久化到配置。

## 生命周期通知和恢复

所有登记、隐藏、销毁和管理器写入在 Unity 主线程完成。作者在创建基础对象之后 Show；隐藏 Hide(hidden)，复用前 Hide(rebound)，销毁前 Hide(destroyed)。不因会话清空就丢失退场身份；等实际隐藏再登记离场。服务不需要来源心跳或每帧 Tick。

ManagedSurfaces 在首帧或之后的 NPC 创建事件中构造；游戏在 OnEnable 返回后才登记模组目录。原生纯图片包保留空入口。自定义创建者初始化失败须清理并记录，不逐帧重试，停用时取消尚未执行的初始化。

创建者用官方 `SendMessage(providerId,"static-managed",json)` 通知，管理器监听 `providerId:static-managed` 并验证真实 sender。changed 为完整 header+op，表示重新读取快照；不是成功接管 ack。hide 在快照移除旧行后、Hide 返回前同步发出，含 header、op=hide、targetId、displayId、visitId、displayEpoch、reason。来源通知不能回调修改同一登记器。

hide(hidden) 是管理器同步清理入口：核对之前持有的 instance/行身份和 lastWritten 后，在该通知返回前恢复仍属于自己的原图；没有匹配记录则不写。rebound/destroyed 只取消旧写入、准备及租用，不赋旧原图。管理器若延后处理 hidden，只能取消和释放，不得稍后依据旧事件恢复，以免覆盖已复用对象。所有事件仍以当前快照与实际对象为准。

Dispose 先逐行 hidden 通知，再发布 enabled=false 的空快照并撤下服务。管理器旧 delegate 随后读取也只得到禁用快照，不能继续写旧对象。丢失通知后在下次快照校验停止写入；恢复只在身份和自身持有关系仍可确认时执行。来源不主动加载、赋图、恢复或销毁管理器资源。

## 交付和验收

原生纯图片成品只带 manifest、空入口 DLL、两份声明及实际引用的图片；自定义创建者沿用原工程发布文件。原工程 metadata 校验不按纯图片白名单删文件。托管 skill 自带模板、三份自定义登记源码、接入示例和校验/构建工具。

作者侧验收声明、默认/候选、原写入口退出、主体身份、生命周期及无逐帧图片 IO。管理器侧验收扫描授权、表面发现、用户配置/随机保留、其他 writer 协调、全局预算、照片/场景及停用恢复。
