为作者的现有换图模组加静态接口，保留原工程和功能。只有图片、需要新工程时适合 portrait-studio-pack；自动表情、动作或剧情变图使用 portrait-studio-dynamic。管理器旧来源兼容另行处理。

先用一句简单的话提示路线：“你的模组已经能换图，适合保留原做法，只加接口；从图片开始做则用独立包模板。”用户已说明情况时直接采用对应路线；情况不清楚时只问“你已经有能换图的模组，还是只有图片？”，无需作者判断技术实现。

如果作者明确愿意依赖管理器、把静态显示和大小位置全部交出去，推荐 portrait-studio-managed。已选定当前路线就直接执行，不反复询问或自动转成托管。

读 [公开协议](references/静态资源公开协议.md) 和 [既有模组接入](references/既有模组接入.md)，按以下步骤完成：

先读 [范例用法](references/范例用法.md)，将示例接到作者原工程的真实入口。资料以工具包和作者指定工程为起点；需要确认游戏行为再查指定游戏的公开 API 或程序集，不遍历其他已安装模组来猜实现。只要求诊断测试问题时，先报告原因和工具包缺陷，不改被测工程或成品。

接接口保留原有图片分辨率和采样。涉及图片转换或性能判断时读 [图片处理与预算](references/图片处理与预算.md)，查原工程与桥的实际驻留和准备峰值，不因候选总量擅自缩图，不把换图失败称为加载器拒绝模组。

保留原工程的显示方式和画面设置；接口只协调静态资源与写图权限。

原版顾客先区分“只换某个职业”与“换所有共用这张图的人”，详见 [职业与图片键](references/原版职业与图片键.md)。职业查 [职业表](references/vanilla-client-roles.tsv)，共用图片查 [图片键表](references/characters.tsv)；已说明就直接采用，不多问。

1. 阅读入口、实际写图代码和资源映射，查清字典替换、补丁、直接赋图等现有方式，以及大小位置由图片几何、对象布局还是配置控制。记录基础图、默认图、全部写图者、生命周期和权限。工程缺失时说明需要哪些材料。
2. 用作者能理解的话概括“原来怎样换图、大小位置在哪调、准备保留什么”。接接口默认保留原构图和调整方式，不重新套原图宽高；原图像素尺寸不等于固定相框。只有作者要求改构图时，才检查实际裁切和布局，按期望的完整人物、半身或参考效果处理。技术实现由 AI 决定，不让作者选择补丁、渲染器或 PPU。
3. 只公开能够独立处理的静态位置，根、资源组、位置、图片均声明 static。动画、表情、剧情变图及未公开位置保留原逻辑。自定义对象使用创建者 ID 和稳定 key。
4. 在原程序集编入 assets/SDK 的 StaticContract、StaticSession、StaticWire、StaticResources、StaticBridge 五份源码，以自己的 mod ID 调官方消息。只接接口无需 StaticBindings，也无需管理器前置。
5. 保全基础图，按真实表面注册 StaticDisplay，全部最终写图分支走 display.Resolve()，严格遵守 shouldWrite；silent 完全跳过该表面写图/附加层。显式报告 show/hide/visit，对象换人先解绑，原图由可信入口保全；同步提交/回滚失败向上传出。每帧只维护已知对象和 Tick/Resolve；禁用先恢复显示、解绑事件，再 Dispose。保留原有大小位置、配置、NPC创建、剧情、语音和交互。
6. 增加 portrait-studio-provider.json，区分 writer 与 resources，填写稳定资源引用、多候选、完整纹理/几何和 source 默认，分别维护 writer revision、catalogRevision 和 resourceRevision。图集或嵌入图片可在构建时导出独立 PNG。校验用 `python scripts/validate.py <原包>`，沿用原工程构建和发布文件范围，扫描实际能力。
7. 集中检查无管理器时的原行为、接口选图、还原、失联恢复、自定义身份和未公开动态功能。安装、运行游戏和上传按用户授权范围进行；只修改作者指定工程。

已有套装开关时保留原设置，在资源清单 portraitSets 公开固定静态图片的逐目标映射；不改成调用管理器私有方法，不把自动剧情变图声明成静态套装。详见公开协议“套装声明与切换”。

交付说明只记录：采用的路线、保留的大小位置调整入口、已接入和未公开的位置、已做检查与待验收项。写当前用法和边界，不附迭代历史或重复免责声明。清单定义与示例在 references。
