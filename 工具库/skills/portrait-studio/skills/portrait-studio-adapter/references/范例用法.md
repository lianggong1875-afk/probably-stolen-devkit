# 原工程接口范例

[AdapterLifecycle.cs](../assets/AdapterLifecycle.cs) 演示一个模组的一处 SpriteRenderer 静态位置，包含注册、Show/Hide、最终写图决策和释放。以作者实际工程入口接入，保留原有创建、配置和构图；不把这个类当成通用自动扫描器。

在首帧或之后、自己的模组目录和表面都已可用时构造一次：

```csharp
adapter = new AdapterLifecycle(modId, targetId, renderer, trustedOriginal,
    () => currentAuthorDefault, visitId, creatorSurfaceId);
```

trustedOriginal 来自首次替换前的可信入口；currentAuthorDefault 是原工程持有的静态默认图。清单可从 [资源与位置示例](provider-example.json) 取字段，按 [既有模组接入](既有模组接入.md) 改为原工程的 source 默认和真实身份。

原工程每条最终赋图路径接入 `adapter.Refresh()`；同一表面的 overlay 也必须遵守 shouldWrite。隐藏调用 Hide，重新显示调用 Show，每帧调用 Tick，停用 Dispose。作者主动改变已显示位置的静态默认图时调用 `adapter.SourceChanged()`；不要把管理器写入的结果反读成作者默认图。

多处表面共用一个 StaticBridge，各自 RegisterDisplay，以真实 displayId/surfaceId 区分；不要为每个 NPC 复制该类并重复订阅同一模组消息。具体注册代码见 [公开协议](静态资源公开协议.md)。同对象换人先解除旧显示，再用新的 target/visit 注册。Image 用它自己的读取和赋图回调，清单仍按真实身份匹配。

接入范围依据作者原工程判断，不改其他已安装模组。只排查被测模组时先报告原因和工具包改进，不直接改被测源码。

已有作者的静态套装开关保持原样；在 provider 的 portraitSets 中公开每套各目标的精确资源引用即可。source 默认图变化沿用 SourceChanged 与生命周期，不另调用独立包的 SetPortraitSet。

只换原版某个职业时，先读 [职业与图片键](原版职业与图片键.md)。完整 SDK 的 `examples/build_examples.py --occupations` 可生成两套职业范例；本 skill 单独使用时，从自带模板按职业表填写目标与资源组。
