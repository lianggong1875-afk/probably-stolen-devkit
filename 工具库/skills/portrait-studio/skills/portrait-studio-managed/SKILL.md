---
name: portrait-studio-managed
description: 把 Probably Stolen 模组的静态立绘显示和大小位置调整交给 Portrait Studio，制作托管图片包或改造已有工程；用于作者明确愿意依赖管理器、停止自行绘制已托管位置的情况。
---

先简单说明：“这条路线把静态图片的显示、大小位置和选图交给管理器，模组需要 Portrait Studio；NPC、剧情和语音仍由原工程负责。”作者已选托管就直接执行。希望无管理器也能换图时，推荐独立包；希望保留自己的显示系统时，推荐原工程接口接入。不替作者擅自改路线。

读 [托管接入](references/托管接入.md) 和 [托管显示协议](references/托管显示协议.md)。图片元数据遵守 [静态资源协议](references/静态资源公开协议.md)。

先读 [范例用法](references/范例用法.md)。纯图片包从自带空入口工程创建，原工程与自定义 NPC 按示例接实际生命周期。资料以工具包、作者素材和指定工程为起点；需要确认游戏行为再查指定游戏的公开 API 或程序集，不遍历其他已安装模组来猜实现。只要求诊断测试问题时，先报告原因和工具包缺陷，不改被测工程或成品。

图片默认保留原分辨率，默认比例和锚点写入资源几何。涉及图片转换或性能判断时读 [图片处理与预算](references/图片处理与预算.md)，以管理器实际预算和加载路径为准，不把协作桥的默认预算套成托管包总容量，不因候选总量擅自缩图。

需要调整作者默认构图时，可用 `python scripts/framing.py --source <源码目录>` 本地预览并保存；它同时更新托管清单的资源引用。运行时大小位置由管理器负责，画面设置沿用游戏和用户已有模组。

原版顾客先区分“只换某个职业”与“换所有共用这张图的人”，详见 [职业与图片键](references/原版职业与图片键.md)。职业查 [职业表](references/vanilla-client-roles.tsv)，共用图片查 [图片键表](references/characters.tsv)；已说明就直接采用，不多问。

1. 查工程和资源，列出要托管的固定单图/用户主动选择候选。人物、通缉照片、场景和自定义 NPC 分别标识；原版人物按上述职业表或图片键表确定身份，自定义对象用创建者 ID 和稳定 key。动画、表情、剧情自动变图以及无法单独控制的共用位置不声明托管。
2. 只有图片时，用 `python scripts/new_managed.py --output <新源码目录> --id <唯一ID> --name <名称>` 创建空入口工程，替换图片和清单。已有工程则修改自己的源码，保留 NPC 创建、剧情、语音、交互及其他位置；不要对现成 DLL 猜测打补丁。
3. 发布 `portrait-studio-provider.json`（role=resources）和 `portrait-studio-managed.json`（显式 static、renderOwner=PortraitStudio）。每个位置列完整身份、binding、默认图和候选引用；所有资源引用在自己的清单内，根、资源组、位置、图片均声明 static。按 [清单 Schema](references/portrait-studio-managed.schema.json) 校验。资源需完整 PNG/纹理/几何，不能只提供路径。
4. 在已托管位置移除原换图补丁、字典替换、持续赋图、缩放偏移和附加层写入。已有工程保留原构图并转换为资源几何基准；新图按作者期望设置默认比例和锚点，未说明时保留完整构图。原图像素尺寸不等于固定相框，先查实际裁切与布局，不默认裁成半身或强行填满。后续调整入口在管理器，不另加作者端调整循环。共用逻辑只能按声明位置精确退出；不能把未公开功能一起关闭。无法隔离或保真时，说明具体阻碍并保留该位置原实现，不伪造已完成托管。
5. 原生已支持位置不编入显示 SDK。自定义 NPC 的创建工程参考 [登记示例](assets/CustomNpcLifecycle.cs)，编入 assets/SDK 的三份源码，用 ManagedSurfaces 只报告表面、原图、登场和离场；角色复用前先 Hide(rebound)，销毁前 Hide(destroyed)。每帧不重复 Show/Lookup，不加载候选或自行写图。为别人创建的 NPC 制作图片包时，复用其创建者提供的登记入口；入口缺失就记录该位置尚待接入。
6. manifest 声明 PortraitStudio 前置，不猜支持版本号。纯图片包用 `python scripts/managed_validate.py <源码目录>`，再用 `python scripts/build_managed.py --game-root <游戏目录> --source <源码目录> --output <不存在的成品目录>`。原工程沿用原构建，metadata 校验不加 --runtime；严格白名单只用于纯图片包，不能删除原工程其他运行文件。
7. 集中验证静态声明、默认/多候选、原写入口已退出、通缉元素、场景几何、自定义换人及停用恢复。安装、开游戏、上传按用户授权范围进行。托管包需支持 `portrait-studio-managed/1` 的管理器才能显示。

多套资源在 provider 清单 portraitSets 声明套装名与逐目标引用，托管清单的候选包含这些图片；不增加作者端显示或套装写图循环。由支持通用套装声明的管理器提供套装选择，缺图跳过。详见静态资源协议“套装声明与切换”。

交付简记托管范围、默认图、大小位置在管理器调整、保留功能、已检查和待联调项。代码与文档只写当前用法，不加迭代历史。
