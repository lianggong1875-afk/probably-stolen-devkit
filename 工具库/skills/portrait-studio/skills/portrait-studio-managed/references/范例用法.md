# 托管范例

[完整工程](../assets/template/PortraitPack.csproj) 使用[空入口](../assets/template/Entry.cs)，两份声明列出导师多候选、房东、通缉照片和场景。用 `scripts/new_managed.py` 创建自己的新工程，`scripts/build_managed.py` 构建，命令见 [托管接入](托管接入.md)。纯原生图片包保留空入口，修改资源和声明即可。

范例声明 PortraitStudio 前置，需要支持托管协议的管理器。它没有独立换图功能，大小位置由管理器调整。新图的默认比例和锚点写入 geometry，不能为了补显示再加一套赋图循环。

设置作者默认构图可执行 `python scripts/framing.py --source <源码目录>`，在浏览器里拖动、缩放、点选锚点并保存。可选用自己的截图作参照；默认背景和柜台线仅为示意。保存同时更新两份声明的资源引用，PNG 不变，之后重新构建。画面设置沿用游戏和用户已有模组。

Windows 也可双击 `scripts/启动构图工具.cmd` 后选择源码工程，或把工程文件夹拖到启动文件上。自动查找 Python 3.10+，缺少时提示安装，无需管理员权限。

自定义 NPC 创建者使用 [CustomNpcLifecycle.cs](../assets/CustomNpcLifecycle.cs)，配套 [资源声明](custom-provider-example.json) 和 [托管声明](custom-managed-example.json)。创建者模组只持有一个登记器，在首帧或之后的 NPC 创建事件里初始化一次：

```csharp
registry = new CustomNpcLifecycle(creatorModId);
registry.Appeared("npc-main", displayId, visitId, renderer, trustedOriginal);
// 实际隐藏、复用、销毁分别调用：
registry.Hidden(displayId);
registry.BeforeReuse(displayId);
registry.BeforeDestroy(displayId);
// 停用时先清理登记，再销毁自己的基础对象。
registry.Dispose();
```

上面每个离场调用对应实际事件，按发生的事件使用；不是依次调用三种离场。初始化失败清理并记录，停用取消等待任务，不逐帧重试。Image 可以直接使用 ManagedSurfaces.Show 的 Image 重载。

基础 NPC、剧情和语音沿用创建者工程。代码只登记表面和可信原图，不加载候选、赋图或改变布局；第三方图片作者使用创建者公开的身份和登记入口。

套装在 portrait-studio-provider.json 的 portraitSets 中声明，候选仍列在托管 targets 内。模板含立绘1和立绘2；管理器需接通通用套装读取后才有套装下拉框，纯托管包不增加独立选图代码。

只换原版某个职业时，先读 [职业与图片键](原版职业与图片键.md)。完整 SDK 的 `examples/build_examples.py --occupations` 可生成两套职业范例；本 skill 单独使用时，从自带模板按职业表填写目标与资源组。
