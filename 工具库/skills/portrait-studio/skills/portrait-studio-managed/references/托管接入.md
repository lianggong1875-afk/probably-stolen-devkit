# 把静态显示交给管理器

原版职业与共用图片分开声明，填写前读 [职业与图片键](原版职业与图片键.md)，身份见 [职业表](vanilla-client-roles.tsv) 或 [图片键表](characters.tsv)。

自定义对象按创建者的实际就绪事件登记，目录可读不代表存档或显示对象已创建。需要访问存档时先检查 `PlayerStore.HasInstance`，不要用会自动创建游戏状态的 Instance 判空。Image 提供实际有效图片对应的可信原图；登记不另建候选缓存或显示循环。

原生图片包只需两份清单、PNG 和空 IMod 入口。管理器负责扫描、选图、解码、缓存、布局与还原。包依赖支持托管协议的 Portrait Studio；没有支持时保持游戏/创建者基础图，不提供独立替换。

## 从图片开始

执行 scripts/new_managed.py 创建 Mods 外的新工程。模板带人物多候选、独立通缉照片及 16:9 场景示例。修改 manifest 作者/游戏版本，替换示例资源，维护内容哈希与完整几何；删去不使用的位置和资源。用 scripts/managed_validate.py 和 scripts/build_managed.py 生成严格运行包，输出目录必须不存在且在 Mods 外。模板 Entry 不读图片、不订阅消息，也不逐帧运行。

原图像素宽高不代表固定相框。先查看真实显示表面、遮罩、布局和遮挡，按作者想要的完整人物、半身或参考效果确定默认大小与锚点；未说明时保留新图完整构图和比例。AI 负责换算资源几何，不让作者在“按原图宽”“按原图高”之间被迫选择。裁切、拉伸或重采样按作者要求处理，不默认实施。显示效果尚未查看时明确待验收，不仅凭宽高声称必然溢出。

托管包通过资源几何提供默认构图，后续大小位置由管理器调整。若实际显示约束或现有托管布局无法满足作者要求，记录具体位置和阻碍，不擅自增加持续赋图或修改共用界面；不把多种未经确认的构图分配给不同角色当作最终方案。

## 改造已有工程

保留原工程和构建方式，从实际最终写图入口查起：补丁、字典、SpriteRenderer/Image 赋值、缩放/偏移、附加层、配置事件。将要托管的静态位置资源导出成 PNG，记录完整纹理和 Sprite 几何。资源几何保存作者的默认比例与锚点；对象布局回到游戏/创建者基准，后续大小位置在管理器调整，避免原工程与管理器重复应用。

逐位置退出原写入。只在初始化设过字典图，也要移除该替换并恢复干净基准；不能只停 LateUpdate。混合模组的动画、剧情、NPC、语音、交互和未托管表面保留。共用全局字典无法按位置隔离时，不声明该位置已托管；可以只提供 resources。不要新增失联后自行写图的第二套降级逻辑。

manifest 增加 `<Prerequisites><Mod>PortraitStudio</Mod></Prerequisites>`，保留原有前置、程序集及实际能力。托管不会豁免原工程其他权限限制。自定义登记需要 files 读取自己的清单；纯原生图片模板不需要额外运行能力。

## 自定义 NPC

在 NPC 创建者工程编入 assets/SDK 的 StaticContract.cs、ManagedContract.cs、ManagedSurfaces.cs，需要游戏 Assembly-CSharp、UnityEngine.CoreModule、UnityEngine.UI 和 Newtonsoft.Json。参考 [生命周期示例](../assets/CustomNpcLifecycle.cs)。同一个模组只创建一个 ManagedSurfaces；每个实际 SpriteRenderer/Image 分别登记。

完整清单可从 [自定义资源示例](custom-provider-example.json) 和 [自定义托管示例](custom-managed-example.json) 起步，分别保存为 portrait-studio-provider.json 和 portrait-studio-managed.json。将两处 providerId、subject.owner 和所有引用的 providerId 改成实际创建者 ID；示例 targetId 为 npc-main。图片路径只是模板几何图，换成自己的资源并更新哈希/几何。清单里只保留自己的实际位置，不把示例 NPC 当作游戏已有角色。

创建时先由原工程建立基础对象和可信 immutableOriginal，之后调用 Show(targetId, displayId, visitId, component, original, originVisitId)。固定 displayId 表示创建者的表面槽，visitId 表示一次登场；同次登场的多个表面可共享 originVisitId。只在生命周期变化时调用；每帧不分配快照或轮询全部对象。基础对象不含其他作者替换后的图片。

隐藏调用 Hide(displayId)，同对象换人先 Hide(displayId,"rebound")，销毁前 Hide(displayId,"destroyed")；所有调用在 Unity 主线程、实际对象复用之前完成。重新显示即使同 visit 也登记新 epoch。停用原工程先 Dispose，再销毁基础对象。管理器是唯一托管写图方；创建者不执行 Resolve、图片解码、布局应用或恢复赋图。

给第三方自定义 NPC 提供图片时，用其创建者身份匹配资源，显示表面必须由创建者登记。图片包不能冒名登记其他模组的对象；创建者入口缺失时该自定义位置待接入。原生人物、通缉照片、已支持场景由管理器自身发现。

## 交付

写清托管的位置、默认和候选、保留的功能，提示大小位置在管理器调整及需要支持托管协议的管理器。元数据检查不验证原工程已经停止写图，须审查实际代码并在双方联调验证。作者可用其他模型/CLI 实际演练，保留失败输入、对话、改动和日志反馈。
