---
name: portrait-studio-dynamic
description: 为 Probably Stolen 的动画、表情、服装合成或剧情变图模组接入 Portrait Studio 动态显示接口，保留作者独立运行和动画实现。
---

保留作者的动态效果，通过公开接口协调候选选择、写图交接和大小位置。先简单提示：“你的立绘会自动变表情或播放动作，适合动态接入，动画仍由你的模组负责。”只有固定图片时使用工具包的静态路线。

读 [动态协议](references/动态立绘接入协议.md)，先看 [接线范例](assets/example/接线说明.md)。管理器需支持 dynamic-display-control/1；作者可先完成独立模组与接线，不修改、不寻找玩家电脑上的管理器源码，也不声称旧版管理器已支持。

1. 阅读作者指定工程的角色身份、默认候选、最终赋图、纹理合成、附加层及启停入口。已有动画原样保留；从头开发先做能独立运行的动态效果，再加接口。
2. 在原程序集编入 assets/SDK 两份源码，用自己的 mod ID 创建一个 DynamicBridge。人物、通缉照片、场景、自定义 NPC 分别声明完整身份与 renderMode=dynamic；自动表情属于一个动态候选，服装或不同整套效果才拆候选。原版职业与共用图片的区别见 [身份说明](references/原版职业与图片键.md)。
3. 每个真实显示槽注册 DynamicDisplay，登场 Show，换人先 Hide("rebound")，销毁前注销。保全可信原图，登记实际主表面和作者拥有的嘴部等附加层；不猜名字、不读当前管理器选图充当原图，不把全局相机登记为人物图层。
4. 所有最终写图和纹理修改先检查 ShouldWrite；异步完成还需核对本次登场。source 回调记录候选和布局，silent 同步停止主图/附加层写入并收起自有图层。保留剧情、语音、NPC创建；回调失败抛错，不能假报成功。每帧 Tick；禁用先停循环、Dispose，再释放自建资源。
5. 布局参数只应用一次，以原构图为基准。主图、嘴部和其他随人物移动的图层使用一致坐标，不逐帧累乘。独立设置保留，管理器断开后恢复独立选择。范例只是两个完整 Sprite 的切换，不要求作者改成帧动画或丢弃已有合成方式。
6. 添加 portrait-studio-dynamic.json，运行 `python scripts/validate.py <源码目录>`。静态资源可另行公开，但同一显示位置不同时登记静态 writer/托管。动态帧、嘴部和过渡纹理不当作完整静态候选导出。
7. 集中验证无管理器独立运行、两候选切换、silent后所有写入停止、租约恢复、换人旧回调无效、布局不累乘和禁用释放。管理器联调另核对动态/静态/原版往返。构建只引用目标游戏程序集，不复制进包；实际扫描整个运行包。

交付只列作者改动、动态范围、保留的独立设置、检查结果和管理器接线状态。工具不替作者实现任意动画算法；图片素材与异步加载沿原工程管理。
