# 从范例开始

| 要做什么 | 工程或代码 | 修改范围 |
| --- | --- | --- |
| 做能独立换图的新包 | `portrait-studio-pack/assets/template` · `references/范例用法.md` | 新工程的图片、清单、作者信息和构图 |
| 保留已有模组，加静态接口 | `portrait-studio-adapter/assets/AdapterLifecycle.cs` · `references/范例用法.md` | 原工程的静态显示入口和资源声明 |
| 把静态显示交给管理器 | `portrait-studio-managed/assets/template` · `references/范例用法.md` | 图片和两份声明；已有工程退出托管位置的写图 |

以上路径从对应 skill 文件夹读取，公开工具包的 skill 放在 `skills` 目录，各自附有完整 SDK 与说明。

独立包和托管工程都包含导师的两张候选、房东、通缉照片和场景背景。图片是原创几何图，用于确认绑定和构图。两套工程都声明“立绘1／立绘2”；独立范例可在游戏设置切换，托管范例由支持通用套装声明的管理器提供选择。立绘2只含导师，用来演示缺图时其他目标保持。自定义 NPC 的接入代码见各路线用法；NPC 对象、剧情和身份由创建者工程提供。

在本目录执行以下命令，会在指定的新目录生成两套源码与对应运行包：

```text
python build_examples.py --game-root "目标游戏目录" --output "不存在的范例输出目录"
```

输出的 `source` 用于阅读和修改，`runtime` 下每个子目录是一份完整模组。脚本只读取目标游戏的程序集，不安装、不启动游戏。独立范例可单独换图和切换套装；托管范例需要支持 `portrait-studio-managed/1` 的管理器。

给 AI 的请求可以这样写：

> 先读对应 skill 和范例用法，从自带工程创建我的包。普通换图保留范例的入口、SDK 和构建流程，主要改图片、清单和构图。只读取工具包、我的素材和指定工程；需要确认游戏 API 时再查看指定游戏的公开 API 或程序集。不要参考其他已安装模组的内部实现。

普通包从现有代码开始；新增显示位置或接入原工程时，再按真实创建入口、生命周期和写图路径调整。只为排查测试问题时，先报告工具包中的原因和建议，不修改被测工程或成品。

## 职业范例

增加 `--occupations` 可生成医生、化学家、废料客和共用科学家图片的两套范例。医生和化学家可以使用同一原图而各选候选；没有职业声明的药商沿用共用图片；junker 与 junker2 共用废料客槽。独立包保留设置内的立绘1／立绘2。

```text
python build_examples.py --occupations --game-root "目标游戏目录" --output "不存在的职业范例目录"
```

职业清单和主 key 见各 skill 的 `references/vanilla-client-roles.tsv`。范例只用于开发目录，不会安装或启动游戏。

## 动态接入范例

有动画或自动表情的工程见 [动态接线说明](dynamic/接线说明.md)。包含可编译的两帧切换、独立候选设置、显示交接与大小位置处理。SDK 在 `skills/portrait-studio-dynamic/assets/SDK`；管理器需支持动态显示协议。
