# 动态接线范例

这是供原工程编入的接线类，不是安装即运行的成品模组。示范两张完整人物图片按时间切换；替换 Tick 的选帧部分即可沿用作者原有表情、服装合成或纹理更新。

1. 将本目录接线类和动态 SDK 两份 .cs 编入原工程。skill 内 SDK 在 `../SDK`；完整 SDK 里使用 `skills/portrait-studio-dynamic/assets/SDK`。
2. 把清单 providerId 改成自己的 manifest ID，按实际角色修改 target。示例为原版导师 mentor、两个候选 normal/quick。
3. 原工程实际显示导师时，保存首次可信原图，并传入真实 SpriteRenderer、作者已加载的两帧和默认画布世界尺寸，创建 DynamicPortraitExample。visitId 每次登场使用新的标识。
4. 原工程每帧调用实例 Tick。独立设置切换调用 SetStandaloneCandidate("normal"/"quick")。离场或禁用时 Dispose；然后由原工程清理自建图片。
5. 原项目如果已有 LateUpdate/补丁/异步回调直接写同一图，也要统一检查对应 DynamicDisplay.ShouldWrite。不可只把这个范例放旁边，同时保留不受控制的旧写图。

没有管理器时也能切帧。支持动态协议的管理器可选择候选、调整构图或让作者暂停写图；静态 SDK 不接管这些动画帧。

源码编译检查：`dotnet build DynamicPortraitExample.csproj -p:GameRoot="游戏目录" -p:DynamicSdk="动态SDK目录"`。只生成接线程序集，不复制游戏程序集，不安装、不启动游戏。实际制作需接到作者自己的入口；清单校验使用 skill 的 scripts/validate.py。

图层很多时，以作者现有的共同布局节点或统一几何函数处理参数，silent 收起作者自己的覆盖层。范例改 transform 是单渲染器示意，不能照搬到同时被其他代码移动的公共节点上；基准坐标应在该次登场和作者布局完成后取得。
